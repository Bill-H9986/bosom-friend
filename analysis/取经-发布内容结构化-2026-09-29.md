# 取经：发布内容应该怎么产出（2026-09-29）

> 背景：今天把发布链路跑通了，但作品简介发出去的是**助手对用户说的话**（「已经准备完成。请点击下方
> 「去发布」按钮…」）。根因是「模型自由文本 → 服务端正则抠」。带着这个问题去查业内成熟做法。

## 一、业内共识（三条）

### 1. 不要解析自由文本；要么 Structured Outputs，要么 Function Calling
- **OpenAI 官方**（Introducing Structured Outputs in the API）：用 `json_schema` + `strict: true` 时，
  模型输出**保证**符合 schema ——不是「尽量」，是解码层约束。
- **JSON mode ≠ Structured Outputs**：前者只保证「是合法 JSON」，后者保证「符合你给的 schema」。
  只开 JSON mode 再自己校验/补字段，等于把当年的老问题换个地方重来。
- **Function Calling**：工具的参数定义本身就是 schema，模型「填参数」而不是「写文章」，
  格式错不了——**Agent 的动作应当做成工具**，这是两条正道的第二条。

### 2. 结构化输出与工具调用怎么选
- 要模型**产出数据**（文案、字段）→ Structured Outputs；
- 要模型**执行动作**（发布、写回）→ Function Calling（工具）。
- 我们的场景两者都要：**先产出结构化发布内容，再调用发布工具**。

### 3. 短视频发布内容是有固定结构的（不是一个 title + 一段 body）
社区里成熟的短视频脚本 Skill（short-video-script-skill）把可发布成品拆成：
**选题分析 / 标题钩子 / 口播脚本 / 分镜建议 / 封面文案 / 发布文案 / 话题标签 / 评论区引导**。
其中与「发布」直接相关的是四项：**标题钩子、发布文案、话题标签、封面文案**。
对照我们今天的产物：标题有（对）、正文是对话（错）、话题空（缺）、封面文案无（缺）。

## 二、我们的差距

| 项 | 现在的做法 | 成熟做法 |
| --- | --- | --- |
| 发布内容来源 | 模型自由文本 → 服务端正则抠（extractPublishContent/回落） | 模型**直接产出结构化内容**（工具参数 / schema） |
| 格式保证 | 靠提示词「要求」，模型可能不照做（今天就发生了） | schema 硬约束；不满足就**让模型重来**，不回落、不猜 |
| 内容要素 | 只有 title/body，且常缺 | 标题钩子 + 发布文案 + 话题标签 + 封面文案 |
| 缺字段时 | 回落成整段对话 → 垃圾内容发到平台 | 校验失败即拒绝（宁可这次不发） |

## 三、落地方案（三步）
1. **把发布做成工具**：`bosom_publish_video`，参数即契约——
   `title`（≤30 字）/ `body` / `topics[]` / `coverText` / `declaration` / `mediaUrl` / `accountId`。
   模型调用时必须给全，schema 不过就报错重来；服务端不再做任何「提取」。
2. **文案生成对齐行业结构**：扩展 `bosom_content_generate_script` 的返回，
   从 `{title, content}` 扩到 `{title, body, topics[], coverText}`（也就是上面四项）。
3. **服务端只校验、不提取**：schema 过了就发，不过就让模型重来。
   本轮已经落地的严格口径（缺正文 → 不给「去发布」入口）正是这个方向的第一步，保留。
