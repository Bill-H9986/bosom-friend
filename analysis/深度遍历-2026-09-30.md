## 五、发现清单（按处理优先级）

### P0-A｜明文 API Key 落在业务数据文件（违反 0 号铁律第 3 条）

- **事实**：`~/.bosom-friend/bosom-friend/llm-user.json`（1,399 B）含 `apiKey` 明文（`sk-` 样式，长度 51），另有 `imageApiKey` / `videoApiKey` 字段位。
- **代码路径**：`server/src/api.ts:1284` `writeStoredLlm()` 直接把整份配置 `JSON.stringify` 写进 `llm-user.json`；`readStoredLlm`（:976）、`readStoredLlmRaw`（:985）从同一文件读回。
- **规则原文**：0 号铁律第 3 条 ——「业务数据文件（如 `llm-user.json`）**不得保存明文密钥**」。
- **对照**：`~/.bosom-friend/.credentials.yaml`（98 B）与 `settings.yaml`（509 B）确实存在，`api.ts:1242` 也把 Key 写进凭据库 —— 即**同一份密钥被双写，其中一处是规则明令禁止的**。
- **门禁**：`qa/run-gate.mjs` 全文**没有**任何密钥存储检查（仅 :364 一句注释提到"占位密钥"）→ 属"规则不进门禁"，与 0 号铁律第 6 条同族。
- **建议**：`llm-user.json` 只留 `providerId/baseUrl/model` 等非敏感字段，Key 一律取 `CredentialRef`；迁移后删旧字段；补一条门禁（扫数据根与仓库内 JSON 的 `sk-`/`apiKey` 明文）。
- 注：**本次只读**，未读取/未导出该密钥值，仅统计长度与样式。

### P0-B｜DSH `examples/` 与 `packages/examples/*` 源文件整体缺失
