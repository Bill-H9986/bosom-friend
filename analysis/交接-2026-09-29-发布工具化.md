# 交接：把「发布」改成 AI 智能体的工具（2026-09-29 晚）

> 给下一个会话：这是**当前真实状态**，不是计划。读完直接接着干。

## 一、用户要什么（一句话）
APP 是 **AI 驱动的 agent 工具**：用户说一句话，AI 智能体全自动把事办完。
**发布必须由 AI 智能体以「工具调用」的方式完成**，而不是服务端用正则从模型回复里抠内容。

## 二、为什么这是「开发做错了」，不是产品问题
开发文档写得很清楚，是实现违背了它：
- **铁律 #2 第 1 条**：agent 执行必须走 DSH 的 agent/session/tool 扩展点，**禁止在 REST 路由里重新实现一套独立 agent 循环**。
- **铁律 #0 第 1 条**：能力先于功能（Service Definition / Service Provider / Consumer 三角色）。
- **ADR-002**：业务能力一律注册为 DSH 插件/服务；**只有 AI 主动决策执行的动作才做成工具**，普通增删改查经服务直调，长外部任务走任务队列。

→ 「发布」正是「AI 主动决策执行的动作」，**按文档就该是一个工具**；实际却在 server/src/api.ts 里用正则猜模型回复的排版。

## 四、根因（已定位到行）
server/src/api.ts 的发布分支（约 2403-2434 行）：
1. marker（📝 小红书笔记文案…）未命中 → actionableText = fullText（整段回复）
2. extractPublishContent(fullText) 返回空 title/body/topics
3. agentTitle = parsed.title || titleFallback → 回落成「整段回复的第一句」
4. agentBody  = parsed.body  || cleanText     → 回落成「整段对话」← 灾难

**已做的临时修复（已构建、未重启、未验证）**：
- extractPublishContent 重写：标题容忍「标题：/- 标题：/| 标题 | xxx |」三种写法；
  正文取不到时**逐行剥掉元信息行**（META_LINE），绝不再把对话原文当正文；新增 topics 提取。
- 服务端 lib 已构建，但**服务没重启**，所以还没生效 → 重启前不要用它验证。

## 五、正确做法（下一步要做的）
1. **在 kernel/src/index.ts 注册发布工具**（照现有模式，参考 bosom_content_generate_script）：
   - name: bosom_publish_video
   - parameters（结构化，AI 直接给）：accountId / platform / mediaUrl / title / body / tags / declaration / coverUrl
   - execute: 创建发布记录并拉起引擎（等价于现在前端「去发布」触发的那条链路）
   - output.render: 返回结构化结果（任务 id、提交状态），供界面渲染动作卡
2. **提示词侧**：工具描述里写清参数含义与平台约束（抖音标题 ≤30 字、话题 3-5 个、内容标注必选），
   引导 AI 先写好文案再调工具。
3. **删除脚本式抠取**：api.ts 的 extractPublishContent / titleFallback / tagLine 那套启发式不再用于发布。
4. **前端**：动作卡改为渲染「工具调用结果」，不再依赖自定义字段 navigateToPublish。
