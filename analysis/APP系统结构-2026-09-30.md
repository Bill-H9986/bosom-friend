## 一、用户看到的那一层：7 个侧栏板块 + 2 个常驻入口

| 板块 | 路由 | 干什么 | 数据落在哪 |
| --- | --- | --- | --- |
| **内容创作** | `/draft-box` | 创作（AI 生成图文/视频）+ 素材库 + **形象**（弹窗） | `contents.json` `draft-generations.json` `long-video-tasks.json` `material-groups.json` |
| 任务记录 | `/tasks-history` | 智能体做过什么、每一步的步骤与截图 | `agent-tasks.json` |
| 发布日历 | `/calendar` | 排期 + 已发布 | `publish-records.json` |
| 数据中心 | `/data-statistics` | 作品、播放、互动、平台贡献 | `metrics.json` `publish-records.json` |
| 全局监控 | `/monitor` | 7×24 接待、待办、按客户收纳的 AI 回复 | `reception-*.json` |
| AI互动 | `/ai-interaction` | 热点热榜 + 评论搜索 | 外部服务 |
| 知识库 | `/knowledge` | 笔记、检索注入、蒸馏 | `knowledge.json` |
| 添加频道（侧栏底部） | 弹窗 | 扫码接平台账号、账号库 | `accounts.json` |
| **AI 助手**（右侧常驻） | 全站 | 对话 + 跟随模式执行 | `agent-tasks.json` |

**内容创作页内部**（2026-09-30 融合后）：
- 标签只有两个：`创作` / `素材库`
- 工具栏里有「**形象**」按钮 → 弹窗（上传照片或 2~12 秒人像视频、名字、9 种念法、形象列表与删除）
- 长视频能力不单独成页：**时长档到 300 秒**，超过单次上限自动走分段工作流

**已下线（重定向到内容创作，独立页面不存在）**：`#/long-video`、`#/digital-humans`、`/statistics`、`/account`、`/login`
**不在侧栏但可达**：`/`（介绍页）、`/accounts`（账号页）、`/chat/:taskId`（任务详情）、`/chat`（只读分享页）、`/settings`

## 二、AI 智能体怎么统筹全局（关键）

**它的位置**：右侧助手，全站常驻；「跟随模式」开着时，它发起的页面动作会被前端自动执行。

**它的工作方式**（2026-09-30 重写的系统提示词）：
1. 听清目的 → 2. 拆成"在这个 APP 里该做哪些动作" → 3. 逐个**调用对应板块的功能** → 4. 用页面上的真实结果验收

**它能调的功能（内核注册的 16 个工具）**：

| 类别 | 工具 | 对应的板块功能 |
| --- | --- | --- |
| 只读（看清事实） | `bosom_kernel_ping` | 存活探针 |
| | `bosom_platform_list_accounts` `bosom_platform_login_status` | 账号库 / 登录态 |
| | `bosom_material_list` `bosom_content_list_drafts` | 素材库 / 草稿箱 |
| | `bosom_data_dashboard` `bosom_platform_sync_works` | 数据中心 / 作品同步 |
| | `bosom_reception_list_pending` | 待接待（评论/私信） |
| | `bosom_job_list` | 任务记录 |
| | `bosom_content_video_status` | 出片进度 |
| 执行（把事办完） | `bosom_content_generate_script` | 写脚本/文案 |
| | `bosom_content_create_video` | 发起生成（走内容创作那条链路） |
| | `bosom_content_resume_video` | 从断点继续 |
| | `bosom_content_create_draft` `bosom_content_update_draft` | 存草稿 / 改草稿 |
| | `bosom_publish_content` | 发布（→ 前端弹发布弹窗 → 引擎执行） |

**它不做什么**：不直连后端接口、不写数据文件、不绕过页面；做不到的（热点、知识库、扫码、设置）如实说"去哪个页面做"。

## 三、后端的四层

```
前端（Web，端口 31280）
  │  REST：/bosom-friend/api/*（信封 {code,data,message}）
  ▼
① 服务端  products/bosom-friend/server/src/   （41 文件 / 19,556 行）
    路由：api.ts(6283 行，主) · routes-channels · routes-content · routes-knowledge
    业务：agent-context（语境）· platform-login（登录/发布）· platform-sync（数据回流）
          long-video（分段出片）· video-compose（ffmpeg 拼接）· reception-engine（7×24 接待）
          knowledge-distill（检索/蒸馏）· object-actions（对象级 AI 动作）· agent-skills（经验升格技能）
    存储：store.ts（JSON + schema 信封 + 原子写 + 跨进程同源保证）
  ▼
② 内核  products/bosom-friend/kernel/src/   （5 文件 / 1,247 行）
    DSH 官方运行时（dsh-base）+ 产品插件；注册上面那 16 个工具
    工具面收敛：禁用 pwsh / fs / subagent / workflow 等编码类工具（对普通用户是风险）
    纯文本生成（写稿/检查）时工具面为 0，模型看不到任何工具
  ▼
③ 平台引擎  products/bosom-friend/engine/   （worker.py 73.8KB + vendored social-auto-upload）
    子命令：login / daemon / sync / profile / publish / cover / interact
    真实 Chrome + CDP + 拟人化节奏；验证码出现即暂停等真人（600 秒）
  ▼
④ 数据根  %USERPROFILE%\.bosom-friend\bosom-friend\
    30+ 个 JSON 域（账号、内容、素材、发布记录、指标、接待、知识、长视频任务…）
    发布任务目录：platform-login/publish/<taskId>/{input.json,state.json,worker.log,error.log}
```

## 四、一条业务流穿过哪几层（创作 → 出片 → 发布 → 数据）

1. 用户对 AI 说一句"做条无人机培训的视频并发到抖音"
2. **AI（内核）**拆步骤 → 调脚本生成 → 调出片 → （完成后）调发布
3. **服务端**接住：建任务、写盘、调度
4. **引擎**：真实浏览器逐镜出片 / 在抖音逐项填写并提交
5. **数据落盘** → 页面刷新可见（草稿箱、发布记录、数据中心）
6. **AI 回读**真实结果（N/M 镜、平台作品 ID）→ 如实汇报

## 五、当前状态与缺口（2026-09-30）

**已完成**
- 长视频页 / 数字人页**已下线**（路由重定向），功能并进内容创作页：形象管理是工具栏里的弹窗
- 智能体规则重写为"**APP 操作员**"视角：拆步骤 → 调各板块功能 → 前端执行；A/B/C/D 四块能力面 + 标准工作流（形象→提示词→增强→参数→生成→盯进度→交付）
- 发布 / 建草稿 / 改草稿三个动作改为**前端执行**（AI 只申请，前端页面动手）
- 续跑校验修掉"僵尸任务"死锁（进程已死但状态还挂在 generating → 现在能识别并允许续跑）

**缺口**
- **长片的进度 / 生成记录 / 断点继续还未进内容创作页**（只在工具层）；这正是你那条 `lv-d5b7dea0` 停在 18/21 镜却看不到、也点不了的原因
- 规则与上述改动**需要重启实例才生效**
