## 1 背景与目标

### 1.1 背景

RTM 回答的是「需求有没有被测试覆盖」，它的起点是 **REQ 编号**。
本轮重构后，需求的载体变成**能力**（一句话 + 工具 + 页面可见结果），
且 BFS-500 第 6 节把追溯链明确定义为四环：

| 环 | 内容 | 缺了会怎样 |
| --- | --- | --- |
| ① 能力 | 用户会说的那句话 + 归属管家（登记在能力台账） | 不知道为谁做 |
| ② 工具 | 管家可调用的工具 + 服务端实现位置 | 关掉页面办不成事 |
| ③ 证据 | C 档验收记录（工具序列 + 三方交叉） | 无法证明办成过 |
| ④ 记录 | 工作日志 + 能力台账 + 活记忆（缺陷另记缺陷台账） | 下次没人知道做过 |

**判据**：随机挑一条能力，能在 5 分钟内找齐四环（BFS-500 第 6 节）。

### 1.2 目标（编号化）

| 编号 | 目标 | 判据 |
| --- | --- | --- |
| **G1** | 每条已工具化能力四环可指 | 每一行都能指到工具位置、证据形式与记录去处 |
| **G2** | 断链可见 | 缺环的行显式标注，不允许「默认认为有」 |
| **G3** | 不重复能力状态 | 能力现状只写在能力台账，本矩阵只记链路 |
| **G4** | 可被门禁抽查 | 门禁可随机抽行并检查工具定义位置是否存在 |

## 3 追溯矩阵

### 3.1 读法

| 列 | 含义 | 取值口径 |
| --- | --- | --- |
| 那句话 | 用户会说的原话 | 与能力台账一致 |
| 工具 | 内核已注册的工具名 | `kernel/src/index.ts` 的 `ctx.tools.register` |
| 位置 | 工具定义所在文件与 `name` 声明行号（2026-10-11 实测） | 行号以当日文件为准，漂移即修 |
| 证据 | 验收时要留的 C 档证据形态 | 三方交叉的具体可核对对象 |
| 记录 | 结果写到哪三处 | 工作日志 / 能力台账 / 活记忆 |

**链路列取值**：`齐`＝四环都有；`待证`＝工具已注册但还没有 C 档证据；`断`＝缺环。
**能力状态（已有 / 待验证 / 需工具化）以能力台账为准，本表不复制。**

### 3.7 断链清单（缺口能力）

缺口明细**以能力台账第 6 节为准**（唯一事实源），本矩阵只记「链路断在哪一环」：

| 断在哪一环 | 表现 | 处置 |
| --- | --- | --- |
| 第 ① 环之前 | 能力只在页面有入口，管家完全不会（例如复盘、涨粉分析） | 先在能力台账登记那句话，再补工具 |
| 第 ② 环 | 有服务端能力但没注册工具（例如排期、回复评论） | 按 BFS-102.1 注册工具 |
| 第 ③ 环 | 工具已注册但从未取得 C 档证据（上表标「待证」的行） | 补一次一句话端到端验收 |
| 第 ④ 环 | 办成了但三处记录没写 | 按 BFS-303 补齐 |

## 4 维护规则

| # | 规则 | 判据 |
| --- | --- | --- |
| 1 | 新工具注册后**必须**在本矩阵补一行 | 矩阵行数 = `kernel/src/index.ts` 的工具注册数 |
| 2 | 能力状态变更只改能力台账，本矩阵不改 | 两处出现同一条现状即判重复 |
| 3 | 断链**必须**显式标注并写明补链计划 | 「断」的行都有对应待办 |
| 4 | 行号漂移**必须**修正 | 抽查 3 行的位置能否在文件里找到同名工具 |
| 5 | 每次发布**必须**复算一次行数 | 见第 6 节 |

## 5 判据与验收（本件自身）

| # | 判据 | 怎么验 |
| --- | --- | --- |
| V1 | 四环可指 | 随机抽 3 行，5 分钟内找齐能力 / 工具 / 证据 / 记录 |
| V2 | 行数对得上 | 矩阵行数 = 工具注册数（2026-10-11 为 31） |
| V3 | 位置有效 | 抽查行的文件与行号能找到对应工具名 |
| V4 | 无重复事实 | 全文不出现能力的完成状态判断（那是能力台账的事） |
| V5 | 断链可见 | 标「断」的行都有缺陷编号或待办 |

**未达成时的处置**：V2 不达标即本矩阵过期，当场补齐；V3 不达标修正行号；V1 不达标说明链路事实缺失，按第 3.7 节处置。
