## 1 背景与目标

### 1.1 背景

ADR-005 把产品形态改为 AI 管家后，项目里同时存在三代文档：

1. **板块制时代**（19 板块 / 132 功能点 / 页面点得对）；
2. **对标时代**（飞书 × 豆包形态）；
3. **管家形态**（BFS-100 v2.0 / BFS-104-R）。

三代文档混在一起时，最大的风险不是「有旧文档」，而是**旧文档被当成现行口径引用**——
执行者按旧标准干活，做完才发现判据早就换了。

### 1.2 目标（编号化）

| 编号 | 目标 | 判据 |
| --- | --- | --- |
| **D1** | 每一篇文档都有唯一裁决 | 逐份清单能对上磁盘实际文件，无漏项、无多余项 |
| **D2** | 每一篇裁决都有理由与去向 | 每行都回答「为什么」与「接下来去哪」 |
| **D3** | 现行事实源唯一 | 同一事实只在一个地方写（BFS-400 第 6.4 节） |
| **D4** | 裁决可执行 | 废止与重写项有具体动作；归档项有明确落点 |

### 1.3 范围

| 范围 | 数量 | 说明 |
| --- | --- | --- |
| `products/bosom-friend/docs/**/*.md` | **117 篇** | 含 115 篇既有文档 + 本次新增的 2 篇（总纲 v2.0、本表 v2.0） |
| `products/bosom-friend/qa/*.md` | **14 篇** | qa 顶层规则类文档（含 qa/README.md） |
| `qa/` 下的脚本与分析档案 | 口径裁决，不逐份列举 | 见第 5 节 |

**不在范围**：`qa/` 子目录里的报告、证据、缺陷台账（缺陷台账是独立事实源）；`engine/`、`server/`、`kernel/` 等代码目录下的说明文件。

## 2 术语与裁决口径

### 2.1 术语

| 术语 | 定义 |
| --- | --- |
| **现行事实源** | 被别的文档引用时可以直接当依据的那一份（BFS-400 第 6.4 节：一个事实一个家） |
| **被替代件** | 已被新版本替代但仍保留的文档（BFS-400 第 8.3 节：不删除、要标注） |
| **归档** | 移出当前事实层、只作历史追溯的文档 |
| **废止** | 内容与管家形态冲突、明确不再使用的文档 |
| **去向** | 这份文档接下来落到哪里（保持 / 移入归档 / 重写为某件 / 只作历史） |

### 2.2 四类裁决的判据

| 裁决 | 判据（同时满足才可判此） | 处置动作 |
| --- | --- | --- |
| **保留** | ① 仍服务于「一句话端到端 + 管家形态」；② 内容是现行事实或仍有效的资产 | 保持原样；若属于规范级，按 BFS-400 补齐结构 |
| **重写** | ① 主题仍然需要；② 内容口径过时（板块制、页面监考、旧对标）或结构不合 BFS-400 | 按 BFS-400 对应级别重写；旧版归档 |
| **归档** | 内容是某个时点的过程记录（日志、审计、测试报告、旧方案），不再是当前事实 | 移入 `过程档案/`；正文不得作为现行口径引用 |
| **废止** | 内容与管家形态直接冲突，或已被新文档完整替代且无独立价值 | 标题或文档头标注替代 / 废止关系后保留，供追溯 |

### 2.3 裁决依据

| 依据 | 用途 |
| --- | --- |
| ADR-005 | 产品形态是 AI 管家（一切裁决的第一判据） |
| BFS-100 v2.0 | 判断某文档是否还服务于管家形态（101~109、201~206、301~306） |
| BFS-104-R | 判断验收类文档是否还成立（三档证据、三方交叉、六步流程） |
| BFS-400 | 判断文档结构是否合格（A / B / C 三级必备结构） |
| 能力台账 v1.0 | 判断「功能清单」类文档是否已被取代 |
