## 一、先看清你现在的真实位置

你**不是零基础**。你做出来的东西已经踩在 AI 工程最难的那一层上，只是知识点是散落的。把项目里的既成事实摊开：

| 领域 | 你已经做到的（有代码与实测为证） | 位置 |
| --- | --- | --- |
| **模型接入（LLM 调用层）** | BYOK 多厂商配置、流式输出、超时预算、失败可读回退、模型配置单一权威 | `server/src/`、`qa/verify-llm-config.mjs` |
| **提示工程** | 口播稿/标题/文案的指令约束、结构化产出、按平台调性改写；接待话术规则；知识库蒸馏 | `engine/worker.py`、`qa/knowledge-distill.mjs` |
| **工具调用 / Agent 循环** | 9~14 个 `bosom_*` 内核业务工具、任务卡闸门（按意图拦/放）、动作卡与前端联动 | `products/bosom-friend/kernel/` |
| **运行时与内核** | 装官方 DSH 内核（插件化：Service Definition / Provider / Consumer）、会话日志即事实源、`SESSION_FORMAT_VERSION` 迁移 | `products/bosom-friend/kernel/`、`launcher/` |
| **检索与知识库** | 390 篇笔记的笔记库、结构/契约/来源三要素检索、按需注入上下文（不用向量库） | `electron/main/knowledge/`、`docs/知识库/` |
| **多模态生成** | 文生图（分辨率/画幅契约）、图生视频（首帧契约）、数字人（音色 + 形象）、ffmpeg 合成；**AI 带货片九步工序**（脚本 → 配音为母时钟 → 分镜表 → 参考图集 → 逐镜生成 → 时间轴校验 → 组装 → QC）与厂商能力边界实测 | `server/src/video-*`、`digital-human` |
| **评测与质量** | 门禁红黄绿三色语义、S 级前端监考、可重放快照、负向对照、缺陷台账与根因归类 | `qa/run-gate.mjs`、`qa/defects/` |
| **成本 / 性能 / 数据** | 轮询预算标定、低配降载、数据落盘与编码完整性、零外发与安全边界 | `qa/probes/`、`perf-profile.cjs` |

**这些不是"用过 API"，是 AI 应用的完整骨架。** 你缺的不是入门，是三样：

1. **理论闭环**：知道"为什么这么设计"，能把经验说成原理（否则换个场景就不会了）；
2. **评测与数据能力**：现在靠门禁和人工判断，没有**量化指标**（召回率、准确率、通过率曲线）；
3. **训练侧能力**：从没训过/微调过模型——而你手里**恰好有最稀缺的东西：真实任务轨迹数据**。

## 二、总路线（24 周，五阶段）

```text
P0 把经验变成原理（第 1~3 周）      —— 目标：能讲清原理，能改内核行为
P1 检索与评测（第 4~9 周）          —— 目标：知识库从"能搜"到"可量化"
P2 训练与微调（第 10~16 周）        —— 目标：用本项目数据训出第一个自己的模型
P3 Agent 工程化（第 17~21 周）      —— 目标：多智能体分工与护栏，跑得稳、算得清
P4 系统与持续（第 22~24 周 + 长期） —— 目标：推理优化、成本账本、跟上领域
```

**三条铁律（沿用你自己项目里的口径）**：

1. **没有端到端证据不算学会**（对应项目铁律 #13）：每阶段的产出必须能跑出 PASS 原文或指标曲线；
2. **每学一个概念，就在本项目里找一个真实缺陷作对照**（你的 68 条缺陷就是最好的习题集）；
3. **学完就写一篇知识库条目**（`docs/知识库/条目/13-…` 起），并同步 Obsidian——这是你的复习机制，不是作业。

## P0　把经验变成原理（第 1~3 周）

### 学什么

| 主题 | 必须能回答的问题 |
| --- | --- |
| Transformer 与注意力 | 为什么上下文越长越贵？KV cache 是什么？为什么"长上下文 ≠ 记得住"？ |
| Tokenization | 中文为什么比英文贵？为什么同一条提示词换个写法成本差一倍？ |
| 采样与解码 | temperature / top_p / 惩罚项怎么影响"口播稿"这种创作任务？ |
| 提示工程的结构化写法 | 角色、约束、示例、输出格式四段式；什么是"指令漂移"（你的 DEF-044 就是活例） |
| 上下文工程 | 系统提示 / 工具描述 / 历史 / 检索片段 / 当前任务，各占多少预算、谁先被截断 |
| 幻觉与不确定性 | 为什么必须"无源不显示"（你的要求二 R3）？模型自评可信吗？ |

### 用项目做的练习（每项都有产出）

1. **给"口播稿生成"写提示词规格**：输入契约（主题/时长/平台/风格）、输出契约（可解析的结构）、失败态（信息不足时的回退话术）。落到 `docs/规范/提示词规范.md`，并把现有硬编码提示词迁进去（提版本号，别改行为）。
2. **做一次上下文预算实验**：固定任务，逐步增加检索片段与历史轮数，记录质量与 token 花费的曲线，写成条目（这是 P1 评测的前置）。
3. **复盘三个缺陷的理论根因**：DEF-050（轮询预算 < 真实耗时 ⇒ 静默降级）、DEF-044（意图闸门把"写笔记"当"发布"）、DEF-040（承诺了做不到的兜底）——每个写一段"用 AI 工程术语解释这条缺陷"。

### 验收判据

- 能**不看资料**讲清：token 计费口径、上下文窗口与截断策略、采样参数对输出的影响；
- 产出一份 `提示词规范.md` + 一篇实验条目；
- 三个缺陷的理论复盘各 200 字以上，且能被别人按同样术语复述。

**材料**：DeepSeek / OpenAI 官方 API 文档与提示词指南；`docs/知识库/条目/07-门禁设计原则.md`（把"判据思维"迁移到模型评测）。

## P1　检索与评测：从"能搜"到"可量化"（第 4~9 周）

这是**投入产出比最高**的一段，也是你现在最薄的一环：知识库有 390 篇，但没有任何量化指标。

### 学什么

| 主题 | 关键点 |
| --- | --- |
| Embedding 与向量检索 | 语义相似度、维度、归一化；为什么关键词检索在中文短查询上会输 |
| 分块（chunking） | 按标题/段落/语义切；重叠窗口；"一片一事" |
| 向量库与混合检索 | 关键词 + 向量 + 元数据过滤（时间、来源、类型）三路融合 |
| 重排（rerank） | 先粗召回再精排；为什么 rerank 常常比换更大模型更划算 |
| RAG 评测指标 | 召回率@k、命中率、MRR、忠实度（答案是否有出处）、拒答率 |
| 评测集构建 | 从真实使用里挖问题；正例 + **负例**（该拒答的）缺一不可 |

### 用项目做的练习

1. **建 100 条评测集**：从工作日志、缺陷台账、知识库条目里出题（"0.2.51 修了什么"、"端口隔离为什么假红"…），一半是**知识库里有答案**的，一半是**故意没有答案**的（考"该说不知道"）。
2. **给知识库加一路向量检索**（先离线脚本即可，不必接进 APP）：关键词 / 向量 / 混合三种跑同一套评测集，出一张对比表。
3. **实现拒答与出处分级**：命中强证据 → 直接回答并给出处；弱证据 → 明示不确定；无证据 → 明说不知道（延续你"无源不显示"的产品口径）。
4. **把评测接进门禁**：新增一项 `qa/verify-knowledge-retrieval.mjs`，输出"通过率 + 失败样例"，红黄绿语义沿用现有口径。

### 验收判据

- 评测集 ≥100 条，含负例；**有一套可复跑的脚本**（不是手工数）；
- 混合检索相对纯关键词，在召回率或答案命中率上有**可复核的提升**（表格 + 脚本输出）；
- 拒答行为可测：负例上的"该拒答就拒答"通过率 ≥ 90%；
- 产出一篇条目《RAG 评测怎么做才不骗自己》，含失败样例。

**材料**：向量检索与 RAG 的综述文章、主流向量库文档（Chroma / Qdrant / pgvector 任选其一）、rerank 模型说明。

## P2　训练与微调：用你自己的数据训一个模型（第 10~16 周）

**这是你和 90% 的"AI 应用开发者"拉开差距的地方**：他们只有提示词，你有数据。

### 学什么

| 主题 | 关键点 |
| --- | --- |
| 数据集构造 | 从会话日志与任务轨迹里抽 (输入 → 正确输出) 对；清洗、去重、脱敏 |
| SFT（监督微调） | 数据格式（对话/指令）、样本量级与质量的关系、过拟合的信号 |
| LoRA / QLoRA | 为什么小样本适配用 LoRA 就够；rank、alpha、target modules 怎么选 |
| 评测与回归 | 微调后必须跑**同一套评测集**（P1 的成果直接用上），并防"改好了 A 弄坏了 B" |
| 部署与版本 | 权重版本化、推理服务（vLLM / llama.cpp）、灰度与回滚 |
| 成本与合规 | 训练成本、数据是否可以出境、用户数据脱敏边界（你的零外发口径） |

### 用项目做的练习（三选一，建议按顺序）

1. **小任务 A：风格适配**。用你项目里"口播稿/标题"的真实产出构 300~1000 条样本，LoRA 微调一个小模型（1.5B~7B），目标：在固定评测集上**风格一致性**优于通用提示词基线。
2. **小任务 B：意图分类器**。把 DEF-044 那类"该拦不该拦"的判断做成小分类模型（发布/创作/闲聊三分），用缺陷台账里的历史案例当测试集——目标是让闸门不再靠正则。
3. **小任务 C（进阶）：工具调用小模型**。从内核工具调用日志里抽 500 条 (用户话 → 工具名+参数)，微调后与"通用模型 + 提示词"对比准确率。

### 验收判据

- 有**数据集卡**（来源、条数、脱敏处理、许可）+ 训练脚本可复跑（固定随机种子）；
- 与基线对比表：至少 3 个指标（准确率 / 风格一致 / 成本或延迟）；
- 微调模型能在本机以 OpenAI 兼容接口起服务，并被你的应用通过"模型配置"接进去（你的 BYOK 设计天然支持）；
- 一篇条目《用 500 条真实轨迹微调小模型：踩了什么坑》。

**注意**：微调**不是**万能药。先做 P1 的检索与评测——数据不行，微调只会把错误学得更像。

## P3　Agent 工程化：从"能跑"到"跑得稳、算得清"（第 17~21 周）

你现在已经有 Agent 循环与工具，缺的是**多智能体分工、记忆管理、护栏体系、成本账本**。

### 学什么

| 主题 | 关键点 |
| --- | --- |
| 规划与反思 | ReAct / plan-and-execute / 反思重试；什么时候该拆任务 |
| 多智能体 | 编排者—执行者模式、并行 fan-out 的收益与风险、子智能体结果如何汇总 |
| 记忆分层 | 工作记忆（当前任务）/ 情节记忆（会话轨迹）/ 语义记忆（知识库）/ 长期偏好 |
| 护栏（Guardrails） | 输入校验、意图闸门、危险动作二次确认、输出脱敏；**你的动作卡闸门就是雏形** |
| 可观测性 | 轨迹留痕、每一步的输入输出与耗时、失败归因（区分模型错 / 工具错 / 环境错） |
| 成本与延迟工程 | 预算、缓存、并行、模型分级路由（简单活给小模型） |

### 用项目做的练习

1. **把"全自动发布"改造成显式状态机**：每个状态有进入条件、证据、失败出口；红灯不许静默跳过。
2. **做一份 Agent 成本账本**：一条完整业务（创作→生成→发布→互动）的 token 与耗时分解，找出最贵的三步并优化其中一步（用实测数字说话）。
   > **已实测澄清（2026-09-16，见条目 14）**：Agnes 的**文本调用是有用量的**——非流式响应带 `usage`，流式需 `stream_options.include_usage`；是我们自己的中间层把它丢了（`kernel-client.ts` 只取文本，`api.ts` 把 `usage` 硬编码成 0），而**图像/视频端点确实没有用量**（只有张数/秒数）。所以账本分三档并分别标注：**A 实测**（文本 token，取自 `assistant/message` 事件的 `usage`）、**B 估算**（图像/视频按业务量，文本按带标定的字符换算）、**C 墙上时间**（本地计时，覆盖全链路）。硬编码的 0 比「没有字段」更糟：它看起来像实测值。
3. **给内核工具加"轨迹回放"**：把一次真实任务的所有工具调用录下来，可离线重放（这也顺手解决你项目里"真模型测试要额度"的老问题）。
4. **子智能体并行跑一次**：把一个可并行的任务（例如批量平台素材整理）拆给多个子智能体，记录加速比与失败率。

### 验收判据

- 有状态机图 + 代码，且**每个失败分支都有测试**；
- 成本账本有真实数字，优化前后对比可复核；
- 回放可复现：同一轨迹重放，工具调用序列一致（差异必须能解释）；
- 一篇条目《Agent 的成本都花在哪》。

## P4　系统与持续（第 22~24 周 + 长期）

| 主题 | 你要达到的程度 |
| --- | --- |
| 推理优化 | 量化（int8/int4）、批处理、KV cache 复用、投机解码的基本取舍 |
| 服务化 | vLLM / Ollama / llama.cpp 各自适用场景；你的应用如何做模型路由 |
| 评测工程化 | 评测集纳入版本管理；模型/提示词变更必须跑回归（就像你的门禁） |
| 安全与合规 | 提示注入防护、密钥管理、用户数据边界、内容合规（你已有平台红线经验） |
| 跟上领域 | 每周 1 篇论文/技术报告精读 + 1 次小实验；把结论写成条目 |

### 长期习惯（最重要，成本最低）

1. **每周一篇"条目"**：结论 + 证据 + 反例，进 `docs/知识库/条目/`，并同步 Obsidian；
2. **每月一次"回放复盘"**：挑一条自己的历史决策，问"用今天的知识会不会做得不一样"；
3. **每季度一次"能力盘点"**：对照本文件五个阶段，标注真实水平（不许美化）。

## 六、常见误区（都被你的项目验证过）

| 误区 | 你的项目里的对应事实 |
| --- | --- |
| "换个更大的模型就好了" | DEF-050：真正的坑是**超时预算没按实测标定**，不是模型不行 |

| "等做完再补测试" | DEF-014：空台账让门禁空过——没有断言的质量体系等于没有 |
