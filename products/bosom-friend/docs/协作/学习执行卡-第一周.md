# 怎么用这个项目真正学会 AI（学习执行卡）

> 成文：2026-09-16　｜　配套：`docs/协作/AI深度学习方案与学习计划.md`（路线与判据）
> **这份文件的唯一目的**：把"看别人做完"变成"你自己做出来"。
> 你上一轮的原话：「那我干什么？你做了我不还是啥也不会吗！」——这句话是对的，所以从这一份开始改分工。

---

## 一、分工怎么改（这是全文最重要的一节）

| 谁 | 干什么 | 不干什么 |
| --- | --- | --- |
| **你** | 读代码、写第一版脚本、跑真实调用、记录数字、下结论、写条目 | 不用从零查 API 文档（我给入口） |
| **我（AI）** | ①给任务卡与判据；②卡住时给**提示**（不直接给代码）；③**批改**你的产出，指出哪里是推测哪里是实测；④你要求时才代做，并注明"这是代做，学不到东西" | 不再默认替你写完 |

**判断有没有学会的唯一标准**：**能不能不看我的结论，自己重做一遍并得到可复现的证据。**

---

## 二、每个练习的固定形状（照这个格式做，别改成"看一遍"）

```text
① 预言：先写下"我认为会是什么/为什么这么设计/我会怎么测"（不看代码、不看我的结论）
② 实测：写脚本或读代码，拿到真实输出（贴原始结果，不是转述）
③ 对照：我的结论 vs 你的实测，差在哪，为什么
④ 一句话结论 + 证据：写进 docs/知识库/条目/（含"我原来的猜想错在哪"）
⑤ 复盘：这次学到的方法，能不能套到别的地方
```

第 ①⑤ 步是学习发生的地方；跳过它们，第 ②③ 步就只是看答案。

## 三、第一周（7 天）逐日任务卡

时间：每天 45~90 分钟；全部围绕**已经存在的真实代码与真实数据**，不需要额度和新环境。

### Day 1（45 分钟）：自己回答「用量到底有没有」
- **① 预言**（先写下来，10 分钟）：Agnes 的文本/图片/视频三类调用，各自会不会返回 token 用量？为什么？
- **② 实测**（25 分钟）：读 `qa/probes/agnes-usage-probe.mjs`，然后**自己重写一个更小的版本**（允许参考它，但你要能逐行解释），改成只打一个端点、只打印响应顶层键。
- **③ 对照**（10 分钟）：跟 `docs/知识库/条目/14-Token与成本记账.md` 比。**你漏了哪一类端点？为什么漏？**
- **交付**：新脚本 + 三行结论（贴在聊天里给我批改）。

### Day 2（60 分钟）：亲手跟一遍"数据在哪丢的"
- 打开 `products/bosom-friend/server/src/kernel-client.ts`，找到 `assistantTextOf`：
  - 问题 A：一个 `session.event` 里除了文本增量，还有哪些字段？（读上游 `packages/core/session/src/types.ts` 的 `assistant/message` 事件定义）
  - 问题 B：`usage` 从适配器到这个事件，中间经过哪几个包？（画出链路，允许只画主干）
- **交付**：一张链路图（手画拍照也行）+ 一句"如果只改一处最省事，改哪一处、为什么"。

### Day 3（60 分钟）：真实产出在哪里
- 找到 `recordDistillation`（`server/src/knowledge-distill.ts`），回答：产物落在哪个文件、最多存多少条、一条里有哪些字段？
- 然后打开 `~/.bosom-friend/bosom-friend/knowledge.json`，**用脚本**统计：`distillations` 有多少条？成功/失败各多少？带 `knowledgePaths` 的占比？
- **交付**：脚本 + 统计数字。**注意**：这是你未来的训练语料，先摸清它有多少、干不干净。

### Day 4（60 分钟）：文件阅读（先别问模型）
- 任务：从 `知识库/条目` 里挑 10 篇，每篇读**首段 + 各级小标题**，写出 10 个候选问题，其中 5 个必须"知识库里没有答案"。
- **交付**：问题清单（正例 5 + 负例 5）。这是 P1 评测集的第一批，**必须自己出题**——出题能力就是评测能力。

### Day 5（60~90 分钟）：关键词检索基线
- 写一个脚本：输入问题 → 在 390 篇笔记里做关键词/字面匹配 → 输出命中的前 3 篇与片段。
- 然后在 Day 4 的 10 个问题上跑，记录：**命中率（正例里排前 3 的有几个）**与**误召回（负例里也"命中"的有几个）**。
- **交付**：一张表（问题 / 命中第几 / 是否正确拒答）+ 你踩到的 2 个坑。

### Day 6（90 分钟）：读真实会话（不用 API 额度）
- 去 `~/.bosom-friend/sessions/` 找一份会话日志，用脚本打印：事件类型分布、一次用户请求对应多少次模型调用、工具调用序列。
- 回答：**这条会话里，"最慢的一步"是哪一步？（只有墙上时间可量，就用墙上时间）**
- **交付**：一段"这条会话发生了什么"的叙述 + 你观察到的 1 个问题（例如某步重试了、某步静默失败了）。

### Day 7（60 分钟）：收口
- 把 Day 1~6 的产出压缩成 **1 篇条目**（`docs/知识库/条目/15-…`，标题自己起），含：结论 3 条、证据 5 条、我原来的猜想错在哪、下一步想问的问题 2 个。
- **交付**：条目 + 一段 3 分钟的口头讲解（能不看稿讲清链路与数字）。

## 四、什么时候找我（把"用 AI"变成能力而不是拐杖）

| 场景 | 怎么用我 |
| --- | --- |
| 卡住超过 20 分钟 | 只说"我在做 X，卡在 Y，我试过 Z" → 我给**提示**，不给成品 |
| 做完想验对错 | 贴你的产出 → 我批改：哪句是实测、哪句是推测、判据缺什么 |
| 概念不懂 | 我给你一个**最小可跑的对照实验**（例如"上下文截断到底发生在哪"），你自己跑 |
| 赶时间 | 你说"这次代做"，我做完会**标注这是代做**，并列出"你需要补的三件事" |
| 想要答案 | 先写你的预言，我再给结论——顺序反了，学习就不发生 |

## 五、自我检查（每周一次，5 分钟，写下来）

1. 这周我**自己动手**做出了什么？（没有具体产出 = 这周没学到）
2. 我能不能**不看资料**讲清这周的核心链路？
3. 我的结论里，哪些是**实测**、哪些是**推测**？标了吗？
4. 我提的问题比上周更具体了吗？（"为什么慢"→"第 3 段轮询了 7 次、每次 5 秒，为什么预算是 180 秒"）
5. 我有没有把"AI 帮我做完"当成"我学会了"？

---

## 六、警戒线（这几件事一做，学习就白费了）

- ❌ 让 AI 写完，自己只跑一遍 → 你学会的是"运行命令"，不是"建立链路认知"；
- ❌ 跳过 Day 1 的"预言"直接看结论 → 你失去了唯一能暴露认知缺口的机会；
- ❌ 只收集文档不产出数字 → 你的知识库已经很厚了，缺的是你脑子里的判断；
- ❌ 遇到报错就丢给 AI → 报错是最好的老师，先自己读三遍再问；
- ❌ 把"我让 AI 写了脚本"当成"我会写脚本" → 标准永远是：**关掉 AI 还能不能重做一遍**。
