## 1 背景与目标

### 1.1 背景

产品此前只有一个智能体：一份写死的系统提示词（`server/src/agent-rules.ts` 的 `AGENT_RULES`）+ 一整包工具。
它带来三个具体问题：

| # | 问题 | 现场表现 |
| --- | --- | --- |
| 1 | **职责糊在一起** | 创作、发布、接待、设置全在同一个提示词里；越权动作（未获指令的发布）只能靠一句「红线」约束 |
| 2 | **工具面没有边界** | 34 个 `bosom_*` 工具对同一个智能体全部可见，任何一步都可能直接触达对外动作 |
| 3 | **规则改一处动全身** | 一条业务规则改动等于改提示词全文，无法按管家单独演进、单独验收 |

ADR-005 定的形态是**一个总管 + 四个管家**（创作 / 发布 / 运营 / 设备）。本规格把形态落成可施工的组装说明：
每个管家由一份 preset（人设 + 技能 + 工具面）组装，规则写进技能文件，工具面按职责切分。

### 1.2 目标（编号化）

| 编号 | 目标 | 判据 |
| --- | --- | --- |
| **G1** | 五个 agent 各有独立 preset | `presets/` 下五份 `agent.cordis.yml` 均可加载并完成内核握手 |
| **G2** | 工具面即权限边界 | 任一管家看不到、也调不到不属于自己职责的工具；越权请求被移交或拒绝 |
| **G3** | 规则住在技能文件里 | 改一条业务规则只改技能文件，不改代码（BFS-106.2） |
| **G4** | 管家之间靠交接协作 | 跨管家任务在留痕里能看到结构化的交接记录（谁交给谁、交什么、交到哪一步） |

### 1.3 范围

| 项 | 内容 |
| --- | --- |
| 管 | 五份 preset 的组装规格、四管家的职责与边界、工具面分配、技能清单、交接约定 |
| 不管 | 工具的内部实现（属能力层）、风控数值（属 BFS-800）、验收流程（属 BFS-104-R）、界面呈现（属呈现层） |
| 现状口径 | 本规格的「现状」列一律标 2026-10-11 实测来源；**未建成的目录与未注册的能力不写成现状** |

> **重要前提**：`presets/`、`skills/` 两个目录**当前尚未建立**（来源：结构说明 v2.0 第 6 节、开发报告 v2.0 第 78 行）。
> 本规格定义的是**目标结构与验收判据**，落地进度以《能力台账》与工作日志为准。

## 2 术语

| 术语 | 定义 | 出处 |
| --- | --- | --- |
| **管家** | 由一份 preset（agent.cordis.yml + 技能 + 人设）组装出来的专职 agent | BFS-100 §0.4 |
| **总管** | 不归属任何垂直业务、负责理解与分派的管家 | ADR-005 |
| **preset** | 管家组装目录：一份 `agent.cordis.yml`（人设 + 工具面 + 技能装载） | BFS-100 §0.4 |
| **工具面** | 某个管家在工具目录里**能看到并调用**的工具集合；工具面之外的工具对该管家不存在 | 本规格第 5 节 |
| **技能（Skill）** | 一段可被模型按需加载的专业流程（适用场景 / 步骤 / 判据 / 反例 / 来源） | BFS-106.3 |
| **交接** | 一个管家把任务（含对象标识与已完成的步骤）移交给另一个管家或用户的结构化动作 | 本规格第 7 节 |
| **拍板** | 用户在四类动作（发布 / 删除 / 花钱 / 对外沟通）上的明确指令 | BFS-105.1 |
| **一句话端到端** | 人话输入 → 管家自行拆解并执行 → 页面可见结果 | BFS-104.1 |

## 3 组装规格

### 3.1 组成：一个总管 + 四个管家 = 五份 preset

| preset | 代号 | 角色 | 工具面规模（目标） |
| --- | --- | --- | --- |
| `steward` | 总管 | 理解那句话 → 分派 → 汇总 → 汇报 | 3 |
| `creator` | 创作管家 | 从选题到成片到草稿箱 | 19 |
| `publisher` | 发布管家 | 从草稿到平台作品，并回读结果 | 4 |
| `operator` | 运营管家 | 数据回读、评论私信接待 | 4 |
| `device` | 设备管家 | 账号、登录态、模型配置、个人资料 | 4 |

### 3.2 目录规格（目标结构）

| 路径 | 内容 | 状态 |
| --- | --- | --- |
| `presets/steward/agent.cordis.yml` | 总管线：人设 + 分派规则 + 总管工具面 | 待建（P2） |
| `presets/creator/agent.cordis.yml` | 创作管线的组装 | 待建（P2） |
| `presets/publisher/agent.cordis.yml` | 发布管线的组装 | 待建（P2） |
| `presets/operator/agent.cordis.yml` | 运营管线的组装 | 待建（P2） |
| `presets/device/agent.cordis.yml` | 设备管线的组装 | 待建（P2） |
| `presets/<管家>/skills/<技能名>.md` | 该管家专属技能文件 | 待建（P3） |
| `skills/<技能名>.md` | 跨管家共用的技能文件 | 待建（P3） |

**组装规则**

1. 一份 preset **只**声明本管家的：人设（persona / agent-instructions）、工具面（本管家工具注册）、技能装载（skills 根）。
2. 与业务无关的宿主能力（沙箱、审批、持久化、模型路由）**不得**写进管家 preset，它们留在宿主组合层。
3. 总管 preset **不得**挂载任何对外副作用工具（发布 / 回复 / 删除）；它只做分派与汇总。

### 3.3 命名与编号规则

| 对象 | 规则 | 例 |
| --- | --- | --- |
| preset 目录名 | 小写英文单数（`steward`/`creator`/`publisher`/`operator`/`device`） | `presets/creator/` |
| 管家中文名 | 创作管家 / 发布管家 / 运营管家 / 设备管家（对外一律用中文名） | —— |
| 技能名 | `^[a-z0-9]+(?:-[a-z0-9]+)*$`（只允许小写 ASCII 与连字符）；**中文名会被技能通道静默丢弃** | `bosom-friend-content` |
| 技能文件名 | `<技能名>.md`（与 frontmatter 的 `name` 一致） | `bosom-friend-content.md` |

> 技能名规则的来源：`server/src/agent-skills.ts` 的 `SKILL_NAME_PATTERN` 与官方 provider 实测（非 kebab-case 的名字不会出现在会话技能目录里）。

## 4 四个管家的职责与边界

### 4.1 总管（steward）

| 项 | 内容 |
| --- | --- |
| 一句话 | 「用户说的这件事该谁办」 |
| 职责 | 理解那句话、判断归属管家、分派、汇总各管家回报、对用户给最终答复 |
| 工具面 | `bosom_kernel_ping`、`bosom_job_list`、`bosom_learn_from_history` |
| 技能 | `bosom-friend-agent`（能力边界 / 流程 / 实事求是三态） |
| 不得做 | 直接发布、直接回复评论私信、直接改账号设置；替管家编造执行结果 |

### 4.2 创作管家（creator）

| 项 | 内容 |
| --- | --- |
| 一句话 | 「我要一条能发的内容」 |
| 职责 | 选题与脚本 → 出片（短片 / 长视频）→ 封面 → 数字人形象 → 素材入库 → **存草稿箱** |
| 工具面 | 19 个：脚本与草稿（`generate_script`/`create_draft`/`update_draft`/`list_drafts`）、视频（`create_video`/`create_short_media`/`video_status`/`resume_video`）、长视频（`long_video_list`/`redo_shot`/`extend_script`/`stop`）、封面与提示词（`make_cover`/`enhance_prompt`/`split_fourview`）、素材（`material_list`/`material_import_video`）、数字人（`digital_human_list`/`digital_human_create`） |
| 技能 | `bosom-friend-content`（创作全链路）；待建：选题方法、封面规则、长视频分镜、数字人 |
| 不得做 | 发布（**NEVER publishes**）；替用户决定发布时机 |

### 4.3 发布管家（publisher）

| 项 | 内容 |
| --- | --- |
| 一句话 | 「把这条发出去，并告诉我结果」 |
| 职责 | 草稿 / 素材发布 → 回读平台作品 ID → 发布记录核验 → 作品数据同步回本地 |
| 工具面 | 4 个：`bosom_publish_draft`、`bosom_publish_content`、`bosom_publish_list_records`、`bosom_platform_sync_works` |
| 技能 | `bosom-friend-publish`（六项参数 + 回读作品 ID + 需用户明确指令）；待建：平台适配（抖音 / 小红书） |
| 拍板约束 | 只有当次指令里有明确发布意图才可执行（BFS-105.4；DEF-240） |
| 不得做 | 改草稿内容（属创作管家）、替用户选择发布账号之外的参数（位置、标注要如实说不在链路上） |

### 4.4 运营管家（operator）

| 项 | 内容 |
| --- | --- |
| 一句话 | 「数据怎么样、有没有人要回」 |
| 职责 | 数据看板与作品数据回读 → 拉取最新互动 → 待接待列表 → 回复评论与私信 |
| 工具面 | 4 个：`bosom_data_dashboard`、`bosom_reception_poll_now`、`bosom_reception_list_pending`、`bosom_reception_reply` |
| 技能 | `bosom-friend-ops`（数据回读 + 接待）；待建：复盘口径、涨粉与作品分析 |
| 拍板约束 | 回复属对外沟通，需当次明确指令 |
| 不得做 | 主动给非粉丝发私信、批量互动（BFS-800 第 810 条） |

### 4.5 设备管家（device）

| 项 | 内容 |
| --- | --- |
| 一句话 | 「我的号、我的配置还好吗」 |
| 职责 | 账号列表与登录态 → 账号连接与重登引导 → 模型配置查询 → 个人资料 → 远程访问与数据清理（后续） |
| 工具面 | 4 个：`bosom_platform_list_accounts`、`bosom_platform_login_status`、`bosom_settings_get_llm`、`bosom_user_update_profile` |
| 技能 | `bosom-friend-account`（连接 / 登录 / 同步）、`bosom-friend-setup`（设置与底座） |
| 不得做 | 代持密码、代替用户完成扫码、后台自动重登（BFS-800 第 805 条） |

### 4.6 边界汇总（谁不做什么）

| 动作 | 归谁 | 其他管家 |
| --- | --- | --- |
| 改草稿、出片、做封面 | 创作 | 一律不得直接改内容 |
| 发布、回读作品 ID | 发布 | 只能把草稿 id 交过去 |
| 回复评论 / 私信 | 运营 | 不得代发 |
| 账号登录、模型配置 | 设备 | 不得代改配置 |
| 分派与汇总 | 总管 | 不得替管家执行 |

## 5 工具面

### 5.1 定义与判据

**工具面 = 该管家能看到的工具集合**。它不只是「提示词里说不要用」，而是**注册范围**：不给它注册，它在工具目录里就看不到。

判据三条：

1. 工具目录一致：某管家会话里的工具清单与第 5.2 节的表逐项一致；
2. 越权拒绝：让创作管家「现在发出去」，它**必须**答复「这需要发布管家来做，需要我现在交给它吗」，而不是调用发布工具；
3. 拍板标注：发布、回复、删除、花钱类工具的描述里**必须**写明「只有用户当次明确指令才能调用」。

### 5.2 五份工具面（34 个工具，2026-10-11 实测清单）

| 管家 | 工具数 | 工具名 |
| --- | --- | --- |
| 总管 | 3 | `bosom_kernel_ping`、`bosom_job_list`、`bosom_learn_from_history` |
| 创作 | 19 | `bosom_content_generate_script`、`bosom_content_create_draft`、`bosom_content_update_draft`、`bosom_content_list_drafts`、`bosom_content_create_video`、`bosom_content_create_short_media`、`bosom_content_video_status`、`bosom_content_resume_video`、`bosom_long_video_list`、`bosom_long_video_redo_shot`、`bosom_long_video_extend_script`、`bosom_long_video_stop`、`bosom_content_make_cover`、`bosom_content_enhance_prompt`、`bosom_content_split_fourview`、`bosom_material_list`、`bosom_material_import_video`、`bosom_digital_human_list`、`bosom_digital_human_create` |
| 发布 | 4 | `bosom_publish_draft`、`bosom_publish_content`、`bosom_publish_list_records`、`bosom_platform_sync_works` |
| 运营 | 4 | `bosom_data_dashboard`、`bosom_reception_poll_now`、`bosom_reception_list_pending`、`bosom_reception_reply` |
| 设备 | 4 | `bosom_platform_list_accounts`、`bosom_platform_login_status`、`bosom_settings_get_llm`、`bosom_user_update_profile` |

### 5.3 拍板类工具的标注要求

| 工具 | 拍板类型 | 描述必须包含 |
| --- | --- | --- |
| `bosom_publish_draft` | 发布 | 「只有用户在这一句话里明确要求发布时才能调用」 |
| `bosom_publish_content` | 发布 | 同上 |
| `bosom_reception_reply` | 对外沟通 | 「只有用户在这一句话里明确要求回复时才能调用」 |

> 现状核对：上述三条工具的描述当前**已含**强制语（2026-10-11 实测 `kernel/src/index.ts`）；工具面拆分后必须原样保留。

### 5.4 现状与差距

| 项 | 现状（2026-10-11） | 目标 | 差距 |
| --- | --- | --- | --- |
| preset 目录 | 无 `presets/` 目录 | 五份 `agent.cordis.yml` | 未建（P2） |

## 6 技能清单

### 6.1 技能文件规格

| 项 | 要求 | 来源 |
| --- | --- | --- |
| 名字 | `^[a-z0-9]+(?:-[a-z0-9]+)*$` | `agent-skills.ts` 的 `SKILL_NAME_PATTERN` |
| frontmatter | 必含 `name`、`description`、`whenToUse` 三项，缺一会**静默跳过** | `agent-skills.ts` 的 `renderSkillFile` |
| 正文 | 适用场景、步骤、判据、反例、来源（五段） | BFS-106.3 |
| 落点 | 开发期：`presets/<管家>/skills/`；蒸馏技能：用户数据根 `skills/` | `agent-skills.ts` 的 `SKILLS_DIR` |
| 数量上限 | 每个技能根最多 12 个（超出归档，不删除） | `agent-skills.ts` 的 `MAX_SKILLS` |

### 6.2 技能与管家对应表

| 管家 | 技能名 | 覆盖什么 | 现状 |
| --- | --- | --- | --- |
| 总管 | `bosom-friend-agent` | 能力边界、请求怎么流转、不可用时怎么如实说 | 现成 |
| 创作 | `bosom-friend-content` | 写脚本 → 出片 → 存草稿（**从不发布**） | 现成 |
| 创作 | 待建：选题 / 封面 / 长视频分镜 / 数字人 | 各自领域口径 | 缺 |
| 发布 | `bosom-friend-publish` | 六项参数 + 回读作品 ID + 需明确指令 | 现成 |
| 发布 | 待建：平台适配（抖音 / 小红书） | 平台差异与合规（内容标注） | 缺 |
| 运营 | `bosom-friend-ops` | 数据回读 + 评论私信接待 | 现成 |
| 运营 | 待建：复盘口径 | 「这条为什么好」的分析方法 | 缺 |
| 设备 | `bosom-friend-account` | 连接频道、登录 / 换号 / 重新授权、同步作品数据 | 现成 |
| 设备 | `bosom-friend-setup` | 大模型配置、主题语言、备份、远程访问、端口 | 现成 |

**维护规则**

1. 技能是**专业流程的家**；同一流程不得同时写在技能与代码里（BFS-106.1、106.2）。
2. 技能改动**不**需要改 preset；preset 只声明技能根。
3. 新增技能**必须先**在《能力台账》里找到它服务的能力条目（不允许无归属的技能）。

## 7 交接约定

### 7.1 总管 → 管家（分派）

| 步 | 动作 | 必带信息 |
| --- | --- | --- |
| 1 | 识别那句话落在哪个管家 | 用户原话 |
| 2 | 分派（交出去执行） | 原话 + 已识别的对象（账号 / 草稿 / 素材 / 作品） + 期望的可见结果 |
| 3 | 汇总 | 各管家的回报（做成 / 没做成 / 卡在哪） |
| 4 | 汇报 | 对用户一句人话结论 + 证据（对象字段或页面可见结果） |

**约束**：总管**不得**把「还没做完」说成「已完成」；多个管家串行时，前一个的产物标识必须传给后一个。

### 7.2 管家 → 管家（移交）

| 从 | 到 | 交什么 | 标识 |
| --- | --- | --- | --- |
| 创作 | 发布 | 一条可发布的草稿（含封面） | 草稿 id（`draftId`） |
| 创作 | 发布 | 一条素材 | 素材 id（`materialId`） |
| 发布 | 运营 | 发布结果与作品标识 | 平台作品 ID + 发布记录 id |
| 设备 | 发布 / 运营 | 可用的账号 | 账号 id（`accountId`）+ 登录态 |

**约束**

1. 移交**必须**带对象标识；**禁止**用「那条」「刚才那个」口头指代。
2. 接收方**不得**修改移交对象的归属属性（发布管家不得改草稿正文）。
3. 移交前发起方**必须**确认前置条件（草稿有封面、账号登录态正常）；不满足时**必须**如实回报，**不得**硬试。

### 7.3 管家 → 用户（拍板）

| 项 | 要求 |
| --- | --- |
| 触发 | 发布、删除、花钱、对外沟通四类动作 |
| 必给 | 要做什么、对哪个对象、不可撤销的后果 |
| 记录 | 用户原话 + 时间 + 动作 + 对象 |
| 禁止 | 未获当次指令即执行；把拍板包装成「已自动完成」 |

### 7.4 失败交接

| 情形 | 谁收尾 | 用户看到 |
| --- | --- | --- |
| 管家自己能重试的失败 | 发起管家 | 人话原因 + 三个选择（断点继续 / 重新生成 / 放弃） |
| 需要另一个管家才能继续的失败 | 发起管家负责移交并跟踪 | 同上，附加「已交给 X 管家」的人话说明 |
| 不可控结果（平台限流、封禁） | 发起管家如实告知 | 现象 + 原因 + 恢复方式（BFS-800 第 809 条） |

**约束**：失败**禁止**静默；跨管家失败**不得**出现「两边都以为对方在办」。

### 7.5 交接记录格式（可判定）

每次交接**必须**留一条记录，字段如下：

| 字段 | 内容 | 例 |
| --- | --- | --- |
| 时间 | 时间戳（本地时区） | 2026-10-11 15:04:22 |
| 从 / 到 | 发起管家 → 接收方 | 创作 → 发布 |
| 对象 | 对象类型 + 标识 | 草稿 `cnt-xxxx` |
| 已完成 | 发起方做完了哪几步 | 脚本已定稿、封面已挂 |
| 待办 | 接收方要做什么 | 发布到抖音账号 douyin-01 |
| 结果 | 接收方的回报 | 成功（作品 ID 7695288326089116991） / 失败（原因） |
