## 0. 结论摘要（v2）

**v1 的"34 项全部有真实实现"结论过于乐观，三份深度审计后（v4）修正为：✅ 14 项 · 🟡 13 项 · ⛔ 7 项。**

四个系统性根因（不是零散 bug）：

1. **服务端只消费 2 个请求字段**：`createDraftGeneration`（`server/src/api.ts:1856`：`body as { quantity?: unknown; groupId?: unknown }`，**已复核**）把 `model / captionPrompt / imageUrls / videoUrls / audioUrls / platforms / draftType` **7 个字段全部静默丢弃** → A1-03 目标平台、A1-04 参数限制、A1-06 文案要求、A1-09 参考素材这四项的「设置 → 生成」闭环**实际断开**。
2. **两处前端桩**：`captionPrompt` 在 `server/src` **全目录 0 命中**（**已复核**）→ A1-06「文案要求」用户填了等于没填；「风格」胶囊 `StyleSelect` 无 value/onChange 出参、请求类型里也没有 `style` 字段（**已复核**）→ 点击只改按钮文字。
3. **媒体删除/移动只动一张表**：`removeMaterials`（`routes-content.ts:1317-1349`，**已复核**）显式保留被生成记录引用的素材，且从不触碰 `files.promotions` → A2-05 在视频/图片视图删 AI 草稿：前端乐观移除、**刷新回魂**（假成功）。
4. **自检用"文案自满足"正则**：17 项里 7 项的断言关键词就在被点击的按钮/弹窗标题里 → 弹窗没打开也能 PASS；另 3 项可静默跳过。**上述所有缺口都不在自检射程内**。

**唯一 S1 级链路缺陷仍是排期（A4-06）**：改期不重排（G-1）+ 进程内 setTimeout 无持久化（G-2），见 §4。

### 6.1 病根：一个「内容条目」被存进两张表

| 存储域 | 落盘文件 | id 前缀 | 谁写入 | 谁读 |
| --- | --- | --- | --- | --- |

代码自己承认这是补丁 —— `routes-content.ts:340-341` 注释：

> 「推广素材（promo-*，POST material 写入）与素材库（mat-*，上传流程写入）原先互不可见，导致「刚建的素材在素材库里查不到」。读路径统一为一条列表，用 source 区分来源。」

**在读取端拼接 ≠ 消除重复**，代价全部变成线上缺陷：

| 重复带来的缺陷 | 证据 |
| --- | --- |
| 重复卡片 + 计数虚高 | GA-6（`routes-content.ts:342-362` 无去重） |

| 移动只改 `materials`，前端却传 promotion id → 静默无效 | GB-8（`:1351-1362` vs `TransferDraftDialog.tsx:140`） |
| 组归属两套字段（`groupId` / `materialGroupId`） | `routes-content.ts:366-367` |
| 上传素材写死 `grp-default`，当前组看不到 | GB-3（`:1438`） |

**重复度实测（决定性证据，2026-09-10 复核）**：解析真实备份 `~/.bosom-friend/bosom-friend/backups/2026-09-09T10-00-45-852Z/`：

| --- | --- |
| `media.json`（素材表） | **52 条**，52 个唯一 url |
| `promotions.json`（草稿表） | **19 条**，其 `mediaList` 引用 **52 个唯一 url** |
