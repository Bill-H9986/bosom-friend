## 二、脚本（qa/ 实测 716 个 · analysis/ 937 个文件）

裁决原则：脚本只剩两种合法用途——**能力门禁**与**一次性诊断（查清即删）**。

| 类别 | 处置 |
| --- | --- |
| qa/acceptance/（S 级前端监考） | **作废**，按《验收标准-一句话端到端》重建 |
| qa/probes/ 中判「页面点得对不对」的 | **废** |
| qa/probes/ 中判「一句话办成了没」的 | **留**（升级为能力门禁） |
| qa/defects/ | **保留**，改为能力视角（缺陷必须挂到某条能力上） |
| qa/reports/ | **归档** |
| 一次性诊断脚本 | **删**（查清即删，不再沉淀） |
| analysis/ 全部 | **归档**（历史现场，不再作为当前事实） |

**目标**：qa/ 从 716 个降到「一能力一门禁」的量级；**脚本数下降本身就是重构成功的证据之一**。

## 三、执行次序

1. 先按本表把废止件标记（文件头加一行「已废止，见 ADR-005」或移入 archive/）；
2. 再重建能力门禁（P1 随能力一起做）；
3. 最后清 analysis/ 与一次性脚本（P4 交付前完成）。
