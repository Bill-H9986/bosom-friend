## 第一条：一切按 DSH 官方标准开发（0 号开发铁律）

**结论：本项目是基于 DeepSeek Harness（DSH）官方基座打造的 AI Agent Harness 应用；所有能力一律照 DSH 官方标准落地，不另起一套。**

具体六条（全文见 `docs/规范/项目铁律.md` 的「0 号开发铁律」）：

1. **能力先于功能（能力缝三角色）**：新能力先有 Service Definition（`packages/<group>/<name>`：服务与事件、类型、`invariant.ts`），再有 Service Provider（唯一实现、可换厂商），最后由 Consumer 调用。没有 Definition 不许在业务里拉直连。
2. **厂商 HTTP 只能出现在 Provider 包里**：`server/`、`launcher/`、前端、内核业务插件不得 `fetch` 非回环地址；调模型/厂商一律经内核。
3. **密钥只住凭据能力**：密钥只存 `credentials` / `.credentials.yaml` 的 `refs`；业务数据文件（`llm-user.json` 等）不得存明文密钥；配置走 `settings` 能力。
4. **注册即 effect**：贡献走 `ctx.effect()` / `ctx.on()`，返回 disposer；按 `packages/AGENTS.md` 的目录、命名、README、不变量规则落地。
5. **过渡例外必须登记、只减不增**：写进 `qa/run-gate.mjs` 的 `ALLOWED_DIRECT`，每条注明"内核侧还缺什么能力"。
6. **规则不进门禁等于没有规则**：出网白名单（不枚举端点，新厂商/新模态自动被拦）＋ 能力缝完整性检查必须接进门禁。

### 为什么要立这条（2026-09-21 审计现场）

| 事实 | 证据 |
| --- | --- |
| 内核只跑**文本** | 智能体对话/文案/稿件/客服经 `kernel.prompt()`（`server/src/kernel-client.ts`、`api.ts:488`）；内核会话 `~/.bosom-friend/sessions/…-bundle-kernel-…/turn-*` 最近 8 条为 19:59–20:21 |
| **图片、视频、配音是产品直连厂商** | `api.ts:3134/3135`（`/images/generations`）、`api.ts:3466/3490/3505/3570`（`/videos`、`/agnesapi`）、`tts-provider.ts:285`（`/audio/speech`）——共 8 处 |
| 内核侧**没有**这些能力面 | `packages/llm/**` 只有 `stream()` 文本流（`GenerateOptions → StreamChunk`） |
| 门禁**看不见**这些直连 | `qa/run-gate.mjs`「禁止直连模型接口」原只匹配 `chat/completions`，且扫描目录不含 `server/src` |
| 密钥**两处都有** | 内核 `settings.yaml` + `.credentials.yaml`（refs）已有；产品 `llm-user.json` 另存一份明文 key → 直连永远是成本最低的路 |

后果（已观察到）：模型配置两套来源（改一处有的生效有的不生效）；限流/重试各自为政（2026-09-21 18:26–18:29 视频轮询连环 429 全发生在直连通道）；内核会话留痕只有文本这一半。

## 第二条：按官方模板补齐 media 能力缝（✅ 已完成 2026-09-23）

| 步骤 | 内容 | 状态 |
| --- | --- | --- |
| 1 | 出网白名单门禁 + 直连登记制（`qa/verify-kernel-only.mjs`、`run-gate.mjs` 的 `ALLOWED_DIRECT`） | **已落地** |
| 2 | 三条直连收敛为**一个**媒体模块（provider 雏形）：`server/src/media-gateway.ts` | **已完成**（图片现场验证；视频/配音已改道且端点契约核对，未现场跑厂商） |
| 2b | 媒体路由与凭据进**内核同一份配置**（`settings.yaml` 的 `media-pi-ai` 段 + `.credentials.yaml` refs） | **已落地**：设置页保存时两个段一起写（`api.ts` 的 `writeKernelModelSettings`），Provider 读的就是它们；产品侧不再需要把密钥交给媒体路径（`llm-user.json` 只留给界面与旧客户端） |
| 3 | 建 `packages/media`（Definition）+ `media-pi-ai`（Provider），产品经内核调用 | **图片、视频、配音全部改经 `ctx.media` 调用**：`api.ts` 只保留超时预算、重试与失败分类（`media-gateway.ts` 成了消费方适配层），方言、尺寸协商、产物下载都在 Provider 里；产品直连 **8 → 0 处**，门禁 `ALLOWED_DIRECT` 归零（`verify-kernel-only` 只剩 Agnes 基址常量这一条"配置而非调用"） |
| 4 | 配音来源的**各家差异**（音色字段名 `voiceField`、附加字段 `extraBody`）表达进能力面 | **已落地**：写成 `settings.yaml` 里 `media-pi-ai` 的 `bf-voice` 路由 + 该路由的 `speech` 方言；产品侧 `tts-provider.ts` 只调 `ctx.media.synthesizeSpeech`，原先的 `postVendorSpeech` 已删。用例：`voice-media-route.spec.ts`（保存写成路由 / 试听厂商收到的字段 / 关掉来源路由随之消失） |语音来源是用户自建的 OpenAI 兼容服务（`voiceField`/`extraBody`/本机地址），能力面的语音请求还没表达这些差异 |

第 2 步的现状（2026-09-21）：厂商端点从 **8 处 / 3 个模块**收敛到 **1 个模块**（`media-gateway.ts`，7 处端点拼装全部限定在此文件）；门禁的 `ALLOWED_DIRECT` 随之只允许这一个文件，别处出现厂商端点即判红。同一轮现场验证：`imageCount=3` 的图文生成经网关出图 **3/3**、清理正常。

收尾（2026-09-23）：最后一条直连（配音）也进了能力面——`media-gateway.ts` 从此只做策略（超时、失败分类、可读文案），
一处厂商 HTTP 都不再持有；门禁 `ALLOWED_DIRECT` 清空后「禁止直连模型接口」转**绿**。

**2026-09-25 修订（第 4 步的语音那一半整体删除）**：产品不再自己合成语音——成片里那一声由厂商（Agnes）
在出片时按**念法（persona）**自己念。`server/src/tts.ts`、`server/src/tts-provider.ts`、`msedge-tts` 依赖、

（出图 / 视频下单 / 视频轮询），`media-pi-ai` 路由的 `speech` 方言随之删除。**直连仍为 0 处**（门禁规则不变）。
同时：数字人 = 形象素材（照片，或视频抽首帧 + 一段 2~12 秒参考视频）+ 念法 + 种子；内容创作 >12 秒档

## 第三条：验收方式（不许再用"我实测通过了"）

- 规则 → 门禁：`node products/bosom-friend/qa/run-gate.mjs`（直连检查：未登记直连判红、只剩已登记判黄并打印欠债）；
- 行为 → 可判红的用例：`qa/e2e/specs/delete-consistency.spec.ts`（删除后必须同屏与服务端一致，负向对照实测可判红）；
- 每轮汇报只写：**哪条断言红了/绿了，以及它到底能不能红**。
