## 0. 一句话

把「19 个板块的功能软件」重造为「**四个管家的 AI 管家系统**」；旧标准即刻失效，新标准按管家形态重立。

## 1. 运营期痛点 → 根因 → 重构动作（本次手术的切除范围）

彻底改的依据不是「架构不漂亮」，而是「**后期运营会脑袋痛**」。逐条倒推：

| 运营期会怎么痛 | 根因 | 重构动作 |
| --- | --- | --- |
| 每天还得自己点按钮、记步骤 | 能力不长在 AI 身上（贾维斯化率 17%） | 54 条能力全部工具化 |
| AI 换个对话就失忆，每次都要重教 | 任务级会话用完即回收；记忆不分层 | 管家长期会话 + 记忆分层（总管 / 管家 / 技能 / 画像） |
| 数据会坏、对不上、越用越乱 | 多个 JSON 文件、152 个写点、无事务语义 | 数据层重造：单写入点 + 事务语义 + 迁移器 |
| 不知道 AI 在干什么、卡在哪、花了多少 | 只有一段对话流，没有管家视图 | 管家团队可视化 + 全链路留痕 + 用量成本看板 |
| 失败了要自己盯着、自己救 | 无统一自愈口，各链路各写一套 | 统一失败处理：三选择 + 自动续跑 + 升级上报 |
| 想加平台 / 加能力就痛 | 页面写死执行器、路由堆在一个 8256 行文件里 | 能力注册制（一能力一文件）+ preset 组装 |
| 封号、风控、合规风险 | 无体系化风控 | 平台风控体系：拟人化、限频、账号隔离、留痕 |
| 升级要重装、数据怕丢 | 无版本迁移与备份机制 | 版本升级迁移 + 备份 / 恢复 / 换机搬迁 |
| 出了问题查不动 | 门禁服务于「页面点得对」 | 门禁改为「一句话办得成」+ 能力级用例 |

## 2. 目标形态

- **一个总管**：理解你那句话 → 分派 → 汇总 → 向你汇报；
- **四个管家**：创作管家 / 发布管家 / 运营管家 / 设备管家（垂直业务，不是通用设备层）；
- **一个入口**：一句话；
- **过程可见**：谁在干活、干到哪、卡在哪；
- **四类拍板**：发布、删除、花钱、对外沟通。

## 3. 目标架构（六层）

| 层 | 职责 | 来源 |
| --- | --- | --- |
| ① 运行时层 | Electron 壳 + DSH 内核 + 平台引擎 | 保留 |
| ② 能力层 | 一条能力 = 一个工具 + 一份实现（页面与 AI 共用） | 改造（不重写业务） |
| ③ 编排层 | 总管 preset + 4 个管家 preset（agent.cordis.yml） | 新建（DSH 原生） |
| ④ 技能层 | 专业流程写成 Skill（选题 / 文案 / 封面 / 风控） | 新建（DSH 原生） |
| ⑤ 呈现层 | 对话主入口 + 管家团队 + 看板（旧板块降级） | 重建 |
| ⑥ 记忆层 | 管家长期记忆、画像、经验、知识库 | 新建 |

## 5. 标准体系（九条，逐条替代旧标准）

| # | 新标准 | 判据 | 替代了什么 |
| --- | --- | --- | --- |
| 1 | 产品定义 | 没有对应工具的能力不算能力 | 功能清单（132 功能点 / 板块制） |
| 2 | 架构 | 能力先注册成工具，页面才是可视化 | 页面优先 + 双入口 |
| 3 | 交互 | 每个能力必须能从一句话触发 | 动作卡 + 按钮流 |
| 4 | 验收 | 一句话 → 管家自己干完 → 页面看到结果 | S 级前端监考 / 铁律 #1 #2 |
| 5 | 权限 | 只有四类要拍板：发布 / 删除 / 花钱 / 对外 | 逐动作 gate |
| 6 | 技能 | 专业流程写进 Skill，不写进代码 | 提示词里堆规则 |
| 7 | 记忆 | 管家长期存活，越用越懂你 | 任务级会话回收 |
| 8 | 门禁 | 每个能力配一条一句话门禁 | 716 个页面型脚本 |
| 9 | 交付 | 打包 + 端到端 + 装机，缺一不算完成 | 保留（唯一不动的一条） |
