# 对标基线：飞书 × 豆包工作（本项目的理想状态与判据）

> **这份文档是本项目唯一的方向事实源。**它回答两件事：我们要做成什么样（判据，带编号），以及**现在差在哪**（差距矩阵）。
> 任何功能、任何报告、任何方案，都必须声明自己对标的是哪一条（写法见 §4）。**其余文档只引用编号，不复述判据。**
> 上游：`docs/adr/ADR-004-飞书与豆包融合形态与本产品设计.md`（形态决策）、`docs/开发报告.md`（0 号开发铁律：一切按 DSH 官方标准）。

## 1. 一句话

**前端 = 飞书式工作现场**（对象自带 AI、结果回到同一个对象、助手知道你正在看什么、权限就是上下文边界）；
**后端 DSH 内核 = 豆包式执行者**（对象即上下文、能力面完备、执行有痕、结果回流成更厚的上下文）。

## 2. 判据（可观察、可验，不是口号）

### 2.1 飞书侧（工作现场）

| 编号 | 判据 | 怎么算做到（可观察） |
| --- | --- | --- |
| **F1** | 对象即入口 | 任何一条业务对象（草稿 / 账号 / 发布记录 / 笔记 / 任务 / 接待）上都能直接发起 AI，不需要先跳到某个「AI 页面」 |
| **F2** | 结果就地回写 | AI 产出写回**发起的那条对象**的对应字段，服务端回读确认；不靠用户复制粘贴 |
| **F3** | 焦点可见 | 助手知道用户正在看哪条对象（类型 / 标题 / 摘要），并且这条焦点进当轮提示词 |
| **F4** | 权限即边界 | 能不能做取决于权限与登录态；不可用时给可读原因，**不假装成功** |
| **F5** | 过程可追溯 | 每次 AI 动作留下过程与依据（用了哪条知识、几次工具调用、耗时），事后能回放 |
| **F6** | 交互语言一致 | 同一动作在不同对象上叫法、位置、反馈一致（同一能力的入口不因对象而异形） |

### 2.2 豆包侧（执行者）

| 编号 | 判据 | 怎么算做到（可观察） |
| --- | --- | --- |
| **D1** | 对象即上下文 | 给定对象，自动装配**四类语境**：领域（产品规则）/ 约束（硬数字，从唯一出处派生）/ 历史（踩过的坑 + 本机真实失败）/ 记忆与画像 |
| **D2** | 能力面完备 | 每一类能力（文本 / 图片 / 视频 / 语音 / 联网 / 技能）都由**能力缝三角色**提供：Service Definition（`packages/<group>/<name>`）＋ Provider（唯一实现、可换厂商）＋ Consumer；**厂商 HTTP 只能出现在 Provider 包里** |
| **D3** | 执行有痕 | 每一次模型/厂商调用都可回放：输入、产出、用量、知识来源；缺一不算 |
| **D4** | 结果沉淀回流 | 产出回流为更厚的上下文：样本、按真实表现的评分、技能、画像 |
| **D5** | 工具面受控 | 模型只拿到业务能力与语境工具，**拿不到宿主编码工具**（pwsh / 文件读写 / subagent）；纯文本生成会话一个工具都不挂 |
| **D6** | 失败可解释 | 失败给可读原因与下一步动作；禁止静默失败与空原因 |

### 2.3 交付轴（0 号开发铁律的可验证形态）

| 编号 | 判据 | 怎么算做到 |
| --- | --- | --- |
| **E1** | 规则不进门禁等于没有规则 | 每条新规则同期落一条门禁检查，且**负向对照**证明它会红 |
| **E2** | 过渡例外只减不增 | 直连等例外登记在册、注明「内核侧还缺什么能力」；数量只许下降 |
| **E3** | 无端到端证据不算完成 | 功能状态以「真机 / 页面 / 真实模型」证据为准；`code=0`、单测通过都不算 |

## 4. 所有文件怎么「看齐」（硬约定）

1. **每个新功能 / 每个改动**：在功能清单那一行里带上对标编号（例：`F2/D1`）；没有编号的改动视为没说明用途。
2. **每份报告 / 方案 / 复盘**：开头必须有一段 `> 对标定位：<编号> —— <一句话>`，并链接本文；正文按**五段骨架**写：

   ```
   对标定位（哪几条判据）→ 本期推进（做了什么）→ 差距变化（哪条从 🟡/⛔ 变成什么）→ 证据（真机/门禁/报告编号）→ 未做（照实写）
   ```
3. **差距矩阵随事实走**：状态变化时**当场**改本文（与功能清单同步）；本文与功能清单冲突时，功能清单管「有没有」，本文管「离理想还差多少」。
4. **门禁盯着**：`node qa/verify-benchmark-alignment.mjs`（接在 `run-gate.mjs` 的「对标看齐」检查里）会判红——
   判据齐全、关键文档都带「对标定位」、矩阵每条都有状态标记。改了本文却没同步关键文档，门禁会拦。
