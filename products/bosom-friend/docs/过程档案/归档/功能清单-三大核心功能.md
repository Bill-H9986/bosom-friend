## 1. 怎么读

- 编号：`A/B/C/D + 小功能区号 + 功能点号`，例如 `A4-05 真实发布`。
- 每条含四要素：**入口（用户点哪里）· 说明（做什么）· 实现位置（代码在哪）· 状态**。
- 「自检」指 `qa/acceptance/full-chain-loop.mjs` 的 82 项（按三大核心汇总输出）；「门禁」指 `qa/run-gate.mjs` 等脚本。
- 只查一个板块时用 `$env:BF_CHAIN_ONLY='A,L2-B,L3-B'`（id 前缀过滤），层闸门只统计跑过的项。

### 分层测试（层层递进，低层失败即停）

自检脚本按四层执行，**上一层不过就不跑下一层**：

| 层 | 覆盖 | 命令 | 说明 |
| --- | --- | --- | --- |
| **L1 小功能点** | 67 项 | `$env:BF_CHAIN_LAYER=1; node qa/acceptance/full-chain-loop.mjs` | 每个功能点单独验，页面每步重载 |
| **L2 小功能区** | 8 项 | `$env:BF_CHAIN_LAYER=2; node qa/acceptance/full-chain-loop.mjs` | 同一小功能区内的功能串起来跑 |
| **L3 核心板块** | 3 项 | `$env:BF_CHAIN_LAYER=3; node qa/acceptance/full-chain-loop.mjs` | 内容创作 / 账号管理 / AI 智能体各一条主链路 |
| **L4 整体集成** | 4 项 | `$env:BF_CHAIN_LAYER=4; node qa/acceptance/full-chain-loop.mjs` | 跨核心联动：智能体→发布、知识库→生成、账号→创作、设置→对话 |

不带 `BF_CHAIN_LAYER` 时按 L1→L2→L3→L4 顺序全跑，并在每层结束打印闸门结果：

```
--- L1 闸门：67/67 通过 ---
--- L2 闸门：8/8 通过 ---
--- L3 闸门：3/3 通过 ---
--- L4 闸门：4/4 通过 ---
LAYER_GATE PASS（逐层通过）
```

> 安全约定：自检**绝不触发真实发布**——L4-1 会先关闭「跟随模式」，
> 只验证动作卡能打开发布弹窗并预填，不点提交。
- 前端页面与入口：侧栏 7 项（内容创作 / AI互动 / 我的任务 / 发布日历 / 数据中心 / 全局监控 / 知识库）
  ＋ 底部「添加频道」＋「Bosom Friend 客户端 → 设置」。
