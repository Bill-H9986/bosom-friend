## 差距分级与改造路线

**P0（阻塞交付，建议本轮完成）**
1. **离线自包含**：后端依赖实体化内嵌（npm 平铺实体布局替代 pnpm 链接；由于该环存在 Windows 长路径限制，改用「独立 npm 布局镜像 + 启动器内置」策略）——预估改动 2-3 轮；
2. **品牌图标**：从 logo 生成 16/32/48/256 多尺寸 .ico，接入 electron-builder（exe/安装器/快捷方式）——1 轮内；
3. **单实例锁** + 首启窗口最小化等待、失败提示——30 分钟内。

**P1（发布级）**：版本号单源（package.json + 后端 appVersion 统一切换）；代码签名流程（self-signed → 正式证书）；安装升级路径（升级时保留数据）；窗体尺寸/DPI 适配。

**P2（运营级）**：crashReporter + 崩溃收集（本地文件）；启动性能优化（预热/懒加载）；自动更新（electron-updater + 版本源）；许可证清单生成。

## 结论

产品在**安全（#2/#9）、数据（#6）**两项已达行业优秀；**安装/卸载生命周期（#5）基本达标**；**主要差距 = 离线自包含（#7）、品牌身份（#4）、单实例（#3）、工程化版本/签名（#11）**。按 P0→P1→P2 路线执行后即满足正规 APP 交付标准。

（审计不引用知音为标准；知音仅作为「重开发动机」的教训记录：依赖堆、旧桥、中断版本线。）
