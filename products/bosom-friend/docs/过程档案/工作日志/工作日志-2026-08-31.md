## 平台评论/私信接待真实化（2026-08-31 夜 · 本轮专项）

问题根因：网页版此前没有任何真实平台互动通道——评论/私信组件全部调用桌面 IPC
（window.ipcRenderer / zhiyinHarness），网页版拿不到时直接显示假的「已接入/运行中」，
「回复成功」只是本地 JSON 落库，平台实际没有收到任何内容。

本轮把 Electron 主进程里成熟的页面驱动（commentPageDriver / xhsCommentPageDriver /
douyinImPageDriver / xhsImSender）移植为 Python 引擎（Patchright + 真实 Chrome +
账号登录态），新增 `engine/interactions.py`，由 `worker.py interact` 执行，前后端全链路：

1. **抖音评论**：评论列表走平台评论管理页真实接口（页面自签名），回复在平台页面
   真实执行。已实测：公开发布的人社局视频评论「很棒」→ 回复成功（平台出现回复线程）；
   私密作品评论 → 平台返回 status_code=15421「私密作品无法评论」，应用如实展示，不再假装成功。
2. **抖音私信**：会话列表从创作者私信页真实读取（昵称/最后消息/时间均可对上）；
   私信发送已接新版 summon 聊天面板，但该面板在无头环境未稳定渲染出输入框，待换
   imapi protobuf 通道，失败时如实报错。
3. **小红书**：IM 接口与网页版动作需要「消费者端 web_session」（当前账号只有创作者
   creator cookie），且当前网络 IP 被平台标记「IP存在风险（300012/300031）」，应用
   如实展示这两个平台真实原因，绝不伪造已回复。
4. **7×24 接待引擎**：新增 `reception-engine.ts`，10 分钟一轮真实轮询（评论+私信），
   命中接待规则才回复，seen 去重、每账号每轮上限 3 条；真实结果写入
   reception-status.json / reception-logs.json。
5. **前端**：全局监控改为展示接待引擎真实结果并新增「立即轮询」；「自动接待」页新增
   「评论接待 / 私信接待」真实收件箱，可读取平台评论/私信并真实回复。

实测结论（真实账号）：抖音账号扫描 8 条评论、私信会话 10 条全部真实读取；

## AI 智能体前端全自动执行器（最终实现）

### 目标

普通用户只需说一句话，AI 智能体必须自己在 Web 前端完成“生成内容 → 选账号 →
点击发布 → 发布成功 → 跳转数据中心 → 自动同步数据”，不得让用户再点按钮，也
不得绕过前端直接调后端写接口。

### 实现方式

- 右侧 AI 助手出现发布动作卡后，前端自动点击“去发布”。
- 发布弹窗自动按目标平台选账号、预填内容、点击“发布”。
- 发布提交后自动跳转数据中心。
- 数据中心自动选中刚发布的账号并点击“同步数据”。
- 同步引擎修复小红书新作品时间格式 `YYYY-MM-DD HH:MM` 的解析，避免同步失败。

### 最终真机验收（只做了一次用户输入）

- 13:24:57 agent 自动点击“去发布”。

- 13:25:18 自动同步完成。
