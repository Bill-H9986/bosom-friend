## 十五、【硬规范】测试一律在前端实操，禁止用后端直连接口代替（用户 2026-09-28 强制要求）

### 为什么必须这样（本次的实证）

一下午修的 6 个 bug，**没有一个能靠"后端直连接口"发现**：

| # | Bug | 后端直连能发现吗 |
| --- | --- | --- |
| 1 | 外层硬塞 `form: 'scene'`，内部分段编排的自动推断整段被跳过 | 不能（除非逐行读日志） |
| 2 | `personImageUrls` 只在 talkingForm 时才传 → 要形象才出镜、要出镜才传图、要图才建形象（死循环） | **完全不能** |
| 3 | 自动建形象额外要求"没有产品图"，而 scene 一定传产品图（第二道锁） | **完全不能** |
| 4 | **`localAssetFile` 不补扩展名** —— 界面传的素材 URL 是 `/assets/file/asset-e27h0rb6`（无扩展名），磁盘是 `asset-e27h0rb6.png` | **完全不能**（API 测试时我手写的是带路径的完整名） |
| 5 | 剪出来的角度图宽高比 0.27，被厂商 400 拒（要求 0.4–2.5） | **完全不能**（我自造的测试图恰好合规） |
| 6 | 提示词增强丢项（「等级证」被删） | **完全不能**（我没在界面上点过那个 ✨） |

**根本差别在于**：API 直连绕过了整条前端链路——上传、素材引用、表单拼装、
提交参数、结果渲染，全都没走。**假链路永远测不出真链路的问题。**

### 规范（今后一律执行）

1. **凡涉及内容创作的功能验证，必须在产品界面上像真人一样操作**：
   上传素材 → 输入提示词 → 点增强 → 选参数 → 点生成 → 看进度 → 验收成片。
2. **测试数据的唯一来源是前端实操产物**（界面上传的素材、界面提交的任务、
   界面跑出来的成片）；后端直连产生的数据只能用于**定位问题**，不得作为验收依据。
3. **浏览器窗口必须留给用户看**：自动化脚本跑完不得关闭窗口；
   需要长时间观察时用独立进程打开（`Start-Process msedge`），而不是 Playwright 的临时会话。
4. **报告里必须写明"这条是在前端实操跑出来的"**，否则不算验证通过。

## 十、提示词增强按业界做法重构（用户要求"去网上学，回来优化"）

### 学到的（三份来源）

| 来源 | 关键结论 |
| --- | --- |
| 腾讯 **Hunyuan-PromptEnhancer** 官方文档 | 增强器的系统提示词要管**四件事**：Task Definition / **Preservation Rules** / **Output Structure** / Style Guidelines |
| **Picva**「专业多视角角色参考图」提示词原文 | 四角度角色表的标准写法：四列、每列上全身下特写头像、左→右为正面/左侧/右侧/背面、等距对齐、**轮廓清晰·面板分隔干净·无文字·细边框·平光** |
| **PromptEnhancer (CVPR 2026)** | 改写器要用**细粒度奖励**约束——"保留原意"与"补全细节"必须分开评估，不能自由改写 |

### 找到的真问题（用户截图实证）

用户输入"**根据图片做 人物建模四视图！大头照+站立三视图！**"，产品生成的却是一张**普通站立人物图**。
根因：增强只做"扩写形容词"（主体/场景/风格…），**没有 Output Structure 这一层**——
用户要的是**一张按行列排好的版面图**，而版面结构没有写进行列描述，模型自然只画单幅画面。

### 改法（`long-video.ts` 的 `enhanceVisualPromptInstruction`）

新增第 2 条 **版面图识别与展开**：原话出现"四视图/三视图/五视图/多视图/角色参考图/角色表/建模图/
三面图/九宫格/拼图/对比图/分镜图"时，必须写清四件事：
① 几列几行；② 每格画什么、格的顺序；③ 格间对齐与间距（等宽等距、同一人物同一服装同一光线）；
④ 版面通用约束（轮廓清晰、对齐一致、面板分隔干净、无文字、细边框、平光）。
字数上限 200 → 300（版面图要写清行列）。

### 实测对比（同一句原话，调 agnes-2.5-flash）

**改前**：出一张普通站立人物图（用户截图即此）。

**改后**（336 字，HTTP 200）：
> 人物建模四视图，**四列排版**。第一列正面，**上格为站立全身像，下格为同一视角的特写大头照**；
> 第二列左侧…第四列背面…**人物为同一人，穿着同一套服装，保持同一光线**，四格姿态表情服饰细节完全一致。
> …轮廓清晰，平光照明…**构图中无文字，细边框分隔各格，面板对齐整齐，间距均匀**。

检查项 9 项命中 7（"头像/侧面"两项是我的检查词与输出用词不同：输出写的是"大头照/左侧右侧"，实际都对）。

学习结论存档：`analysis/prompt-research/学习结论.md`

## 八、内容创作画面跑偏的真凶（用户当场质问后重查）

**先纠正一处我自己的判断错误**：我上一轮按 `desktop-pages/LongVideoPage.tsx` 去改，但**那个页面已经下线**——
`app/layout/routerData.tsx` 第 35-38 行写着「长视频创作」「我的数字人」两个入口已下线，界面上**只有「内容创作」**（`/draft-box`）。
页面组件与路由仍在，需要时把两项加回数组即可。

但这次搞错反而挖到了真凶——**内容创作的 30 秒 / 1 分钟档走的就是那套分段引擎**：

```
/draft-box（内容创作，界面上唯一的创作入口）
  ├─ 时长 ≤ 12 秒  → generateAiVideoDirect    提示词经 mediaPrompt 直达厂商 ✅
  └─ 时长 30/60 秒 → generateSegmentedVideo   写稿 → 分镜 → 逐镜出片 → 拼接
                       └─ api.ts:4730  topic: title.slice(0, 24)   ★ 真凶
```

### 两个致命断点（都已修）

**断点 1：分段链路把「模型写的标题前 24 字」当成题材**

`api.ts` 第 4730 行原本是 `topic: title.slice(0, 24)`。`topic` 是分段链路**唯一**的题材与要求来源
（写稿、抽题材、排分镜全靠它）——用户在内容创作里填的提示词**在这条链路上连门都没进**。
一条 60 秒的片子于是按"标题那 24 个字"排画面。

> 这也是我上一轮"加 `visualBrief: topic`"实际没生效的原因：那个 `topic` 拿到的正是标题前 24 字。

修法：`topic: userVisualPrompt !== '' ? userVisualPrompt : title.slice(0, 24)` —— 用户写的优先，没有才退回标题。

**断点 2：逐镜下单调没有二次钉住用户要求（用户点名要的那步）**

分镜提示词里写"逐条落实"不等于模型照做（实测它会压缩、换词、整段丢）。而厂商**只看单镜那一段 prompt**——
分镜这一步丢掉的信息，出片时无处可寻。

修法：`storyboard.ts` 新增 `pinVisualBrief(shots, brief)`，在镜头卡片落盘前把用户原文**贴在每一镜 visual 的最前面**：

```
【用户对画面的硬要求 · 逐条落实，不许概括或改写】无人机 装调检修操作工 …（原文 217 字）。<模型写的这一镜画面>
```

接入点四处（两个生成器的 模型路径 + 兜底路径）：`pinVisualBrief(ensureBrollShots(...), topic)`、
`pinVisualBrief(fillMissingLines(...), topic)`、两处 `pinVisualBrief(fallbackShotPlan(...), topic)`。
**兜底路径也钉**——否则"模型挂了"就等于"用户要求丢了"。

## 十七、图片链路对标官方 + 参数真实性（2026-09-29 凌晨）

用户追问两件事：**整个内容创作板块（不只视频）是否换成官方内核**、**所有参数是否返回真实数据**。
审计结论：视频换的是"规范"，官方那套确定性本地媒体工具**一个都没接**；**图片链路此前是零对标**。

### 图片链路补齐的四件事

| 差距（审计发现） | 证据 | 修法 |
| --- | --- | --- |
| 官方四套图像提示词结构**定义了却零调用点** | `AGNES_IMAGE_PROMPT_STRUCTURES` 只在 agnes.ts:157 出现一次，全仓无使用 | 新增 `enhanceImagePromptInstruction`，按参考图张数选结构（文生图 / 图生图 / 多图合成），增强接口按 `kind` 分流（图片不再套视频六段） |
| **参考图只传第一张** | 适配层 `imageBody` 用 `(request.images ?? []).find(...)`；官方文档写明 `image` 是**数组**、"多图合成时传入多张图像" | 实测 `image:[图1,图2]` → **HTTP 200**、产物保住人物与设备；适配层与产品层都改成传全部 |
| 多图**不指名用途** | 官方要求"说明每张参考图的角色，以及最终图像应如何组合" | 提示词以 `<Picture 1> 是人物身份参考；<Picture 2> 是素材参考…` 开头（接口实测原文） |
| 图/视频增强口径混用 | 增强接口只有一套视频指令 | 前端按 `contentType` 传 `kind` 与参考图张数；接口实测返回 `<Picture 1>作为人物身份参考，<Picture 2>作为产品/设备外观参考…` |

尺寸这一环**本来就对**：产品把"档位 + 画幅"算成成品像素，落盘前用 `cropImageToSize` 裁到 720x1280
（厂商 1K 9:16 原生是 736x1312，实测确认）。

### 参数真实性：三处改动

1. **成片时长改为实测落盘**（`actualSeconds`）：记录里原有的 `voicedSeconds` 是母时钟**估算**
   （第六轮 62 秒），成片实测 67.2 秒——两个语义不同的数不能混用。
2. **时长账本核对**：逐镜 ffprobe 实测合计 **67.11 秒**，成片 **67.20 秒**，差 0.09 秒（拼接误差）✅
3. **新增今日额度接口**（`GET ai/video-quota`）：厂商没有额度查询接口，官方只给"免费档每天 500 秒、
   每分钟真正执行 1 次"两条硬事实，所以这是**本机记录口径**并在字段里标注 `source: 'local-records'`。
   第一次实现把失败任务的目标时长也加进去（显示 631 秒、虚高），已改成"成功任务用实测秒数、
   未完成任务按已跑成镜数 × 5 秒"——修正后 **270 / 500 秒**。界面上显示在时长选择器弹层里。
