# 工作日志 2026-09-15（内核运行时解压：同一台机器上的第二次失败 → 自带解压器）

> 用户口径：「这又是什么问题？如何解决？！」——现场截图是 0.2.47 在**那台 4 核 / 7.9GB 机器**上的启动页：
> 80%「加载产品界面」+ 错误框
> 「内核运行时解压失败（PATH 上的 tar.exe 失败（spawn tar.exe ENOENT）；随包 Python 失败（Command failed: … python.exe -m zipfile -e …））」。

## 1. 先反推：这次不是 DEF-045 没修好，是"修法本身还会失败"

截图里有三条判据，不用猜：

| 现象 | 反推 |
| --- | --- |
| 失败清单里**没有**「系统自带 tar.exe」 | 那台机器上 `%SystemRoot%\System32\tar.exe` **真的不存在**（0.2.47 已按 DEF-045 先判绝对路径，命中才会出现这一项） |
| 随包 Python 报 `Command failed` 而不是 `ENOENT` | `python.exe` 起来了，失败在**解压过程**里 |
| 错误框里只有一整行命令行 | 文案把 `execFile` 的 stderr 丢了——真实原因从未出现在用户面前，也没落盘（DEF-056） |

## 2. 根因：MAX_PATH 260（Windows 默认关闭长路径支持）

- 这份 zip：**200537 个条目**、385MB，最深相对路径 **232 字符**（运行时文件里最深 226）；
- 解到 `%APPDATA%\Bosom Friend\kernel-runtime` 后最深 **289~290 字符**，超过 MAX_PATH 260；
- Windows 的长路径支持默认是 **关**（`HKLM\SYSTEM\CurrentControlSet\Control\FileSystem\LongPathsEnabled=0`），而且微软文档写明它**按进程缓存**、"只对声明了 longPathAware 的应用生效"；
- Python 3.6+ 的 `zipfile` 与 libuv（Node/Electron）都吃这一条：manifest 声明了 longPathAware，也要注册表开关为 1 才真正越过 260。

于是那台机器上三条路全断：系统没有 tar → PATH 上没有 tar → 随包 Python 撞 MAX_PATH。

**上一轮为什么没发现**（测试有效性缺陷，如实记）：0.2.42 那轮"随包 Python 深路径实测（352 / 459 字符全部成功）"是在**本开发机**上做的，而本机 `LongPathsEnabled=1`（本机实测 `reg query` 为 0x1）。结论只在"已经开了长路径的机器"上成立，却被写成了"没有 tar 的机器也能自救"。

**测试抓到两个真问题**（不测就会带着出门）：

| 问题 | 表现 | 修法 |
| --- | --- | --- |
| 数组 splat 传参按位置绑定 | `& $ladder @('-AppDir', $AppDir, …)` 让阶梯把安装目录读成字符串 `-AppDir`，于是去 `-AppDir\resources\kernel-runtime.zip` 找 zip → 报"zip 缺失" | 改具名传参 `& $ladder -AppDir … -UserData … -UnzipScript …`；探针加断言禁止回到 `@ladderArgs` |
| `.cmd` 内容不能有中文 | cmd.exe 按 OEM 代码页读文件，UTF-8 中文路径变乱码 → `cmd /c` 报"文件名、目录名或卷标语法不正确" | 入口 `.cmd` 只放 ASCII（中文**文件名**可以），中文提示放进带 BOM 的 `.ps1`；探针断言 `.cmd` 全 ASCII |
| 修复包"先解压再判成败" | 在**安装期解压成功过**的机器上跑（zip 已被安装器删掉）：先打一句 `FAIL: …zip is missing`，紧接着又说"修复完成"，自相矛盾——用户不知道该信哪句 | 判定口径改成**只看 `runtime\bin-desktop.mjs` 是否在位**：在位且没加 `-Force` 就直接跳过并说"本来就在位，无需解压"；解压阶梯非 0 但入口在位时，如实解释"那句 FAIL 通常是 zip 已被删"，不假装解压成功 |

**修复包验收**（本机实测）：造"含 `runtime/bin-desktop.mjs` 的小 zip + 硬链接 `runtime\node.exe`"冒充安装目录 →

探针从 39 项扩到 **44 项全绿**（新增：修复包成员齐全、`.cmd` 纯 ASCII、入口做 A+B 两件事、禁止数组 splat、生成器引用仓库同一份阶梯与解压器）。
