## 2. 定位：这句话从哪来

代码路径都在 `desktop/electron/main.cjs`：

1. `kernelRootForVersion()`（26-32 行）：先看 `%APPDATA%\Bosom Friend\kernel-runtime\runtime\bin-desktop.mjs`，
   没有就退回 `kernel-runtime-<版本>`；
2. `ensureKernelExtracted()`：两份都没有 → 找 `resources\kernel-runtime.zip`；
   zip 不在会报「内核运行时缺失，请重新运行安装包完成修复安装」；**zip 在**才去 spawn tar；
3. 屏幕上出现的是 spawn 错误而不是"内核运行时缺失" ⇒ **zip 确实还在**；
   而 `build/installer.nsh` 只在解压成功（`StrCmp $0 "0"`）时才删 zip ⇒ **安装期那次解压也没成功**。

也就是说：这台机器上内核运行时压根没解压出来，应用启动时的兜底解压又起不来 tar.exe。

## 3. 为什么 tar.exe 会起不来（本机实测复现）

用 Node 24 在 Windows 11 上逐条验证，**三种完全不同的原因给出的是同一句话**：

| 条件 | 实测结果 |
| --- | --- |
| 正常 PATH + 正常当前目录 | OK |
| `System32\tar.exe` 存在，但进程 PATH 里没有 System32 | `spawn tar.exe ENOENT` |
| 绝对路径 + 进程当前目录不存在 | `spawn tar.exe ENOENT`（连绝对路径也一样） |
| 机器上真的没有 tar.exe | `spawn tar.exe ENOENT` |

判据：安装器用的是**绝对路径** `"$SYSDIR\tar.exe"`、当前目录也正常，所以后两条解释不了"安装器也失败"。
**如果那台机器装的是安装包，最合理的解释是第 1 条：系统里没有可用的 tar.exe**
（1803 以前的老 Win10、精简/ghost 镜像被删过 System32 工具、被"系统瘦身"工具清理过）。
