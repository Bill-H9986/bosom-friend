## 第 1 章 这个 APP 是什么（大白话版）

### 1.1 一句话

装在你自己 Windows 电脑上的 **AI 自媒体工作台**：双击安装、扫码登录你的抖音/小红书账号、用中文说一句话（比如"帮我写一篇招工笔记并发出去"），AI 就替你把内容写出来、把账号数据同步回来。

### 1.2 用户能看到的六件事

| 页面 | 用户在这里干什么 |
| --- | --- |
| 智能助手 | 用中文下命令，AI 干活并回话 |
| 账号管理 | 扫码绑定抖音/小红书，看头像、昵称、粉丝数 |
| 内容创作 | 生成文案/图片/视频草稿，选平台、参数 |
| 发布 | 把草稿发到真实平台，看发布记录 |
| 数据中心 | 看作品、互动数据的真实统计 |
| 设置 | 填自己的大模型 API 地址和密钥 |

## 第 2 章 你自己怎么判断"能不能用、好不好用"

> 你不需要懂编程。下面两套检查，照着点就行。

### 2.1 "能用"5 条硬检查（5 分钟）

| # | 检查 | 通过标准 |
| --- | --- | --- |
| 1 | 双击安装包，一路下一步 | 装完桌面出现图标，中途没有报错弹窗 |
| 2 | 双击图标启动 | 30 秒内出现窗口，能看到主界面（不是白屏、不是转圈不动） |
| 3 | 打开"账号管理" | 能看到你绑定的账号和头像；绑定过程只用扫码，不用改文件 |
| 4 | 在助手对话框说一句"看看我的账号数据" | AI 回话并给出**真实数字**；没有数据就明说"没有"，不编造 |
| 5 | 关掉窗口、再从任务管理器看 | 没有残留的后台进程在偷偷跑 |

任一条不通过，就是"不能用"，不用继续往下测。

### 2.2 "好用"10 个问题（把业界公认的可用性十条翻成普通话）

来源：Nielsen Norman Group《10 Usability Heuristics》([原文](https://www.nngroup.com/articles/ten-usability-heuristics/))。

| # | 问自己 | 不合格的样子 |
| --- | --- | --- |
| 1 | 点了之后，界面有没有马上告诉我"正在做什么/做完了"？ | 点了没反应、转圈没有文字 |
| 2 | 界面说的话我听得懂吗？ | 出现 `code=500`、`ECONNRESET`、文件路径、堆栈 |
| 3 | 我点错了能不能撤回/取消？ | 删了就没了，或者删完还显示着 |
| 4 | 同一个东西在不同页面的叫法一样吗？ | 一处叫"素材"一处叫"推广素材" |
| 5 | 会不会容易误操作？ | 删除没有二次确认，或者默认勾选危险项 |
| 6 | 我要靠记忆吗？ | 必须记住上一步在哪、刚才填了什么 |
| 7 | 熟手能不能更快？ | 每件事都得点 5 下 |
| 8 | 界面干净吗？ | 一堆看不懂的按钮和数字 |
| 9 | 出错时告诉我"哪里错了、怎么办"了吗？ | 只说"操作失败"，不说原因 |
| 10 | 有简单说明或帮助入口吗？ | 第一次用完全不知道从哪开始 |

### 2.3 发现问题怎么报（三件套，缺一不可）

1. **截图**：出问题那一屏（不要只截弹窗，要能看到页面标题）。
2. **哪一步**：你点的是哪个页面、哪个按钮、第几步。
3. **你期望什么、实际看到什么**：一句话说清。

有这三样，AI 才能复现并修；只说"又坏了"无法定位，只能反复试。

## 第 3 章 开发标准与依据（这些是网上查来的权威资料）

> 每条都写清"依据什么 → 本项目怎么落地"。落地不上的，写进第 7 章缺口，不装作已经做到。

### 3.1 桌面软件安全

依据：Electron 官方《Security》安全清单 20 条（[链接](https://www.electronjs.org/docs/latest/tutorial/security)）。要点：只加载 HTTPS 内容、不给远程内容开 Node 集成、开启上下文隔离与沙箱、定义 CSP、禁用 `webSecurity=false`、限制导航与新窗口、用当前版本 Electron、校验 IPC 消息来源。

本项目落地：Electron 主进程只加载本地页面；桌面脚本改为外部文件以符合严格 CSP；渲染层通过 `preload` 暴露 `window.bosomKernel`，不直接给页面 Node 能力。

### 3.2 安装与代码签名（直接影响"好不好用"）

依据：Microsoft《Windows 应用开发者的 SmartScreen 声誉》([链接](https://learn.microsoft.com/zh-cn/windows/apps/package-and-deploy/smartscreen-reputation))。关键事实：

- 未签名的安装包，用户运行时会看到"Windows 已保护你的电脑"，必须手动点"仍要运行"；企业策略可以直接拦住。
- 有效证书（OV/EV）签名：首次仍可能提示"无法识别的应用"，但会显示**已验证的发布者名称**；信誉随下载量累积。
- **EV 证书不再绕过 SmartScreen**，不必为绕过警告多花钱。
- 官方建议的非商店分发签名方式是 Artifact Signing（约 9.99 美元/月起，无需硬件令牌，可接 CI）。
- 上架 Microsoft Store 的包由微软重签，**永不出现 SmartScreen 警告**。

依据：Microsoft《Windows 桌面应用认证要求》([链接](https://learn.microsoft.com/en-us/previous-versions/windows/win32/win_cert/certification-requirements-for-windows-desktop-apps))：桌面应用必须"可独立安装、可干净卸载、安装不失败、不留垃圾"，用 Windows App Certification Kit 验证。

本项目落地：安装/卸载/升级保留数据已做（0.2.0 干净室验收），**但 0.2.33 未做**，且**未签名**——这是当前"好用"最大的短板，见 8.2。

**实测现状（2026-09-09）**：`Get-AuthenticodeSignature` 对 `BosomFriend-Setup-0.2.33.exe` 返回 **NotSigned**；本机 `Cert:\CurrentUser\My` 无代码签名证书；`electron-builder.yml` 未配置签名；`CSC_LINK` 未设置。用户首次安装必然遇到 SmartScreen 警告。

**产品决策（2026-09-09，用户拍板）：不做代码签名。** 本机不购买、不配置任何代码签名证书；
安装包保持未签名状态，接受首次安装出现 Windows SmartScreen 提示。原因与取舍：

- 用户明确要求"不要签名"，本项从 P0 清单移除；
- 未签名的实际影响只有一条：首次下载运行会提示"无法识别的应用 / Windows 已保护你的电脑"，用户点"仍要运行"即可；
- 对内测/自有账号使用不构成阻塞；若将来面向陌生用户大规模分发，再重新评估（届时按下面清单采购）。

**（以下为将来重启该决策时的采购参考，当前不执行）买哪种证书（2026 年市场行情）**：

| 类型 | 适用主体 | 价格/周期 | 说明 |
| --- | --- | --- | --- |
| IV 个人验证 | 个人开发者、个体户 | 1–3 个工作日 | 只需身份证，无需营业执照；签名后显示已验证的个人姓名 |
| OV 组织验证 | 注册企业 | 约 3,588–4,888 元/年 | 需营业执照等企业资质 |
| EV 增强验证 | 仅注册企业 | 约 6,888 元/年 | **EV 不再绕过 SmartScreen**（微软官方文档），不必为此多花钱 |
| Microsoft Artifact Signing | 个人或企业 | 约 9.99 美元/月起 | 无需硬件令牌，可直接接 CI/CD |

**证书到手后要做的三步（配置已备好，届时直接加）**：

```yaml
# electron-builder.yml → win 段
win:
  certificateFile: ${env.CSC_LINK}          # .pfx 路径或 base64
  certificatePassword: ${env.CSC_KEY_PASSWORD}
  signingHashAlgorithms: [sha256]
  rfc3161TimeStampServer: http://timestamp.digicert.com
```

1. 加上述配置 + 在构建机设置 `CSC_LINK` / `CSC_KEY_PASSWORD`（不写进仓库）。
2. 构建后校验：`Get-AuthenticodeSignature` 必须为 `Valid`，发布者名称与证书一致。
3. 把安装包 SHA256 与签名结果写入发布就绪清单，作为发布证据。

**预期管理**：签名只解决"发布者身份可信"；SmartScreen 信誉仍随下载量与时间累积，首次下载可能仍提示"无法识别的应用"（但会显示已验证的发布者名称）。要完全无警告，只能上架 Microsoft Store。

## 第 4 章 产品铁律：AI 全自动不可妥协 + 风险缓解

### 4.0 已拍板的产品决策（2026-09-09，任何情况下不改）

| 项 | 内容 |
| --- | --- |
| 驱动核心 | DSH（唯一运行时） |
| 产品理念 | AI Agent 全自动一站式服务平台 |
| 面向人群 | 普通用户（不懂编程、不懂技术） |
| 核心卖点 | **AI 驱动全自动——任何情况下都不改** |

**全自动的范围（全链路，无人工兜底节点）**：内容创作 → 素材 → 发布 → 互动（点赞/评论/私信/关注/浏览）→ 数据同步 → 客服接待 → 账号运维，全部由 AI 自动完成。

由此确定三条不可动摇的开发准则：

1. 每个功能的验收标准都是"**普通用户说一句话，AI 全自动办完**"，不设"必须真人点最后一下"这类降级要求。
2. 任何以"降低风险"为名削弱自动化的方案一律作废。本文档 v2.0 初稿曾提出"真人确认发布"，**已作废**。
3. 互动自动化同样全自动（2026-09-09 拍板，见 4.3）；风险一律通过 4.2 的缓解措施与 4.4 的告知处理。

### 4.1 必须记录的事实（不影响决策，只影响怎么做）

**平台规则**：小红书 2026-07-17 治理公告禁止"用技术手段模拟真人、非真实内容创作或虚假互动"，列举范围含自动生成并自动发布、用脚本或自动化 APP 代替真人操作、批量模拟真人互动，已处置 **42 万个**账号（[报道](https://www.ctdsb.net/c1716_202607/2803091.html)）。抖音开放平台曾对滥用接口权限的开发者封禁整改（[报道](https://www.geekpark.net/news/275021)）。

**法律义务**：《个人信息保护法》（[全文](http://www.npc.gov.cn/npc/c2/c30834/202108/t20210820_313088.html)）第六条最小必要、第十三与十四条充分知情自愿明确的同意、第十七条清晰易懂的告知、第二十四条自动化决策的透明度。

**后果**：全自动发布在第三方平台上存在账号被限流或封禁的风险。这是**用户账号的风险**；产品的应对方式是"可告知、可缓解、可恢复"，而不是降低自动化。

### 4.2 全自动前提下的风险缓解清单（开发必须做，逐条进 RTM）

| # | 措施 | 落地要求 |
| --- | --- | --- |
| 1 | 账号环境隔离 | 一个账号一套独立浏览器数据目录，登录态互不串用 |
| 2 | 拟人化操作（主手段） | 真实浏览器 + patchright 反检测 + 真实鼠标轨迹/键盘节奏 + 随机停顿与滚动 + 非固定时间点；禁止接口直灌 |
| 2b | 按平台规则适配 | 逐平台维护"平台规则 → 我们的做法"对照表（见 4.5），不做一刀切限额 |
| 3 | 内容质量把关 | AI 生成后过质量检查（重复、空话、敏感词），低质不自动发 |
| 4 | 登录态健康巡检 | 周期检查登录有效性，失效即在页面提示"请重新扫码"并引导重登 |
| 5 | 一键换号与恢复 | 账号异常可立即切换；任务队列状态可恢复、不卡死 |
| 6 | 失败如实报错 | 平台拒绝就显示真实原因，禁止假成功（铁律 #4/#7） |
| 7 | 全流程可回放 | 每步操作截图留痕（AC-017），用户能回看 AI 干了什么 |
| 8 | 数据本地化 | Cookie/密钥只存本机、不进备份轮转，提供导出与删除 |
| 9 | 风险告知 | 首次启动与首次发布用大白话提示平台风险，写进用户协议 |

### 4.3 自动互动：同样全自动（2026-09-09 拍板）

自动互动 = 替用户对别人点赞、评论、私信、关注、浏览。**已拍板：全自动，不设人工触发兜底。**

落地要求（并入 4.2 一起进 RTM）：

| # | 要求 | 说明 |
| --- | --- | --- |
| 1 | 全自动执行 | 用户一句话即可让 AI 自动完成互动，无需再点确认 |
| 2 | 节奏拟真 | 严格限频 + 间隔随机化，禁止固定秒级机械节奏（对应 4.2 第 2 条） |
| 3 | 内容质量把关 | 评论/私信内容过质量检查，禁止模板刷屏、重复灌水（4.2 第 3 条） |
| 4 | 过程可回放 | 每条互动留截图与说明，用户可回看（4.2 第 7 条） |
| 5 | 失败如实 | 被平台拒绝或限流时如实显示原因，禁止假成功 |
| 6 | 可随时停止 | 用户说"停"即停，正在执行的任务可中止 |

风险事实见 4.1，已记录不再重复；产品方向以本节为准。

### 4.4 用户告知文案（首次启动 / 首次发布）

> 本软件会以自动化的方式替你操作你在第三方平台的账号。平台可能对自动化操作进行限制，极端情况下可能导致账号被限流或封禁。请自行评估风险后再使用；你可以随时在"账号管理"里解绑账号并删除本机数据。

### 4.5 平台规则 → 我们的自动化策略（逐平台维护）

抗风控靠**拟人化行为 + 按平台规则适配**，不是"一天只发一条"的一刀切限额。

| 平台 | 平台规则要点（公开） | 我们的做法 |
| --- | --- | --- |
| 小红书 | 禁止用脚本/自动化代替真人发布与互动；禁止 AI 批量填充主页 | 真实浏览器拟人操作 + 真人可读内容 + 合理限频；不接官方开放接口 |
| 抖音 | 滥用开放接口权限会被处罚，强调真实创作者 | 同上；不做接口批量调用 |
| 视频号 / 快手 / 哔哩哔哩 … | 待补 | 接入前先把"平台规则 → 我们的做法"写进本表 |

**通用拟人化清单（每个平台任务都必须满足）**：

1. **真实浏览器**：优先用本机真实 Chrome（`engine/social-auto-upload/conf.py` 的 `LOCAL_CHROME_PATH`），缺失时用随包 chromium；开启 patchright 反检测。
2. **节奏拟人**：点击/输入前后随机停顿 200–1500ms；滚动与鼠标轨迹自然；同一动作间隔随机 5–25 分钟；禁止固定秒级节奏。
3. **单账号串行**：同一账号同一时刻只允许一个平台任务。
4. **内容门槛**：AI 产出后过滤重复/空话/敏感内容，低质不自动发。
5. **频率可配置**：默认每账号每天发布 ≤3 条、互动 ≤20 次；参数写在配置里，不写死。
6. **失败即停**：同一场景连续失败 2 次停止并定位，不反复重试刷。

## 第 5 章 架构与边界（v1.0 内容保留）

### 5.1 唯一目标

做一个对标腾讯 WorkBuddy 的纯正 Windows `.exe` 桌面软件：DSH 是唯一应用运行时（大脑 + 躯干都长在 DSH 上）；前端是自研显示层，不用 DSH 网页 UI；普通用户双击安装、桌面图标、扫码登录、自然语言下达任务；安装/升级/卸载干净，升级保留数据，退出无进程残留。

### 5.2 一条主线

- 主线目录：`products/bosom-friend`（含已验证的 DSH 内核运行时、业务工具、门禁与追溯体系）。
- `products/bosom-friend-v2` 冻结为只读参考；自研 `bosom-friend-harness`、直连 `/chat/completions`、`dsh-web-app` 进入淘汰清单。
- Web 端（0.13.x）已冻结，改动需明确批准；桌面端 0.2.x 是唯一主线。

### 5.3 边界定死（DSH 单运行时）

1. DSH 是唯一应用运行时，所有业务能力注册为 DSH 插件/服务。
2. AI 主动决策执行的动作 = 类型化工具，供 Agent 调用。
3. 普通增删改查 = 服务缝直调，不经过 Agent 循环。
4. 长外部任务（登录/发布/同步/客服）= 带状态、重试、审批的任务队列，一个平台共享一个浏览器实例，退出可恢复、不残留进程。

详见 `products/bosom-friend/docs/adr/ADR-002-DSH边界与数据所有权.md`。

### 5.4 数据所有权

- DSH Session 日志：只负责 AI 对话历史、Agent 状态、工具调用记录。
- 产品数据店（schema 版本化原子存储）：账号/素材/草稿/发布/数据/接待的唯一事实源。
- 前端不保存第二份会话状态；删除必须多实体一致，失败要报错，禁止假装成功。

### 6.3 完成定义（中文可执行版 DoD）

一个功能只有同时满足下面 7 条，才算"做完"：

1. RTM 里有一条 AC，写明 Given-When-Then。
2. 在**前端页面**上能操作出结果（不是接口返回 0）。
3. 有同一时刻的**页面截图/可见文本**作为证据。
4. 增删改查四步都通（新增→列表出现；编辑→立即反映；删除→列表消失且详情不可再读）。
5. 出错时有**人能看懂**的错误提示，不是堆栈。
6. 一键门禁该项为绿。
7. 变更日志有记录。

不满足的，一律说"没做完"，不许说"基本完成"。

### 6.5 跟随模式（侧边栏「跟随模式」按钮）到底是什么

| 项 | 说明 |
| --- | --- |
| 位置 | AI 助手侧边栏顶部，**默认开启**（`store/agentFollow.ts`，localStorage key `bosom-friend-agent-follow`） |
| 开启时 | AI 回复带动作卡（去发布 / 去草稿箱 / 去数据中心…）后，前端执行器 400ms 后自动点击并跳转；发布弹窗随后自动选账号、自动提交、自动跳数据中心同步。**全程只在前端 DOM 操作** |
| 关闭时 | AI 照常回答并展示动作卡，但必须由用户自己点 |
| 实现 | `components/AIAssistantPanel/index.tsx`（`autoExecutedKeyRef` + `executeAgentPublishAction` / `executeAgentNavigateAction`） |
| 边界 | 跟随模式只执行"前端动作"：它不代替 AI 思考，也不允许用后端接口补动作 |

实测（2026-09-09 S 级监考）：跟随模式开启时，一次"发送"即可让 AI 自动完成
"出内容 → 点去发布 → 发布 → 跳数据中心 → 同步账号"，两个平台各 1 次，均 PASS。

### 6.7 APP 智能体的规则（模型可见系统提示）

规则不再是几十行临时文案，而是一份十节结构的专业规则，单一事实源在
`products/bosom-friend/server/src/agent-rules.ts`，每次对话随系统提示下发给内核模型。

| 节 | 作用 |
| --- | --- |
| 一、身份与目标 | 全自动一站式服务平台的执行者；判断标准 = 普通人一句话能否办完 |
| 二、最高原则 | 全自动 / 前端动手 / 每步可见 / 诚实 / 风控优先 / 数据不出本机 |
| 三、能力边界 | 能做什么、不能做什么（含封禁无法保证、扫码必须真人） |
| 四、工具使用规则 | 只有只读工具；先查后答、空就是空、报错就说、不重复刷 |
| 五、标准业务流程 | 发布 / 登录换号 / 数据同步 / 客服接待 / 互动运营 五套 playbook |
| 六、输出契约 | 固定开头语、必给字段、禁止输出的内容与话术 |
| 七、失败与异常处理 | 六类现象 → 人话原因 → 下一步动作；连续失败 2 次停 |
| 八、合规与风控 | 拟人化、按平台规则适配、限频、内容门槛、不刷量 |
| 九、自检清单 | 每次回复前 9 条自查 |
| 十、红线 | 泄露密钥 / 伪造成功 / 绕过前端 / 编造数据 / 违反平台规则 / 无视限频 |

**门禁**：`node products/bosom-friend/qa/verify-agent-rules.mjs` → `AGENT_RULES_OK`；
缺少任一章节、红线或 `api.ts` 未引用即红灯。

**改规则的纪律**：只增不改语义；改语义必须同步本节与门禁清单，并在变更日志留痕。

### 6.8 开发迭代方式：Web 端是开发版，打包只在发布节点

| 场景 | 命令 | 耗时 |
| --- | --- | --- |
| 改前端 | `powershell -File products/bosom-friend/launcher/scripts/dev-web.ps1 -Frontend` + 浏览器硬刷新 | ~1 分钟（**不重启**） |
| 改服务端 / 内核 | `powershell -File products/bosom-friend/launcher/scripts/dev-web.ps1` | ~2–3 分钟（tsx 重载模块） |
| 发布打包 | `bash products/bosom-friend/desktop/build-win.sh` | 10+ 分钟（1.9GB 引擎 + NSIS 压缩） |

- 开发版地址：`http://127.0.0.1:31280/bosom-friend/`；数据根仍是 `~/.bosom-friend`
  （与安装版共用，二者只能同时跑一个）。
- 版本号：开发版由 `dev-web.ps1` 注入 `BOSOM_FRIEND_VERSION`（取 desktop/package.json）；
  安装版由桌面壳注入 `app.getVersion()`。两条路径都不会回落成前端构建期旧版本号。

## 第 9 章 小白术语表

| 词 | 大白话 |
| --- | --- |
| Electron | 把网页技术做成桌面软件的"外壳"，本 APP 的窗口就是它 |
| DSH / 内核 | 负责"AI 思考和调工具"的大脑；本 APP 的大脑 |
| 前端 / 后端 | 前端=你看到的界面；后端=界面背后干活的程序 |
| 门禁 | 一套自动检查脚本，跑完给红/黄/绿灯 |
| S 级验收 | 只能用真实页面操作、留截图取证的验收，最严格那一档 |
| RTM | 需求-验收对照表，每条需求对应一条可验收的准则 |
| AC | 验收准则（Acceptance Criteria），一条可判断真假的标准 |
| DoD | 完成定义，一个功能"算做完"的清单 |
| 冒烟测试 | 快速跑一遍主流程，看有没有立刻崩 |
| 回归 | 改完一处后，回头确认没把别的地方弄坏 |
| SemVer | 版本号规则：主.次.修订 |
| 代码签名 | 给安装包盖"身份章"，让 Windows 认得出发布者 |
| SmartScreen | Windows 的安全提示，未签名的软件会被它拦 |
| Cookie | 网站记住"你已登录"的凭据，本 APP 存在你本机 |
