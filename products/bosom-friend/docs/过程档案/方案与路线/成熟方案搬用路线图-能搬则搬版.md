## 一、对症下药总表（你报的问题 → 搬什么 → 治在哪）

| 你报的问题 | 对症方案 | 许可证 | 搬法 |
|---|---|---|---|
| 创作参数永远不对 | Customer-Agent 开发规范：**先 curl 实测真实请求/响应结构再写代码**，字段名以实测为准、不凭猜（含单位换算如分→元） | MIT | 规范直接搬，写进项目铁律 |
| 参数不对（工程面） | 参数五环追踪测试：UI 填写→请求体→生成任务→产出物→页面回显，逐环断言 | 自研（半天量） | 挂进测试清单 F 组 |
| AI 发布有很大问题 | social-auto-publisher 的 **16 个真实踩坑 SOP**：抖音文件上传必须走 CDP `DOM.setFileInputFiles`（页面 API 是沙箱的）；登录→提交必须同一连续会话；反检测 flag + 持久档案 | MIT | SOP 直接照做，代码可搬 |
| 发布引擎本身 | social-auto-upload（项目 8/31 已在用，9.5K 星，持续活跃，patchright 驱动）——**不换，深用+升级** | MIT | 已集成，补齐平台覆盖 |
| 登录/退出状态不对 | Douyin-mcp 的 storage_state 持久化登录态思路（扫码一次、落盘、重启免扫）| AGPL ⚠️ | 只学思路，自实现 |
| 实时数据不对 | 页面驱动采集创作者后台（项目 engine/worker.py 已有底子）+ Customer-Agent 的**断线重连+心跳**模式 | MIT（模式） | 模式照搬 |
| AI 客服用不了 | Customer-Agent 整套架构：**消息队列+处理器链（预处理器→AI→关键词）+ 双知识库 + 关键词转人工 + WebSocket 重连** | MIT | 架构图级搬用 |
| 抖音私信发不出（历史遗留） | Douyin-mcp 的 **Draft.js paste 事件注入**（抖音输入框是 Draft.js，fill()/type() 无效；ClipboardEvent paste 触发 onChange，两套降级链路）+ **DOM 零成本消息提取**（不 OCR） | AGPL ⚠️ | 只学思路，代码自己写（技术方法不受版权保护） |
| 各自为政、没关联 | Electron 专业测试的 **typed IPC channel maps**（共享 TS 类型定义所有通道+负载，编译期抓契约漂移）+ 数据流集成验收链 | 方法论 | 直接落地 |
| 智能体只能对话 | 就是 0.2.0 方案 M4 没干完：搬来的发布/采集/接待能力全部注册为 **DSH 类型化工具**，Agent 循环才有手 | DSH 官方 | 按 DSH Service/Tool seam 接 |

## 三、测试方法论升级（治"测了还是不能用"）

依据：Electron 官方自动化测试文档 + 2026 桌面 QA 指南。

| 层 | 方法 | 治什么 |
|---|---|---|
| L1-L2 | **typed IPC channel maps**：全部 IPC 通道+负载用共享 TS 类型定义，两侧编译期校验 | 模块各自为政、契约漂移 |
| L2.5 | **IPC 负向测试**：每个 preload API 至少一条非法输入路径，必须被拒 | 静默吞错、脏数据入库 |
| L3 | **Playwright `_electron.launch`**：真实启动 desktop/main.cjs，断言窗口/IPC/主进程行为 | 只测过 Web 皮、没测过桌面壳 |
| L4 | 保留现有 S 级监考（页面可见=验收） | 功能造假 |
| L5 | 打包冒烟：ASAR 内容校验、安装/启动/升级（既有清单 A 组） | 装不上/升级丢数据 |
| 全层 | 接口改动前 **curl 实测契约**（Customer-Agent 规范） | 参数"永远不对" |
