## 0. 结论速览

1. 仓库根有 **44 个 `.md`**：基座官方 10 篇、混合 1 篇（`Vibe-Coding-避坑实战指南.md`，被 `AGENTS.md` 引用）、**产品过程文档 33 篇**。另有 7 个散件文件与 5 个非基座目录。
2. 根目录产品文档**不是"没人要的垃圾"**——它们全部是知识库导入脚本 `原文/本仓库` 组的素材（2026-09-14 那次导入收了 309 篇本仓库文档）。整理必须**同时**满足"根目录变干净"和"导入不丢篇"。
3. **最高优先级约束**：导入脚本对"仓库根目录下的 `.md`"有专门规则，路径含 `/` 的一律不收。因此**产品过程文档只能移到 `products/bosom-friend/**` 之下**，移到任何新建的根级目录（`docs/`、`归档/`、`过程档案/`）都会让它们整体掉出知识库，且不会报错。
4. 仓库根 `docs/` 是 **DSH 基座文档区**，受 `pnpm run doc-sync` 与 VitePress 死链门禁管辖，**禁止**放产品过程文档。
5. `products/` 下有 5 处冗余已逐个核实（第 2 节），其中只有 `products/products/` 和 `products/bosom-friend/.a2-verify/` 是明确的误放；`desktop/dist`、`desktop/release`、`desktop/vendor-kernel5` 是 14.4 GB 的**已忽略构建产物**，属清理而非整理。
6. **知识库当前是空的**：`~/.bosom-friend/bosom-friend/knowledge.json` 现在只有 1 篇笔记（`自动沉淀/生成记录.md`）。2026-09-14 导入的 341 篇已不在文件里（其备份文件同样只有 1 篇）。结论：**必须先整理、后导入**，否则会在知识库里留下"旧路径 + 新路径"两份同名笔记且永远删不掉。

### 3.2 每一类的落点理由

1. **产品过程文档 → `products/bosom-friend/docs/`**：这是唯一同时满足三方约束的落点。① 导入脚本对 `products/bosom-friend/**` 下的 `.md` 无条件收录（`rel.startsWith('products/bosom-friend/')` 直接返回 true），**移动后零篇丢失、脚本零改动**；② 不进入基座 `docs/`，不触发 `doc-sync` / VitePress 死链门禁；③ 与既有 `products/bosom-friend/docs/` 分区（`adr/`、`releases/`、`requirements/`、`reviews/`、`trace/`、`工程经验/`）是同一套约定。
2. **`工程经验/` 保持原样不动**：导入脚本对它是独立的 `条目` 组（`flatten: true` → 笔记名 `工程经验/条目/<文件名>`），且被显式排除出 `原文/本仓库` 组。任何增删改文件名都会直接改变知识库的条目清单。
3. **`过程档案/` 按文档生命周期分子目录**：`工作日志/`（持续追加）、`方案与路线/`（决策性）、`审计/`+`测试报告/`（一次性产出）、`归档/`（已证伪/已被取代）。这让"当前有效"与"历史留痕"在目录层面就分开。
4. **`def011-app-window.png` → `qa/evidence/`**：`evidence` 在导入脚本 `SKIP_PATH` 内 —— 截图本来就不是"经验"，放这里既符合脚本口径又符合同类证据的既有归置。
5. **`tools/installer/` → `products/bosom-friend/installer/`**：`Installer.cs` 是安装器的**唯一源码副本**，必须入库；把它放到产品层而不是仓库根 `tools/`，是因为 `tools/` 不属基座也不属产品的任何约定分区，且当前完全未跟踪。
6. **`analysis/` 保留为分析工作区**：本方案自身就写在 `analysis/plan/`，所以 `analysis/` 的新语义定义为"临时分析工作区"——`plan/` 纳入跟踪，大体积素材（46 MB mp4）移出或忽略。与 `docs/参考资料/` 的分工：跨领域/未定论的调研留在 `analysis/`，已定论并入产品知识体系的放 `docs/参考资料/`。
7. **新增目录命名避开 `SKIP_PATH` 关键字**：新目录名**不得**含 `vendor`、`dist`、`lib`、`release`、`legacy-archive`、`evidence`、`acceptance`、`website`、`node_modules`、`config-catalog`、`module-graph`、`tool-catalog` —— 否则会被导入脚本静默丢弃。本次目标结构中的所有新目录名均已核对通过。

## 6. 知识库同步

### 6.1 导入脚本的收集规则（实测确认，非推测）

```
HERE    = <repo>/products/bosom-friend/qa/probes
PRODUCT = resolve(HERE, '..', '..')    = <repo>/products/bosom-friend
REPO    = resolve(PRODUCT, '..', '..') = <repo>
KB_FILE = %USERPROFILE%\.bosom-friend\bosom-friend\knowledge.json
```

| 组 | 根 | 规则 | 笔记路径 |
| --- | --- | --- | --- |
| `条目` | `products/bosom-friend/docs/工程经验/` | 全部 `.md`，`flatten: true` | `工程经验/条目/<文件名>` |
| `原文/本仓库` | 仓库根 | `.md` 且不在 `SKIP_PATH` 且不在 `docs/工程经验/`，然后：`products/bosom-friend/qa/**` √ / `products/bosom-friend/**` √ / `工作日志-*`（任意深度）√ / **其余含斜杠的一律 ×** / 根级文件排除 `SKIP_ROOT` | `工程经验/原文/本仓库/<相对路径>` |
| `原文/另一份副本` | `~/Desktop/bosom-friend-app` | `.md` 且不在 `SKIP_PATH` | `工程经验/原文/另一份副本/<相对路径>` |
| `原文/历史备份` | `~/Documents/项目历史备份` | 同上 | `工程经验/原文/历史备份/<相对路径>` |
| `原文/DSH内核` | 仓库根 | 仅 `--include-dsh`：`.agents/notes/**` + `docs/**` | 同左 |

- `SKIP_PATH` = 路径段 `node_modules|.git|vendor|dist|lib|legacy-archive|evidence|acceptance|website|release`，或子串 `config-catalog|module-graph|tool-catalog`，或后缀 `.i18n.yaml`
- `SKIP_ROOT` = 文件名以 `README|CONTRIBUTING|BRAND_GUIDELINES|LICENSE|THIRD_PARTY_NOTICES|CLAUDE` 开头
- 单篇 200 B ~ 80 KB；超 80 KB 切片为 `…-part1.md`；跨组按 SHA256 去重；**只增不改，从不删除笔记**

### 6.2 外部来源核实结论：**两处都存在**

> **替代方案（若日后失效）**：这两个目录是**仓库外**的路径，换机器/重装系统/改用户名即消失，且脚本对"目录不存在"只打一行 `skipped` 日志、**不报错**（`existsSync` 判断后 `continue`）。建议：① 把这两个来源纳入常规备份；② 或在 `groups()` 增加"缺失即失败"的开关；③ 最稳妥是把两处打包成 git 之外的归档介质保存。
