## 1 背景与目标

### 1.1 背景

能力层与组装机制已经完成：内核注册 **36 个** `bosom_*` 工具（`products/bosom-friend/kernel/src/index.ts`，注册点行号见附录 A），**工具面即权限边界**已由 `config.tools` + `BF_AGENT_ROLE` + `products/bosom-friend/presets/roles.json:2-26` 落地，服务端已把对话入口固定归总管（`products/bosom-friend/server/src/api.ts:2766-2768` 的 `role: 'steward'`）。

**缺的是呈现层**。今天的界面仍然是「一个侧边导航 7 项 + 右侧一个 AI 助手小面板」：

| 事实 | 证据 |
| --- | --- |
| 左侧导航只有 7 项（内容创作 / 任务记录 / 发布日历 / 数据中心 / 全局监控 / AI 互动 / 知识库） | `products/bosom-friend/project/bosom-friend-web/src/app/layout/routerData.tsx:29-77` |
| 首页是官网式介绍页（含产品生态图、提示词画廊、首页聊天框），不是对话主入口 | `products/bosom-friend/project/bosom-friend-web/src/desktop-pages/SystemIntroPage.tsx:8-10` |
| 对话是「右侧附加面板」，与板块并排，不是主入口 | `products/bosom-friend/project/bosom-friend-web/src/desktop-pages/WebAppLayout.tsx:141` |
| 全仓前端源码里没有任何一处出现「管家」二字（`bosom-friend-web/src` 下检索命中 0 条） | 2026-10-11 实测：在 `products/bosom-friend/project/bosom-friend-web/src` 检索「管家」→ 0 条 |
| 「花了多少」是死数字：`currentCost` 在 web 全前端只有 3 处（类型声明、初始值、重置为 0），没有任何赋值点 | `.../src/store/agent/agent.types.ts:293`、`.../src/store/agent/agent.state.ts:34`、`.../src/store/agent/agent.methods.ts:372` |

### 1.2 目标（编号化）

| 编号 | 目标 | 判据（怎么算做到） | 依据 |
| --- | --- | --- | --- |
| **U1** | 对话成为唯一第一入口 | 打开 APP 首屏即可说一句话；不说「点哪个板块」也能办成一件事 | ADR-005 第二节第 4 条；BFS-103.1 |
| **U2** | 过程看得见 | 任一时刻界面能回答：谁在干、干到哪、卡在哪 | BFS-205.1；总纲 v2.0 目标 G4 |
| **U3** | 结果看得见 | 每件办成的事在界面上有落点（草稿 / 素材 / 发布记录 / 数据），能一键跳过去 | BFS-103.2；BFS-101.1 三要素 |
| **U4** | 拍板点集中且只有四类 | 全应用只有一个「待拍板」清单，只收发布 / 删除 / 花钱 / 对外沟通 | BFS-105.1、105.5 |
| **U5** | 板块降级不删功能 | 旧 19 个板块的每一项仍可达，但不再占据第一入口 | 总纲 v2.0 第 6.1 节、第 10.1 节第 3 条；开发报告 v2.0 第 3.6 节 |
| **U6** | 花费看得见 | 单次任务与今日累计的模型调用成本在界面上有数，且口径可查 | BFS-202.1、202.4 |

## 2 术语

| 术语 | 定义 | 出处 |
| --- | --- | --- |
| **呈现层** | 六层架构第 ⑤ 层：对话主入口 + 管家团队 + 看板 | 总纲 v2.0 第 4.2 节 |

### 3.8 现状结论（五条）

1. **界面代码在 `bosom-friend-web`，路由与打包在 `bosom-friend-electron`**，两者靠 `@web` 别名合成一个编译单元（`vite.config.mts:65`）——改造必须同时动这两棵树，只改一边不生效。
2. **主入口错位**：`/` 是官网式介绍页（`SystemIntroPage.tsx:8`），而对话被降级为右侧面板（`WebAppLayout.tsx:141`）——与 ADR-005 第 2 节第 4 条相反。
3. **过程数据已经够用**：服务端已推工具事件（`api.ts:2673-2736`），前端已有 `IWorkflowStep` 与中文标签——「谁在干什么、干到哪」**不需要新后端接口**就能做出来。
4. **「谁在干」缺一个字段**：任务对象 `ZyAgentTask`（`server/src/types.ts:368-399`）没有「归属管家」字段；`presets/roles.json` 的五角色只用于注入工具面，不进任务数据。
5. **「花了多少」是空的**：`currentCost` 全前端无赋值点（3.1 节表），且服务端没有面向界面的用量 / 成本接口——BFS-202.1 的记账在呈现层尚无落点。
