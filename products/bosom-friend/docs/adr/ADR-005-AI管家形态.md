# ADR-005：产品形态改为「AI 管家」（替代 ADR-004）

> 状态：已接受
> 日期：2026-10-11
> 关联：ADR-004（被本文替代）、ADR-002 / ADR-003（部分条款重审）
> 评审：产品负责人 2026-10-11 决策 ——「我要的是贾维斯」「整个项目像 Marvis 看齐」「彻彻底底的改」
> 读者：产品负责人 + 实现者
> **统一口径（2026-10-13 产品负责人拍板，最高优先级）**：
> 「我要的是一个**全面对标腾讯 Marvis Agent 功能**的一站式工具！用户说一句话，管家自己拆解、自己调工具、自己操作电脑与平台把事办完；页面只是过程与结果的可视化。」
> 本件、BFS-901 章程、2026-09-09 定位拍板（AI Agent 全自动一站式）三处表述以此为准；原二·2「不抄它的通用设备层」的排除**由本次取代**（不再作为形态边界；落地先后由 BFS-901 章程排期）。

## 一、背景（现场事实，2026-10-11）

| 事实 | 数据 | 出处 |
| --- | --- | --- |
| 产品负责人当场判定「整个系统看起来就是一个大号的脚本仓库」 | qa 脚本 716 个、probes 520 个 | 本会话 |
| AI 的手太少 | AI 工具 18 个（其中能写的 9 个），而服务端写操作 54 条 | kernel/src/index.ts、server/src/api.ts |
| **贾维斯化率 ≈ 17%** | 9 / 54 —— 系统 83% 的能力长在页面按钮与脚本上，不长在 AI 身上 | 本会话盘点 |
| 要求早已存在，却从未被当成验收门禁 | 铁律 #3.5（2026-09-01）：「任何功能若只能手动操作、AI 无法代劳，都视为未完成」 | docs/规范/项目铁律.md |
| 前端写死执行器已被判定「不是 AI 动手」 | kernel/cordis.patch.yml 的 bosom-computer-use 注释 | kernel/cordis.patch.yml |

## 二、决策

1. **形态**：从「19 个板块的功能软件」改为「**AI 管家**」——用户说一句话，管家自己拆解、自己调工具、自己操作电脑与平台把事办完；页面只是过程与结果的可视化。
2. **对标（2026-10-13 修订）**：**全面对标腾讯 Marvis Agent 功能**——一句话入口、多 Agent 分工、Skill、权限闸门、端云协同、记忆、过程可视化、操作电脑与平台；详见本件顶部「统一口径」。产品业务重心保持垂直：内容创作与自媒体运营——**10 家平台的真实自动化是护城河**。
3. **ADR-004 废止**：飞书 × 豆包（工作现场 + 执行者）不再作为方向事实源；对标基线及其 F/D 判据随之失效，改为《管家形态基线》。
4. **第一入口变更**：「一句话」是唯一第一入口；页面按钮不再是第一入口。铁律 #1 / #2（S 级前端监考、前端动手）不再适用于业务动作验收，改为《一句话端到端》验收。
5. **组织方式**：一个管家 = DSH agent-presets 的一个 preset 目录（agent.cordis.yml + skills + 人设）；总管负责理解与分派。
6. **会话模型**：管家会话长期存活（推翻 ADR-003 的「任务级会话用完即回收」），记忆按管家分层。
7. **彻底性**：一切「为了现在能跑」的临时物（写死执行器、动作卡、过渡例外、绕过脚本）在本次重构中清零，不留「只减不增」的欠债清单。

## 三、后果

**变好的**
- 用户路径：从「点 5 个页面」变成「说 1 句话」；
- 能力长在 AI 身上，页面只做可视化；
- 加能力 = 加工具 + 加 skill，不再堆脚本。

**要付代价的**
- 54 条写操作逐条工具化；
- 716 个脚本、104 篇文档逐条裁决（留 / 删 / 废）；
- 旧验收体系（S 级监考）作废，需按「一句话端到端」重建。

**不能动的（手术台与器官，不是妥协）**
- DSH 内核底座（造管家的机器）、平台引擎（10 家平台自动化）、媒体能力缝、账号与数据、打包与装机链路。
