# 架构决策记录（ADR）索引

本目录存放 Bosom Friend 的重大技术决策，编号唯一、终身不变。目的：把“为什么这么设计”写下来，防止反复争论、反复返工。

## 规则（来自《工程化流程与可追溯体系规范》）

1. 编号从 ADR-000 起，文件名 `ADR-NNN-主题.md`，没有编号就没有立项。
2. 状态只有四种：提议 / 已接受 / 已废弃 / 被替代。
3. 必填字段：日期、背景、决策、后果、参与评审、关联需求或缺陷、链接。
4. 任何影响 DSH 边界、进程结构、数据格式、对外接口的改动，必须先写 ADR 并评审通过，再动代码。
5. 被替代的 ADR 不删除，只在状态栏注明“被 ADR-NNN 替代”。

## 当前有效决策（一句话版）

按影响面从大到小，今天的实现必须服从这五条：

1. **单运行时**：产品只有 DSH 一个内核，不再有第二套模型调用路径（ADR-002）。
2. **会话是上下文的家**：一个任务 = 一个 DSH 会话，历史不再每轮重发（ADR-003 口径一）。
3. **稳定语境走官方通道**：领域/约束/历史三类语境写在 `$DSH_HOME/AGENTS.md`，由 `dsh-agent-instructions` 注入；每轮变的东西（焦点对象、本轮知识）才走每轮请求（ADR-003 口径二）。
4. **对象自带 AI 入口**：草稿/账号/发布记录/知识笔记上的 AI 动作，结果**写回那条对象**，不是弹一段文本（ADR-004 §2.2 ②）。
5. **经验要复利**：成功且被认可的样例既进"质量语境"，也能被升格成技能文件（ADR-003 口径四）。
