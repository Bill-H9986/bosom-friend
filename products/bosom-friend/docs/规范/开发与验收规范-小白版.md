# 开发与验收规范（小白版）

> 给谁看：**不懂编程、只关心"APP 能不能用"的项目主人**。
> 怎么用：每条功能做完，拿这份文档逐项打勾；**打不勾就不算做完**。
> 依据（专业资料）：验收准则写法 [Acceptance Criteria](https://docsio.co/blog/acceptance-criteria)、
> AI 编码代理审计清单 [audit-skills](https://github.com/danygiguere/audit-skills)、
> 生产级 vibe coding 规则 [vibe-coding-rules](https://github.com/yerdaulet-damir/vibe-coding-rules)、
> 上线前产品评估 [Founder-Grade AI Product Evals](https://www.ybuild.ai/en/blog/founder-grade-ai-product-evals-before-launch)。

## 一、什么叫"功能做完了"（Definition of Done）

任何一条功能，必须同时满足下面 6 条，缺一条就是**没做完**：

| # | 标准 | 你要看到的东西 |
| --- | --- | --- |
| 1 | **页面上能用** | 你在界面上点得出来，不是只有接口能跑 |
| 2 | **增删改查四步全通** | 新增→列表出现；编辑→立刻变；删除→列表消失且打不开 |
| 3 | **数据对得上** | 页面显示 = 数据文件 = 平台真实值，三处一致 |
| 4 | **没有假数据** | 没数据就显示"空"，不拿示例/模板冒充 |
| 5 | **失败看得见** | 出错有中文原因，不静默失败、不假成功 |
| 6 | **有证据** | 截图或可复现步骤，能当场重演一遍 |

## 二、每条需求怎么提（你只需要说清 4 件事）

1. **谁用**：普通用户 / 运营 / 客服
2. **从哪进**：页面名 + 按钮名
3. **做什么**：一句话动作（例：在素材库新建一个素材）
4. **怎么算成功**：你希望看到的结果（例：列表里立刻出现，刷新还在）

> AI 不要自己去猜优先级和取舍——**你说要什么，它做什么**；它擅自"优化"（改名、删数据、换数据源）都属于越权。

## 三、每个模块的验收清单（照抄用）

对**每个**模块（账号、创作、草稿箱、素材、发布、数据中心、知识库、客服、任务、设置）逐项打勾：

- [ ] **新增**：点新建 → 填必填 → 保存 → 列表出现
- [ ] **查看**：列表/详情能看到，刷新后还在
- [ ] **编辑**：改一个字段 → 保存 → 列表和详情都变了
- [ ] **删除**：删除 → 列表消失 → 再点详情打不开
- [ ] **空态**：没有任何数据时显示空态，不是假数据
- [ ] **异常**：断网/没登录/额度用完 → 显示中文原因
- [ ] **一致性**：页面数字 == 数据文件 == 平台真实值
- [ ] **刷新**：在平台上删掉的东西，同步后 APP 里也消失

## 四、AI 助手必须遵守的红线（对应项目铁律 #9）

1. 禁用假数据（无数据就空态）
2. 完整增删改查（四步都要在页面上走通）
3. 所有交互有效（点了必须有结果）
4. 明确数据存储（每个域写哪个文件、谁读）
5. 编码一律 UTF-8 无 BOM，发现 `?` 就是数据损坏，必须定位写入方
6. **不可逆操作必须先问**：删数据、改名字、真实发布、真实同步——先说明"题目/账号/影响范围"，等你同意

## 五、真实平台操作（最容易出事）

- **真实发布**（发到抖音/小红书）＝ 不可撤回的对外动作，必须先获批，并保存发布前/后截图
- **真实同步**（只读拉数据）＝ 相对安全，但也要注意频率，别把账号搞成风控
- 出现"登录已失效"时，先看平台是否真的拒绝（用接口验证），**不要反复重试**

## 六、每次交付必须附的"交付单"

```
【改了什么】文件 + 一句话
【怎么验证】可复现步骤（点哪、看什么）
【证据】截图/接口返回
【没做的】如实列出，不许写"已完成"
【影响面】会不会动用户数据、会不会发到平台
```

## 七、问题台账（问题只会越修越多的解法）

每次发现的问题登记到 `qa/defects/`，字段固定：

```
编号 | 模块 | 现象 | 复现步骤 | 等级(红/黄/绿) | 状态(待修/已修/不修) | 证据
```

**规矩**：新问题先登记再修；修完附证据改状态。**台账上的"待修"数量必须逐轮下降**，
否则就是"越修越多"——这正是之前发生的事。
