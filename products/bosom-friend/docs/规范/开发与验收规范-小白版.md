## 1 这份文件解决什么

**一句话**：让你不用懂技术，也能判断「这件事到底做完了没有」，以及「出问题时该问什么」。

**判定线**：读完这份文件，你能对任何一次汇报直接问出「证据呢」，并且知道该要哪种证据。

---

## 2 什么叫「做完了」（四条，缺一不算）

| # | 条件 | 反面（不算完成） |
| --- | --- | --- |
| 1 | **你说了那句话，它真的做了** | 它说「我做了」、或给你一张卡让你自己去点 |
| 2 | **结果在页面上看得见** | 接口返回成功、日志里有记录，但页面上什么都没有 |
| 3 | **失败时给了人话原因 + 三个选择**（断点继续 / 重新生成 / 放弃） | 只报错不说怎么办，或假装成功 |
| 4 | **上面三条都有证据** | 只有一句「已完成」 |

**一句话版本**：**没有页面看得见的结果，就不叫完成。**

---

## 3 你只需要说清四件事

1. **你想让它做什么** —— 用你平时说话的方式说一句就行（例如「帮我写一条关于 XX 的图文，存进草稿箱」）；
2. **这件事归谁管** —— 创作 / 发布 / 运营 / 设备（说不清也没关系，它会自己判断）；
3. **你想看到什么结果** —— 例如「草稿箱里多一条」「抖音上真的发出去了」；
4. **如果不成功你希望怎么办** —— 断点继续 / 重新生成 / 放弃。

**你不需要**：说出文件在哪、按钮叫什么、接口怎么调。

---

## 4 每次交付必须附的「交付单」

| 项 | 内容 |
| --- | --- |
| 这次做了什么 | 一句话说清 |
| 你怎么验 | 说哪句话、看哪个页面、看什么变化 |
| 证据 | 工具调用记录 + 页面结果 + 落库数据（三者一致） |
| 没做的 | 明确列出（不许含糊） |
| 风险与边界 | 例如「免费档限流，长片会很慢」 |
| 怎么退 | 出问题怎么回到上一版 |

**没有交付单的交付，视为没交付。**

---

## 5 AI 必须遵守的红线（违反即返工）

| # | 红线 |
| --- | --- |
| 1 | 不许说「已完成」而没有证据 |
| 2 | 不许让你去试它自己没验过的东西（**验证是它的活，不是你的**） |
| 3 | 没有你的明确指令，不许发布、删除、花钱、对外沟通 |
| 4 | 不许用脚本绕过做不到的事（脚本只能是门禁或一次性诊断） |
| 5 | 不许把内部报错、堆栈、接口名原样丢给你 |
| 6 | 不许假装成功、不许编造数据、不许用模板冒充结果 |
| 7 | 不许只跑「能成功的那条路」，失败路径必须也走过 |

---

## 6 真实平台操作（最容易出事）

| 事项 | 规矩 |
| --- | --- |
| 扫码登录 | **必须你本人做**（平台要求真人授权） |
| 发布 | **必须你明确说**才发；「写一条」不等于「发出去」 |
| 频率限制 | 由平台决定，可能失败；失败会如实告诉你原因和怎么救 |
| 账号安全 | 账号密码、Cookie、密钥不出本机；不展示、不上传 |
| 风控 | 会限频、拟人化操作，但**不能保证不被平台限制** |

---

## 7 出问题怎么查（三问）

1. **是在哪一步断的？**（要具体到文件、行号、接口或页面）
2. **为什么之前没发现？**（是不是验证方式本身有盲区）
3. **怎么保证不再犯？**（要落到一条门禁或一条流程）

**如果三个问题答不上来，就是没查清。**

---

## 8 你每周 / 每发布要看什么

| 看什么 | 在哪看 | 看什么 |
| --- | --- | --- |
| **AI 能办几件事了** | 能力台账 | 管家化率（有工具的能力 ÷ 总能力） |
| **有没有没闭环的大问题** | 缺陷台账 | P0 / P1 的 Open 条数（打包前必须为 0） |
| **现在在做什么、卡在哪** | 活记忆 | 「正在做」「卡在哪」两行 |
| **这次交付能不能装** | 发布就绪清单 | 逐项勾选状态 |

## 9 术语大白话表

| 术语 | 大白话 |
| --- | --- |
| 管家 | 一个专职的 AI（创作管家、发布管家…） |
| 能力 | 一句你会说的话 + 它能调的工具 + 页面上看得见的结果 |
| 工具 | 它的一只手（能做一件具体的事） |
| 一句话端到端 | 你说一句话 → 它自己干完 → 页面上看得到 |
| 内核握手 | 确认 AI 的「大脑」真的启动了（不是只看服务开着） |
| 管家化率 | 有工具的能力占全部能力的比例 —— 越高越像管家，越低越像按钮软件 |
| 发卡 | 它只给你一张卡、让你自己去点（已废止的做法） |
| 自证 | 它自己跑一遍并留下证据，而不是让你去试 |
| 假成功 | 它说做完了，其实没做完 |

---

## 9.5 关键词约定（必须 / 应当 / 可以）

| 关键词 | 含义 |
| --- | --- |
| **必须** | 强制；违反即返工 |
| **应当** | 强烈建议；不做要写明理由 |
| **可以** | 可选 |

> 三级语义的完整定义见《管家化标准体系（BFS-100）》第 0.5 节。

## 10 反例与违规处置

| 情形 | 处置 |
| --- | --- |
| 汇报说「已完成」但给不出证据 | 直接判未完成，返工 |
| 让你自己去试 | 返工（违反红线 2） |
| 没经你同意就发布 | 按 P0 事故处理（DEF-240 教训） |
| 报错只说「失败了」 | 返工补原因与三个选择 |

## 附录 A · 你可以直接抄的验收话术

- 「做完了？给我看：我说哪句话、页面上出现什么、证据在哪。」
- 「你说已经写进草稿箱了，那草稿箱里现在有几条？」
- 「失败的时候我会看到什么？三个选择在哪？」
- 「这条能力对应的工具叫什么？关掉页面它还办得成吗？」
- 「AI 的大脑（内核）你验了吗？别只告诉我服务开着。」
- 「这次没做的是什么？风险是什么？出问题怎么退回去？」
