## 1 目的

**901** 本规范规定 Bosom Friend 界面在**间距、圆角、阴影、层级、留白、颜色、动效**七方面的统一口径。

**901.1** 为什么需要它：产品负责人 2026-10-11 指出「**布局乱了**」。排查结论是——**配色没有问题**（白底 `#fff` + 近黑 `#0a0a0a` + 浅灰边 `#e5e5e5`，甚至已有 `--ease-apple` 缓动曲线），**乱在布局**：同一屏混用两套外边距、信息密度过高、层级不清、卡片圆角与阴影各一。

**901.2** 本规范只解决布局一致性，**不改配色体系**。

## 4 术语与定义

| 术语 | 定义 |
| --- | --- |
| **间距刻度** | 8 的倍数序列，界面所有外边距/内边距只允许取自该序列 |
| **层级** | 视觉重要性顺序，本规范要求靠**字号与字重**表达，不靠颜色 |
| **极柔阴影** | `0 1px 3px rgba(0,0,0,0.04)`，只用于分层，不用于装饰 |
| **视觉中心** | 一屏之内用户第一眼应落在的元素（首屏为对话输入框） |
| **收起态** | 高级选项默认不展开，用户主动点击才显示 |

## 6 编号化条款

### 6.1 间距（BFS-901）

**906.1** 间距**必须**取 8 的倍数，且只允许下列档位：

| 用途 | 值 | Tailwind |
| --- | --- | --- |
| 页面外边距 | 32px | `p-8` |
| 区块之间 | 32px | `space-y-8` / `gap-8` |
| 卡片之间 | 24px | `gap-6` |
| 卡片内边距 | 24px | `p-6` |
| 元素之间（同组） | 12px | `gap-3` |
| 图标与文字 | 8px | `gap-2` |

**906.2** **禁止** `py-4.5`、`gap-[13px]` 这类随手值。

**906.3** 同一个页面**必须**只出现一套外边距。

### 6.2 圆角与阴影（BFS-902）

**906.4** 圆角与阴影**必须**按下列口径：

| 元素 | 圆角 | 阴影 |
| --- | --- | --- |
| 卡片 / 面板 | 16px（`rounded-2xl`） | 极柔 `0 1px 3px rgba(0,0,0,0.04)` |
| 输入框 | 12px（`rounded-xl`） | 无；聚焦时 2px 品牌色环 |
| 按钮（主） | 胶囊（`rounded-full`） | 无；悬浮轻微抬升 |
| 标签 / 徽标 | 胶囊（`rounded-full`） | 无 |
| 弹窗 | 20px | `0 24px 60px rgba(0,0,0,0.12)` |

**906.5** 阴影**必须**只用于分层。大多数卡片**应当**只有 1px 边框、无阴影。

### 6.3 层级（BFS-903）

**906.6** 视觉层级**必须**靠字号与字重表达，**禁止**用颜色区分层级：

| 层级 | 字号 / 字重 |
| --- | --- |
| 页面标题 | 28px / 600 |
| 区块标题 | 20px / 600 |
| 卡片标题 | 17px / 500 |
| 正文 | 15px / 400 |
| 次要说明 | 13px / 400（`--muted-foreground`） |

### 6.4 留白与聚焦（BFS-904）

**906.7** 一屏**必须**只讲一件事；首屏的视觉中心**必须**是对话输入框。

**906.8** 高级选项（如生成参数）**必须**默认收起，用户主动点击才展开。

**906.9** 同一屏卡片**不得**超过 6 张，超出**必须**分页或折叠。

### 6.5 颜色（BFS-905）

**906.10** 中性色**必须**占界面的 90% 以上。

**906.11** 品牌紫 `#8b7cf6` **只允许**用于主 CTA、选中态、进度；**禁止**写正文、**禁止**大面积铺色。

**906.12** 成功/警告/失败色**只允许**用于状态，**禁止**做装饰。

### 6.6 动效（BFS-906）

**906.13** 动效时长**必须**为 200ms、曲线**必须**为 `--ease-apple`。

**906.14** **只允许**淡入 + 轻微位移（`opacity` + `translateY(4px)`）；**禁止**弹跳、旋转、超过 300ms 的动画。

### 6.7 深色模式（BFS-907）

**906.15** 改样式**必须**两套（浅色 / 深色）都验证；颜色**必须**走语义 token（`text-foreground` / `border-border`），**禁止**硬编码色值。

## 8 证据要求

**908** 界面改动**必须**提交下列证据，缺一不得声称完成：

**908.1** **改前 / 改后截图对比**（同一页面、同一视口）。

**908.2** 构建退出码：`cd project/bosom-friend-electron && npx vite build --mode=test` → **0**。

**908.3** S 级监考门禁输出原文：`FRONTEND_SUPREME_GATE PASS`。

**908.4** 深色模式截图（改了 token 时**必须**）。

**908.5** 改设计 token（CSS 变量）时**必须**单独列出改了什么、影响面，**禁止**夹带。

## 9 反例与违规处置

**909** 下列写法**不得**进入代码：

| 反例 | 为什么错 |
| --- | --- |
| `className="px-4 md:px-6 py-4 md:py-5"` 与 `p-6` 混用 | 同一屏两套外边距（V1 违反） |
| `shadow-xl shadow-primary/10` | 用重阴影 + 品牌色做装饰，不是分层（906.5 违反） |
| 正文用品牌紫 | 违反 906.11 |
| 卡片一次渲染 8 张 | 违反 906.9 |
| 硬编码 `#8b7cf6` 而不走 token | 深色模式会破（906.15 违反） |

**909.1** 违规处置：门禁未覆盖的违规由**代码评审**拦截；同一违规**第二次**出现时**必须**升级为门禁断言（BFS-600 精神）。
