## 1 目的与适用范围

### 1.1 目的

规定本产品从需求到发布再到复盘的全流程：**六个阶段各自干什么、进出的门是什么、留什么痕迹、谁来判。**

**判定线**：任何一次改动都能被追溯成「哪条能力 → 哪个工具 → 哪次证据 → 哪份记录」。

### 1.2 适用范围

适用于 products/bosom-friend 下全部开发活动：代码、文档、脚本、门禁、出包与装机。

**不适用**：DSH 官方源码的开发（遵循仓库根 AGENTS.md）。

## 2 术语与关键词

| 术语 | 定义 |
| --- | --- |
| **阶段门** | 进入/离开某阶段必须满足的条件集合（准入 / 准出） |
| **能力** | 一句话 + 工具 + 页面可见结果（BFS-101） |
| **痕迹** | 可事后回放的记录：提交、ADR、变更日志、缺陷、发布清单、复盘 |
| **两级闭环** | 能力级闭环（一句话走通）+ 交付级闭环（装机验收） |
| **在制品** | 同一时刻正在推进的工作条目 |

| 关键词 | 含义 |
| --- | --- |
| **必须** | 强制；违反即返工 |
| **应当** | 强烈建议；不遵从须写明理由 |
| **可以** | 可选 |

## 3 六条总原则

| 编号 | 原则 | 含义 |
| --- | --- | --- |
| 500.1 | **小批量** | 一次只改一点，改完立刻验；在制品不超过 2 条（BFS-302） |
| 500.2 | **快速反馈** | 改完几分钟内知道坏没坏（类型检查 + 定向门禁） |
| 500.3 | **可回退** | 任何改动都有回退路径；安装包与数据都要有基线 |
| 500.4 | **证据优先** | 只认 C 档证据（BFS-104）；接口返回、日志、构建成功都不算 |
| 500.5 | **一个事实一个家** | 功能状态在能力台账、决策在 ADR、缺陷在缺陷台账、坑在知识库 |
| 500.6 | **不留暗债** | 过渡例外、临时脚本、绕过路径必须登记且只减不增；本次重构要求清零 |

**判据**：六条中任一条被违反时，能指出违反了哪一条以及当时的记录。

| 角色 | 职责 | 不得 |
| --- | --- | --- |
| **产品负责人** | 定优先级、拍板四类动作（发布/删除/花钱/对外沟通）、最终验收 | —— |
| **AI 实现者** | 定义能力、实现工具、自证与举证、记录、立缺陷 | 让用户代劳验证；无证据宣称完成 |
| **管家**（被构建对象） | 自己拆解、自己调工具、自己完成 | 把执行推给前端页面 |

## 5 六个阶段与阶段门

### 5.1 需求阶段

**准入**：产品负责人提出一个想法或问题。

**准出（必须全部满足）**：

| 编号 | 条件 |
| --- | --- |
| 501.1 | 写成**那句话**（用户会说的原话），不是功能名 |
| 501.2 | 指明归属管家与主链路环节 |
| 501.3 | 写出预期可见结果（对象、字段、变化） |
| 501.4 | 写出失败预期（人话原因 + 三个选择） |
| 501.5 | 登记进《能力台账》（新增或更新现有条目） |

**证据**：能力台账条目。

**反例（判红）**：只写「支持草稿管理」这类功能名；没有那句话。

### 5.2 架构与设计阶段

**准入**：能力台账里已有该条目的准出五条件。

**准出**：

| 编号 | 条件 |
| --- | --- |
| 502.1 | 明确这是**哪条能力、复用什么既有实现**（禁止两套实现，BFS-102.2） |
| 502.2 | 明确工具的参数表与返回（模型视角写清楚） |
| 502.3 | 工具描述含「必须调用本工具完成」强制语（BFS-102.4） |
| 502.4 | 影响面三行写清：改哪个文件 / 为什么 / 会影响谁（BFS-306） |
| 502.5 | 涉及架构、进程、数据格式、对外接口的，**必须**先写 ADR 并评审通过 |

**证据**：ADR（如涉及）、代码位置、工具 schema。

### 5.3 开发阶段

**准出**：

| 编号 | 条件 |
| --- | --- |
| 503.1 | 同一份业务实现被页面与工具共用（BFS-102.2） |
| 503.2 | 工具 execute 真正执行并返回真实产物 id（禁止发卡，BFS-102.5） |
| 503.3 | 类型检查通过（exit 0） |
| 503.4 | 失败路径已实现：人话原因 + 三个选择（BFS-104.4） |
| 503.5 | 变更未破坏既有能力（回归：至少跑通受影响能力的用例） |

**证据**：类型检查输出、构建产物、代码 diff。

**硬约束**：开发期一律用 Web 端迭代，**禁止**为验证改动而打包（BFS-109.3）。

### 5.4 测试与验收阶段

**准出**：

| 编号 | 条件 |
| --- | --- |
| 504.1 | 一句话端到端走通（C 档证据） |
| 504.2 | 三方交叉一致（工具返回 / 助手回复 / 落库或页面） |
| 504.3 | 内核握手已验证（不得只看 HTTP 200） |
| 504.4 | 失败路径也走过 |
| 504.5 | 结果记入工作日志 / 能力台账 / 活记忆 |

**证据**：SSE 工具序列、落库数据、页面结果、记录链接。

**反例（判红）**：只跑类型检查或构建就宣布完成；未验内核握手；只走成功路径。

### 5.5 发布阶段

**准入**：本条能力在开发态验证通过（504 全部满足）。

**准出**：

| 编号 | 条件 |
| --- | --- |
| 505.1 | 全链路在开发态走通 |
| 505.2 | 发布就绪清单逐项勾选（含数据指纹、回退包） |
| 505.3 | 产物哈希留存 |
| 505.4 | 版本号单源一致（desktop/package.json 为唯一权威） |

**证据**：《发布就绪清单》、产物哈希、门禁报告。

### 5.6 运维与复盘阶段

**准出**：

| 编号 | 条件 |
| --- | --- |
| 506.1 | 装机验收走过：升级安装 → 真实业务 → 卸载 → 装回（数据指纹前后一致） |
| 506.2 | 同根因复发**必须**升级为门禁断言（BFS-304.1） |
| 506.3 | 事故**必须**出复盘报告并写入知识库 |
| 506.4 | 活记忆更新并同步 |

**证据**：装机验收报告、门禁断言、复盘报告。

## 6 追溯链：能力 → 工具 → 证据 → 记录

**两级闭环**：

| 级别 | 闭环 | 判据 |
| --- | --- | --- |
| **能力级** | 那句话 → 工具 → 页面可见结果 | 一句话端到端走通 |
| **交付级** | 打包 → 端到端 → 装机 | 陌生人在干净机器上走通主链路 |

**追溯链四环**（缺一环即断链）：

1. **能力**：《能力台账》条目（那句话 + 归属）；
2. **实现**：工具注册位置 + 服务端路由/函数；
3. **证据**：C 档验收记录（工具序列 + 三方交叉）；
4. **记录**：工作日志 + 缺陷台账（若有）+ 活记忆。

**判据**：随机挑一条能力，能在 5 分钟内找齐四环。

## 7 痕迹规范

### 7.1 代码提交

- 遵循 Conventional Commits：类型(范围): 说明；
- 提交信息用**简体中文**描述行为，不写「修复了一些问题」这类空话；
- **禁止**把用户数据、密钥、产物包提交进库。

### 7.2 架构决策（ADR）

- 影响 DSH 边界、进程结构、数据格式、对外接口的改动**必须**先写 ADR；
- 编号终身不变；被替代的 ADR 标注「被 ADR-NNN 替代」而不删除；
- ADR **必须**含：日期、背景、决策、后果、评审、关联。

### 7.3 变更日志（CHANGELOG）

- 每次出包**必须**有对应条目，写清用户能看到的变化。

### 7.4 缺陷记录（DEF）

- 字段齐全：编号、标题、严重度、状态、类型、根因归类、关联需求、回归用例、责任人、计划版本、重开次数；
- 无根因归类不得进入修复；
- 同根因复发不等第三次，直接升级门禁。

### 7.5 发布就绪清单

- 每次出包前逐项勾选：数据指纹、回退包、版本单源、门禁绿、验收记录。

### 7.6 复盘报告

- 事故与迭代收尾**必须**出复盘：现象、根因、处置、防复发（门禁或流程改动）。

## 8 自动化门禁

| 编号 | 要求 |
| --- | --- |
| 508.1 | 每条能力上线**必须**带一条可重复门禁（BFS-108.1） |
| 508.2 | 新增断言**必须**附负向对照（证明它会红） |
| 508.3 | 门禁判「办成了没」，不判「页面点得对不对」 |
| 508.4 | 门禁清单**必须**与能力台账对得上（每条能力都有对应门禁，或登记为待建） |
| 508.5 | 一次性诊断脚本查清即删，不得沉淀为常驻（BFS-305.2） |

**证据**：门禁运行输出（PASS/FAIL）、负向对照记录。

## 9 节奏

| 频率 | 动作 |
| --- | --- |
| 每次开工 | 三问（哪句话 / 哪一环 / 什么证据）+ 读活记忆 |

| 每次事故 | 复盘报告 + 门禁升级 + 知识库条目 |

## 10 反例与违规处置

| 反例 | 等级 | 处置 |
| --- | --- | --- |
| 无 C 档证据宣称完成 | L1 | 停止、回滚状态、重做 |
| 未写影响面三行就动手 | L1 | 停止，补写后再动 |
| 跳过 ADR 改架构 | L1 | 回退改动，补 ADR |
| 为验证改动去打包 | L2 | 当期整改 |
| 缺记录（日志/台账/活记忆） | L2 | 当期补齐 |
| 门禁缺失或不可重复 | L2 | 当期补齐或登记待建 |
