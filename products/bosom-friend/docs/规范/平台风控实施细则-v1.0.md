## 1 目的与适用范围

### 1.1 目的

把 BFS-203 的五条风控要求（限频拟人化、账号隔离、可回放、禁止绕过、如实告知）展开成**可执行、可判定、可追责**的实施口径，
回答三个问题：**怎么做**、**凭什么算做到了**、**没做到怎么办**。

**本细则的判定线**：任取一次对外平台动作，都能回答「它的触发概率凭什么被降低、被拦之后怎么止损、用户被怎么如实告知」；答不上即判红。

**本细则不回答**：平台风控的判定算法（平台单方掌握、随时变更），也不承诺任何风控结果。

### 1.2 适用范围

| 维度 | 管 | 不管 |
| --- | --- | --- |
| 动作 | 一切**对外平台动作**：发布、回复评论、回复私信、拉取互动、同步作品、登录与重登 | 纯本机动作（生成文案、改草稿、看数据看板） |
| 对象 | 全部平台（抖音 / 小红书 / 视频号 / 快手 / B 站及后续接入的平台） | 厂商模型调用（其边界见 BFS-202.3） |
| 角色 | AI 实现者、总管与四个管家、平台引擎（engine/）、门禁脚本 | 用户本人的手动操作（本细则只约束产品行为） |
| 阶段 | 开发、灰度、运营全阶段 | —— |

## 2 术语与定义

| 术语 | 定义 |
| --- | --- |
| **对外平台动作** | 会在平台上产生可见痕迹或影响他人可见状态的操作（发布、回复、拉取、同步、登录） |
| **风控** | 平台为识别自动化与异常行为所采取的检测与处置（验证码、限流、限制功能、封禁） |
| **熔断** | 检测到被拦信号后，产品主动冻结该账号全部自动动作并转人工的止损机制 |
| **节律** | 动作在时间轴上的分布（活跃时段、间隔分布、每日总量），是平台判定机器行为的主要特征 |
| **拟人化** | 让行为特征（轨迹、节奏、停留、会话时长）落在真人分布内的一系列做法 |
| **账号隔离** | 账号之间在登录态、浏览器 profile、出口网络、指纹四方面互不相通 |
| **留痕** | 每一次对外动作的五要素记录（谁、何时、对谁、做了什么、结果如何） |
| **灰度观察期** | 新账号首次启用自动化后的观察窗口，期间只用单个账号验证 |
| **如实告知边界** | 把「不可控结果不承诺」写进用户可见文案与助手回复的义务 |
| **四承诺** | 可降（降低概率）、可止损、可隔离、可定位；第五件「绝不封号」不承诺 |

## 4 条款正文

> 编号规则：`8xx.y`，前三位为本细则标准号，后一位为条款序号。每条标准末给出判据、证据要求与反例（判红情形）。

### 801 诚实边界（对应 BFS-203.5）

**目的**：先把「做不到的」说清楚，再谈做法。风控是攻防对抗，承诺绝对安全就是假话。

- 801.1 本细则任何条款**不得**被解读、转述或宣传为「保证不被封号」「保证不限流」；助手回复、前端文案、安装包说明中**禁止**出现此类承诺。
- 801.2 产品只承诺四件事：**可降**（把触发概率从必然降到低概率）、**可止损**（被拦后限时冻结、不扩大）、**可隔离**（一个账号出事不牵连其他账号）、**可定位**（每次被拦都能查到动作、时间与当时频率）。第五件「绝不封号」**不承诺**。
- 801.3 本细则**不得**用于绕过平台规则；它只约束「在规则内如何降低被误判的概率」。
- 801.4 本细则的全部数值（每日上限、冻结时长、观察期、目录规模阈值）**必须**可配置且改动留痕；数值调整**必须**同步修订本细则，**禁止**只改代码不改文档。
- 801.5 发布、删除、花钱、对外沟通四类动作**必须**有用户当次的明确指令（BFS-105.1、105.4；DEF-240 事故教训）。

**判据**：全文检索无「保证不封号 / 绝对安全 / 包不封号」类表述；四类动作的调用日志都能对上一条用户指令。

**证据要求**：文档与前端文案检索结果；工具调用日志与对应会话消息 id。

**反例（判红）**：任何面向用户的「不会被封」承诺；无用户指令的自动发布。

### 802 拟人化（对应 BFS-203.1）

**目的**：把机器特征从行为里去掉。技术指纹只决定「像不像浏览器」，行为与节律才决定「像不像人」。

- 802.1 平台操作**必须**在真实浏览器会话中执行（用户已登录的持久化 profile）；**禁止**接口直灌、**禁止**后台无痕批量提交。
- 802.2 鼠标交互**必须**带轨迹（曲线移动、轻微过冲、落点在目标区域内随机）；**禁止**以程序化合成点击作为唯一交互方式。
- 802.3 文本输入**必须**逐字进行且每字间隔随机（基准 60~200 毫秒）；**禁止**一次性赋值填表。
- 802.4 页面滚动**必须**带惯性与随机停顿；**禁止**瞬间跳转到目标位置。
- 802.5 相邻动作之间**必须**有随机停顿（基准 200~1500 毫秒）；**禁止**固定毫秒节奏。
- 802.6 单次会话时长**必须**落在 2~10 分钟区间内并随机取值；**禁止**「连续数百次操作后立即关闭」。
- 802.7 同一账号在同一时刻**至多**一个浏览器会话；**禁止**并发多开同一账号。

**判据**：任取 20 组相邻动作的间隔样本，不出现完全相同的间隔值；会话时长全部落在 2~10 分钟；同账号无并发会话记录。

**证据要求**：动作时间戳序列（留痕表）、浏览器会话开始/结束时间记录。

**反例（判红）**：固定 10 分钟一轮的等间隔轮询；秒级连发；同一账号两个会话同时开工。

### 803 限频与节律（对应 BFS-203.1）

**目的**：把「跑得越勤越自动」改成「在平台察觉不到的前提下把事办完」。

- 803.1 默认活跃时段为 09:00–12:00、14:00–18:00、20:00–23:00（用户本机时区）；时段外**不得**主动发起对外动作。
- 803.2 用户明确指令的即时动作（例如当次说「现在就发」）**可以**在活跃时段外执行，但**必须**计入当日上限。
- 803.3 轮询与检查间隔**不得**取固定值；**必须**用随机分布（基准：对数正态），且相邻两次间隔**不得**完全相同。
- 803.4 每日动作上限按账号执行，默认值如下（**只能收紧，不得放宽**；放宽必须走 801.4 的修订流程）：

| 动作 | 每日上限 |
| --- | --- |
| 读自己作品的公开数据 | 2 次 |
| 读评论 / 私信 | 6 次 |
| 回复评论 | 10 条 |
| 回复私信 | 20 条 |
| 发布内容 | 3 条 |
| 点赞 / 关注 / 评论他人 | **0 次（见 810 禁止）** |

- 803.5 超出上限的动作**必须**排队到下一个活跃时段；**禁止**补发、**禁止**追平。
- 803.6 扫到新消息后**必须**随机等待 30 秒~5 分钟再回复；**禁止**秒回。
- 803.7 同一动作的相邻两次之间**必须**有不小于 5 分钟的随机间隔（基准区间 5~25 分钟）。
- 803.8 单次会话内**至多**发布 1 条内容。
- 803.9 免费档模型的能力边界（如 `freeTierRpm=1`）**必须**在开跑前如实告知；因限流中断**必须**给三个选择（断点继续 / 重新生成 / 放弃）。

**判据**：任取一个自然日的动作留痕，逐项不超过 803.4 的表值；间隔样本非固定值；回复延迟全部大于 30 秒。

**证据要求**：每日动作计数表、间隔样本、开跑前的告知记录。

**反例（判红）**：一天 144 轮固定轮询；超限后「补发」把当日配额追平；秒回。

### 804 账号隔离（对应 BFS-203.2）

**目的**：一个账号出事，不牵连其他账号；账号之间不互相「串味」。

- 804.1 一个账号**必须**对应一个独立浏览器 profile 目录与一份独立登录态，三者**不得**交叉使用。
- 804.2 同一出口网络**不得**同时承载超过 1 个自动化账号。
- 804.3 时区、语言、分辨率、字体、Canvas / WebGL、硬件并发数**必须**与该账号出口网络归属地一致，并按账号固定；**禁止**随会话漂移。
- 804.4 账号之间的 cookie、会话目录、缓存**必须**物理分离；**禁止**共用同一 profile。
- 804.5 熔断**必须**是账号级：A 账号熔断期间，B 账号的动作不受影响、也不被连带冻结。
- 804.6 数据中心 IP（机房 / 云主机出口）**不得**用于平台操作；单账号场景以用户本机真实网络为准，多账号或跨地域场景**必须**用住宅网络出口。

**判据**：任取两个账号，其 profile 路径、指纹摘要、出口网络三者互不相同；A 账号熔断期间 B 账号动作记录正常。

**证据要求**：账号配置表（profile 路径 / 指纹摘要 / 出口）、熔断记录、隔离验证记录。

**反例（判红）**：两个账号共用一个 profile；指纹随会话变化；账号级熔断升级为全局冻结而拖垮正常账号。

### 805 登录态与凭据（对应 BFS-203.2）

**目的**：每一次重新登录都是一次高风险事件；凭据又是最不能外泄的资产。

- 805.1 平台登录**必须**由用户本人扫码完成（真人授权动作）；产品**不得**代持账号密码。
- 805.2 登录态**必须**持久化复用；**禁止**周期性自动重登；同一账号的登录次数**应当**保持「一次授权、长期复用」。
- 805.3 登录态失效时**必须**只提示用户手动重登并给出重登入口；**禁止**后台自动重试登录。
- 805.4 登录会话残骸**必须**定期清理（默认保留最近 7 天，可配置）；登录会话目录规模**应当**不超过 500 MB，超过即**必须**清理。
- 805.5 凭据（密码、cookie、token、API Key）**必须**只落在用户数据根；**禁止**进入模型上下文、日志、助手回复与诊断导出。

**判据**：连续 30 天的登录事件次数与用户实际扫码次数一致；登录会话目录规模低于阈值；日志与模型请求体中检索不到凭据原文。

**证据要求**：登录事件记录（时间 + 触发原因）、目录规模实测、凭据扫描结果。

**反例（判红）**：后台自动重登；登录会话堆到 GB 级；助手回复里出现 cookie 或密钥。

### 806 内容去重与合规（对应 BFS-203.4）

**目的**：平台判定「营销骚扰」看的是内容重复与引流痕迹，不是发送次数。

- 806.1 每条对外回复**必须**由模型按当次语境现场生成；同一账号的同一句话 7 天内**不得**重复出现。
- 806.2 固定短语（「好的」「收到」等）**必须**有 20 种以上变体；**禁止**两条回复只替换称呼。
- 806.3 回复内容**禁止**出现外链、微信号、手机号、二维码，以及「加我」「私聊」等引流词。
- 806.4 发送前**必须**过一遍敏感词与合规过滤；命中**必须**拦截并转人工确认。
- 806.5 价格、合同、法律、医疗等敏感话题**禁止**自动作答；**必须**给模板级回复并提示用户人工确认。
- 806.6 发布内容**必须**带平台要求的内容标注（AI 生成标注等，见知识库条目 20）。
- 806.7 重复、空话、敏感、夸大承诺的内容**不得**自动发布。

**判据**：7 天窗口内两两回复的相似度低于阈值（默认 0.9）；敏感词扫描 0 命中；发布记录的内容标注字段非空。

**证据要求**：回复正文库、过滤日志、发布记录中的标注字段。

**反例（判红）**：两条固定模板反复发送；回复里带微信号；未标注的 AI 生成内容被发布。

### 807 熔断与止损（对应 BFS-203.1、203.5）

**目的**：被拦之后最重要的事是**立刻停**。被拦后重试等于向平台举手说「我是机器人」。

- 807.1 触发任一条件**必须**立即冻结该账号全部自动对外动作并转人工：出现验证码 / 滑块 / 人脸核验；页面出现「账号异常」「操作频繁」「请稍后再试」；连续 2 次动作失败；登录态失效。
- 807.2 冻结时长**必须**阶梯递增：首次 6 小时 → 二次 24 小时 → 三次 7 天；冻结期内**禁止**任何自动重试。
- 807.3 熔断**必须**在触发后 1 分钟内生效并写入留痕。
- 807.4 熔断**必须**通知用户，内容含人话原因、冻结时长、恢复方式与三个选择（断点继续 / 重新生成 / 放弃）。
- 807.5 未挂载熔断守卫的账号**不得**开启任何自动对外动作；守卫缺一（熔断 / 节律 / 去重）时**必须**降级为「生成内容待人工确认」。
- 807.6 熔断阈值与冻结节梯的改动**必须**留痕并注明依据。

**判据**：人为制造一次失败（断网、错误选择器、登录态失效），熔断在 1 分钟内触发且冻结记录可查；冻结期内该账号动作日志为空。

**证据要求**：熔断记录（时间、触发条件、冻结时长）、冻结期内的动作日志（应为空）、通知文案。

**反例（判红）**：被拦后立即重试；熔断只写在文档里、代码里没有守卫；冻结期仍有动作。

### 808 留痕与可回放（对应 BFS-203.3）

**目的**：出了问题查不动，等于没有风控体系。

- 808.1 每一次对外动作**必须**留五要素：**谁**（账号）、**何时**（时间戳）、**对谁**（对象：作品 / 评论 / 私信 / 会话）、**做了什么**（动作与参数摘要）、**结果如何**（成功 / 失败 / 被拦）。
- 808.2 被拦事件**必须**额外留：当时频率（近 1 小时动作计数）、触发条件、平台原文提示。
- 808.3 留痕**必须**可回放：任一动作都能按时间线还原其前后 10 分钟的动作序列。
- 808.4 留痕**必须**与账号绑定；**禁止**只写现象不写账号。
- 808.5 留痕**不得**包含密码、cookie、token 原文。
- 808.6 留痕保留期**应当**不少于 30 天，且**必须**支持导出用于诊断。

**判据**：抽查任一条对外动作，五要素齐全；任取一次被拦，能回答「哪个动作、几点、当时频率多少」。

**证据要求**：动作留痕表、被拦事件记录、导出样例。

**反例（判红）**：只有一句「操作失败」没有账号与频率；留痕里带 cookie 原文。

### 809 封号与限流的如实告知（对应 BFS-203.5）

**目的**：把不可控结果如实交还给用户，而不是藏在产品里。

- 809.1 首次开启自动对外动作前**必须**告知：自动化操作存在被平台限制的可能，概率无法保证为零，并给出四承诺边界（801.2）。
- 809.2 首次发布前**必须**再次提示同样的边界，文案对用户可见、不折叠、不隐藏。
- 809.3 发生限流、封禁、验证码时**必须**如实报告：现象、可能原因、已冻结的动作、恢复方式；**禁止**静默失败、**禁止**假成功。
- 809.4 **禁止**用「已成功」「没问题」等措辞掩盖被拦的中间状态。
- 809.5 不可控结果**必须**给三个选择（断点继续 / 重新生成 / 放弃）。
- 809.6 面向用户的文案**不得**给出确定性承诺（例如「明天一定能发出去」），只能给观察与建议。

**判据**：首次开启与首次发布各有一条告知记录；被拦事件的用户可见文案包含现象、原因、恢复方式三项。

**证据要求**：告知记录（时间 + 用户可见文案原文）、被拦事件报告、失败路径验收记录。

**反例（判红）**：被拦后只显示「操作失败」；把平台验证码说成「网络波动」；承诺恢复时间。

### 810 禁止动作（对应 BFS-203.4）

**目的**：有些动作不是「风险高」，是**必封**，必须从产品层面不存在。

- 810.1 **禁止**主动给非粉丝发送私信。
- 810.2 **禁止**批量点赞、批量关注、批量评论他人。
- 810.3 **禁止**刷量、互赞互粉、制造虚假互动。
- 810.4 **禁止**多账号矩阵式分发同质内容。
- 810.5 上述动作**禁止**注册为工具、**禁止**在界面提供入口；管家收到此类请求**必须**用人话拒绝并说明理由。

**判据**：工具目录中不存在上述工具；界面走查无对应入口；助手对此类请求给出拒绝话术而非执行。

**证据要求**：工具清单、界面走查记录、拒绝话术样本。

**反例（判红）**：以「互动运营」为名提供批量点赞入口；用脚本绕过工具面执行上述动作。

### 811 官方接口优先（对应 BFS-203.4）

**目的**：唯一能长期活下去的架构——平台改版时换 Provider，不动业务逻辑。

- 811.1 平台能力**应当**抽象为可替换 Provider：有官方开放接口走官方接口，没有资质时用浏览器自动化兜底。
- 811.2 已具备官方接口资质的能力**必须**切到官方接口，**不得**继续用自动化实现同一动作。
- 811.3 平台改版或规则变更时**只**更换 / 修改 Provider 层，**不得**改业务逻辑。

**判据**：新增或替换平台时，改动 diff 只落在 Provider 层；同一能力在两种 Provider 下产出结构一致的结果。

**证据要求**：改动 diff、Provider 接口定义、双通道对比记录。

**反例（判红）**：平台一改版就改业务逻辑；有官方接口仍用自动化批量调用。

### 812 落地、灰度与复核（对应 BFS-203.1、203.5）

**目的**：细则不落地等于没有细则。落地顺序是**保命 → 降压 → 提效**。

- 812.1 P0 两项（熔断与止损、登录态长期复用）**必须**在任何真实自动对外动作之前完成。
- 812.2 新账号首次启用自动化**必须**先灰度观察 7 天，且只在一个账号上跑。
- 812.3 灰度判据：7 天内 0 次验证码、0 次限流、回复成功率高于 90%；未达标**不得**扩大到第二个账号。
- 812.4 平台规则更新后**必须**在 7 天内复核本细则，给出修订或「无需修订」的结论并留痕。
- 812.5 本细则**必须**至少每年复核一次；内容过期（数值与现状不符）即视为本细则失效。

**判据**：真实自动动作的启用时间晚于 P0 两项的完成记录；灰度报告含四项指标；复核结论有日期与结论。

**证据要求**：P0 完成记录、灰度观察报告、复核记录。

**反例（判红）**：熔断未做完就开自动发布；灰度未达标即扩到第二个账号；细则两年未复核。
