## 1 目的

**把「整个项目像 Marvis 看齐」从一句口号，变成可测量、可排序、可判红的施工顺序。**

依据产品负责人的两次表述：
- 2026-10-11：「**我要的是贾维斯**」「整个项目像 Marvis 看齐」「彻彻底底的改」
  ——前者是对后者的通俗比喻（2026-10-12 产品负责人当场纠正：「是腾讯的 Marvis 不是贾维斯，我只是打个比喻」）；
- 2026-10-12 连续三问：**初衷是什么、达到没有、按初衷肃清**。

**判定线**：本件做完的标志不是"打完一个包"，而是——**关掉页面，用户说一句话，管家能把事办成**。

**统一口径（2026-10-13 产品负责人拍板，最高优先级）**：
「我要的是一个**全面对标腾讯 Marvis Agent 功能**的一站式工具！用户说一句话，管家自己拆解、自己调工具、自己操作电脑与平台把事办完；页面只是过程与结果的可视化。」
—— 本件 P0~P5 的施工与准出、「抄什么」的取舍全部以此为准；ADR-005 原「不抄通用设备层」的排除由本次取代。

## 4 术语与定义

| 术语 | 定义 | 出处 |
| --- | --- | --- |
| **腾讯 Marvis** | 本产品的**形态基准**：操作系统级 AI 助手／AI 管家。项目记录把它的形态拆成五项——**多 Agent 分工 ＋ Skill ＋ 权限闸门 ＋ 端云协同 ＋ 可视化** | ADR-005 二·2 |
| **对标范围** | **全面对标腾讯 Marvis Agent 功能**（一句话入口、多 Agent 分工、Skill、权限闸门、端云协同、记忆、过程可视化、操作电脑与平台）；2026-10-13 起不再设「不抄」的排除项 | ADR-005 统一口径 |
| **我们的护城河** | **10 家平台的真实自动化**（内容创作与自媒体运营垂直）。原话：「它的护城河是通用，我们的护城河是 10 家平台的真实自动化」 | ADR-005 二·2 |
| **管家化率** | 能力长在管家身上的比例。三项度量：①**工具覆盖率**＝有效工具数 ÷ 服务端写操作数；②**管家形态占比**＝kernel/bundle/presets/skills 行数 ÷ 全项目行数；③**页面依赖率**＝必须点页面才能完成的能力数 ÷ 总能力数 | 本件 6.1 |
| **一句话端到端** | 人话输入 → 管家自己调工具办成 → 页面可见结果；三方交叉（工具返回 ＋ 助手回复 ＋ 落库/页面数据），缺一不算过 | BFS-104-R |
| **器官** | ADR-005 明列「不能动」的部分：内核底座、平台引擎、媒体能力缝、账号与数据、打包装机链路 | ADR-005 三·不能动的 |
| **旧形态** | 把「点页面按钮」当第一入口的那套实现：前端页面、长在路由上的写操作、一功能一脚本的门禁 | ADR-005 |
| **棘轮** | 只允许朝一个方向变化的受控基线（能力侧只增，旧形态侧只减） | 《项目分区图》七 |

## 5 关键词约定

- **必须 / 不许**：违反即返工，无例外；
- **应当**：默认执行，不执行须在记录里写明理由；
- **可以**：可选做法。

三级语义与 BFS-100 第 0.5 节一致，本件不另立定义。

## 6 编号化条款

### 6.1 总目标与度量（901.1 ~ 901.5）

- **901.1** 能力**必须**长在管家身上。工具覆盖率目标 **100%**（现状 42%：51 工具 ÷ 121 条写操作）。
- **901.2** 管家分工**必须**在运行时生效。现状为 0（纸面）——DSH SDK 的 server 明写不做 preset 组装。
  判据：同一句「发到抖音」，creator 角色下**拿不到**发布工具，publisher 下**能拿到**；是**被拒绝**，不是被叮嘱。
- **901.3** 页面**必须**降级为过程与结果的可视化。前端行数**只减不增**，功能入口**必须**归零。
  判据：关掉页面，主链路（生成→出片→发布→失败恢复）仍可一句话办成。
- **901.4** 验收**必须**就是一句话。主链路用例 **应当** ≥ 12 条（现状 3 条只读），且**必须**跑在看得见的窗口里。
- **901.5** 验收**必须**是一句话端到端跑通（工具返回 ＋ 助手回复 ＋ 落库三方交叉）。
  **打包不在本流程内**（2026-10-12 产品负责人明确要求）：「把整个项目里打包这一条彻底删了，要打包的时候我会告诉你」。
  打包**不是**开发流程的一步，**不是**进度指标，**不是**准出条件——它是产品负责人**下令后才做**的一次动作。
  因此：**禁止**为了"进度好看"或"形成闭环"自行打包；两个打包入口的授权闸（无 BF_PACKAGE_AUTHORIZED=yes 即 exit 3）**必须**保留。
  打包链路作为**器官**仍在「不能动」之列（见 68 行）。

### 6.2 施工顺序（901.10 ~ 901.15）

- **901.10（P0 立判据）** 门禁判红时一切进度不可信。**必须**先修 DEF-285 让 `qa-all` 回绿，再把一句话端到端扩成主链路用例集，并把管家化率三项指标接进棘轮门禁。
- **901.11（P1 补能力·核心）** **必须**把 121 条写操作逐条工具化。排序原则：先做用户最常说的那句话——创作 → 发布 → 数据回流 → 接待 → 账号与设置。工具描述**必须**写明「必须调用本工具，不要自己直接做」。
- **901.12（P2 通编排）** **应当**优先在内核侧自建组装（不动官方包）；改动 DSH SDK **必须**先评估升级成本。
- **901.13（P3 降前端）** **必须**先做「页面与一句话双轨」过渡期，再撤页面入口；**禁止**一次性重排（2026-10-12 排版被打乱已是教训）。
- **901.14（P4 收门禁）** `qa/` 顶层脚本数**只减不增**；每个能力**应当**至少一条门禁；**不许**存在「打印 FAIL 但退出码恒为 0」的脚本。
- **901.15（P5）不是阶段，是动作**：P0~P4 之外**不再有"交付阶段"**。产品负责人下令打包时**才**执行，
  且执行前**必须**过 verify-before-package（门禁红了拒绝打包——那是脚本自带的判断，不是流程要求）。
  **日常施工的目标是 P0~P4，不是"出包"。**

### 6.3 施工纪律（901.20 ~ 901.24）

- **901.20** 每次改动**必须**先答三行：改哪个文件 / 根因证据 / 会影响谁。
- **901.21** 每个节点完成**必须**当场写三处：工作日志 ＋ 缺陷台账 ＋ 知识库（铁律 #17）。
- **901.22** 删除任何代码前**必须**做运行态验证，**不许**只依据静态 import 图（2026-10-12 曾把 4 个活页面簇误判为死代码）。
- **901.23** 免费模型档（`freeTierRpm=1`）的能力边界**必须**在开跑前如实告知；长链路验证**应当**放夜间。
- **901.24** 未经明确发布指令，**不许**自动发布（DEF-240 事故教训）。

## 8 证据要求

- **三方交叉，缺一不算过**：工具返回 ＋ 助手对用户的回复 ＋ 落库/页面数据（BFS-104-R 第 3.2 节）。
- **过程可见**：禁止无头浏览器做业务验证；一次操作一张截图，能在界面上回放「它到底干了什么」。
- **只认结构化信号**：接口响应体、落库数据、退出码；**不许**用「页面出现了某段文字」当 PASS。
- **数字要有口径**：任何规模数字**必须**注明统计范围与工具（2026-10-12 教训：api.ts 行数因 `Get-Content` 与 `readFileSync().split` 口径不同而差 1395 行）。
- **轨迹要留档**：每条准出**必须**有可复跑的命令与其退出码。

## 9 反例与违规处置

| 反例 | 为什么是反例 | 处置 |
| --- | --- | --- |
| 新增一个「只有页面能点」的功能入口 | 直接违反 901.1 与铁律 #3.5 | 返工：改成工具 ＋ 技能 |
| 新增 `qa/` 顶层脚本却没有对应能力门禁 | 违反 901.14，旧形态继续变厚 | 棘轮门禁判红，返工或删除 |
| 内核工具数没增加，前端行数增加了 | 形态在倒退 | `verify-zone-discipline` 判红 |
| 用接口 `code=0`、日志、JSON 单独作为 PASS | 假阳性（2026-10-12 曾据此误报端到端成功） | 结论作废，补三方交叉 |
| 按静态 import 图删「死代码」 | 曾把 4 个活页面簇误判，照删三页全崩 | 删除前必须运行态验证 |
| 报「全绿」而实际是管道退出码 | 2026-10-12 踩过：`node ... \| Tee-Object` 吞掉真实退出码 | 结论作废，重跑并读日志 |
| 把对标对象写成比喻名（如「贾维斯」） | 判据术语必须指真实对象，否则无从对标 | 一律写 **腾讯 Marvis**；引述原话时加注 |
| 未记录就宣布完成 | 违反 901.21，下一会话必然失忆 | 视为未完成 |

**违规处置三级**：① 单点违反 → 当场返工并登记台账；② 同类第二次 → **必须**升级成门禁断言；③ 明知故犯（如未经指令发布）→ 停工，交由产品负责人处置。
