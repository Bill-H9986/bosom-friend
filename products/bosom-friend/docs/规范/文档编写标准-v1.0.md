## 1 目的与适用范围

### 1.1 目的

规定本产品全部文档的**结构、语言、编号、版本与检查要求**，使任何一篇文档都能被独立读懂、被逐条判定、被追溯来源。

**本标准的判定线**：一篇文档合格，当且仅当——**一个没有上下文的人读完它，能知道该做什么、凭什么算做到了、没做到怎么办。**

### 1.2 适用范围

适用于 products/bosom-friend 下的全部 Markdown 文档，包括：规范、标准、方案、ADR、台账、清单、报告、日志、索引。

**不适用**：DSH 官方源码文档（docs/、packages/ 下），那部分遵循仓库根 AGENTS.md 与 docs/AGENTS.md。

### 1.3 与文档裁决表的关系

判定一篇文档该不该存在，走《文档裁决表》；判定存在的文档写得好不好，走本标准。

## 2 术语与关键词

| 术语 | 定义 |
| --- | --- |
| **规范级（A 级）** | 约束行为、可判红判绿的文档：标准、规范、规则、验收细则 |
| **方案级（B 级）** | 描述决策与计划的文档：总纲、方案、ADR、台账、清单 |
| **记录级（C 级）** | 记录已发生事实的文档：工作日志、测试报告、过程档案、索引 |
| **条款** | 文档正文中可被单独判定的一条要求（编号化） |
| **判据** | 可以回答「是/否」的检验方式 |
| **反例** | 明确判红的典型情形 |

| 关键词 | 含义 |
| --- | --- |
| **必须** | 强制；违反即返工 |
| **应当** | 强烈建议；不遵从须写明理由 |
| **可以** | 可选 |

## 3 A 级（规范级）必备结构 · 十二项

A 级文档**必须**按顺序包含以下十二项；缺一项即不合格：

| # | 结构项 | 要求 |
| --- | --- | --- |
| 1 | **文档头** | 文档编号、版本、状态、生效日期、责任人、执行人、上位依据、替代关系 |
| 2 | **修订记录** | 表格：版本 / 日期 / 修订内容 / 依据 |
| 3 | **目的** | 这份文档解决什么问题，一句话说清判定线 |
| 4 | **适用范围** | 管什么、不管什么 |
| 5 | **与其他文档的关系** | 上位、下位、配套文档各是谁 |
| 6 | **术语与定义** | 本文用到的专有名词，逐条定义 |
| 7 | **关键词约定** | 必须 / 应当 / 可以 三级语义 |
| 8 | **正文条款** | **编号化**（形如 101.1、201.3），一条一个要求，禁止混装 |
| 9 | **判据** | 每条标准后给「怎么算做到」的可判定方式 |
| 10 | **证据要求** | 做到之后要留什么证据、从哪取 |
| 11 | **反例与违规处置** | 明确判红情形与处置等级（L1 立即返工 / L2 限期整改 / L3 记录例外） |
| 12 | **附录** | 至少含：执行检查清单、与旧文档的对照表 |

**现有合格样例**：《管家化标准体系（BFS-100）v2.0》《验收标准-一句话端到端（BFS-104-R）v2.0》。

## 4 B 级（方案级）必备结构 · 七项

| # | 结构项 | 要求 |
| --- | --- | --- |
| 1 | 文档头 | 编号、版本、日期、依据、状态 |
| 2 | 修订记录 | 版本 / 日期 / 内容 |
| 3 | 背景与目标 | 为什么做、要做到什么 |
| 4 | 术语（涉及时） | 专有名词定义 |
| 5 | 正文（结构化） | 表格或编号条目；禁止大段无结构叙述 |
| 6 | 判据与验收 | 怎么算完成 |
| 7 | 附录 | 对照表、待办、风险 |

**适用**：重构总纲、能力台账、文档裁决表、ADR、发布清单。

## 5 C 级（记录级）必备结构 · 四项

| # | 结构项 | 要求 |
| --- | --- | --- |
| 1 | 标题与日期 | 何时、何主题 |
| 2 | 目标或范围 | 这份记录覆盖什么 |
| 3 | 事实与证据 | 做了什么、结果如何、证据在哪（接口/落库/页面/日志） |
| 4 | 未完成与下一步 | 明确遗留项 |

**适用**：工作日志、测试报告、过程档案、索引页。

## 6 写作规范

### 6.1 语言

- 一律**简体中文**；代码、标识符、命令、路径、报错原文保持原样。
- 一句话表达一个意思；**禁止**一句话里塞两个要求。
- **禁止**口号式表述（如「大幅提升体验」）——除非紧跟可判定判据。

### 6.2 结构

- 表格优先于长段落；列表优先于连续叙述。
- 每节标题**不得**使用英文小标题。
- 数字、单位、时间格式统一：日期用 YYYY-MM-DD；时间用 24 小时制并注明时区。

### 6.3 可判定性

- 每条要求**应当**能被回答「是/否」。
- 每个数字**应当**有来源（文件、行号、命令输出、会话时间）。
- **禁止**无来源的断言（「性能良好」「基本可用」）。

### 6.4 禁止事项

| 禁止 | 原因 |
| --- | --- |
| 过程叙述写进规范（「我们先是……然后……」） | 规范只写要求，不写经过 |
| 同一事实在两处各写一遍 | 一份事实只有一个家（docs/README.md 规定） |
| 用「应该差不多」「基本没问题」 | 不可判定 |
| 引用不存在的文件或路径 | 误导执行者 |

## 8 变更与版本规则

1. **主版本 +1**：结构变化、判据变化、替代关系变化；
2. **次版本 +1**：内容补充、措辞修订、示例增补；
3. **被替代的文档不删除**：在标题下标注「**已被 X 替代**」并保留供追溯；
4. 任何规范级文档修订**必须**同步更新其修订记录表；
5. 新增文档**必须**在 docs/README.md 的对象地图里登记所在目录（否则 qa/verify-docs-index.mjs 判红）。

## 9 检查与门禁

### 9.1 门禁（2026-10-11 已建成）

门禁脚本：products/bosom-friend/qa/verify-docs-standard.mjs（退出码 0 = 通过，1 = 判红）。

| 检查项 | 判据 |
| --- | --- |
| A 级文档结构 | BFS-400 十二项缺任一 → 判红 |
| 历史件 | 标题已标注「被 X 替代」的跳过（不判红） |
| 非 A 级 | B 级台账类（如需求台账）跳过 |
| 负向对照 | --selftest 必须打印 SELF_TEST_OK（证明门禁真会红） |

### 9.2 例外处理

结构缺项可按 **L3 记录例外**登记（须写明理由与补做计划），但**不得长期挂账**：门禁每次运行都会打印例外清单。

### 9.3 运行方式

    node products/bosom-friend/qa/verify-docs-standard.mjs
    node products/bosom-friend/qa/verify-docs-standard.mjs --selftest

### 9.4 当前状态（2026-10-11）

6 份 A 级文档全部通过（DOCS_STANDARD_OK files=6 items=72），例外清零。
