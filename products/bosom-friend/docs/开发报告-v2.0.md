## 1 背景与目标

### 1.1 背景

旧《开发报告》立文于 2026-09-21，回答的是当时的问题：**「按什么标准建」**（0 号开发铁律）与**「媒体能力缝补齐了没有」**。
它的两条结论仍然成立，但叙述方式已经过期：

| 旧版写法 | 为什么过期 |
| --- | --- |
| 按「条」组织：第一条铁律、第二条媒体缝、第三条验收方式 | 读者拿不到产品当前的分层结构，也回答不了「这条能力长在哪一层」 |
| 以「页面点得对」为验收落点 | 已被 BFS-104-R 的「一句话端到端 + C 档证据」取代 |
| 以「功能点」计数 | 能力的计数单位是「那句话 + 工具 + 页面可见结果」（BFS-101.1） |
| 引用《项目铁律》与《对标基线》 | 前者已被 BFS-100 v2.0 替代，后者已废止（ADR-005 改对标 Marvis 形态） |

**本版的定位**：产品当前的结构说明书（按六层架构）＋ 能力进度的实测报告（按能力视角）。
「规则按什么执行」不在本件重复，只引条款号——规则的家是 BFS-100 v2.0。

### 1.2 目标（编号化）

| 编号 | 目标 | 判据（怎么算做到） |
| --- | --- | --- |
| **D1** | 六层各自有唯一落点 | 每一层都能指到具体目录或文件，且该路径在磁盘上存在 |
| **D2** | 能力进度可复算 | 工具数、管家化率、缺口数都能用一条命令或一份文件复算出来 |
| **D3** | 边界不含糊 | 厂商调用只出现在 Provider、密钥只住凭据能力、业务实现页面与工具共用，三条都能被门禁或代码位置佐证 |
| **D4** | 未完成项可交接 | 风险与待办逐条带归属阶段与判据 |

## 3 六层架构：职责、落点与判据

### 3.1 总表（2026-10-11 实测）

| 层 | 职责 | 实际落点（相对 products/bosom-friend/） | 本次动作 | 判据 |
| --- | --- | --- | --- | --- |
| ① 运行时层 | Electron 壳 + DSH 内核 + 平台引擎 | `launcher/config/kernel.cordis.yml`、`launcher/config/desktop.cordis.yml`、`bundle/app|cordis.patch.yml`、`bundle/kernel/cordis.yml`、`desktop/electron/`、`engine/` | 保留（不动） | 内核握手一次通过，且真实对话有回应 |
| ② 能力层 | 一条能力 = 一个工具 + 一份实现（页面与 AI 共用） | `kernel/src/index.ts`（工具注册）、`kernel/src/{drafts,jobs,runner,data}.ts`、`server/src/routes-content.ts` 等路由、`server/src/store.ts` | 改造（不重写业务） | 关掉页面，一句话仍能办成 |
| ③ 编排层 | 总管与四个管家的组装（人设 + 技能 + 工具面） | `packages/preset/agent-presets`、`packages/preset/persona`（DSH 原生机制）；产品侧入口 `launcher/config/*.cordis.yml` | 新建 | 四个管家各走通一句话 |
| ④ 技能层 | 专业流程写成技能文件（选题 / 文案 / 封面 / 风控 / 复盘） | `server/src/agent-skills.ts`（技能装载）、`server/src/agent-context.ts`、`server/src/agent-rules.ts` | 新建 | 一句话创作自动加载对应技能 |
| ⑤ 呈现层 | 对话主入口 + 管家团队 + 看板（旧板块降级） | `project/bosom-friend-web/`（前端源码）、`project/bosom-friend-electron/`（构建宿主）、`shim/` | 重建 | 页面只做三件事：展示过程、展示结果、接收拍板 |
| ⑥ 记忆层 | 管家长期记忆、画像、经验与知识库 | `server/src/memory-store.ts`、`server/src/knowledge-distill.ts`、`server/src/self-evolution.ts`、用户数据根 `%USERPROFILE%\.bosom-friend\bosom-friend` | 新建 + 分层 | 同一类任务第二次执行更快或返工更少 |

> **落点口径**：表中路径均为 2026-10-11 磁盘实测存在。**规划中但尚未建立的目录**（`capabilities/`、`presets/`、`skills/`、`boards/`、`team/`，见管家化重构总纲-v2.0.md 第 6.1 节）不在本表，避免把计划写成现状。

### 3.2 运行时层（保留）

| 事实 | 证据位置 |
| --- | --- |
| 开发态与随包态用同一套组合补丁层：基础层 → app / desktop → kernel | `bundle/app/cordis.patch.yml`、`bundle/desktop/cordis.patch.yml`、`bundle/kernel/cordis.yml` |
| 内核运行时入口：`bundle/kernel/runtime/bin-kernel.mjs`、`bin-desktop.mjs` | `bundle/kernel/runtime/` |
| 平台引擎（抖音 / 小红书 / 视频号）以 Python 随包 | `engine/`（vendored 上游库 + 胶水层） |
| 产品数据根与开发机 DSH 数据严格隔离 | `%USERPROFILE%\.bosom-friend` 与 `%USERPROFILE%\.dsh` |

**本层不在本次重构范围**（BFS-100 第 0.2 节「不适用 DSH 官方源码」；总纲第 1.5 节第 2 条）。

### 3.3 能力层（改造，不重写业务）

| 事实 | 证据位置 |
| --- | --- |
| 工具注册集中在一个文件，逐个 `ctx.tools.register` | `kernel/src/index.ts`（1839 行；2026-10-11 实测 **31 个** `bosom_*` 工具注册点） |
| 业务实现仍在服务端路由与领域模块，页面与工具共用同一份实现 | `server/src/api.ts`、`server/src/routes-content.ts`、`server/src/routes-channels.ts`、`server/src/routes-knowledge.ts` |
| 厂商 HTTP 只出现在 Provider 一侧，业务代码不得直连非回环地址 | `server/src/media-gateway.ts`（策略：超时、失败分类、可读文案）；门禁 `qa/run-gate.mjs` |
| 能力工具经回环地址调用服务端能力 | `server/src/kernel-client.ts` | 

**改造口径**：一条能力落地顺序固定为「定义能力 → 注册工具 → 页面呈现」（BFS-102.1），顺序颠倒即按钮软件。

## 4 能力视角：从「功能点」到「能力」

### 4.1 计数口径

| 口径 | 数值 | 来源与复算方式 |
| --- | --- | --- |
| 服务端写操作（系统能做的事） | **49 条** | 能力台账-v1.0.md（`server/src/api.ts` 全部写操作） |
| 内核已注册 `bosom_*` 工具 | **31 个** | 2026-10-11 实测：统计 `kernel/src/index.ts` 的 `ctx.tools.register` 与 `name: 'bosom_*'` |
| 管家化率 | **以能力台账当日值为准**（台账 2026-10-11 记 37%） | 能力台账-v1.0.md 第 0 节 |
| 未闭环缺口 | **以能力台账当日值为准**（台账 2026-10-11 记 40 条） | 能力台账-v1.0.md 第 6 节 |

> **两个数字为什么不同**：能力台账按「能力的写口径」统计（能写的能力工具才计入），本报告按「工具注册点」统计（含只读工具与握手探针）。**对外报进度一律引用能力台账当日值**——它是能力状态的唯一事实源（docs/README.md 的「一份事实只有一个家」）。

### 4.2 已工具化能力（按管家归位）

| 管家 | 代表性工具 | 对应那句话 |
| --- | --- | --- |
| 总管 | `bosom_kernel_ping`、`bosom_job_list`、`bosom_learn_from_history` | 「帮我把这件事办了」「我的任务到哪了」 |
| 创作管家 | `bosom_content_create_draft`、`bosom_content_generate_script`、`bosom_content_create_video`、`bosom_content_update_draft`、`bosom_content_make_cover`、`bosom_content_enhance_prompt`、`bosom_content_split_fourview`、`bosom_material_import_video`、`bosom_material_list`、`bosom_content_list_drafts` | 「写一条关于 XX 的图文」「做个 15 秒视频」 |

| 运营管家 | `bosom_data_dashboard`、`bosom_reception_list_pending` | 「这周数据怎么样」「有多少评论要回」 |

**缺口以能力台账为准**（第 6 节按 P1/P2/P3 排好序），本报告不复制其待办清单，避免两处维护同一事实。

### 4.3 边界的三条硬约束（仍然有效）

| # | 约束 | 当前状态 | 佐证 |
| --- | --- | --- | --- |
