# 09 平台发布与运营引擎经验

**一句话**：平台侧的能力"能被扫出来"不等于"能被调用"——参数默认值、发布意图、参考图素材这三处都真实翻过车。

## 平台范围（收敛后的 10 家国内平台）

抖音、小红书、快手、微信视频号、哔哩哔哩、微博、闲鱼、支付宝等（**全部国外平台已移除**）。发布能力按平台分档：图文/视频、是否支持定时、是否需要扫码。

**能力清单不能靠源码正则扫**：DEF-033 的教训——正则扫得出"有登录函数"，扫不出"参数对不对"。当时 worker 对 11 个平台固定传同一套登录参数，而只导出 `*_setup` 的平台默认 `handle=False`，于是扫码流程**根本不会启动**（点了没反应）；`alipay/weibo` 的 `*_cookie_gen` 又没有 `cdp_url` 参数，固定传会 TypeError。修法：对每个白名单平台走一遍**真实产品链路**（`v2/channels/accounts/auth/:platform` → `platform-login/qr/:sessionId`）并断言拿到真二维码图。

## 发布意图闸门（DEF-044，P0：没让发布也会发布）

用户只说"写一篇小红书笔记"，智能体照样产出"去发布"动作卡，跟随模式自动点掉 → 内容被直接发到平台。
根因：动作卡闸门正则 `/(小红书|抖音|发布|创作|生成|种草|笔记)/` 把"创作/生成/笔记"和"发布"当成同一件事。
修法：闸门必须接在 `api.ts` 上，并且**"写一篇笔记"不得产出 `navigateToPublish`**（正文如实标注"尚未发布"）、**明确说"发布"时必须产出该卡**（`agent-publish-intent.spec.ts`）。

**通用教训**：涉及"对外产生副作用"的动作（发布、删除、支付），闸门的关键词表要按"意图"而不是"话题"来写，并且要有**两个方向的断言**（该拦的拦、该放的放）。

## 素材链路（DEF-043：参考图没进生成链路）

用户加的参考图从头到尾没进媒体生成链路，成片是模型按文案另画的图拼的。
根因：`request.imageUrls` 只落盘留痕（`attachGenerationMedia` 的 request 参数类型里没有它），`generateAiVideoDirect` 也只发 `mode:'text'` 的纯文生视频请求。
修法：`mode=keyframe` + `first_frame` 用用户那张图的 Data URI（字节逐位相等）；无参考图时**不得带任何图片字段**。厂商契约用真实探测确认（`POST /v1/videos` + Data URI 首帧 → HTTP 200）。

**通用教训**：用户提供的素材要在**链路每一跳**都能指出它落在哪；"落盘留痕"不等于"送进模型"。

## 风控与限频（产品铁律）

- 平台动作默认**低频**：接待引擎轮询低配 20 分钟 / 标准 10 分钟；
- 发布/采集失败要**如实标记**（登录失效、风控、上游超时各有自己的状态），不能混成"成功"；
- B 站发布走随包 `biliup` 二进制（不随包的话首次发布会去 GitHub 现下，实测 225 秒）；
- 账号失效参与刷新是假刷新（DEF-017 同类）：过滤条件要同时看 `status` 与 `loginState`（DEF-005）；
- 平台占位昵称（"No name"）要用平台 uid 兜底，否则多账号无法区分（DEF-009）。
