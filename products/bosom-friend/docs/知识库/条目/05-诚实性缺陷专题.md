# 05 诚实性缺陷专题（这个项目最贵的一类缺陷）

**一句话**：用户看不懂的报错、看起来在动其实卡死的进度、没采集到却显示 0 的数据、"成功"但什么都没做——这些不是体验问题，是**这个项目定义的最高优先级违规**。

## 项目铁律里的两条根

- **铁律 #7 实事求是**：做不到就说做不到、未配置就说未配置、失败就如实记录原因；任何假文案/假数据/假成功都是最高优先级违规；
- **铁律 #3 普通用户视角**：任何需要技术操作（命令行/控制台/接口/改配置）的步骤都视为**未完成**。

| DEF-045 | 错误框只有 `spawn tar.exe ENOENT` | libuv 原文既不说缺什么、也不说怎么办；用户只能"完全退出" | 人话文案：缺什么 + 下一步做什么；三种成因都给出口 |
| DEF-046 | 安装"成功"，几分钟后打不开 | 安装期解压失败只打一行日志就继续 | 当场可见提示（静默安装留日志）+ 说明 zip 会留到首次启动 |
| DEF-055 | 错误框已经写成人话（缺什么 + 重装） | 文案里承诺的那条"保底"（随包 Python）在默认设置的 Windows 上**根本不可能成功**——长路径开关默认关闭，而 zip 里就有超过 MAX_PATH 的条目；"实测通过"只在开发机（已开长路径）成立 | 自带解压器显式 \`\\\\?\\\` 前缀 + 长路径探测决定阶梯顺序 + 以运行时入口在位判定成败；引用"实测"时必须写清测试机器的前提 |

## 可复用的做法

1. **三态代替二态**：任何"没有数据"都要区分"真的没有""这次没取到""平台不提供"，并让界面显示**原因**；
2. **错误文案 = 可执行动作**：写完问一句"用户看完这句，知道下一步点哪里吗？"不知道就重写；
3. **不确定就是不确定**：进度、耗时、等待上限宁可走不确定态，也不要用时间假装百分比；
4. **注释也是承诺**：注释里写的兜底、注释里写的保证，都要能在代码里指出对应的分支（DEF-040 就是因为注释与文案在撒谎）；
5. **如实跳过 > 冒充通过**：外部服务不可用时 `test.skip(true, 原因)`，不写"必然通过"的断言；
6. **自动化脚本/探针不能污染用户数据**：探针改配置、写时间戳这类副作用，要么隔离数据根，要么明确禁止。
