# 28 平台「禁言」：发布被拒的真实形态与判定

> 来源：2026-10-13 夜真机发布第 1–6 轮（`rec-13yp2ma7` / `rec-s9203nnx` / `rec-7epudomh` / `pub-axrg4gl1`）。
> 关联：条目 29（HTTP 200 ≠ 平台收单）、条目 21（发布链路的验证码/并发/凭据错位）。

## 现象

引擎日志一路「🥳 图文发布成功」，记录 status=1，但平台创作者中心里**一条新作品都没有**——账号被平台**禁言/处罚**后，平台对发布请求照常回 HTTP 200，只在响应体里写拒绝理由。2026-10-13 实测原文：

```json
{"result":-102,"success":false,"msg":"您的账号处于禁言状态，请联系薯队长","can_show_err_msg_to_user":true,"need_retry":false}
```

## 怎么判定（三步，全部结构化）

1. **读发布接口响应体**（不是只看 HTTP 状态）：`success:false` 或 `code≠0` 即平台明确拒发；
2. **创作者中心直查**（陌生人的眼睛）：可见浏览器打开「笔记管理」，看「全部/已发布/审核中/未通过」任何页签是否出现该条；
3. **产品同步**：跑一次账号同步，看作品列表与计数是否变化。

三步都不见新作品 = **未发出**，与引擎文案无关。

## 处置口径

- **账号侧**：平台处罚只能由账号方申诉/联系平台（本产品不可自解）；恢复前该账号发布一律被拒。
- **产品侧**：引擎必须把平台原文落到记录与通知（「平台原文：您的账号处于禁言状态，请联系薯队长」），
  收尸文案统一为「**可能已发出 → 先同步确认、不要重复发布**」——宁可不发，也不发两条（DEF-240 教训）。
- 管家看到「可能已发出」的谨慎文案时**拒绝盲目重发**是正确行为；人工复核引擎日志后再订正记录为「确认未发出，可安全重试」。

## 一句话口诀

**平台说不行会写在响应体里——读它；平台说行也要眼见为实——去创作者中心看。**
