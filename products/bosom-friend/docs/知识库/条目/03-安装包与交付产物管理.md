# 03 安装包与交付产物管理（含回滚网教训）

**一句话**：交付物只有一样——`BosomFriend-Setup-<版本>.exe`；而"回滚网"这类安全资产必须放在**不会被清理**的地方，否则一次整理就没了。

## 安装期为什么解压（设计权衡）

内核运行时 417MB / 约 23 万个文件。放在首次启动解压，低配机械盘要十几分钟，用户面对的是启动页；放在安装期解压，代价变成"安装时多等几分钟"，但应用一打开就能用。

`build/installer.nsh`（`customInstall`）的契约：
1. 先删掉旧的 `%APPDATA%\Bosom Friend\kernel-runtime`，重建，解压到**固定目录**（与 `kernelRootForVersion()` 的约定一致）；
2. **解压成功才删** `resources\kernel-runtime.zip`（省 417MB）；失败则保留它，作为首次启动兜底的原料；
3. 失败**不能静默**：给出可见提示（静默安装只留日志），说明 zip 会留到首次启动（DEF-046）；
4. 与主进程同一阶梯：系统 tar → 随包便携 Python。

**坑（DEF-011）**：electron-builder 只认默认文件名 `installer.nsh`；自定义名字必须在 `electron-builder.yml` 的 `nsis.include` 里显式声明，否则自定义钩子被**静默忽略**，解压全部落到首次启动。

## zip 的生命周期（三条路径要一致）

| 路径 | zip 去留 |
| --- | --- |
| 安装器解压成功 | 删除（省 417MB） |
| 应用兜底解压成功 | 删除（与安装器同契约） |
| 两者都失败 | 保留，等待修复安装或现场脚本 |

因此「固定目录缺失 + zip 也已删除」的机器，唯一出路是**重新运行安装包做修复安装**——这句话必须原样写给用户（DEF-040 的教训：注释与文案都不能承诺做不到的兜底）。

## 装机验收（每次出包都做，缺一不可）

- 静默安装 `BosomFriend-Setup-<版本>.exe /S` exit 0，注册表 DisplayName 与 `desktop/package.json` 版本一致；
- `%APPDATA%\Bosom Friend\kernel-runtime` 文件数约 **199,984** 且 `runtime\bin-desktop.mjs` 在；
- `verify-splash-progress.mjs --packaged` 8/8（真实安装包冷启动走完进度并进产品页）；
- 卸载后安装目录/桌面/开始菜单/注册表/进程清零、`%APPDATA%\Bosom Friend` 不存在，而 `%USERPROFILE%\.bosom-friend` 原封不动（DEF-042）；
- 记录产物 SHA256 到 `qa/reports/release-<版本>-<日期>.md`。

## 回滚网（R8）与 2026-09-14 的口径修订

**原来**：`qa/baseline/installer-checksums.json` 钉住 5 个历史安装包（0.13.5/0.13.6/0.13.7/0.13.8/0.2.0），门禁「安装包只读保护」逐文件校验 SHA256，清单里的文件放在 `<仓库根>/release/`。

**出了什么事**：那次清理明确写了"保留"，但之后整理仓库时 `<仓库根>/release/` 整个被删（`.exe` 从未进 git，历史里查不到），5 个包全丢，门禁转红；连带 0.2.41 的回滚包也没了。**根因不是有人手滑，是安全网放在了每次整理都会被清扫的房间里。**

**现在的口径（2026-09-14 起）**：
1. 回滚网 = **当前出货版本 + 上一版本**（不再保留改名前的 0.13.x；它们的数据根与格式都变过，装回去也读不了现有数据，留着只是"假绿"）；
2. 安装包存放在**仓库外**的固定目录（清单里的 `dir` 字段指定），仓库被清理不影响；
3. 只增不减：每出一版，把新包复制进回滚库、更新基线、在 `qa/reports/cleanup-*.md` 留一条决策记录；
4. 门禁语义：**存放目录不在位 → 黄**（外置盘没接？），**目录在但文件缺失/哈希不一致 → 红**。

## 产物与构建的硬约束

- **打包读的是 `dist/`，不是源码**：改了 `server/src` 没同步进 runtime，装出来的还是旧行为；
- **构建与门禁不能并发**（09-11 踩过）：构建会改写 `dist`/`release`，并发门禁读到半成品；
- **`dist`/`lib`/`release` 都是可清理产物**：任何一个"必须存在"的检查，都要区分"环境未就绪（黄）"与"产物在但坏了（红）"。
