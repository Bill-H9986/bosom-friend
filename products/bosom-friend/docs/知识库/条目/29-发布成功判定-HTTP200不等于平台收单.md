# 29 发布成功判定：HTTP 200 ≠ 平台收单

> 来源：DEF-306（2026-10-13 真机第六轮坐实）；修复见 `engine/social-auto-upload/uploader/xiaohongshu_uploader/main.py` 与 `engine/VENDORED.md`。

## 现象

小红书 Web 接口在**风控/校验失败**时同样返回 HTTP 200，只把结果写在响应体里（`success:false` / `code≠0`）。
旧的成功判据是「匹配到发布接口 POST 且 HTTP 200」→ **被平台拒发会被记成「已发布」**：记录 status=1、
页面显示成功，平台账号里零作品。2026-10-13 两次真机发布（21:39、22:16）全部如此，直到第六轮抓到响应体原文才定案。

## 做法

1. **成功 = HTTP 200 + 响应体确认**：`success:true` 或 `code==0`；`success:false`/`code≠0` 抛专用异常
   （`XhsPublishRejected`）**穿透重试与兜底逻辑**——继续点「发布」只会把同一条内容反复提交；
2. **响应体落日志**（URL / HTTP 状态 / 前 600 字）：它是对质「假成功 / 真成功 / 平台拒发」的唯一结构化凭据；
3. 响应体不可判读时保持旧行为（按 200 通过）**但必须有日志**，下次现场有据可查；
4. 平台回执的最终判据仍是**回读作品 ID**（时间窗 + 标题，见条目 9/21），响应体判读是它前面的第一道闸。

## 反例（别重犯）

- 「看页面跳了成功页就算成功」：成功页在风控拒发时也可能出现；
- 「看日志出现成功字样」：日志是流程输出，不是平台回执；
- 「HTTP 200 就当收到」：本条目全部证据都指向它的反面。

## 一句话口诀

**200 只说明网络通了；收没收到，读响应体、等作品 ID。**
