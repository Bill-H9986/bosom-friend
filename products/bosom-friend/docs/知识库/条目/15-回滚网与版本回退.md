# 15 回滚网与版本回退

**一句话**：回滚网 = 当前出货版本 + 上一版本，两处各存一份（本机仓库外目录 + GitHub Release）；0.2.58 出问题时先用下面的对照表分清是内核运行时打包的问题还是业务代码的问题，再决定回退还是改代码。

## 口径

- 回滚网 = **当前出货版本 + 上一版本**；改名/改架构之前的老版本（0.13.x）不保留：数据根与格式都变过，装回去读不了现有数据，留着只是「假绿」。
- **本机副本放仓库之外**（`C:/Users/Jay/BosomFriend-Releases`）：仓库里的 `dist`/`lib`/`release` 都是会被整理清理的可重建产物。2026-09-13 的清理就把放在 `<仓库根>/release/` 的 5 个回滚包弄丢了。
- **GitHub Release 是第二份来源**：**2026-10-14 起改挂主仓 `Bill-H9986/bosom-friend`**（资源地址形如 `https://github.com/Bill-H9986/bosom-friend/releases/download/v<版本>/BosomFriend-Setup-<版本>.exe`，v0.4.0 起生效）。原下载仓 `Bill-H9986/zhiyin` 已归档只读，历史包（v0.2.51–v0.2.61）继续可下载、旧链接不失效；其 latest Release 的 `version.json` 为迁移清单（指向主仓 0.4.0）。2026-09-18/19 时 v0.2.51 / v0.2.55 / v0.2.56 / v0.2.57 / v0.2.58 五份 `state=uploaded`、远端字节数与本机逐一相同（历史记录）。
- **上传走 REST API，不依赖网页**：本机 `github.com` 网页与 `gh` 登录都不可用，但 `api.github.com` 与 `uploads.github.com` 稳定可达；凭据取自 Windows 凭据管理器里已有的 `git:https://github.com`（账号 `Bill-H9986`，`repo` scope），用 `CredRead` 读出后只走内存与临时文件，不写入仓库。上传速率 2.6~4.1 MB/s。
- **下载侧被限速（约 0.2 MB/s）**：所以「从 GitHub 下回来逐字节核对」在本机没跑完，现有证据是 Release API 的 `state=uploaded` 加字节数一致；要补完整回环核对就用下面的 `fetch-release-installer.ps1`（它下载后按基线核对 SHA256）。
- 权威指纹在 [qa/baseline/installer-checksums.json](../../qa/baseline/installer-checksums.json)（`files` = 回滚网现有两份，`retired` = 已放弃的版本，留指纹与重建来源）。门禁「安装包只读保护」按 `dir` 逐文件校验 SHA256：目录不在位判**黄**（外置盘未接入），文件缺失或哈希不一致判**红**。
- **本机不压多份**：同一版本曾经在桌面、`desktop/release/<版本>/`、回滚库各存一份，实测桌面 5 份 + 仓库 6 份共约 15GB。现在本机只保留回滚网那两份。

## 0.2.58 出问题时怎么定位

0.2.58 相对 0.2.56 的改动集中在三处，**先看故障落在哪一侧**：

| 症状 | 判断 | 处置 |
| --- | --- | --- |
| 安装器卡在「正在准备内置运行时」、或装完 `%APPDATA%\Bosom Friend\kernel-runtime` 文件数明显不是 23,297 | 内核运行时解压 / 打包侧 | 回退 0.2.56（用上面的取回命令），并把安装日志与 `%APPDATA%\Bosom Friend\` 下的解压日志留在现场 |
| 内容创作「视频时长」弹层里没有 `4/5/6/8/10/12/30 秒/1 分钟` 八个档位，或选了 30 秒又弹回默认档 | 前端档位层（DEF-105 曾在此） | 先确认模型已配置（模型面板里 `durations`/`longDurations`），再按 DEF-105 的三处落点查；判据是**界面**，不是接口 |
| 30 秒 / 1 分钟档位生成记录写「媒体生成超时」但盘上已有成片 | 媒体预算层（DEF-107 曾在此） | 看内核日志 `[generation] 媒体预算 … budgetMs=`：30 秒档应为 **2,050,000（34 分钟）**，若仍是 15 分钟说明跑的是旧运行时 |
| 长视频提交后被判「稿件只有 N 字」，但界面上没提前说要多少字 | 门槛前置层（DEF-108） | 调 `GET long-videos/script-requirement?producer=scene&targetSeconds=300`，应回 1350 字；返回「任务不存在」说明路由被通配吃掉（DEF-110） |
| 手工做的备份目录在下次启动后消失 | 备份轮转层（DEF-109） | 看日志有没有 `[security] 备份轮转已删除 …`；没有这行却少了目录，说明跑的是旧运行时 |
| 内核起不来、日志出现 `Cannot find package '<名字>'` | 扁平树的依赖闭包侧（漏包 / 版本冲突） | 回退 0.2.56；把缺失包名与 `dist/kernel-runtime-flat` 是否含该包一起记进缺陷台账 |

## 0.2.56 与 0.2.55 之间的结构性改动（历史，定位老问题时仍要看）

0.2.56 起内核运行时改为「先算成扁平树再压缩」（pnpm 部署产物不再展开联接点）：同一份依赖闭包，条目数 195,539 → 23,297，zip 419.3MB → 62.5MB。因此 0.2.55 与 0.2.56 之间的问题定位先看这一层，其余是业务代码提交，可用 git 直接定位。
