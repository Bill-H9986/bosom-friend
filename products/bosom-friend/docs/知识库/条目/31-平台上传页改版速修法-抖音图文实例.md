# 31 平台上传页改版速修法（抖音图文实例）

> 来源：DEF-309（2026-10-14 凌晨：`pub-3xfr7ol2` 卡 3 分钟无进展、人工止损；探针 `engine/_douyin_upload_probe.py` 实证后一次修好）。

## 现象与根因

抖音图文发布卡在「等图片上传完成」的循环里直到 17 分钟子进程超时，日志只剩刷屏。根因是**三件事叠加**：

1. **页签渲染竞态**：上传页默认停在「发布视频」，「发布图文」页签要等渲染（实测 +8 秒才在 DOM 里）；
   旧逻辑在 +1 秒就判定「没有入口、跳过切换」；
2. **选择器没有限定**：跳过切换后页面里可见的 file input 是**视频输入框**（accept=video/*），
   图片塞进去 DOM 层「成功」但页面毫无反应；
3. **两处无界等待**：「等进入编辑页」与「点发布重试」都是 `while True`，把一次卡住放大成 17 分钟空转。

## 速修法（探针先行）

1. **只读探针**（`_douyin_upload_probe.py`，绝不点发布）：dump 页面上所有 `input[type=file]` 的
   accept/可见性/父级路径 → 点击「发布图文」→ 再 dump → 对**图片输入**试 `set_input_files`，
   观察 URL 是否进入 `post/image`。实测点击后：视频输入（隐藏）+ 图片输入（可见）并存，
   对图片输入 set_files 后 URL 立即跳转；
2. **修复三件套**：① 先 `wait_for`（20 秒）页签再点击，真旧版才跳过；② 上传选择器**只认
   `input[accept*='image']`**（含 CDP 兜底）；③ 所有等待**有界化**＋超时留现场截图并如实失败
   （点发布重试还要节流：≥5 秒一次、总时长 150 秒）；
3. **复验**：真机直发一轮——修复当晚回读第 1 轮即命中作品 ID。

## 通用口径

平台页面是**外部依赖**，随时会改版。**能拦住改版的不是「记住选择器」，而是「有界等待 + 现场截图 + 只读探针」**
这条修复路径本身。

## 一句话口诀

**页面等不动的第一时间不是加等待，是去 dump 真实 DOM——然后让所有等待有上限。**
