# 32 出包窗口纪律与出包链手工前置

> 来源：2026-10-14 凌晨 0.4.0 打包实测两处；DEF-310 与「并发写假红」见工作日志-2026-10-14。

## 纪律一：出包窗口内不要跑真发布

打包前置门禁包含「一句话端到端」13 条只读用例，**整轮有哨兵判定「全程未改业务数据」**。
0.4.0 第一次打包时，我正并发跑真机抖音发布——真发写下的发布记录/账号计数被哨兵判成
「只读用例改了业务数据」，门禁**假红**、打包被拒。

**口径**：出包窗口内只跑门禁自己的用例；真发、清数据、删账号这类写操作等窗口结束。
遇到整轮哨兵红先问一句「**是不是我自己正在并发写**」，再谈是不是产品问题。

## 纪律二：kernel-runtime-unpacked 是手工前置产物（DEF-310）

`rebuild-kernel-and-installer.ps1` 第 2 步要求 `desktop/dist/kernel-runtime-unpacked` 已存在；
它由 `pnpm --filter @deepseek-ai/dsh-bosom-friend-kernel-bundle deploy --prod <该目录>` 物化
（`kernel-upgrade-plan.md` §3 有档），**不在打包脚本里自动执行**。缺失时脚本 fail-loud，
按文档补跑 deploy（514 包约 24 秒；尾部 `ERR_PNPM_IGNORED_BUILDS` 是已知噪声、无影响）后继续。
建议（未做）：脚本在目录缺失时自动 deploy 自愈。

## 纪律三：冻结前端的产物校验长什么样

前端固定为 0.2.62 产物后，`qa-guard` 静态检查改为**对产物本身**断言：
`index.html` 的 SHA256 与 `FRONTEND-FROZEN.md` 声明一致 + index.html 引用的 assets 全部存在
（防 2026-09-29 白屏类事故）。源码扫描仍保留，但不再是「被交付物」的唯一证据。

## 一句话口诀

**打包窗口是只读窗口；出包链的手工前置要有名有姓（写进文档 + 报错文案里给正解）。**
