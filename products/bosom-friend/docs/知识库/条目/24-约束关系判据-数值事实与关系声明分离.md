# 24 · 约束关系判据（数值事实 / 关系声明 / 关系验证）

> 归属：D 公共底座 / 工程质量
> 日期：2026-10-09
> 结论：**跨模块配置的一致性，不能靠比较数值判断；必须先声明关系，再由检测器实算。**

## 一、为什么不能直接比数值

两个地方的数字不同，**不一定是漂移**；两个地方的数字相同，**也不一定一致**。

- 平台允许 1000 字、Prompt 要求不超过 900 字 → 可能是**有意留修改空间**；
- 两处都写 1000，但一处含标题、一处只算正文 → **仍不是同一份事实**。

所以判据不是 `a !== b → DRIFT`，而是**先声明关系**。

## 二、三个事实必须分开

| 事实 | 来源 | 说明 |
| --- | --- | --- |
| **数值事实** | 代码提取 | 检测器只读，不猜 |
| **关系声明** | **结构化标记** | 人工声明设计意图 |
| **关系验证** | 检测器实算 | 声明**不豁免**验证 |

**结构化标记形式**（示例，实际以检测器解析器为准）：

```ts
/**
 * @constraintRelation gen-le-platform
 * @constraintTarget PLATFORM_CONTENT_LIMITS.*.topics
 * @constraintRationale shared-multiplatform-draft
 */
export const MAX_TOPICS = 8
```

**标记必须绑定字段与目标**：缺 `@constraintTarget` 即无效（否则标记本身会成为一份新的漂移事实）。

## 三、结果码与判定条件

| 条件 | 结果 |
| --- | --- |
| 已声明关系，实际数值满足 | `CONSISTENT` 或 `INTENTIONAL_DIFFERENCE`（按关系类型） |
| 已声明关系，实际数值违反 | **`DRIFT`** |
| 数值存在配对，但未声明如何关联 | `UNVERIFIED`（**不猜、也不静默跳过**） |
| 关系目标不存在 / 无法提取 | `EXTRACTION_FAILED` |

## 四、四类关系

| 关系 | 含义 | 判据 |
| --- | --- | --- |
| `same-source` | 同一份事实的多处渲染 | 必须追到**同一个定义** |
| `gen-le-platform` | 生成上限 ≤ 平台上限 | 不等式成立 → 有意差异；违反 → `DRIFT` |
| `different-semantics` | 语义不同 | **必须登记**，否则 `UNVERIFIED` |
| `producer-consumer` | 字段须有生产者 | 消费者 > 0 且生产者 = 0 → **`DRIFT`**（接线断裂） |

**`gen-le-platform` 必须对全部适用对象成立**，取最小值：`MAX_TOPICS ≤ min(已声明平台话题上限)`。
只拿一个平台证明跨平台策略是不成立的。

## 五、实际发现（DEF-230）

`maxTotalTextLength`：消费者 2 处、生产者 0 处 → `producer-consumer` 报 `DRIFT`。
**代码事实已确认，产品预期行为待确认**（补生产者 or 删消费者）。台账保持 `Open`。

## 六、汇总口径必须分两级

只看规则级会掩盖事实级：一条规则内若同时存在 `DRIFT` 与 `UNVERIFIED`，规则级只显示 `DRIFT`，
**汇总就会显示 `UNVERIFIED=0`**，让人误以为没有未声明的候选关系。因此两行分开输出。

## 七、可复用范围

同一套模型可直接套到**价格、超时、重试次数、内容限制**等任何跨模块配置：
先声明关系 → 再实算 → 记录证据。**不要为"让门禁变绿"而填值或加例外。**
