# 13 AI 视频生成工作流与厂商能力边界

> 面向"AI 数字人带货片"这条产品线的知识条目：**工序怎么做**（开源界已收敛的范式）与
> **本厂商能做到哪**（2026-09-16 真实调用实测）。改这条产品线之前先读这两节。
> 实测原文：`qa/probes/agnes-capability-report-2026-09-16.md`、证据 `qa/evidence/agnes-probe-2026-09-16/`。

## 一、工序：行业已收敛的九步（四个开源项目的交集）

调研对象：ClipFactory、OpenDirector、H3Loom、Shopro-AI（均为可读源码的开源项目）。

```
创意/商品 → 脚本(带情绪与节拍) → 配音(真实时长为母时钟) → 分镜表
   → 视觉一致性层(参考图集) → 逐镜画面生成
   → 时间轴校验 → 组装/后期(转场/调色/字幕/BGM/响度) → QC → 成片
```

要点（按重要性）：

1. **分镜表是核心数据结构，不是中间态**：ClipFactory 先把时间轴落成**校验过的 JSON** 再交给 ffmpeg 渲染，
   所以"改一镜"不需要重跑整条；
2. **配音的真实时长为母时钟**：ClipFactory 明确用配音时长驱动整个时间轴，字幕按词级时间戳对齐；
3. **视觉一致性必须显式设计**：ClipFactory 的关键帧链式（下一帧以上一帧为参考）、OpenDirector 的角色/场景参考图
   （并警告 image-to-image 模型选错会**静默忽略参考图**）、H3Loom 的"参考图库即资产"；
4. **花钱前先校验**：ClipFactory 专门有一层校验；H3Loom 要求"先做 1~2 个样板确认，再全量生成"；
5. **画面生成与渲染分开**：生成很慢很贵，渲染是纯本地计算，两者解耦才能重排镜头而不重新生成；
6. **镜头语言可复用**：模板（分镜结构 + 镜头时长 + 字幕样式 + 音乐类别）是配置文件，不是代码。

### 镜头节奏的实测参考值

- 光羽案例（`docs/参考资料/抖音-7680454386149100819/REPORT.md`）：**平均镜头长度 6.18 秒**、88 个剪辑点；
- 其屏幕录制披露的方法论：`style = 兴趣全句 × 兴趣画面 × 兴趣声音`，分镜表字段为
  `AE标题 / 承接单元 / AE要素证据解释 / style兴趣触发`，镜头带"连续镜头/单镜头"与"承接范围"标注。

**推论**：一条 30 秒带货片应有 **5~8 个镜头**（口播镜与产品镜交替），而不是"一段口播切成 3 块"。

## 二、厂商能力边界（Agnes，2026-09-16 真实调用实测）

| 能力 | 实测结论 | 对设计的影响 |
| --- | --- | --- |
| 图像图生图 | **不可用**：`image` 字段 200 但**静默忽略**；`images`/`reference_images`/`init_image` 均 400 | 关键帧链式**做不了**；不能靠图像锁产品、锁脸 |
| 图像文生图 | 可用（`agnes-image-2.1-flash`），支持任意 size（含 1080x1920） | 只能"另画"，不能"照着我给的画" |
| 视频多参考图 | **可用**：`mode:reference` + 2 张参考图 + 固定 seed → 成片与参考图同一人 | 多机位数字人可做；参考图集一旦固定不要换 |
| 视频参考音频 | **可用**：真实 mp3（data URI）驱动口播，成片带独立 AAC 音轨 | 口播链路成立；"能否克隆音色"未验证 |
| 生成速度 | 5 秒成片约 50 秒（建任务→completed），输出 720x1280 / 24fps / h264 + AAC 32kHz | 30 秒片 ≈ 6 个镜头 ≈ 5~6 分钟 |
| 模型权限 | **按 key 白名单**：`/v1/models` 列出 11 个，本 key 只许 9 个 | 产品**不能把模型名写死**，保存前必须校验权限 |

## 三、踩过的坑（照抄开源方案会踩的）

1. **模型名在列表里 ≠ 你有权限**：`agnes-image-2.5-flash` 出现在 `/v1/models` 里，
   但本 key 调用返回 403 `team_model_access_denied`——"图片生成失败"的真因是配置里的模型名无权限，
   与网络无关。**保存配置前用一次最小真实调用校验权限**，别等生成时才炸。
2. **"参数被接受"不等于"参数被使用"**：图像的 `image` 字段返回 200 却完全没用参考图；
   而视频的 `audios` 塞错类型会明确报 `invalid_media`（说明它真读）。两个字段的行为完全不同，
   必须用"参考图上带模型猜不到的特征"做对照实验，而不是看状态码。
3. **图像端点靠域名区分队列**：带 `image` 的响应来自 `platform-outputs.agnes-ai.space`，
   不带的来自 `cos-platform-outputs.agnes-ai.cn`——**响应域名变了就该怀疑走了另一条链路**。
4. **别把"展示产品"交给文生视频**：模型会自由发挥包装与文字，出现乱码品牌名（实测
   `ALTLONE / MUSKIRY CADEE` 这类臆造标签）。品牌文字只能走**后期叠加**，或画面避开产品正面。
5. **单段 4~12 秒是硬上限**：长片必须分段；段间**硬切在人脸上**是"一眼 AI"的主因，
   切点要落在产品/场景镜头上，人脸段之间用溶解。
6. **各段独立生成必然有接缝**：光线、色温、音量都会飘。组装层必须有统一调色与响度归一化
   （`loudnorm`），否则再好的单段也像拼的。

## 四、本产品当前的缺口（对照上面的工序）

| 工序 | 现状 |
| --- | --- |
| 分镜表 | **完全没有**（写稿 → 按句切段 → 拼接） |
| 镜头类型 | 只有"口播"与"场景"两种，没有产品镜、没有 B-roll 占位、没有后期文字卡 |
| 一致性 | 只有"同一张形象图 + 固定 seed"，无参考图集概念 |
| 母时钟 | 时长靠字数估算（`CHARS_PER_SECOND`），不是配音真实时长 |
| 组装 | `-f concat` 硬拼、720p、字幕白字细描边 |
| 可返工 | 只能整条重跑 |
| 成本可见 | 无报价、无预估 |
