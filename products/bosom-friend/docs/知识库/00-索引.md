# 工程经验索引（Bosom Friend）

> 这是从本机全部开发资料里整理出来的「过程 + 经验」两层知识库，供人和 AI 智能体检索。
> 整理时间：2026-09-14（2026-09-15 随仓库目录整理同步更新路径）。原文来源与逐篇对应关系见知识库笔记 `知识库/清单.md` 与 `qa/reports/knowledge-import-*.json`。

## 怎么用

- **要结论**：直接看 `条目/` 下的条目（`01-…` 到 `14-…`），每条都是可执行的经验，不是流水账；
- **要证据**：条目里都写了来源文档，去下面的「原文在哪」翻原文；原文一字未改，用于追溯；
- **要查坑**：先看 `12-常见坑速查表.md`，命中再跳对应条目。

## 口径（为什么这么收）

1. **只收"过程与经验"**：工作日志、缺陷台账、复盘/测试/发布报告、规范与铁律、方案与路线图、决策记录。
2. **不收代码、二进制、生成物**：`node_modules`、`vendor`、`dist`、`lib`、`legacy-archive`、`evidence/`（截图）、以及生成型目录 `config-catalog`/`module-graph`/`tool-catalog`——它们是产物，不是经验。
3. **同内容去重**：按 SHA256 去重，重复文件只留一份（在清单里标注）。
4. **DSH 自带的 `.agents/notes`（1482 篇 / 10MB）默认不收**：那是 DSH 内核自己的知识体系，体量会把产品经验淹掉；导入脚本留了 `--include-dsh` 开关，需要时再收。
5. **单篇上限 80KB**：超限的按 80KB 切片成 `…-part1.md` / `…-part2.md`，保证内容不丢。
6. **落点约束**：产品过程文档只能放在 `products/bosom-friend/**` 下——导入脚本对"仓库根目录里含斜杠的 .md"一律不收（基座 `docs/` 是 DSH 官方文档区，同样不收，且受 `doc-sync` 门禁管辖）。

## 更新方式

```powershell
# 干跑（只统计，不写知识库）
node products/bosom-friend/qa/probes/import-dev-knowledge.mjs --dry-run
# 正式导入（先自动备份 knowledge.json）
node products/bosom-friend/qa/probes/import-dev-knowledge.mjs --apply
```

导入是**只增不改**：不会删任何已有笔记，同名笔记按最新原文覆盖；应用自己的 `自动沉淀/` 目录不碰。

> 外部知识库（桌面 Obsidian 库 `C:\Users\Jay\Documents\Obsidian Vault`）是另一套：它按 `01-Bosom Friend 主线/` 等分区手工维护，本脚本不写它。
