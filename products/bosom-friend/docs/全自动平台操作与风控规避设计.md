# 全自动平台操作与风控规避设计 v1.0

> 目标：**保住「AI 全自动一站式服务工具」的产品定义**——自动读数据、自动接待、自动发布——
> 同时把平台风控触发概率降到可控，并保证一旦被拦能立刻止损。
> 关联：`../qa/交付测试规则-v1.0.md`（本文档的动作清单将进入 D1/D2/D4 测试范围）。

## 0. 诚实边界（先说不做到的）

没有任何方案能保证 100% 不被风控。这是攻防对抗：平台每周改检测，我们每周要跟。
本文档承诺四件事，不承诺第五件：

| 承诺 | 内容 |
| --- | --- |
| 可降 | 把触发概率从「必然」降到「低概率」 |
| 可止损 | 一旦被拦，24 小时内冻结该账号，不扩大 |
| 可隔离 | 一个账号出事，不牵连其他账号 |
| 可定位 | 每次被拦都能查到「哪个动作、什么时间、什么频率」 |
| ~~绝不封号~~ | **不承诺**。承诺绝对不封号是假话 |

## 1. 风控到底在看什么（五类指纹）

| 类型 | 平台看什么 | 本项目现状 |
| --- | --- | --- |
| 技术指纹 | navigator.webdriver、CDP 特征、Canvas/WebGL、字体、时区、分辨率、WebRTC 真实 IP | 真实 Chrome + stealth 脚本已做（`engine/interactions.py`） |
| 行为指纹 | 鼠标轨迹、打字节奏、点击落点、滚动惯性、停留时长 | 只有打字延迟随机 60~160ms；鼠标仍是合成点击 |
| **节律指纹** | 活跃时段、动作间隔分布、会话时长、每日动作量 | **固定 10 分钟轮询（`reception-engine.ts`）= 最典型的机器特征** |
| **内容指纹** | 文案是否重复、敏感词、外链、是否秒回 | **两条固定模板（发货/价格），重复发送必被判营销骚扰** |
| 账号画像 | 账号年龄、历史行为、设备一致性、IP 归属地是否跳变 | **3521 次反复登录、5.45 GB 会话残骸 = 异常画像** |

结论：技术指纹做了一半，**节律、内容、账号画像三项全部不合格**——这三项才是封号主因。

## 2. 五层设计（第 0 层保命，越往上越进攻）

### 第 0 层：熔断与止损（最先做）

触发任一条件 → **立即冻结该账号全部自动动作**，转人工并通知用户：

- 出现验证码 / 滑块 / 人脸核验
- 页面出现「账号异常」「操作频繁」「请稍后再试」
- 连续 2 次动作失败
- 登录态失效

冻结时长：首次 6 小时 → 二次 24 小时 → 三次 7 天。

> **铁律：绝不在被拦后立即重试。** 重试等于向平台举手说「我是机器人」。

熔断是账号级：A 账号熔断不影响 B 账号。

### 第 1 层：登录一次、长期复用（消灭 3521 次登录）

现状：`platform-login/` 5.45 GB、3521 个交互会话、`accounts.json` 里 `hasCookie: false`。
**每一次重新登录都是一次高风险事件**，而你现在做了 3521 次。

- 用户扫码一次 → 持久化 profile → 之后**只复用，不再登录**
- 登录态失效：**只提示用户手动重登**，后台不自动重登
- 废弃会话自动清理（保留最近 N 天），杜绝再次堆到 GB 级

### 第 2 层：节律引擎（把机器节律改成人的节律）

现状：`intervalMinutes = 10` 固定轮询，一天 144 轮。改成：

| 维度 | 规则 |
| --- | --- |
| 活跃时段 | 默认 09:00–12:00、14:00–18:00、20:00–23:00（设置可改） |
| 每时段检查次数 | 2~4 次 |
| 间隔分布 | **对数正态分布**，不用均匀分布（均匀本身就是机器特征） |
| 回复延迟 | 扫到消息后随机等 30 秒 ~ 5 分钟再回，**禁止秒回** |
| 超限处理 | 排队到下一个活跃时段，**不补发、不追平** |

每日动作上限（远低于平台阈值）：

| 动作 | 每日上限 |
| --- | --- |
| 读自己作品的公开数据 | 2 次 |
| 读评论 / 私信 | 6 次 |
| 回复评论 | 10 条 |
| 回复私信 | 20 条 |
| 发布内容 | 3 条 |

### 第 3 层：行为拟人化

- 鼠标：贝塞尔曲线 + 轻微过冲 + 落点在元素内随机（不用 `element.click()` 合成事件）
- 打字：逐字 60~200ms 随机，偶尔打错再退格
- 滚动：惯性滚动 + 偶尔回滚，不瞬间跳到底
- 停留：详情页停留 3~15 秒随机
- 会话：单次会话 2~10 分钟，不是「连点 200 下然后关掉」

### 第 4 层：内容去重与合规（防「营销骚扰」判定）

- **每一条回复由 AI 现场生成**，同一句话 7 天内不得重复出现
- 固定短语（「好的」「收到」）也要 ≥ 20 种变体
- 回复内禁止出现：外链、微信号、手机号、二维码、「加我」「私聊」等引流词
- 发送前过一遍敏感词过滤

### 第 5 层：环境隔离（多账号与商用的前提）

- **一账号 = 一浏览器 profile = 一住宅代理 IP**，三者不交叉
- 同 IP 不承载超过 1 个账号；机房 IP 会被直接标记，必须住宅 IP
- 时区/语言/分辨率与 IP 归属地一致（IP 在美国、时区是北京 = 立刻可疑）
- Canvas/WebGL/字体/硬件并发数按账号固定，不随会话漂移

## 3. 动作风险分级（决定哪些能全自动）

| 动作 | 风险 | 结论 |
| --- | --- | --- |
| 读自己作品的公开数据 | 低 | 全自动 |
| 读自己作品的评论 | 低 | 全自动 |
| 回复自己作品的评论 | 中 | 全自动 + 节律 + 内容变化 |
| 读私信 | 中 | 全自动，低频 |
| 回复私信 | **高** | 全自动，严格限频 + 强内容变化 |
| 主动给非粉丝发私信 | **极高** | **禁止**，必封 |
| 批量点赞 / 关注 / 评论他人 | **极高** | **禁止** |
| 刷量、互赞互粉 | **极高** | **禁止** |

最后三条写入红线清单，**UI 上不提供入口**。

## 4. 必须先解决的矛盾：那条铁律

`server/src/reception-engine.ts` 现在写着：

> 铁律：任何平台业务动作（回复评论/发送私信）都不允许在后端自动执行。

**这条铁律与「全自动」的产品定义直接冲突。** 要实现全自动，必须改它，但改它要有交换条件：

| 放开什么 | 用什么换 |
| --- | --- |
| 后台可自动发送 | 第 0 层熔断必须先生效（没有熔断就不许放开） |
| 自动回复评论/私信 | 第 2 层节律 + 每日上限必须生效 |
| 自动发送 | 第 4 层内容去重必须生效（禁止重复文案） |

改法建议：把「禁止自动发送」改为「**自动发送必须挂载熔断 + 节律 + 去重三个守卫，缺一不可**」。
守卫缺失时自动降级为「生成回复待人工确认」——保证任何情况下都不会裸奔。

## 5. 官方接口优先（长期正路）

- 抖音开放平台具备评论管理、私信管理、视频数据能力（需企业资质 + 应用审核 + 用户 OAuth 授权）
- 小红书专业号开放平台能力较弱，但有内容与数据接口
- 架构建议：把平台适配抽成**可替换的 Provider**——同一套业务逻辑，底层可走「官方 API」或「浏览器自动化」
  - 有资质时切官方接口（风险归零，且合规）
  - 没资质时用自动化兜底
  - **这是唯一能长期活下去的架构**：平台一改版，换 Provider，不动业务逻辑

## 6. 实施顺序（保命 → 降压 → 提效）

| 阶段 | 做什么 | 工期 | 产出 |
| --- | --- | --- | --- |
| P0 | 熔断与健康监测 | 1 天 | 被拦立即停 |
| P0 | 登录态长期复用 + 清理 3521 个会话 | 1 天 | 5.45 GB 归零，登录次数 3521 → 1 |
| P1 | 节律引擎（活跃时段 / 对数正态间隔 / 每日上限 / 回复延迟） | 2 天 | 机器节律消失 |
| P1 | 内容去重（AI 生成 + 7 天查重 + 敏感词） | 1 天 | 无重复文案 |
| P2 | 行为拟人化（鼠标 / 打字 / 滚动 / 停留） | 2 天 | 行为指纹消失 |
| P2 | 环境隔离（profile / IP / 指纹绑定） | 2 天 | 多账号可用 |
| P3 | 平台适配器抽象（为官方 API 留位） | 3 天 | 可切换 |

**P0 两项必须在跑任何真实自动动作之前完成。**

## 7. 验收（怎么证明这套方案真的有效）

| 项 | 判据 |
| --- | --- |
| 灰度范围 | 先只在一个账号上跑 7 天 |
| 观察指标 | 每日动作量、被拦次数、熔断次数、回复成功率 |
| 通过判据 | 7 天内 0 次验证码、0 次限流、回复成功率 > 90% |
| 可定位性 | 任一次被拦，日志能查到「哪个动作、几点、当时频率多少」 |
| 反例验收 | 人为制造一次失败（断网/改错选择器），熔断必须真的触发 |

## 8. 与「全自动」的关系（一句话）

全自动不是「跑得越勤越自动」，是「**在平台察觉不到的前提下把事办完**」。
把 144 轮/天降到 8 轮/天、把 2 条固定模板换成 AI 现场生成、把 3521 次登录降到 1 次——
自动化程度一点没降，被发现的概率降了一到两个数量级。
