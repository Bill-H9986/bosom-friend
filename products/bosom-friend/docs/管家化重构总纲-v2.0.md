## 1 背景与目标

### 1.1 背景

产品此前是「19 个板块的功能软件」：功能按板块切、入口按按钮切、验收按「页面点得对」判。
它的**当下可用性**尚可，但**长期运营会持续变贵**：每加一个平台要改页面执行器，每换一次对话 AI 就失忆，
出了问题只能翻日志猜。

ADR-005 因此把产品形态定为 **AI 管家**：用户说一句话，管家自己调工具把事办完，页面只是可视化。

### 1.2 一句话定调

**把「19 个板块的功能软件」重造为「一个总管 + 四个管家」的 AI 管家系统；旧标准即刻失效，规则按 BFS-100 v2.0 重立。**

### 1.3 本次重构的性质

不是产品改版，是**全项目重构**——以下六类同时动，动任何一类都必须回到本总纲核对范围：

| 类 | 动什么 | 不动什么 |
| --- | --- | --- |
| 规范 | 规则按 BFS-100 重立，旧铁律逐条裁决 | 产品负责人指令台账（只增不改） |
| 规格 | 由「功能点清单」改为「能力台账」 | 已实现的业务逻辑（能复用则复用） |
| 文档 | 逐份裁决：保留 / 重写 / 归档 / 废止 | 知识库条目与 ADR（历史的资产） |
| 代码组织 | 一能力一文件 + preset 组装 | 运行时层（Electron + DSH 内核 + 平台引擎） |
| 验收 | 由「页面点得对」改为「一句话办得成」 | 交付三件套（打包 + 端到端 + 装机） |
| 目录 | 代码与文档按管家形态重新分区 | 用户数据根（`%USERPROFILE%\.bosom-friend`） |

### 1.4 目标（编号化）

| 编号 | 目标 | 判据（怎么算做到） | 对应条款 |
| --- | --- | --- | --- |
| **G1** | 能力长在管家身上 | 关掉页面，49 条写操作逐条可用一句话办成，且三方证据一致 | BFS-101、BFS-102、BFS-104 |
| **G2** | 管家不失忆 | 同一类任务第二次执行的用时或返工率下降 | BFS-107 |
| **G3** | 数据不会越用越乱 | 单写入点 + 事务语义 + 迁移器；测试不写用户数据根 | BFS-201 |
| **G4** | 过程看得见 | 任一时刻能回答「谁在干、干到哪、卡在哪、花了多少」 | BFS-202、BFS-205 |
| **G5** | 失败有人接 | 任一条能力注入失败时，用户看到人话原因 + 三个选择 | BFS-104.4、BFS-205.2 |
| **G6** | 交付可装机 | 陌生人在干净机器上走通主链路，升级前后数据指纹一致 | BFS-109、BFS-204 |

### 1.5 明确不在本次范围

1. **不重写业务实现**：创作、发布、接待的既有业务代码按「复用优先」接进能力层（BFS-102.2）。
2. **不改 DSH 内核官方源码**：内核只作为运行时被使用，产品只在插件与 preset 层扩展。
3. **不做界面美化专项**：页面由「入口」降级为「可视化」，改造以看得见结果为准，不做视觉重构。
4. **不为验证改动去打包**：开发期一律走 Web 端迭代（BFS-109.3）。

## 2 术语

| 术语 | 定义 | 出处 |
| --- | --- | --- |
| **管家** | 由一份 preset（agent.cordis.yml + 技能 + 人设）组装出来的专职 agent | BFS-100 §0.4 |
| **总管** | 不归属任何垂直业务、负责理解与分派的管家 | ADR-005 |
| **四管家** | 创作管家 / 发布管家 / 运营管家 / 设备管家 | ADR-005 |
| **能力** | 一句用户会说的话 + 一个管家可调用的工具 + 一个页面上可见的结果，三者合称一条能力 | BFS-101.1 |
| **工具** | 注册到 DSH 工具运行时的可调用单元 | BFS-100 §0.4 |
| **preset** | 管家组装目录（人设 + 技能 + 工具面） | BFS-100 §0.4 |
| **一句话端到端** | 人话输入 → 管家自行拆解并执行 → 页面可见结果 | BFS-104.1 |
| **管家化率** | 已工具化的写操作数 ÷ 服务端全部写操作数 | 能力台账 v1.0 口径 |
| **发卡** | 工具只登记请求、把执行交给前端页面的旧模式（已废止） | BFS-102.5 |
| **内核握手** | 启动 DSH 内核并完成一次 initialize，证明插件树可加载 | BFS-104.5 |
| **C 档证据** | 一句话在页面上走通（含过程与结果），是唯一算数的完成依据 | BFS-104.2 |
| **三选择** | 失败时给用户：断点继续 / 重新生成 / 放弃 | BFS-104.4 |
| **在制品** | 同一时刻正在推进的工作条目，上限 2 条 | BFS-302.1 |

## 3 运营期痛点 → 根因 → 重构动作 → 判据

### 3.1 总表（本次手术的切除范围）

改的依据不是「架构不漂亮」，而是「**后期运营会脑袋痛**」。九条逐条倒推，每条都给可判定判据：

| # | 运营期会怎么痛 | 根因 | 重构动作 | 判据（怎么算改好了） |
| --- | --- | --- | --- | --- |
| 1 | 每天还得自己点按钮、记步骤 | 能力不长在 AI 身上（管家化率 35%，来源：能力台账 v1.0，2026-10-11） | 49 条写操作全部工具化（一能力一文件 + 工具注册） | 关掉页面，逐条能力用一句话触发，管家调工具办成，三方证据一致 |
| 2 | AI 换个对话就失忆，每次都要重教 | 会话按任务用完即回收；记忆不分层 | 管家长期会话 + 记忆四层（总管 / 管家 / 技能 / 画像） | 同一类任务第二次执行，用时或返工率下降；新会话自动读到上次结论 |
| 3 | 数据会坏、对不上、越用越乱 | 多文件 JSON 各自写、无事务语义、无迁移器 | 数据层重造：单写入点 + 事务语义 + 迁移器 | 任一业务动作失败后无半写状态；结构变更后存量数据可读（BFS-201） |
| 4 | 不知道 AI 在干什么、卡在哪、花了多少 | 只有一段对话流，没有管家视图与用量账本 | 管家团队可视化 + 全链路留痕 + 用量成本看板 | 任一时刻能回答：谁在干、干到哪、卡在哪、这条花了多少（BFS-202.1、BFS-205.1） |
| 5 | 失败了要自己盯着、自己救 | 无统一自愈口，各链路各写一套失败处理 | 统一失败处理：三选择 + 自动续跑 + 升级上报 | 注入断网 / 未登录 / 超时 / 限流四类失败，用户都看到人话原因 + 三个选择 |
| 6 | 想加平台 / 加能力就痛 | 页面写死执行器，路由堆在单个大文件里 | 能力注册制（一能力一文件）+ preset 组装 | 新增一条能力只改能力文件与 preset，不改页面执行器；路由文件不再增长 |
| 7 | 封号、风控、合规风险 | 无体系化风控 | 平台风控体系：拟人化、限频、账号隔离、留痕 | 账号之间登录态与节奏互不串味；每次对外动作可回放；不承诺保证（BFS-203） |
| 8 | 升级要重装、数据怕丢 | 无版本迁移与备份机制 | 版本升级迁移 + 备份 / 恢复 / 换机搬迁 | 升级前后数据指纹一致；一键备份可恢复到可继续使用的状态（BFS-204） |
| 9 | 出了问题查不动 | 门禁服务于「页面点得对」 | 门禁改为「一句话办得成」+ 能力级用例 | 每条能力有可重复、有 PASS/FAIL 的门禁；同问题第二次出现升级为断言（BFS-108） |

### 3.2 逐条展开：判据怎么验、证据在哪

| # | 判据 | 证据从哪取 | 条款 |
| --- | --- | --- | --- |
| 1 | 一句话办成且三方一致 | SSE 工具序列 + 工具返回 + 落库或页面数据 | BFS-104.3 |
| 2 | 第二次更快、返工更少 | 两次执行的用时与返工记录（工作日志） | BFS-107.3 |
| 3 | 无半写状态、迁移可用 | 事务回滚记录 + 迁移器运行输出 + 存量读取结果 | BFS-201.2、201.3 |
| 4 | 四个问题都有答案 | 管家团队视图 + 执行留痕 + 用量账本 | BFS-205.1、202.1 |
| 5 | 四类失败都有三选择 | 失败路径验收记录（AC 编号用例） | BFS-104.4 |
| 6 | 新增能力不改页面 | 新增能力的改动 diff（只含能力文件与 preset） | BFS-102.1 |
| 7 | 隔离与可回放 | 账号隔离验证记录 + 对外动作留痕（谁 / 何时 / 对哪个号 / 结果） | BFS-203.2、203.3 |
| 8 | 数据指纹前后一致 | 装机验收报告（升级前 / 升级后指纹） | BFS-204.4 |
| 9 | 门禁可重复且会红 | 门禁运行输出 + 负向对照记录 | BFS-108.1、108.5 |

### 3.3 反面判据（出现即视为本次重构未落地）

1. 关掉页面后管家办不成事，只能回页面点按钮；
2. 「已经工具化」的结论只有接口返回，没有 C 档证据；
3. 工具返回「已交给前端执行」仍被算作完成；
4. 新增能力靠改页面执行器实现；
5. 失败只有一句「操作失败」，没有原因与三选择。

## 4 目标形态与六层架构

### 4.1 目标形态

| 维度 | 形态 |
| --- | --- |
| 入口 | 一个：一句话（对话主通道） |
| 组织 | 一个总管 + 四个管家（创作 / 发布 / 运营 / 设备） |
| 过程 | 可见：谁在干活、干到哪、卡在哪 |
| 拍板 | 只有四类要用户点头：发布、删除、花钱、对外沟通（评论 / 私信 / 分享） |
| 页面 | 只承担三件事：展示过程、展示结果、接收拍板 |

### 4.2 六层架构

| 层 | 职责 | 来源 | 本次动作 |
| --- | --- | --- | --- |
| ① 运行时层 | Electron 壳 + DSH 内核 + 平台引擎 | 既有 | 保留（不动） |
| ② 能力层 | 一条能力 = 一个工具 + 一份实现（页面与 AI 共用） | 既有业务实现 | 改造（不重写业务） |
| ③ 编排层 | 总管 preset + 四个管家 preset（agent.cordis.yml） | DSH 原生 | 新建 |
| ④ 技能层 | 专业流程写成 Skill（选题 / 文案 / 封面 / 风控 / 复盘） | DSH 原生 | 新建 |
| ⑤ 呈现层 | 对话主入口 + 管家团队 + 看板（旧板块降级） | 旧 19 板块页面 | 重建 |
| ⑥ 记忆层 | 管家长期记忆、画像、经验、知识库 | 部分既有 | 新建 + 分层 |

### 4.3 角色与职责边界

| 角色 | 做什么 | 不得做什么 |
| --- | --- | --- |
| 产品负责人 | 定能力优先级、拍板四类动作、最终否决 | —— |
| AI 实现者 | 定义能力、实现工具、自证与举证、记录、立缺陷 | 让用户代劳验证；无证据宣称完成 |
| 总管 | 理解那句话 → 分派 → 汇总 → 汇报 | 把执行推给页面 |
| 四管家 | 自己拆解、自己调工具、自己完成并回话 | 越权执行四类拍板动作 |
| 页面 | 展示过程、展示结果、接收拍板 | 承担业务执行（发卡模式已废止） |

## 5 施工规则（引用 BFS-100，不另立规则）

本总纲只定**范围、分期与判据**；规则的家在 BFS-100 v2.0。下表是施工时最常引用的条款对照：

| 施工场景 | 依哪条 | 一句话 |
| --- | --- | --- |
| 定义一条新能力 | BFS-101 | 三要素缺一即登记为未完成 |
| 决定开发顺序 | BFS-102.1 | 定义能力 → 注册工具 → 页面呈现，颠倒即按钮软件 |
| 写工具描述 | BFS-102.4 | 必须写「必须调用本工具完成，不要自己直接做」 |
| 工具返回 | BFS-102.5 | 必须真执行并回真实产物 id，禁止发卡 |
| 判某功能做没做完 | BFS-104 | C 档证据 + 三方交叉，缺一不算 |
| 放不放确认弹窗 | BFS-105 | 只有发布 / 删除 / 花钱 / 对外沟通要点头 |
| 写业务规则 | BFS-106 | 写进 Skill，不硬编码进代码 |
| 会话与记忆 | BFS-107 | 管家长期存活，记忆分四层 |
| 加门禁 | BFS-108 | 一能力一门禁，新断言附负向对照 |
| 说「完成」之前 | BFS-109 | 打包 + 端到端 + 装机，三者缺一不得说完成 |
| 数据与成本 | BFS-201、202 | 单写入点 + 事务；每次调用记账 |
| 风控与升级 | BFS-203、204 | 限频隔离可回放；升级带迁移与备份 |
| 可观测与自证 | BFS-205、206 | 不静默失败；AI 自己执行并实时监测 |
| 开工与记录 | BFS-301、303、306 | 三问、三处记录、变更影响三行 |

**冲突处理**：本总纲与 BFS-100 若出现表述不一致，**以 BFS-100 为准**，并当场修正本总纲。

| **P3 技能库 + 记忆分层 + 自动任务** | 关掉页面 AI 仍能办事 | P2 准出 | 第二次执行更快；3 类事自动触发并主动汇报 | 未开始 |
| **P4 交付** | 陌生人在干净机器上走通主链路 | P3 准出 | 打包 + 端到端 + 装机验收三件齐；升级前后数据指纹一致 | 未开始 |

**分期规则**：不跳阶段；上一阶段未取得准出证据，不进入下一阶段（BFS-500 阶段门）。
**并行约束**：同时在制不超过 2 条线（BFS-302.1）。
