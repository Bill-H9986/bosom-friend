## 2. 要求一：什么叫「真正的增删改查」

### 2.1 数据对象清单（23 个 = 21 个 JSON + 2 个目录）

| 类别 | 清单 |
| --- | --- |
| 内容类 | contents、media、material-groups、draft-generations、publish-records |
| 账号类 | accounts、account-groups、sessions、users、platform-login 目录 |
| 智能体类 | agent-tasks、ai-logs、share-tokens |
| 接待类 | reception-rules、reception-pending、reception-seen、reception-status |
| 数据类 | metrics、knowledge、notifications |
| 设置类 | llm-user、prefs、security、feedback.jsonl |
| 文件类 | uploads 目录 |

### 2.2 五个动作 × 三个时点（115 项判据）

| 动作 | 立刻 | 刷新后 | **重启后** | 附加要求 |
| --- | --- | --- | --- | --- |
| **增** | 列表出现 | 还在 | 还在 | 不重复、不丢字段 |
| **改** | 值变化 | 是新值 | 是新值 | 不被并发写覆盖回去 |
| **删** | 消失 | **不复活** | **不复活** | **关联数据一并清理**（不产生孤儿） |
| **查** | 数值正确 | 一致 | 一致 | 与平台真实值一致，或如实标注未采集 |
| **失败** | 中文原因 | — | — | **禁止静默、禁止假成功** |

23 × 5 = **115 项判据**，每项都验「立刻 / 刷新 / 重启」三个时点。

### 2.3 设置板块为例（说明为什么必须纳入）

| 子项 | 真正的增删改查要求 |
| --- | --- |
| AI 模型服务 | 增加服务 → 列表出现；编辑 → 生效；删除 → 消失；**切换激活 → 重启后仍是它** |
| 偏好设置 | 改一项 → 刷新是新值 → **重启是新值** |
| 数据安全卡 | 显示的 ACL / 备份数 / 完整性状态**必须是真实探测结果**，不是写死的文案 |
| 版本信息 | 安装包 / 页面 / 服务 / 注册表**四处同源**（已有门禁校验） |

## 3. 要求二：什么叫「数据绝对真实」

### R1 单一事实源
一个值只存一处。页面不缓存第二份，不许用「页面一份、文件一份、平台一份」互相解释。
**违反判定**：同一个值在两处存储，或前端持有可写副本。

### R2 写后回读
任何写操作写完后**立刻重新读一遍**。目标状态未达成 → **抛错**。
**禁止返回成功。** 这条直接消灭假成功——「删不掉但提示成功」就是它。

### R3 无源不显示
页面上**任何数字**必须能追溯到一条采集记录（来源 + 时间）。追溯不到的显示「**未采集**」。
**禁止用 0 占位。** 「没有数据」和「数据是 0」是两件事，混同即为不真实。

### R4 失败即呈现
平台没给、网络断了、权限不够 → 如实显示原因。**禁止用模板 / 示例 / 旧缓存冒充结果。**

> 四条合起来：**要么是真的，要么明确说没有——结构上无法造假。**

## 5. 大厂打法（只列本项目会用到的）

| 实践 | 本项目怎么用 |
| --- | --- |
| **走通骨架** | 先把「横切机制」（数据服务层 + 三补丁）在项目数据板块跑通，再对接其余板块 |
| **小批量** | 一次一个板块，不做大爆炸式重写 |
| **快速反馈** | 每接入一个板块，立刻跑该板块的 5 动作 × 3 时点 |
| **可回退** | 每板块迁移前留 JSON 快照，按板块回滚 |
| **停止线（Andon Cord）** | 发现假成功立即停线，不带着假数据继续 |
| **在制品上限 ≤ 2** | 单人团队，同时最多两条线 |
| **渐进式交付** | 3 个用户 → 10 个 → 全部 |
| **DORA 口径改造** | 衡量标准是「给到用户」；12 天 74 个版本，给到用户 0 次 |

## 6. 今天交付什么

### 关键判断：今天要建的是「横切机制」，不是一个板块

因为机制建一次、**全部 19 个板块受益**；而板块接入只是接线。
所以今天的产出不是「草稿箱修好了」，是「**一套所有板块都必须遵守的数据规则 + 让它能被自动拦截**」。
