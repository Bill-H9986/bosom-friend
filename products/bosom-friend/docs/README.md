# 开发文档总目

> **总目只有一个作用：让你（或一个 AI 智能体）在三十秒内知道该读哪一份。**
> 结构按「对象地图」组织——每类文档是一个对象，带**是什么 / 什么时候看 / 权威性**。
> **新增文档必须在本表登记所在目录**；目录与文件不一致会被 qa/verify-docs-index.mjs 判红。
> **文档怎么写才算合格**：见 规范/文档编写标准-v1.0.md（BFS-400：三级分类 + 各级必备结构）。
> **最后更新**：2026-10-11（《文档裁决表 v2.0》九件重写件全部收尾：风控实施细则与管家 preset 与 Skills 规格已生效，旧件均标注替代关系）。

## 对象地图

| 目录 | 是什么 | 什么时候看 | 权威性 |
| --- | --- | --- | --- |
| `.` | 本目录根：总纲 v2.0、能力台账、文档裁决表 v2.0、开发报告 v2.0、结构说明 v2.0 | 想了解「产品现在长什么样、下一步做什么」 | **能力台账＝能力状态的唯一事实源**；开发报告 v2.0＝六层架构与落点 |
| `规范/` | 标准体系、验收标准、文档标准、工程化流程、缺陷控制、小白版、平台风控实施细则、需求台账 | 决定「按什么规矩做」之前 | **规则与流程的唯一事实源** |
| `adr/` | 架构决策记录（编号终身不变） | 动 DSH 边界、进程结构、数据格式、对外接口之前 | **决策的唯一事实源** |
| `知识库/` | 提炼经验 + 索引 + 常见坑速查表 | 遇到具体问题（打包、发布、配音、降级、成本…） | **经验与坑的唯一事实源** |
| `releases/` | 变更日志、发布就绪清单 v2.0、发布就绪清单-模板 | 出包、逐项核对准出判据 | **发布记录与准出判据的事实源** |
| `reviews/` | 阶段门记录、复盘报告模板 | 阶段收尾 | 模板与记录 |
| `过程档案/` | 工作日志、审计、方案与路线、测试报告、归档 | 想知道「当时发生了什么」 | **过程是历史，不是当前事实** |
| `参考资料/` | 竞品与素材分析 | 做对标时 | 参考，非事实源 |
| `requirements/` | 历史需求盘点（2 篇均已归档） | 溯源「当初为什么做」 | **只作历史**（见文档裁决表 v2.0） |
| `trace/` | 能力追溯矩阵 v2.0（能力 ↔ 工具 ↔ 证据 ↔ 记录） | 追溯某条能力凭什么算做成 | **追溯链的唯一事实源**（RTM 已标注被替代） |
| `协作/` | 管家 preset 与 Skills 规格 v1.0、学习计划 | 需要知道管家怎么组装、怎么分工（职责 / 工具面 / 技能 / 交接） | 规格为现行；旧提示词口径已作废（只作追溯） |

### `过程档案/` 里面

| 子目录 | 是什么 | 一句话 |
| --- | --- | --- |
| `过程档案/工作日志/` | 逐日工作日志 | 流水账：那天做了什么、遇到什么。**不要拿它当当前事实** |
| `过程档案/方案与路线/` | 方案、路线图、执行档案 | 历史方案；**已废止的对标基线在执行档案里，只供追溯** |
| `过程档案/审计/` | 架构审计报告 | 某个时点的体检 |
| `过程档案/测试报告/` | 各轮测试报告 | 某个时点的测试结论 |
| `过程档案/归档/` | 已被现实取代的旧文档 | 只供追溯 |

## 自检

    node products/bosom-friend/qa/verify-docs-index.mjs

它检查三件事：**docs 下每一个 .md 都落在本表登记过的目录里**；**每篇 ADR 都在 adr/README.md 的索引里**；
**每篇 ADR 的状态词是四态之一**（提议 / 已接受 / 已废弃 / 被替代）。新增文档而忘了登记，这里会判红。

    node products/bosom-friend/qa/verify-docs-standard.mjs

结构门禁检查 `docs/规范/` 下每份现行 A 级文档是否具备 BFS-400 的十二项结构（退出码 0 且 exceptions=0）。
