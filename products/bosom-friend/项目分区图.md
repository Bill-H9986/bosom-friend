# 项目分区图（2026-10-12 立）

> **这份文件为什么存在**：2026-10-12 实测——项目共 694,062 行代码，其中**"AI 管家"形态只占 12,106 行（1.7%）**，
> 而"功能软件"形态（前端页面 + 门禁脚本）占 **422,530 行（60.9%）**。
> 结果是：任何新会话一进来，读到的 98% 都是另一个产品的故事，于是被带偏、继续往旧形态上加东西。
> 本图给每个分区**钉死地位与禁止事项**，并由 `qa/verify-zone-discipline.mjs` 当棘轮守住——边界不是靠提醒，是靠判红。

## 一、形态判据（唯一标尺）

> **用户说一句话，管家自己拆解、自己调工具、自己操作电脑与平台把事办完；页面只是过程与结果的可视化。**

来源：ADR-005《产品形态改为「AI 管家」》。配套判据：

- **BFS-104-R 一句话端到端**：验收只认「人话输入 → 管家自己调工具办成 → 页面可见结果」三方交叉。
- **铁律 #3.5（2026-09-01，仍然有效）**：任何功能若只能手动操作、AI 无法代劳，**都视为未完成**。

**判断一个改动该不该做，只问一句**：它让「关掉页面，一句话能不能办成」变强了，还是变弱了？

## 二、器官（必须留，不许重造）

| 分区 | 是什么 | 依据 |
| --- | --- | --- |
| `packages/`、`vendor/`、`python/`、`native/` | **DSH 内核底座**——造管家的机器 | ADR-005「不能动的（手术台与器官）」 |
| `engine/` | **平台引擎**——10 家平台的真实自动化（护城河所在） | 同上 |
| `server/` 里的生成与发布链路 | **媒体能力缝** | 同上 |
| `desktop/`、`launcher/`、`installer/` | **打包与装机链路** | 同上 |
| `%USERPROFILE%\.bosom-friend` | **账号与数据**（不在仓库内） | 同上 |

## 三、能力本体（唯一该长大的地方）

| 分区 | 地位 | 允许 | 禁止 |
| --- | --- | --- | --- |
| `kernel/` | **管家能力的本体**（51 个 `bosom_*` 工具） | **加工具**；把服务端写操作逐条工具化 | 把能力写成"只有页面能调"的形式 |
| `bundle/`、`presets/`、`skills/` | 管家组装与技能 | 加技能、修工具面 | 让工具面定义出现第二份事实源 |

**棘轮**：内核工具数**只增不减**。

## 四、旧形态（产品现在靠它运行，但**不许再长大**）

| 分区 | 现状 | 在新形态里只做 | 禁止 |
| --- | --- | --- | --- |
| `project/`（前端，260,373 行） | 19 个板块、7 项一级导航、一堆页面按钮 | **过程与结果的可视化** | **新增"功能入口按钮"**；把只做一半的能力做成页面流程 |
| `server/` 的路由（69,011 行） | 121 条写操作长在路由上 | 业务逻辑与数据 | 新增"只有页面能调、管家调不到"的路由 |
| `qa/` 脚本（162,157 行） | 716 个脚本 =「大号脚本仓库」 | **一能力一门禁** | **一功能一脚本**；把一次性诊断沉淀成常驻脚本 |

**棘轮**：前端行数与 `qa/` 顶层脚本数**只减不增**。

## 五、历史（只读，不得被现行代码引用）

| 分区 | 状态 |
| --- | --- |
| `archive/`、`legacy-archive/` | 已归档，只供追溯 |
| `docs/过程档案/归档/` | 已被现实取代的旧文档 |

| `qa/evidence/` | 历史证据留存 |

**棘轮**：现行 `.mjs`/`.ts` **不得 import 或引用**以上路径。

## 七、这份图怎么被执行

```bash
node products/bosom-friend/qa/verify-zone-discipline.mjs
```

它把上表的**棘轮**变成可判红断言；越界即 FAIL。新增分区必须同时更新本图与基线。
