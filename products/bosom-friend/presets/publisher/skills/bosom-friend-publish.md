# 技能 · 从草稿/素材到平台作品 ID｜归属管家：发布管家

> 发布是**对外且不可撤销**的动作：只有用户在这一句话里明确要求发布，才进入本流程。
> 工具面依据：`presets/publisher/agent.cordis.yml`（`bosom_publish_*` / `bosom_platform_list_accounts` / `bosom_platform_login_status`）。

## 适用场景
- 用户明确要发布：草稿发图文笔记、素材发视频、定时发布，或问「发出去了吗」。
- 不适用：「写一条」「生成一条」「做个脚本」都只是创作请求 → 创作管家；改草稿正文 → 创作管家；数据复盘 → 运营管家。

## 步骤
1. **拍板门禁**：确认用户这一句话里有明确的发布意图与对象（哪一条、哪个号）。缺哪个先问清，不要猜；没有指令就不进流程。
2. **取账号**：`bosom_platform_list_accounts`（`limit`）拿 `accountId` 与登录态；`loginState=invalid` 时用 `bosom_platform_login_status` 复核，并如实说明需要重新登录（登录引导属设备管家），**不要硬发**。
3. **取对象标识**：草稿用 `draftId`、素材用 `materialId`——两者都由创作管家或用户作为交接件交过来（发布管家工具面里没有草稿/素材列表工具，**不要凭标题猜 id**，也不要用「那条」指代）。
4. **提交**：
   - 图文笔记（草稿）：`bosom_publish_draft`——`draftId`、`accountId`、`platform`（如 `douyin`、`xhs`）必填；`publishAt` 立即发布传空串、定时发布传**未来时间**的 ISO 字符串；`title` 只在平台字数上限比草稿严时覆盖。工具会读草稿真实内容：标题为空、既没有图也没有封面时会直接报错。**缺图/封面时不要停下问用户**——这是"能继续办"的情况：按 `bosom-friend-handoff` 把「给这条草稿补封面」转交创作管家（`bosom_steward_dispatch`，role=creator，带上 draftId），补完再回到本流程继续发布；只有"补齐也做不到"（如用户明确说不补）才给三个选择。（2026-10-13 DEF-302：此前口径是"告诉用户并请创作管家补"，实测表现为把选择题抛回用户，一句话办事断在半路。）
   - 素材视频：`bosom_publish_content`——`accountId`、`materialId`、`title`（≤30 字，抖音实际 ≤20）、`body`（给平台观众看的正文，不得出现「请点击去发布」这类对用户说的话）、`topics`（逗号分隔 3~5 个、不带 #）。**位置与内容标注不在参数里**：当前链路上没有这两项，不要对用户承诺。
5. **等回执**：调用成功只代表**已提交给平台引擎**。用 `bosom_publish_list_records`（`accountId`/`platform` 可筛，`limit` 默认 10）看状态与平台作品 ID；记录里没有作品 ID 时，就是「还没确认发出去」的时刻。
6. **回报**：拿到平台作品 ID 才算发布成功；失败时把记录里的失败原因原文转述（工具已去掉日志噪声），**不要自己编原因**。

## 判据
- 提交成功 = 返回发布记录 id，状态是「已提交给平台引擎」——此刻**还没有平台回执**。
- 平台回执 = `bosom_publish_list_records` 该条记录里有作品 ID（状态「已发布成功」）。
- 状态口径：-1 发布失败、0 待发布、1 已发布成功、2 发布中、6 排队中、7 已排期、9 已取消。
- 定时发布：`publishAt` 必须是未来时间（工具会拦过去时间，并把当前时间回给你换算）。
- 标题上限：抖音 ≤20 字（引擎实测口径），草稿侧上限 30 字，两者口径不同。

## 反例
- 「写一条」时就顺手发出去——伪造用户的决定。
- 调用返回成功就对用户说「已发布」——这时只有提交，没有平台回执。
- 记录长期停在「发布中」时改口说成功，或编一个失败原因（例如把「标题 21 字超过上限」说成「封面超时」）。
- 登录态 `invalid` 仍硬发；或改了草稿正文再发（正文归创作管家，发布管家不动内容）。
- 缺图/封面时停下问用户「要不要补图」——用户已经明确要发布，补封面是完成发布的必要步骤：先按交接规程转交创作管家，补完继续发。
- 对用户承诺位置标签或「内容由 AI 生成」标注——这两项不在发布链路的参数里。
