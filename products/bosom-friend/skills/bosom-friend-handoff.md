# 跨管家交接（总管 → 管家、管家 → 管家、失败交接）

> 依据：《管家 preset 与 Skills 规格 v1.0》第 7 节。

## 适用场景
- 总管把用户那句话分派给某个管家；一个管家做完要把产物交给下一个管家；一个任务失败要交接收尾。
- 不适用：单一管家内部的步骤（各管家自己的技能里）。

## 步骤
1. **分派（总管）**：① 识别那句话落在哪个管家（创作 / 发布 / 运营 / 设备）；② 分派时**必须带**：用户原话 + 已识别的对象（账号 / 草稿 / 素材 / 作品）+ 期望的可见结果；③ 汇总各管家回报（做成 / 没做成 / 卡在哪）；④ 对用户给一句人话结论 + 证据（对象字段或页面可见结果）。
2. **移交（管家 → 管家）**：按对象带标识——
   - 创作 → 发布：草稿（含封面）带 `draftId`；素材带 `materialId`。
   - 发布 → 运营：发布结果带平台作品 ID + 发布记录 id。
   - 设备 → 发布 / 运营：可用账号带 `accountId` + 登录态。
3. **移交前先确认前置条件**：草稿是否有图或封面、账号登录态是否正常；不满足就**如实回报**，不要硬试。
4. **拍板（管家 → 用户）**：发布、删除、花钱、对外沟通这四类动作必须先拿到用户当次明确指令；给用户「要做什么、对哪个对象、不可撤销的后果」，并记录用户原话 + 时间 + 动作 + 对象。
5. **失败交接**：自己能重试的失败由发起管家收尾；需要另一个管家才能继续的失败，由**发起管家负责移交并跟踪**；不可控结果（平台限流、封禁）如实告知现象、原因与恢复方式。失败**禁止静默**，也不要出现「两边都以为对方在办」。
6. **失败给三个选择**：断点继续 / 重新生成 / 放弃。
7. **留交接记录**（六字段，缺一不可）：时间（本地时区）、从 → 到、对象（类型 + 标识）、已完成（发起方做完哪几步）、待办（接收方要做什么）、结果（成功带作品 ID / 失败带原因）。

## 判据
- 分派信息齐备：原话 + 对象 + 期望结果三样都在。
- 移交带标识：`draftId` / `materialId` / `accountId` / 平台作品 ID 至少有一个真实 id，且来自工具返回。
- 接收方不改对象的归属属性（发布管家不改草稿正文）。
- 拍板四类动作都有当次用户指令可指。
- 失败有归属：谁收尾、下一步是什么，写清楚。
- 交接记录六字段齐全。

## 反例
- 用「那条」「刚才那个」指代对象——禁止口头指代，必须带标识。
- 把「还没做完」说成「已完成」；把拍板包装成「已自动完成」。
- 跨管家任务两边都不动，用户等到最后谁也没办。
- 发起方没确认前置条件就硬移交（草稿没封面、账号已掉登录）。
- 接管后改了移交对象的归属属性（例如发布管家顺手改了草稿正文）。
