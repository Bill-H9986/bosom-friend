## 0.5 会话纪律（2026-10-10 产品负责人当场指出，违反即返工）

> 原话：「第一个废话太多，总是抓不住重点！第二就是换了新对话和项目会话时间跨度太久了后就像失忆了一样！
> 第三就是你在处理事件和编程过程当中感觉根本没经过思考就开始动手！老是改出很多bug！」

1. **只给结论与证据，不复述过程**：回答先给「成/没成 + 证据 + 下一步」，过程写进工作日志而不是回复里。
2. **同一件事只在同一个会话里连续推进**：指挥 AI 智能体时必须回到**同一个 taskId 的会话**继续对话，
   不开新对话（产品侧：内核会话池按 taskId 缓存，换会话等于让它失忆；会话超过上限会被回收，属产品缺陷）。
3. **改动前先想清三行，再动手**：① 改哪个文件 ② 为什么（根因证据）③ 会影响谁（谁在调用它、会不会成环）；
   改完立即 `tsc` + 定向门禁；**验证只认结构化信号**（接口响应体、落库数据、退出码），
   不认「页面出现了某段文字」这类假阳性（2026-10-10 因此误判过三次，并亲手引入过一次循环依赖 bug）。

## 0.6 产品负责人的硬约束（随本文件自动注入，不需要你去读别的文件）

1. **只能用免费模型**：负责人账户没有额度，一律 `agnes-video-2.5-flash` / `agnes-image-2.5-flash`；
   开跑前必须如实告知免费档的能力边界（`freeTierRpm=1`，长片 18+ 镜会被限流打断）。
2. **未经明确发布指令，绝不自动发布**（DEF-240 事故教训）。
3. **失败必须给用户三个选择**：断点继续 / 重新生成 / 放弃。
4. **交付 = 打包 + 端到端跑通 + 装机验收**，三者缺一不得说「完成」（铁律 #13/#19）。
5. **动手前先复述需求**（改哪个文件 / 根因证据 / 会影响谁），改完立刻 `tsc` + 定向门禁；
   **验证只认结构化信号**（响应体、落库、退出码），不认「页面出现了某段文字」。
6. **不许只凭「页面能渲染 / 构建成功」判断可用**：必须用**陌生人的眼睛**走一遍——只用页面可见文字定位，
   禁止使用 `data-testid` 或源码知识（2026-10-10 教训：我用内部 id 点得通，负责人点不通）。
7. **没有产品负责人的明确命令，不许打包**（2026-10-12 立，**机制强制**）：
   `desktop/rebuild-kernel-and-installer.ps1` 与 `desktop/build-win.sh` **都已加授权闸**——
   没有 `BF_PACKAGE_AUTHORIZED=yes`（或授权文件 `.package-authorized`）就 **exit 3 拒绝启动**；
   负向对照实测：不带授权调用 → `BLOCKED: packaging is NOT authorized.` + exit 3，`release/` 未被创建。
   **为什么**：交付是「**全部做完之后的一次动作**」，不是「时间到了就打一个」。
   打一个不能用的包，浪费的是 773 MB 磁盘、十几分钟，还有产品负责人的信任。
   **原话**：「没有我的命令不准打包！！！！！！！！！！」

> 全量归纳（9 大主题 / 4594 条发言 / 每条原话与现状）见 `docs/规范/需求台账-产品负责人指令.md`。

## 0.7 开发系统，不开发脚本（2026-10-11 立，违反即返工）

> 产品负责人原话：「**我是开发系统！！！！不是开发脚本！！！！你总是这样！所以我累啊！！！！**」

- **遇到问题先问「这该是系统里的哪个能力」，不是「写什么脚本绕过它」**；
- 脚本**只允许**两种用途：**门禁**（可重复、进 `qa/`、有 PASS/FAIL）与**一次性诊断**（查清即删）；
- **UI 操作一律走产品里的 AI 智能体**（内核 Playwright MCP），禁止用 playwright 脚本硬编码选择器点页面；
- **只做进脚本、界面上看不见的能力 = 没做**。判断口诀：这件事用户自己能在界面上完成吗？

**现状（2026-10-12 实测）**：`qa/` 顶层 81 个脚本、`qa/probes` 81 个；一次性探针归档区 `qa/probes-archive/`（289 个）
**已按本条规则删除**（BFS-305.3「查清即删」，归档不是合法处置）。分区棘轮 `qa/verify-zone-discipline.mjs`
会盯着「`qa/` 顶层脚本数只减不增」。

## 1. 三条最常被违反的红线

1. **一句话端到端（BFS-104-R，最高验收口径）**：验收以「人话输入 → 管家自己调工具办成 → 页面可见结果」
   三档证据里的**第三档**为准（工具序列 + 助手回复 + 落库/页面数据三方交叉）。
   **《S 级前端监考 v4》已废止**（见 `docs/规范/管家化标准体系-v2.0.md` 的替代声明与 `qa/README.md`）。
   业务动作仍然**只能走 APP 前端页面**
   （`fill/click/select/refresh`）。禁止用脚本/HTTP 客户端/CLI/子进程直接调后端，
   禁止 `page.request` / `context.request`，禁止直接写 `.bosom-friend` 下的数据文件，
   **禁止绕过前端执行发布或登录**。接口 `code=0`、日志、JSON、worker 成功**都不能单独作为 PASS**。

   **过程可见与三方交叉（2026-10-12 产品负责人当场纠正，违反即返工）**：
   1. **禁止无头浏览器做业务验证**——用户看不到过程，等于过程不存在。
      验证要么在**用户自己的 APP** 里跑，要么在**看得见的窗口**里跑。
   2. **每步留证**：一次操作一张截图（S 级监考时代的"操作后截图铁律"仍然有效），
      能在界面上回放"它到底干了什么"。
   3. **三方交叉，缺一不算过**：**工具返回** + **助手对用户的回复** + **落库/页面数据**。
      **只看落库、或只看接口，都不构成证据**（这是 2026-10-12 我犯的错：
      仅凭发布记录就宣称端到端成功，而过程用户一眼没看见）。
   4. **验证由执行者自己跑并实时监测**（BFS-104-R 第 1.2 节原话），不是跑完看结果。
2. **铁律 #13：没有端到端证据不许说「完成」**。改后端必须重建（`dev-web.ps1` 已内置构建）；
   「构建成功 / 页面能渲染」不是功能可用的证据；同一问题第二次出现必须升级成门禁断言。
3. **铁律 #17：实时记录，不等提醒**。每完成一个节点当场写三处：① 工作日志 ② 缺陷台账 ③ 知识库（Obsidian）；
   **没有实时记录的完成 = 未完成**。

## 2. 固定动作

- 启动开发版：`powershell -ExecutionPolicy Bypass -File products\bosom-friend\launcher\scripts\dev-web.ps1`
  （改前端加 `-Frontend`；端口 31280）。**禁止为验证改动去打包**（铁律 #12）。
- 验收前先跑门禁：`node products\bosom-friend\qa\qa-all.mjs`；
  **系统级验收**：`node products\bosom-friend\qa\verify-before-package.mjs`（三层：静态 + 陌生人之眼 + 一句话端到端）。
  **《S 级前端监考》体系已废止并已删除**（`qa/acceptance/` 303 个文件于 2026-10-12 整个删除；
  其中仍在用的 `verify-abort-timing-matrix.mjs` 已搬到 `qa/` 顶层），不要再按它判红绿。
- 改 vendored 引擎（`engine/social-auto-upload`）必须把补丁与原因记进 `engine/VENDORED.md`。
- **每个节点完成 / 每次发现 / 每个决策 → 当场更新活记忆，然后跑同步**：
  `node products\bosom-friend\qa\memory-sync.mjs`（把活记忆的当前状态单向同步进 DSH 全局注入层，新会话自动读到）。
  **活记忆是源**：`C:\Users\Jay\Documents\Obsidian Vault\00-工作记忆（随时更新·新会话必读）.md`（改它，不要手改全局层）。
  **为什么**：2026-10-10 产品负责人质问「你怎么保证新开会话一定会去读」——让新会话「去读」依赖自觉，
  只有内容进入自动注入层才是 100%；两处手写必然漂移，所以由脚本单向生成。

## 4. 产品结构与运行数据

- **三大核心 + 公共底座**：A 内容创作 / B 账号管理 / C AI 智能体 / D 公共底座（编号见功能清单）。
