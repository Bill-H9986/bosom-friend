# 融合创作验证报告：数字人口播 + 文生视频 B-roll（2026-09-20）

> 用户提出的方向：口播长视频走「数字人 + 文生视频」融合。本报告是这条方向的**端到端实测**。
> 口径：真实产品页面操作 + 真实厂商出片；接口与日志只用于归因与规格核对。

## 一、结论：方向成立，画面这次对上了

| 项 | 结果 |
| --- | --- |

| 分镜 | **19 / 19 全部 ready**，用时 49 分 21 秒 |
| 稿件 | 537 字（配音 81.8 秒 / 目标 90 秒） |
| 镜头构成 | **8 个口播镜 + 7 个产品镜 + 3 个空镜**（非口播镜占 11/19 = 58%） |
| 画面 | ✅ 抽帧见：产品镜 = 无人机实训教室（工位、笔记本、电路板、多旋翼）；空镜 = 维修台拆装特写 |

对照上一轮（同一题材、同一目标时长，只有代码不同）：**19/19 全是口播镜**，成片里没有任何设备与场地。
这一轮同一题材的画面里出现了**成排工位、整机、电机、电调、螺丝刀、拆开的机臂**——
题材终于进了画面。

## 二、我做了什么（融合创作的三处改动）

1. **分镜提示词新增硬要求**（`buildStoryboardPrompt` 的 `allowBrollWithoutProduct`）：
   至少 N 个非口播镜，且要求 product/scene 镜**按这段口播讲的东西**写具体画面（设备、工位、操作、场地）；
2. **产品侧兜底不信模型自觉**（`ensureBrollShots`）：模型排出"全是口播镜"时，
   从后往前把每第 3 个口播镜改写成场景空镜，画面按"题材 + 这一句在讲什么"生成；
   **只改 kind/visual/references，不动 line**——台词与配音顺序原样，母时钟与字幕不受影响；
3. **确定性兜底分镜同样支持**（`fallbackShotPlan` 增加 `subject` 参数）：没有产品图但有题材时插空镜，
   既没有产品图也没有题材才退回纯口播。

## 三、厂商能力前置侦察（`qa/probes/vendor-broll-recon.mjs`）

在改产品之前先单独问厂商一句：**给它一段无人机工位的描述，它画不画得出来**：

| 提示词 | 结果 |
| --- | --- |
| 无人机维修实训工位（多旋翼 + 维修台 + 螺丝刀 + 培训教室） | ✅ 3/3 成功，720x1280 / 8 秒 |
| 无人机拆装特写（双手拆机臂、电机电调露出、浅景深） | ✅ 画面是真实的拆装特写 |
| 无人机培训教室全景（成排工位 + 学员操作） | ✅ 画面是教室全景 |

这条侦察的价值：**在写产品代码之前就知道"文生视频能出题材画面"**，避免又白改一轮。

## 四、如实记录的三点

1. **厂商会在画面里画品牌文字**：侦察片里出现了臆造的机身标识与桌垫上的乱码字符。
   产品侧的提示词写了"不出现任何文字与品牌标识"，仍不能保证；建议下一步加一道**产物文字复检**
   （抽帧 + 视觉检查），命中就重跑这一镜。
2. **时长仍偏短**：目标 90 秒、成片 78.77 秒（-12.5%），仍是未决的 DEF-113 口径问题。
3. **这是"机制验证"，不是"题材验收"**：画面里的设备是厂商按题材生成的通用无人机，
   不是某家培训机构真实的那台设备。要"真的"，仍需方案 B（素材位：用户上传实拍片段）。
