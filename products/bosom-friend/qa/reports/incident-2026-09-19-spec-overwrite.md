## 第二次（2026-09-20 03:40，同一个错误又犯了一次）

给 `long-video.spec.ts` 追加 DEF-117 用例时，我又用了"read 取全文 + 拼接 + write 整份写回"，
文件从 1300+ 行缩到 798 行——**同一个坑第二次踩**。已再次从 `git show HEAD:<path>` 恢复（1135 行）。

两次的教训合并成一条硬规则：**这个文件只用 `edit` 改，永不用 `write` 重写**；
即使 read 返回的是"看起来完整"的内容也一样——分页读只保证给你看，不保证给你全文。

恢复后该文件仍是 HEAD 版本（早于当前代码），跑起来有一批"夹具过期"的红灯；本轮的修复没有进这个文件，
DEF-117 的回归用例放在**没被破坏的** `server/test/functional/storyboard.spec.ts`（32 passed）。

## 教训（写进流程，不是写进注释）

1. **不要用"分页读到的片段"整份写回**：`read(offset)` 只返回那一段，写回就等于用片段覆盖全文。
   追加内容只能用 `edit`（锚点替换），或先 `read` 全文再写。
2. 恢复前先看 `git status`：文件干净 = HEAD 即原文，恢复是安全的；文件脏 = 恢复会丢掉未提交改动，必须先找副本。
3. `pwsh -Command "cmd > file"` 里原生命令的重定向可能拿到空流；要落盘用 Git Bash 或 `Set-Content`。
