# 要求二 R3「无源不显示」修复与验证

- 日期：2026-09-12
- 版本：0.2.41
- 提交：`94b4a35`（写入/渲染侧）、`475be4c`（源头与指标行）
- 结论：**通过**。互动指标未采集时不再用 0 冒充，链路四层全部修通。

## 一、问题

平台没返回的计数在四个地方被补成 0，界面无法区分「真的是 0」和「根本没采到」，
于是向用户展示了一个编造的数字。真实数据里已经能看到证据：
`shareCount: 65` 的作品同时写着 `viewCount: 0`——65 次分享不可能 0 播放。

## 二、四个伪造点与修法

| 层 | 位置 | 原写法 | 修法 |
| --- | --- | --- | --- |
| 采集 | `engine/worker.py` 抖音 normalizer | `int(stats.get("play_count") or 0)` | 抖音创作者中心 `item/list` 对播放量一律回 0 占位，该 0 不携带信息，按未采集处理；非 0 才是真值 |
| 采集 | `engine/worker.py` 小红书 normalizer | `int(interact.get("view_count") or 0)` | 平台没返回的计数整键缺省；小红书明确给的 0 是平台声明，保留 |
| 落库 | `server/platform-sync.ts` `upsertRecord` | 新建记录写死 7 个 0 | 只写平台真的给了的字段，本次没给的清掉旧值 |
| 落库 | `server/platform-sync.ts` `upsertMetrics` | `Number(work.viewCount ?? 0)` | 同上，指标行不留陈旧数字 |
| 类型 | `publish.types.ts` / `channel.types.ts` | 7 个字段必填 `number` | 改为可选，缺省即未采集 |
| 渲染 | `RecordCore.tsx` | `activeEngagement[k] ?? 0` | 缺省显示「未采集」（6 语言同步补 `notCollected` 键） |
| 渲染 | `PublishDetailCard` | 隐式窄化 | 显式 `typeof x === 'number'` 收窄，未采集项不显示 |

## 四、遗留与边界

1. **历史数据不可自动区分**。修复前写入的 0 与真实的 0 无法分辨，本次不重写用户数据；
   重新同步一次即可用真实值覆盖（写入路径已改为整对象替换）。本次验证就是这样清干净的。
2. **抖音播放量**：创作者中心 `item/list` 不提供真实播放量，界面永远显示「未采集」。
   要拿到真值需要接入单作品分析接口，属未完成项。
3. 其余未接通平台（TikTok / YouTube / bilibili / 支付宝 / 百家号 / 虎扑 / 微博 / 闲鱼）
   在界面上不给连接入口，不伪造任何数据。
