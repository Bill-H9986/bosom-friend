# Bosom Friend 商用上架准出准则 v1.0

> 本文件是「能不能发布」的唯一判定依据。机器判据看本文件，人工逐项判据看 [RELEASE_GATE.md](RELEASE_GATE.md)（30 条硬验收 + 14 问真人剧本）。
> 定位：把「保证所有功能都能正常用」拆成可执行的硬门槛；做不到的项必须写「做不到」，不得以「能点开」代替「能用」。

## 0. 一条命令判定

```bat
:: 连续 3 次门禁全绿且零黄灯（应用须处于运行态）
node products/bosom-friend/qa/run-gate-triple.mjs --full
```

退出码 0 = 达到机器门槛；退出码 1 = 禁止发布。单次绿灯不作为发布依据——历史故障中同一条门禁脚本 25 分钟后重跑由红转绿，一次绿灯可能是运气。

## 2. 缺陷分级（R5 用语）

| 级别 | 定义 | 准出要求 |
| --- | --- | --- |
| P0 | 核心链路不可用、数据丢失、越权、假成功（未成功却显示成功） | 必须 0 |
| P1 | 功能不可用但有替代路径、阻断操作、明显性能劣化 | 必须 0 |
| P2 | 体验、文案、样式 | 允许 ≤ 10，逐条写明规避方案 |

「假成功」单列为 P0：平台拒绝、风控、断网时界面显示成功，比失败本身更严重。

## 3. 出厂验收（干净机 12 步，必须真机真装）

干净机 = 没装过本产品、没装 Node/pnpm 的 Windows（虚拟机或新建系统账户）。

| # | 步骤 | 通过判据 |
| --- | --- | --- |
| 1 | 双击 Setup.exe | 安装无报错，无需用户自备运行环境 |
| 2 | 看桌面 | 出现品牌图标（非默认 Electron 图标） |
| 3 | 双击图标 | ≤3s 出窗口；启动页只有 LOGO + 正在启动 + 版本号，无「握手/进程/地基」字样 |
| 4 | 等启动完成 | ≤10s 进首页；无命令行窗口、不弹外部浏览器 |
| 5 | 点侧栏 7 项 | 每项有内容，非空白非报错 |
| 6 | 再双击一次图标 | 单实例：只出一个窗口 |
| 7 | 点 X | 窗口消失，进程与内核仍在，托盘图标出现 |
| 8 | 托盘单击 / 右键完全退出 | 单击恢复窗口；完全退出后任务管理器无 Node/Python/Chrome/平台 worker 残留 |
| 9 | 控制面板卸载 | 目录干净、无残留进程、数据保留策略与说明一致 |
| 10 | 旧版装好数据 → 覆盖装新版 | 数据与平台登录态都在（升级不丢数据） |
| 11 | 断网启动 | 不崩溃；需要网络的功能如实提示，不假装成功 |
| 12 | 125% / 150% 缩放 + 双屏 | 界面不破版、不遮挡关键按钮 |

证据命名：`qa/evidence/release/<版本>/释放-NN-说明.png`。任一步不通过 = 整版不发。

## 4. 六层测试（每层跑什么）

| 层 | 覆盖 | 入口 |
| --- | --- | --- |
| L1 静态与追溯 | 版本单源、依赖边界、RTM 覆盖率、缺陷闭环、回滚网、数据编码完整性 | `run-gate.mjs`（快速门禁） |
| L2 服务端功能 | 路由契约、统计口径、批量删除语义、上传票据 | `server` 的 vitest（门禁内自动跑） |
| L3 业务回归 | 三大核心域 CRUD、模型配置链路、知识库蒸馏、智能体任务动作、中断时序矩阵、指标诚实化 | `smoke-all.mjs`、`crud-matrix.mjs`、`verify-*.mjs` |
| L4 专业 E2E | 内容创作 / AI 智能体 / 全局监控 的 CRUD 与不变量 | `qa/e2e`（Playwright） |
| L5 S 级前端验收 | 由前端发起、后端处理、返回前端可见的完整链路 | `qa/acceptance/frontend-supreme-gate.mjs` |
| L6 真实链路 | 真账号、真网络、真发布、真回传 ID、真客服回复 | 人工执行，进 R7 |

接口冒烟、后端白盒、SSE 与持久化审计只能作为基础设施诊断，不能代替 L5/L6 的产品级结论。

## 5. 不通过怎么办

1. 冻结「见一个修一个」，跑一轮门槛，产出《确定缺陷清单》（编号 + 现象 + 证据）。
2. 批量修复一次，出一版，全量回归；最多两轮。
3. 两轮后仍红：连同截图与日志交决策，不发布、不声称完成。

门禁出现假红或假绿时：先修断言，并用负向对照证明「改回旧写法能判红」，不得直接改结论。

## 6. 诚实边界（写在这里，避免被忽略）

- **平台风控不可控**：小红书封禁、抖音 H5 用户确认通道属第三方行为，只能如实告知与降级，不能承诺「必成功」。
- **未实现的功能必须从 UI 移除或明示「未开放」**：AC-009（发布回传真实 ID）、AC-017（每步截图入会话）、AC-018（全对话自动化）、AC-021（多账号矩阵）当前未实现，禁止以「能点」代替「能用」。
- **本准则不保证零缺陷**，它保证的是：功能有清单、清单有证据、门禁不撒谎、安装包在干净机跑通、真实链路真跑通一次、出事能小时级修。
