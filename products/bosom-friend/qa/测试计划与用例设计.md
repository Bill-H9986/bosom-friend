# 桌面应用测试计划与用例设计（0.2.0）

> 依据：ISTQB 黑盒测试技术（EP/BVA/状态迁移/判定表）、testdevlab 桌面应用测试指南、Playwright 官方最佳实践。
> 原则：先手后自动；只测用户可见行为；每一步页面证据；测试与开发/判分角色分离。

## 1. 测试层级

| 层级 | 内容 | 工具 |
| --- | --- | --- |
| L1 单元 | 存储/队列/执行器/工具参数纯逻辑 | node 断言 |
| L2 集成 | 内核+适配器+业务服务的进程级联调 | SDK 客户端 |
| L3 系统 | 桌面窗口内功能、UI、安装/升级/卸载、兼容、性能 | Playwright(Electron) |
| L4 验收 | 真人视角 S 级：页面发起→后端→页面可见 | 监考脚本+人工抽查 |

## 2. 桌面特有测试类型（优先级排序）

1. 安装/升级/卸载：全新安装、旧版升级保数据、卸载无残留文件/注册表/进程；
2. 功能回归：登录、创作、草稿、发布、接待、数据中心核心链路；
3. UI：窗口/弹窗/菜单可见、可点、可缩放、无错位；
4. 兼容：分辨率、DPI 缩放、非管理员账户；
5. 性能：冷启动时间、长时运行内存；
6. 异常：断网、无模型、失败重试、重启恢复。

## 3. 用例设计技术落到本产品

### 判定表（条件组合）

AI 三态：未配置模型 / 已配置且可用 / 已配置但失败，输出必须分别为固定提示、真实回复、如实报错，禁止任何回退冒充成功。

### 状态迁移

发布任务：queued→running→success/failed/cancelled；生成任务：generating→success/partial/failed。每条合法迁移至少一个用例，非法迁移一个用例。

### 等价类 + 边界值

标题长度、话题数量、生成数量、上传大小：各取有效类代表值、无效类代表值、以及边界值（0、最小值、最大值、最大值+1）。

### 场景法

普通人旅程：双击→首页→登录→一句话创作→草稿可见→删除后消失→发布记录→数据中心一致→关闭重开数据在。

## 4. 自动化规范（Playwright）

- 定位器优先 getByRole/getByText，镜像用户视角；
- 用 web-first 断言（自动重试），禁止 waitForTimeout 和一次性 textContent 判读；
- 每个用例独立上下文，无共享状态；
- 只 mock 第三方服务，不 mock 自家应用；
- 失败保留 trace、截图、页面错误清单。

## 5. 入口 / 出口准则

- 入口：构建产物可安装、测试环境隔离、需求有验收条件；
- 出口：L1/L2 全绿、L3 核心场景全绿、无 P0/P1、S 级页面证据齐备、发布清单签字。

## 6. 环境矩阵

- 当前机（非管理员）：主验证环境；
- Windows 沙盒（开启后）：真·干净机复验；
- 分辨率 100%/125%/150% DPI、断网模拟、不同数据根。

## 7. 追溯

每个用例标注 REQ/AC 编号，结果写入 RTM 与缺陷台账；测试结论只认页面证据。
