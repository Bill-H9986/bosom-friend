## 1 背景与目标

### 1.1 背景

旧《测试计划与用例设计（0.2.0）》的分层思路（先想清楚在哪一层测）与自动化纪律（web-first 断言、独立上下文）
至今仍然有效，它的问题只在**判据**：

| 旧口径 | 为什么必须换 |
| --- | --- |
| 用例 = 页面操作步骤 + 页面证据 | 页面出现一段文字可能是历史消息，不能证明业务对象变了（假阳性第 2 条） |
| 追溯挂 REQ 编号 | REQ 口径已被「能力」取代（BFS-500 第 6 节） |
| 出口准则 = S 级页面证据齐备 | S 级前端监考已废止，出口改为「一句话走通 + 三方交叉」 |
| 用例只走成功路径 | 只验成功路径的用例**视为未完成**（BFS-104-R 第 5 节） |

**本版的定位**：回答「用例怎么写、在哪一层写、写完留什么证据、什么时候升级成门禁」。

### 1.2 目标（编号化）

| 编号 | 目标 | 判据 |
| --- | --- | --- |
| **G1** | 每个用例都是可复现的一句话 | 用例含四行（那句话 / 归属 / 预期可见结果 / 失败预期），缺一行不成立 |
| **G2** | 证据只认 C 档 | 用例记录里三方交叉齐全，A / B 档只作诊断 |
| **G3** | 失败路径必测 | 每条能力的用例集里至少一条失败路径用例 |
| **G4** | 可升级为门禁 | 同问题第二次出现时，用例能原地升级为有 PASS/FAIL 的门禁断言 |

## 2 术语

| 术语 | 定义 | 出处 |
| --- | --- | --- |
| **验收单元** | 一次一句话端到端的完整记录（四行构成） | BFS-104-R 第 2.1 节 |
| **AC 编号** | 用例编号，格式 `AC-<能力编号>-<序号>`，一经使用不得回收 | BFS-104-R 第 2.2 节 |
| **C 档证据** | 一句话在页面上走通的证据（唯一算数的完成依据） | BFS-104-R 第 3.1 节 |
| **三方交叉** | 工具返回 / 助手回复 / 落库或页面数据三者一致 | BFS-104-R 第 3.2 节 |
| **内核握手** | 启动内核并完成一次 initialize，证明插件树可加载 | BFS-104-R 第 6 节 |
| **发卡** | 工具只登记请求、把执行交给前端的旧模式（已废止） | BFS-102.5 |
| **假阳性** | 看起来通过、实际没办成的判定 | BFS-104-R 第 7 节 |
| **门禁化** | 把一次性用例升级为可重复执行、有 PASS/FAIL 的检查 | BFS-104-R 第 8 节 |

## 3 测试分层（在哪一层测什么）

| 层 | 测什么 | 工具与入口 | 能否作为完成依据 |
| --- | --- | --- | --- |
| L1 静态 | 类型检查、依赖边界、版本单源、文档与索引门禁 | `qa/run-gate.mjs`、`qa/verify-docs-index.mjs`、`qa/verify-docs-standard.mjs` | **不能**（A 档） |
| L2 单元与契约 | 存储、队列、参数校验、路由契约 | `server/test/functional/`（vitest） | **不能**（A 档） |
| L3 集成 | 内核 + 服务端 + 数据层的进程级联调 | 门禁脚本（`qa/verify-*.mjs`） | **只能作诊断**（B 档） |
| L4 一句话端到端 | 用户说那句话 → 管家调工具 → 页面可见结果 | 对话主通道（读 SSE）+ 页面观察 | **唯一依据**（C 档） |
| L5 装机验收 | 干净机安装 / 升级 / 卸载 / 装回 + 数据指纹 | 见 [发布就绪清单 v2.0](../docs/releases/发布就绪清单-v2.0.md) | C 档（交付级闭环） |

**分层纪律**：低层绿了不等于高层过；高层判红时**先到低层定位**，但结论只在 L4/L5 出。

## 4 用例设计

### 4.1 一个用例的四行（缺一行不成立）

1. **那句话**：用户会说的原话（人话，不是菜单路径、不是参数表）；
2. **归属**：哪个管家、主链路的哪一环；
3. **预期可见结果**：用户在页面上看到什么（对象、字段、变化）；
4. **失败预期**：不可用时用户看到什么（人话原因 + 三个选择）。

### 4.2 编号与登记

| 项 | 规则 |
| --- | --- |
| 编号 | `AC-<能力编号>-<序号>`，例如 `AC-A2-08-1` |
| 回收 | **禁止**回收已用过的编号 |
| 登记 | 用例进 [能力追溯矩阵 v2.0](../docs/trace/能力追溯矩阵-v2.0.md) 的「证据」一栏 |
| 归属 | 每条用例必须挂到一条能力上；挂不上的用例说明它不该存在 |

### 4.3 四类设计技术落到本产品

| 技术 | 用在哪 | 例子 |
| --- | --- | --- |
| **判定表** | 模型三态：未配置 / 已配置且可用 / 已配置但失败 | 三态各自输出固定提示、真实回复、如实报错；**禁止**任何回退冒充成功 |
| **状态迁移** | 发布任务（排队 → 执行 → 成功 / 失败 / 取消）、生成任务（生成中 → 成功 / 部分 / 失败） | 每条合法迁移至少一个用例；非法迁移一个用例（例如终态不得翻转） |
| **等价类 + 边界值** | 标题长度、话题数量、生成数量、上传大小 | 各取有效类代表值、无效类代表值、边界值（0 / 最小 / 最大 / 最大 + 1） |
| **场景法** | 陌生人旅程 | 见 [陌生人验收剧本](陌生人验收剧本.md)：账号 → 内容 → 出片 → 发布 → 数据 |

### 4.4 失败路径用例（必测）

每条能力**必须**验以下至少一类失败，并确认页面给出**人话原因 + 三个选择**（断点继续 / 重新生成 / 放弃）：

| 失败类型 | 注入方式 | 通过判据 |
| --- | --- | --- |
| 模型不可用 | 移开模型配置或断网 | 固定提示 + 三选择，不假装成功 |
| 账号未登录 | 使用未授权账号 | 可读原因 + 引导登录，不静默失败 |
| 素材缺失 | 引用不存在的素材 | 明确指出缺什么 + 三选择 |
| 超时 | 注入超时 | 保留已完成部分 + 三选择 |
| 限流 | 免费档连续调用 | 如实说明限流与预计等待，不判死整条 |

### 4.5 用例不可复现时的处置

| 情形 | 处置 |
| --- | --- |
| 步骤依赖内部 id / 选择器 | 改为**只用页面可见文字**定位（见陌生人验收剧本的禁用清单） |
| 结果依赖执行顺序 | 拆成独立用例，各自准备前置数据 |
| 同一问题第二次出现 | **必须**升级为门禁断言，并附负向对照（BFS-108.3、108.5） |

## 5 自动化规范

| # | 规范 | 理由 |
| --- | --- | --- |
| 1 | 业务动作**必须**由管家执行；脚本只允许门禁与一次性诊断（BFS-305.2） | 脚本绕过管家 = 没测产品 |
| 2 | 页面定位只用**页面可见文字**；**禁止** `data-testid` 与源码内部 id | 2026-10-10 教训：内部 id 点得通，用户点不通 |
| 3 | 断言用 web-first（自动重试）；**禁止** `waitForTimeout` 与一次性 `textContent` 判读 | 假红与假绿都源于时序猜测 |
| 4 | 每个用例独立上下文，无共享状态 | 用例之间不得互相污染 |
| 5 | 只 mock 第三方服务，**不 mock** 自家应用 | 自家应用被 mock 后测的是 mock |
| 6 | 失败保留现场：截图、页面错误清单、工具序列 | 没有现场就无法定位根因 |
| 7 | 新增门禁断言**必须**附负向对照 | 不会红的门禁等于没有门禁 |

## 6 入口准则与出口准则

| 准则 | 内容 |
| --- | --- |
| **入口** | 能力已在能力台账登记四行；测试环境隔离（不写用户数据根）；模型与账号条件明确 |
| **出口** | ① 目标能力的用例全部有 C 档证据；② 失败路径走过；③ 内核握手已验证；④ 三方交叉一致；⑤ 缺陷已登记；⑥ 结果写入三处记录 |

**未达成时的处置**：出口任一项未满足，该能力状态不得标记为完成（BFS-101.2、BFS-104.2）。

## 7 测试环境

| 环境 | 用途 | 注意 |
| --- | --- | --- |
| 本机开发态（Web 端） | 日常迭代与 L4 验收 | 端口与数据根按开发脚本默认；**禁止**为验证改动打包（BFS-109.3） |
| 隔离数据根实例 | 需要破坏性操作时 | 结束后比对回滚（BFS-201.4） |
| 干净机（虚拟机或新建系统账户） | L5 装机验收 | 无 Node / pnpm / 本产品历史 |
| 缩放与分辨率（100% / 125% / 150%） | 界面可用性 | 断网与限流模拟同轮执行 |

## 8 判据与验收（本件自身）

| # | 判据 | 怎么验 |
| --- | --- | --- |
| V1 | 用例四行齐全 | 随机抽 3 条用例，四行缺一即本件失实 |
| V2 | 无假阳性口径 | 全文不出现「页面出现某段文字即通过」这类判据 |
| V3 | 失败路径覆盖 | 随机抽 1 条能力，其用例集中含失败路径 |
| V4 | 可升级为门禁 | 抽 1 条已复现缺陷，能说出它的门禁断言写在哪 |
| V5 | 引用有效 | 本件引用的脚本与文档在磁盘上存在 |

## 附录 A · 用例模板

    【编号】AC-XXX-1
    【那句话】「……」
    【归属】创作管家 / 主链路第 2 环
    【预期可见结果】草稿箱出现 1 条，标题与主题相关
    【失败预期】模型不可用时：人话原因 + 断点继续 / 重新生成 / 放弃
    【证据】工具序列 / 工具返回 / 助手回复 / 落库字段
    【结论】PASS 或 FAIL
    【异常】缺陷编号（若有）
