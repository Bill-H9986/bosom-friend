# DEF-073：厂商视频只收 720P，我们把用户档位直接当 size 发——第 1 镜就被拒

> 编号：DEF-073（唯一、终身不变）
> 状态：Fixed
> 严重度：P1　　优先级：高（用户可见、长视频必然失败）
> 缺陷类型：集成（厂商参数契约）
> 关联需求：REQ-022（长视频创作）
> 报告人 / 日期 / 环境版本：2026-09-16 真机全流程实测发现 / 0.2.52 装机版
> 责任人 / 计划版本：Jay / 0.2.53
> 重开次数：0

## 复现步骤

1. 长视频档位选 **1080p**（库里就有这一档），填主题点生成；
2. 稿件与配音都正常完成（18 镜、96 段、每镜 4~6 秒）；
3. 第 1 镜走厂商视频生成，失败：「第 1 镜生成失败：厂商未返回可用成片」。

## 期望结果 vs 实际结果

- 期望：厂商按用户档位出片；不支持时如实说明到底支持什么。
- 实际：厂商 400 拒收，界面只说"厂商未返回可用成片"，看不出是参数问题还是额度问题。

## 证据（厂商原始响应）

```
POST https://api.agnes-ai.cn/v1/videos   size="1080x1920"
HTTP 400 {"code":"invalid_request","message":"size 必须是 720P 之一",
          "data":{"param":"size","valid_sizes":["720P"]}}
```

## 根因分析（5-Why）

- 直接原因：`generateAiVideoDirect` 把用户档位（`1080p`）大写后直接当厂商 `size` 发出，
  而该字段是**枚举白名单**，厂商只认 `720P`。
- 为什么 1：分辨率在这条链路上被当成"厂商出片像素"用，而实际成品分辨率是**合成阶段**
  决定的（`video-compose` 会把每一镜缩放到目标画布）——两件事被混成一个字段。
- 为什么 2：厂商用业务错误体（HTTP 400 + `data.valid_sizes`）表达参数不合法，
  而底层只判 `resp.ok`，body 从未被读；于是"该退到哪一档"这条信息在代码里根本不可见。
- 为什么 3：同一条链路上还存在**必填 `mode`** 等同类枚举字段，说明厂商参数契约没有一次性对齐，
  是逐个撞出来的（`mode` 已在更早一轮撞出并补上，`size` 这一条漏了）。
- 根本原因归类：**厂商参数契约按猜测实现、按 HTTP 状态判成败**，忽略厂商在错误体里自报的合法取值。

## 修复方案（改根因）

1. **读厂商自报能力**：`supportedSizesOf()` 从 400 响应体里取 `data.valid_sizes`，
   读不到（网关 HTML、空体）时返回空数组，调用方保留原失败，不把失败掩盖成成功；
2. **降档只降一次**：`createWithSizeFallback()` 先用用户档位下单，被以参数不合法拒收时，
   按自报列表降到最接近用户档位的那一档重下一次；`bestSizeFor()` 是纯函数（按像素高度比较，
   不超过目标的最高档；全高于目标时取最低档，仍然出片而不是判死）；
3. **分辨率分两段**：厂商侧按它真实支持的档位下单，成品侧仍由合成阶段统一到用户档位
   （选 1080p 的成片就是 1080x1920）。这不是静默降级：成片分辨率与用户选择一致；
4. 失败日志带上厂商状态与自报档位，下一次同类问题不必再靠手工复现才知道原因。
