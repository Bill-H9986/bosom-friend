# DEF-064：长视频"语速太慢、讲解内容太少"——稿件按目标秒数要求，模型写不出那么长

> 关联需求：长视频创作

> 责任人 / 计划版本：Jay / 待定

## 复现步骤（别人照着能复现）

1. 打开「长视频创作」，选「数字人口播」，目标时长选 60 秒，填一句产品与卖点，点「开始生成」；
2. 稿件很快写完，成片里配音语速明显偏慢、一顿一顿，整条片子翻来覆去就那两三句卖点。

## 期望结果 vs 实际结果

- 期望：60 秒的片子有 60 秒的内容量，语速正常。
- 实际：稿子只写了十来秒的量，配音被拉长去填满段长，听起来就是"念得很慢、没讲什么"。

## 影响范围与发生频率

所有长视频任务，目标时长越长越明显（写稿提示词里从来只有"约 N 秒"这一个尺度）。

## 根因分析（5-Why，没写完禁止修复）

- 直接原因：写稿提示词只给"约 N 秒"，模型按自己的感觉写，通常**远短于**目标；配音时长由字数决定，字数不够只能拖长音。
- 为什么 1：编排层相信"写上目标秒数就等于拿到目标长度"，没有对结果做任何长度校验。
- 为什么 2：长度这个量与模型的沟通单位是**字数**（"不少于 135 字"是可执行要求），秒数不是；把秒数直接丢给模型等于没下要求。
- 为什么 3：`estimateSeconds` 只在切段时用来判断"够不够 4~12 秒"，从没人拿它去比对"实际折算时长 vs 目标时长"。
- 根本原因归类：**缺一个"目标 → 可执行要求 → 结果校验"的闭环**：目标时长没有翻译成字数下限，写完之后也没有任何一步检查是否达标。

## 修复方案（改根因，不是压表现）

1. 把目标翻译成可执行要求：`minScriptChars(目标秒数) = 目标 × CHARS_PER_SECOND`，并生成长度要求（字数下限、不许分点、不许留白）并入写稿提示词；
2. 写完做长度校准：实际字数不足目标折算字数时，用"上一稿只有 N 字、请扩写到不少于 M 字"再补写**一次**（不循环重试；仍不足就如实生成，不拿重试冒充成功）；
3. 稿件字数与正文落盘（`scriptChars` / `scriptText`），生成记录与进度面板都能看到"这条片实际讲了多少内容"；
4. `scriptBrief` 增加段数参数：写稿前就把"全片约 N 个镜头"告诉模型，内容要撑满整段时长而不是一句话收尾。

## 回归用例（必须写，验证修复且不破坏旧功能）

`server/test/functional/long-video.spec.ts`：

- 目标 12 秒 → 段数 1、字数下限 54；目标 30 秒 → 3 段 / 135 字；目标 120 秒 → 10 段；估算秒数与"字数 ÷ 语速"必须一致（同一把尺子）；
- 写短的稿子**必须触发一次补写**，且补写提示词里带上"上一稿只有 N 字"；写够的稿子**不得**多跑一次模型；
- 稿件真实字数落盘（`scriptChars` 等于最终稿长度）。
