# DEF-175 场景种草里的"人物自然走过"不是选定的形象：参考图只带产品图

| 项 | 值 |
| --- | --- |
| 编号 | DEF-175 |
| 发现日期 | 2026-09-24 |
| 发现方式 | 排查「为什么只有数字人口播能选数字人」时顺出来的：`sceneProducer` 不认识数字人 |
| 严重级 | P2（画面里的人不受控：每一镜可能换一张脸，而产品页把它写成"人物自然走过"，用户会以为是自己的形象） |
| 状态 | Open（改法见下，列 0.2.62） |

## 现象与根因

"场景种草"这一形式走的是 `sceneProducer(productImageUrl, SCENE_SEEDING_FORM)`：

- `planShots` 只把**产品图**放进镜头参考图集（`productRefs`），不像 `digitalHumanProducer` 那样挂 `{ role: 'person' }`；
- `produce()` 也只把产品参考图发给厂商（`shot.references.filter(item => item.role === 'product')`）。

所以"人物自然走过"里的那个人是**厂商按文字自由发挥**出来的：跨镜不是同一个人，也不是用户在形象库里选的那位。
内容形式的清单里因此把它的 `needsHuman` 如实标成 `false`（别让用户以为选了就生效），
同时登记本缺陷。

## 改法（未实施，列 0.2.62）

1. `sceneProducer` 增加数字人参数：分镜提示词与镜头参考图集里挂 `{ url: human.avatarUrl, role: 'person' }`，
   `produce()` 把 person 参考图一起发给厂商（厂商按参考图约束画面里的人）；
2. "场景种草"这一形式改成 `needsHuman: true`，前端自然就会渲染选择器（前端已经按 `needsHuman` 渲染）；
3. 验收：同一题材跑两镜，与"跨镜不换人"用同一套取证（成片首帧 + 判官记录），
   并在报告里写明判官当前的局限（见 DEF-174）。
