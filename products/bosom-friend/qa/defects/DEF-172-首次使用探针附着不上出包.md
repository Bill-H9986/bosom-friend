# DEF-172 安装版首次使用探针附着不上出包：fuse 焊死了检查器入口，AC-021-3 的证据停在 0.2.42

| 项 | 值 |
| --- | --- |
| 编号 | DEF-172 |
| 发现日期 | 2026-09-23 |
| 发现方式 | 0.2.61 装机验收：`qa/probes/verify-installed-first-run.mjs` 连续两次 `TimeoutError: Timeout 90000ms exceeded`（`app.firstWindow({ timeout: 90_000 })`） |
| 严重级 | P2（探针缺陷，产品没坏；但 AC-021-3"逐页走查"的证据因此停在 0.2.42 而无人察觉——探针跑不起来时，它守的那条准则就没有证据） |
| 状态 | Fixed（2026-09-24：探针改成 spawn 出包 + Chromium（channel=chrome）驱动产品页，装机态实测 **4/4 PASS**） |

## 现象

```
node products/bosom-friend/qa/probes/verify-installed-first-run.mjs
→ TimeoutError: Timeout 90000ms exceeded.
  at _ProgressController.run (.../playwright-core/lib/coreBundle.js)
```

**产品没坏**——同一时刻手动起同一份出包（`.dsh-build/manual-launch-check.ps1`，端口 31297）：

| 时刻 | 进程数 | 窗口 | 产品页 |
| --- | --- | --- | --- |
| 启动后 5 秒 | 4 | `34352:Bosom Friend` | HTTP 200 |

装好的应用照样起来、有窗口、页面能开；起不来的是**探针的附着方式**。

## 根因

探针用 Playwright 的 `_electron.launch()` 附着 Electron 主进程，而它靠给主进程加 `--inspect` 连检查器。
出包侧的 fuse 把这个入口焊死了（`desktop/electron-builder.yml`，两处声明一致，由 `verify-electron-logging.mjs` 盯着）：

```yaml
electronFuses:
  runAsNode: false
  enableNodeOptionsEnvironmentVariable: false
  enableNodeCliInspectArguments: false   # ← 忽略 --inspect 等调试开关
  enableCookieEncryption: true
```

fuse 本身是**有意的安全收缩**（产品里存着平台登录态，攻击面越小越好），不能为了探针开回去。
两者从 fuse 落地那一版起就不可能同时成立——而探针不在门禁里，所以它坏了没人知道：
AC-021-3 那一行引用的仍然是 0.2.42 的证据。

## 处置（2026-09-24 已实施）

把探针换成与安装版 AI 业务验收（`verify-installed-ai-business.mjs`）**同一种附着方式**：
spawn 出包 exe（自带端口）→ 等产品页 200 → 用 Playwright 的 Chromium 驱动 `http://127.0.0.1:<port>/bosom-friend/`，
逐页抓文本、截图、看 404。这条路不碰 Electron 检查器，与 fuse 不冲突，而且验的还是"用户能看见什么"。

**已实施并实测**（`node qa/probes/verify-installed-first-run.mjs`，0.2.61 装机态）：

```
安装版已就绪：http://127.0.0.1:31295/bosom-friend/
PASS 七页里至少六页渲染出内容 | 6/7
PASS 页面文本不含内部路径/命令行/堆栈 | 未发现技术词
PASS 静态资源无 404 | 0 个 404
PASS 未签名提示如实记录（SmartScreen） | …
INSTALLED_FIRST_RUN PASS checks=4 fail=0
```

浏览器通道与 `qa/e2e/playwright.config.ts` 一致（`channel: 'chrome'`），不碰 Electron 检查器，
因此与出包 fuse 不再冲突；AC-021-3 的证据从 0.2.42 刷新到 0.2.61。
