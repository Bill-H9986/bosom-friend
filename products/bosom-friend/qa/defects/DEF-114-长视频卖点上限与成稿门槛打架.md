# DEF-114 长视频「卖点」上限 200 字，而成稿门槛 369 字起：三态提示的「已够」永远到不了

| 项 | 值 |
| --- | --- |
| 编号 | DEF-114 |
| 发现日期 | 2026-09-19 |
| 发现方式 | 长视频字数门槛三态提示复测（真实页面逐态做出来） |
| 严重级 | P3（不阻断出片；但它让「补够字数」这条路在界面上走不通） |
| 状态 | Open（需要产品拍板：抬上限，还是改口径） |

## 现象（实测证据）

长视频页把卖点输入框填到**上限 200 字**后，提示仍是「不足」：

| 态 | 页面可见文本 | 结论 |
| --- | --- | --- |
| 空 | 还没填卖点：这条片要 369 字成稿（4.1 字/秒 × 90 秒），空着不会开始 | ✅ 可达 |
| 不足 | 卖点 64 字 → 这条片要 369 字成稿；差的字由后端自动补写，补不够就停在这一步、不花厂商额度（琥珀色） | ✅ 可达 |
| 已够 | （做不出来）填到 200 字时提示仍是「卖点 200 字 → 这条片要 369 字成稿」 | ❌ **不可达** |

证据：`qa/evidence/long-video-hint-2026-09-19/`（三张截图 + `REPORT.json` 的三态文本与 class），
探针 `qa/probes/long-video-hint-states.mjs`（只读参数、不下单）。

## 根因

三处上限互相打架：

| 层 | 上限 | 位置 |
| --- | --- | --- |
| 前端输入框 | 200 字 | `LongVideoPage.tsx` 的 `<Textarea maxLength={200}>` |
| 服务端建任务 | 200 字（超出直接截断，不报错） | `server/src/api.ts` 的 `topic.trim().slice(0, 200)` |
| 提示口径 | 90 秒档 369 字 / 120 秒档 492 字 / 300 秒档 1230 字 | `minScriptChars(targetSeconds, charsPerSecond)` |

`briefCharsHint` 的「已够」分支要求卖点字数 ≥ 成稿门槛，而门槛最小的 90 秒档就是 369 字 > 200 字，
所以这一态对**任何**长视频档位都不可能出现——它现在是死分支，用户按提示一路补到上限也补不动。

## 影响

1. 用户看到「差的字由后端自动补写」，自然会想去补；补到 200 字打字框就不动了，提示还在说差 169 字；
2. 后端那条 200 字截断是**静默**的：粘贴一份 400 字的卖点，只有前 200 字进任务，用户不知道；
3. 验收侧：这一态过去被写成「待补测」，实际是「做不出来」，如果不逐态做出来就会一直挂在那里。

## 建议修法（未实施，二选一）

1. **抬上限**（推荐）：卖点本质是稿子的原料，写长是好事。前端 `maxLength` 与两处服务端口径一起抬到
   覆盖最大档位（300 秒档 1230 字，取 1500），并把服务端的静默截断改成如实拒绝（超长要说出来）；
2. **改口径**：承认这个框是「卖点摘要」而不是稿子，把「已够」这一态改成按摘要长度给建议
   （例如「卖点已写 200 字，够后端扩写」），并把三态提示的措辞与之一致。
