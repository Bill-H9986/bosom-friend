## 根因（两处，都是「界面列出的档位」与「解析用的档位表」不是同一份）

### 根因一：拼装档位（30/60）被当成非法档位回退成默认档

`utils/helpers.ts` 的 `getResolvedVideoModelDuration` 只查 `getVideoModelDurationOptions`（pricing 或 `model.durations`）；
30/60 秒不在那张表里——官方单次只收 4~12 秒，这两档由多个 4 秒片段拼成，只声明在模型的 `longDurations` 上，
于是走到「不在档位表里就回退默认档」这支，返回 `model.defaults.duration = 5`。

选择器用 `getEnabledVideoDurations`（原生 durations **+** longDurations）列档位，解析却只查 durations：
用户点得动、界面也显示得住，**下单时被换回默认档 5 秒**。

### 根因二：收敛时没带档位表，于是「什么都留不住」

`useAiBatchGenerateBarController.ts` 的 `handleDurationChange` 调用 `sanitizeVideoDuration(d)` 时**没传档位表**；
该函数在没有 durations 时可用档位只剩默认档一个（`enabledVideoDurationOptions(undefined) === [15]`），
于是 4/6/8/10 秒一律被改成 15，紧接着被模型上限（12 秒）夹一次 → 全部落到 **12 秒**。

## 修法（已实施）

| 文件 | 改动 |
| --- | --- |
| `utils/helpers.ts` | `getResolvedVideoModelDuration` 放行模型声明的拼装档位（`model.longDurations`），与 `sanitizeVideoDuration` 早就写明的口径对齐 |
| `hooks/useAiBatchGenerateBarController.ts` | `handleDurationChange` 改用 `sanitizeVideoDuration(d, getEnabledVideoDurations(selectedVideoModelInfos))`——收敛依据与选择器列出的档位同源 |
| `hooks/useAiBatchCreditState.ts` + `utils/helpers.ts` | 素材时长一个都没读出来时返回 `null`（「还不知道」），不再用 0 冒充有效档位；新增纯函数 `sumInputVideoDuration` |
| `ToolBarInline/components/DurationSelect/index.tsx` + 中英文案 | 只读药丸显示**真正会提交的那个时长**，提示写明「本条按素材合计 N 秒生成，档位选择对这条不生效」 |
