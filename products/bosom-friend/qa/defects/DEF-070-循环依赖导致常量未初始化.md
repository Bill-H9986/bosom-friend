# DEF-070：storyboard 与 long-video 循环依赖，导致常量未初始化、镜头时长被算成 null

> 编号：DEF-070（唯一、终身不变）
> 状态：Fixed
> 严重度：P2　　优先级：高（编译期完全看不出来，只在运行时炸）
> 缺陷类型：设计（模块依赖方向）
> 关联需求：REQ-022（长视频创作）
> 报告人 / 日期 / 环境版本：2026-09-16 本机测试暴露 / 0.2.51
> 责任人 / 计划版本：Jay / 待定
> 重开次数：0（同族第 2 次：上一轮也出现过一次跨模块常量未初始化）

## 复现步骤

1. `storyboard.ts` 与 `long-video.ts` 互相 import（分镜层要用编排层的语速常量，编排层要用分镜层的兜底函数）；
2. 跑任何一条走分镜解析的用例（如 `long-video.spec.ts` 的母时钟两条）；
3. 产品镜的目标时长变成 `null`，落到厂商请求时成了 4 秒兜底。

## 期望结果 vs 实际结果

- 期望：分镜解析把 `seconds: 5` 原样保留。
- 实际：`toSeconds()` 里 `SHOT_MIN_SECONDS` 是 `undefined`，
  `Math.max(undefined, 5)` 得到 `NaN`，序列化成 `null`。
  **TypeScript 编译通过**（类型上常量是 `number`），只有跑起来才暴露。

## 根因分析（5-Why）

- 直接原因：ESM 循环依赖下，某个加载顺序会让一方拿到另一方**尚未初始化的绑定**。
- 为什么 1：分镜层需要语速/切段这类**语言基本量**，而它们被放在了 `long-video.ts`（编排层）里——层次放错了。
- 为什么 2：编排层又需要分镜层的兜底函数，于是两层互相依赖，方向不单向。
- 为什么 3：这类问题在编译期、类型检查、lint 里**没有任何信号**，只有执行到那一行才炸，症状还是 `null` 而不是报错，极难定位。
- 根本原因归类：**模块依赖方向没有约束**——语言单位与编排单位混在同一层。

## 修复方案

抽出叶子模块 `server/src/speech.ts`：语速（`CHARS_PER_SECOND`）、4~12 秒边界（`SEGMENT_MIN/MAX_SECONDS`）、
文本清理（`normalizeSpokenText`）、估时（`estimateSeconds`）、字数下限（`minScriptChars`）、切段（`splitScript`）。
依赖方向变成单向：`speech.ts` ← `storyboard.ts` ← `long-video.ts`。
long-video 对外仍重导出这些名字，调用方契约不变。

模块 JSDoc 写明判据：**往 speech.ts 加东西前先问这是"一句中文怎么念、怎么切"，还是"一条片怎么编排"**——后者不该放。

## 回归用例

`long-video.spec.ts` 的母时钟两条：断言产品镜时长保持 5（不被算成 null）、口播镜回填真实配音秒数；
另有 `storyboard.spec.ts` 16 条钉住 4~6 秒的夹紧行为——循环依赖一恢复，这些断言会立刻变红。
