# DEF-108 长视频的稿件字数门槛没有前置提示，用户被拒两次才明白

| 项 | 值 |
| --- | --- |
| 编号 | DEF-108 |
| 发现日期 | 2026-09-18 |
| 发现方式 | 长视频 300 秒档真实跑：两次失败，第三次靠把材料从 458 字补到 794 字才通过 |
| 严重级 | P2（体验/参数：不花钱，但要用户猜两次才知道门槛） |
| 状态 | **已修复（0.2.58）** |
| 修复版本 | 0.2.58 |

## 现象

300 秒档的成片要 1350 字口播稿（300 秒 × 4.5 字/秒），而界面上**任何地方都没有这个数字**：

- 目标时长按钮只写「5 分钟」；
- 起任务前只有「几镜、约多久」的预估，没有字数；
- 失败文案 `稿件只有 N 字，不足 300 秒所需的 1350 字；请把卖点写细一些，或把目标时长降到约 N 秒` 只在**提交之后**出现。

于是用户的路径是：填一段自认为够详细的卖点 → 等写稿 + 三轮补写（几分钟）→ 被拒 → 再加内容 → 再等 → 再被拒。
实测：材料 458 字时两次被拒，补到 794 字后同档位一次通过。

## 根因

1. 字数门槛只在**任务内部**计算（`minScriptChars(targetSeconds, charsPerSecond)`），从不进入任何给前端的响应；
2. 起任务前的预估 `estimateLongVideo` 只有镜数与耗时，没有字数；
3. 被判「稿件太短」时，最长的一稿**不落盘**（`scriptText` 只在生成成功时才写），所以界面连「写了多少字」都显示不出来，
   更没有可执行的一步——只能整条重来。

## 修复方案（0.2.58 已实施）

### 1. 门槛前置到界面

- 新增 `GET long-videos/script-requirement?producer&producerRef&targetSeconds`：按所选音色的**实测语速**折算这条片要多少字；
  由服务端算而不是前端估——各音色语速差 53%（2.98~4.55 字/秒），前端猜一个数就会与真正的门槛对不上。
- 长视频页在「目标时长」下方实时显示：`这条片要 1350 字口播稿（4.1 字/秒 × 300 秒，约 60 镜）；不够时后端会自动补写 3 轮，仍不够就停在这一步、不花厂商额度`。
- 起任务与断点续跑的预估对象 `LongVideoEstimate` 一并带上 `requiredChars / charsPerSecond / writerPaceCharsPerSecond`。

### 2. 失败时给出字数与可执行的一步

- 稿件不达标时把**最长的一稿与字数落盘**（`scriptText` / `scriptChars`），并打上分类码 `errorCode='script-too-short'`；
  每轮补写拿到更长的一稿也立即落盘，进程被杀不会把已经花钱补出来的字丢掉。
- 界面据此显示「当前稿件 N 字，目标 300 秒」，并给两个按钮：
  - **补写稿件**：`POST long-videos/:taskId/extend-script` 按现有稿件再补写一轮（复用与任务内部同一个提示词构造与语速折算），
    只扩写、不出片，用户看清内容再决定；补后仍不够就如实报「还差多少字」。
  - **按现有稿件继续生成**：走 `resume`，按已定稿的稿件排分镜并逐镜生成，**不会把用户刚补的字重写一遍**。

### 3. 编排层支持「从存稿继续」

`resumeBlockedReason` 原先要求「有分镜表」，从存稿继续这条路被挡住；现在稿件已定稿、只是还没排分镜的任务也允许继续。
`runLongVideoJob` 里的稿件准备抽成 `calibrateScript`：有存稿就采信（只校验长度），没有存稿才写稿 + 三轮补写。
