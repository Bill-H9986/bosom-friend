# 2026-09-18 零运行日志 / 内核无自愈 / 生成任务无限停滞（DEF-101 / DEF-102 / DEF-103）

> 起因：现场（WIN-20251030LYJ，Administrator）内容创作时一直弹「网络连接失败，请检查网络后重试」，
> 卡片显示「生成失败」，App 自带的 AI 助手被要求「查工作日志」也答不出来。
> 采集回来的证据里没有任何日志——这条线索把三个缺陷串在了一起。

## 2. 根因

1. **装机版没有任何运行日志（DEF-101）**。装机 app.asar 里逐串搜索：appendFile / electron-log / GLOBAL_LOG_GET_FLIES 全部不命中；
   旧 Electron 工程（project/bosom-friend-electron）里那套 electron-log 属于**另一条不进包的代码路径**（只有它的 dist/ 前端产物进包）。
   内核侧更隐蔽：**stdout 是 SDK 的 JSON-RPC 独占通道**（写日志会被对端静默丢弃，还会污染协议），
   而 server 里 39 处业务 console.log 恰好写在这里；stderr 只进 SDK 客户端的内存环（最近 400 行），
   只有内核死掉那一刻才随错误消息被主进程看到。"没有日志"不会报错，所以这件事没有任何检查项能发现。
2. **内核死后没有任何检测、自愈与出口**：主进程只在启动时判断一次（isProductServing），
   起来之后内核再死就无人知晓——界面不崩、只是持续报错，用户既看不到原因也没有恢复入口。
3. **生成任务可以无限停在 generating（DEF-102）**：收尾只有启动时的 generationRecovery 一条路；
   运行中没有任何基于时间的兜底，媒体步骤 attachGenerationMedia 整段没有总预算。
   现场那条 38 分钟的记录正是"服务活着、某个 await 永不返回"的形态。
4. **前端把三类失败混成一句、且零落盘（DEF-103）**：连接被拒（内核已停）、超时（后端卡住）、
   非 JSON（网关错误页）三种处置方式完全不同，却共用「网络连接失败，请检查网络后重试」。
   用户因此去查自己的网络，而真正停掉的是本地内核。

## 3. 修法

| 落点 | 内容 |
| --- | --- |
| desktop/electron/run-log.cjs（新） | 按天写 userData\logs\YYYY-MM-DD.log：10MB 滚动、保留 7 天、单行 4000 字符、写入前遮蔽 sk-/Bearer、任何失败静默降级 |
| desktop/electron/main.cjs | 建档并接管 console（在任何会输出的模块之前）；写启动事实；内核启动/握手/退出/失败全部留痕；**抄渲染进程 console**（前端失败因此可查）；把 BF_LOG_DIR 传给内核 |
| main.cjs 内核自愈 | 每 10 秒探活产品服务，连续 3 次失败判掉线 → 通知界面 → 自动重启一次（5 分钟冷却）；IPC bosom-kernel:restart / bosom-log:path / bosom-log:open |
| desktop/electron/kernel-host.cjs | 通知流结束且非主动 close 时上报 onExit —— 内核消失的那一刻立即落盘（错误消息自带 SDK 保留的 stderr 尾部） |
| desktop/electron/preload.cjs | 暴露 restart / onHealth / bosomLog（path、openFolder） |
| server/src/runtime-log.ts（新） | 产品侧运行日志：**只接管 stderr、绝不碰 stdout**，按天写 kernel-YYYY-MM-DD.log，同一套滚动/遮蔽/降级策略 |
| server/src/api.ts | apply() 最前面装载运行日志；媒体步骤加 60 秒心跳 + **绝对截止时间**（图文 8 分钟 / 视频 15 分钟）；运行中停滞看门狗每 60 秒扫描一次；看门狗定时器随插件卸载清理 |
| server/src/generation-watchdog.ts（新） | 纯函数：停滞预算（图文 10 / 视频 20 分钟）、媒体预算（8 / 15 分钟，**必须小于停滞预算**）、判定边界、失败文案（区分"文案已保留"与"请重新生成"）、就地标记且保留 response 与 points |
| 前端 utils/request/client.ts | 失败分类（unreachable / timeout / bad-response / unknown）→ 分别落盘与提示；六语言文案齐备 |
| 前端 components/KernelHealthBanner（新） | 顶部红条如实说明「本地服务（内核）已停止：现在的网络连接失败就是它引起的」+ 重启内核 + 打开日志目录 |
