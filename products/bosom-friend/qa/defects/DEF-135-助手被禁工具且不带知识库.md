# DEF-135 助手被禁止用工具、也不带知识库：提示词自相矛盾，回答只能靠模型记忆

| 项 | 值 |
| --- | --- |
| 编号 | DEF-135 |
| 发现日期 | 2026-09-22 |
| 发现方式 | 读助手链路的提示词组装 → 与 `agent-rules.ts` 的要求逐条对照 |
| 严重级 | P1（"整个 APP 围绕 context 运转"的正面缺口：助手看不到产品事实，也查不了） |
| 状态 | Fixed（2026-09-22：助手放开只读工具、注入知识库上下文并计入蒸馏账本） |

## 现象与根因

助手对话链路（`POST agent/tasks` 的 SSE 分支）组装提示词时是：

```
TEXT_ONLY_GUARD + AGENT_OPERATING_RULES + knowledgeBlock('') + 对话稿
```

两条问题都在这一行里：

1. **`TEXT_ONLY_GUARD` 明写"不要调用任何工具"**，而 `AGENT_OPERATING_RULES` 第四条要求
   "先查后答：涉及'有多少、状态如何'的问题，先用只读工具查，再回答，不凭记忆编"。
   两条要求互相矛盾，模型只能二选一——实测它有时照样调工具（10:27 的会话里确实有 `tool/call`），
   有时凭记忆答（`task-4cd08f20` 那条"能帮你做三类事"全是从系统提示里抄的自我描述）。
   内核工具是真的在跑，但产品把通道掐了。
2. **`knowledgeBlock` 传的是空串**：助手对话根本没有注入内置知识库，
   而同一份代码的非流式路径（`/ai/chat`）传了 `chatKnowledge.block`。同一个"助手"两副口径。

## 修复（2026-09-22）

1. `streamLlmWithDeltas` 增加 `allowTools` 开关：纯文本生成（写稿/分镜/翻译/接待回复）保持禁工具
   （那是 DEF-072 的教训：让模型去调工具会让请求白等），**助手对话放开**（`allowTools=true`）。
2. 助手对话注入 `buildKnowledgeContext` 的命中块（与生成、非流式对话共用同一条检索链路）。
3. 助手这一轮也写进蒸馏账本（`recordDistillation`，带命中的知识条目与状态）——
   自进化的原料必须来自每一次真实任务，而不是只有生成那几条。

## 回归判据

| 判据 | 用例 |
| --- | --- |
| 工具调用照常到达界面与任务记录（放开禁工具后不退化） | `agent-process-steps.spec.ts` |
| 纯文本生成仍然禁工具 | `long-video.spec.ts` / `api-contract.spec.ts`（同一 `streamLlmWithDeltas`，默认 `allowTools=false`） |
| 知识库命中与蒸馏入账 | `agent-process-steps.spec.ts` + `knowledge-distill` 相关用例 |

**未验证的部分（如实标注）**：放开工具后助手在真实模型下的耗时与稳定性，本轮只做了真实调用观察（下方证据），
没有做成可重复的门禁——它依赖厂商网关的时延，放进门禁会变成不稳定红灯。
