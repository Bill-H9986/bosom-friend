# DEF-068：图像端点 image 字段返回 200 却静默忽略参考图（图生图不可用）

> 编号：DEF-068（唯一、终身不变）
> 状态：Fixed（产品侧修法：不依赖该能力，一致性改走视频侧参考图）
> 严重度：P1　　优先级：高（会直接毁掉"画面一致性"整条设计）
> 缺陷类型：环境集成 / 设计（对厂商能力的假设未验证）
> 关联需求：REQ-022（长视频创作）
> 报告人 / 日期 / 环境版本：2026-09-16 探针实测 / 0.2.51
> 责任人 / 计划版本：Jay / 待定
> 重开次数：0

## 复现步骤

1. 用 agnes-image-2.1-flash 生成一张参考图（例如白瓶印 NOTHING + 一串紫色圆点 + 编号 4821）；
2. 再请求同端点，带上 image: <参考图URL>，提示词写"保持这个产品的外观、颜色、标签文字与数字完全不变，放到浴室台面上"。

## 期望结果 vs 实际结果

- 期望：输出保留参考图里的瓶型、NOTHING、7 个圆点与 4821（这才是图生图）。
- 实际：返回 200 成功，但输出是另一支泵头玻璃瓶，标签是臆造乱码（ALTLONE / MUSKIRY CADEE / Torsiinattin Sodi Pretrarg）——参考图完全没有参与生成。同样手法用于人物改机位时，输出是另一个人。

## 影响范围与发生频率

100% 复现。凡是依赖"图生图"的设计（关键帧链式、产品锚点、锁脸）全部不成立。

## 根因分析（5-Why）

- 直接原因：端点在收到 image 字段后返回 200，但生成过程没有使用该图（响应域名从 cos-platform-outputs.agnes-ai.cn 变成 platform-outputs.agnes-ai.space，说明走了另一条队列）。
- 为什么 1：厂商把"参数是否合法"与"参数是否生效"分开了——非法字段（images / reference_images / init_image）明确 400，而 image 这类"认识但未必实现"的字段被静默吞掉。
- 为什么 2：我们的校验只看 HTTP 状态码，200 就当成功。
- 为什么 3：照着开源方案（ClipFactory 的关键帧链式）设计时，把"字段被接受"当成了"能力可用"，没有做对照实验。
- 根本原因归类：用状态码代替有效性验证——缺"用参考图上模型猜不到的特征做对照"的验证手段。

## 修复方案

1. 产品不依赖图像图生图：一致性改走"视频侧多参考图 + 固定 seed"（实测有效）；
2. 需要"产品外观固定"时，画面避开产品正面文字/logo，品牌信息走后期叠加；
3. 探针固化（qa/probes/agnes-probe.mjs）：任何"某厂商字段是否真的生效"的结论，都必须有对照实验证据。

## 回归用例

- 探针已固化：参考图带 NOTHING / 4821 的对照实验（带图 vs 不带图），输出必须人工目视比对并留证据（qa/evidence/agnes-probe-2026-09-16/01~03）；
- 反面样本留存：把人脸改机位失败的那张一并归档，避免以后又有人尝试同一条路。

## 关闭条件
