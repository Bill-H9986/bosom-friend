# DEF-113 长视频「目标时长」不是成片时长：选 90 秒，成片 77.97 秒（短 13.4%）

| 项 | 值 |
| --- | --- |
| 编号 | DEF-113 |
| 发现日期 | 2026-09-19 |
| 发现方式 | 长视频 90 秒档真实全流程验收（前端建任务 → 断点续跑 → 成片 ffprobe） |
| 严重级 | P2（用户按"90 秒"下单，拿到 78 秒的片子；参数与产出不是同一件事） |
| 状态 | Fixed（2026-09-21：统一去标点计字 + 母时钟按真实配音回标对账） |

## 现象（实测证据）

产品页面建的一条 90 秒 / 9:16 / 1080p / 烧字幕的数字人口播片，18 镜全部由真实厂商出片后：

| 层 | 值 | 证据 |
| --- | --- | --- |
| 用户选的目标时长 | 90 秒 | 长视频页「目标时长」高亮 90 秒（`qa/evidence/long-video-2026-09-19/02-目标时长与字数门槛.png`） |
| 页面自报的产出 | **已生成 77.0 秒 / 目标 90 秒** | 进度面板（`final-state-resume.json` 的 `progress`） |
| 成片真实规格 | **77.97 秒** / 1080x1920 / h264 24fps + AAC | `ffmpeg -i lv-lv-e4ab1503.mp4`（`final-state-resume.json` 的 `ffprobe`） |
| 稿件 | 396 字（含标点），18 镜，逐镜配音合计 77.0 秒 | 任务记录 `lv-e4ab1503` |

页面自己就写着「已生成 77.0 秒 / 目标 90 秒」——**这不是静默失败，是目标时长这个参数没有兑现**。
历史两轮同档位（`qa/reports/media-matrix-2026-09-18.md`）走向另一边：90 秒档成片 118.55 秒（+31.7%）、
120 秒档 124.4 秒（+3.7%）。同一个参数，成片时而长 32%、时而短 13%。

## 根因

**字数与语速用的不是同一套单位。**

1. 语速（`charsPerSecond`）是按**去标点**的样音标定的：`qa/probes/voice-pace-2026-09-17.md` 第 2 节写明
   「样音 = 试听文本，**去标点 38 字**」，晓晓 7.97 秒 → 4.02，目录记 4.1（`digital-human.ts`）。
2. 折算却拿**含标点**的字数去除同一个语速：

   ```ts
   // server/src/speech.ts
   export function estimateSeconds(text: string, charsPerSecond = CHARS_PER_SECOND): number {
     return Math.max(1, Math.round(normalizeSpokenText(text).length / pace))  // ← 含标点
   }
   export function minScriptChars(targetSeconds: number, charsPerSecond = CHARS_PER_SECOND): number {
     return Math.ceil(targetSeconds * pace)                                    // ← 按去标点的语速算出的字数
   }
   ```

   而 `normalizeSpokenText` 只去 Markdown 装饰与话题标签，**标点照留**。中文带货稿的标点占比约 15%
   （本条：396 字含标点 / 337 字去标点），于是「稿件下限」被系统性算低约 15%。
3. 门槛判定与补写循环（`long-video.ts` 的 `calibrateScript`、`scriptLengthGap`）同样用
   `normalizeSpokenText(script).length`，所以**补写也会在错误的字数上停下**。

本条的实际数：门槛 = 90 × 4.1 = 369 字（含标点），模型写了 396 字就过闸；
但真实语速是 337 字去标点 ÷ 77 秒 ≈ **4.38 字/秒**（比目录里的 4.1 快 6.8%），
两者叠加就成了 77 秒——比目标少 13 秒。

## 为什么值得记

1. 「目标时长」是长视频板块最贵的一个参数（90 秒 = 18 次厂商调用、约 1.7 小时），
   用户花的是这个参数的钱，拿到的却是另一个时长；
2. 长视频是**唯一**没有时长收敛的产出口径：内容创作的拼装档位（30/60 秒）有「偏差自动裁齐或补足」，
   长视频没有，只有页面上一句如实的「已生成 N 秒 / 目标 M 秒」；
3. 验收脚本只看「出没出片」会把它判成 PASS——本轮就是靠 ffprobe 读成片真实时长才抓到的。

## 建议修法（未实施）

1. **先把单位统一**（最小改动）：语速按去标点标定，字数就按去标点比。给 `speech.ts` 加
   `spokenCharCount(text)`（去标点去空白的字数），`estimateSeconds` / `minScriptChars` /
   `scriptLengthGap` 与 `calibrateScript` 的门槛判定全部改用它；界面上的「这条片要 N 字口播稿」
   同时写明「不含标点」，否则用户按含标点的口径数自己的稿子会觉得够了却被拒。
2. **再用真实配音回标**（性价比最高的一步）：产品在**任何一次厂商出片之前**就已经知道真实成片长度——
   `long-video.ts` 的「母时钟」先把全片配音合成完，再把每镜真实秒数写回 `segments[].audioSeconds`，
   然后才开始逐镜生成画面（注释原话：「先把全片配音定下来…顺序很重要」）。
   也就是说此刻 `Σ audioSeconds` 就是成片时长，差目标多少一目了然，而**一分钱厂商额度都还没花**。
   建议在这一步加一道对账：偏差超过阈值（例如 ±10%）时，要么按差距补写稿件后重跑配音，
   要么在页面上如实告知「按这版稿子成片约 N 秒，目标 M 秒」并让用户选继续或改稿；
   现在这个数只显示在进度面板上，不参与任何纠正。
3. 回归判据写进矩阵：长视频档位的成片时长偏差必须落在 ±10% 内（`qa/probes/run-media-matrix.mjs`
   已有该判据，本轮 90 秒档按它是 failed）。

## 修复记录（2026-09-21）

两条建议都落地了，且顺序就是上面写的顺序：先统一单位，再用真实配音回标。

### 1. 单位统一：`spokenCharCount`（去标点去空白）

`speech.ts` 新增 `spokenCharCount(text)`，用 Unicode 属性保留字母/数字/汉字（手写标点表实测漏过
「·」「～」「……」，每漏一个就少算一两个字）。改用它的是**整条折算链**：

| 位置 | 改动 |
| --- | --- |
| `estimateSeconds` | 分子改去标点字数 |
| `minScriptChars` | 只改文档（它本来就是"按语速算字数"，语速是去标点标定的） |
| `scriptLengthGap` / `calibrateScript` / `extendLongVideoScript` | 门槛判定与"还差多少字"改去标点 |
| `task.scriptChars` | 落盘去标点字数（界面上写明"不含标点"） |
| 提示词（写稿/补写/分镜） | 一律写"不少于 N 字（**不含标点**）" |
| 界面文案 | 门槛提示、进度面板、补写弹窗全部写明"不含标点" |

**注意**：切段（`splitScript`）送去做 TTS 的文本**保留标点**——标点是停顿的唯一来源
（Edge 朗读接口不吃 `<break>`，见 `tts.ts` 的接口边界）。标点只在**计数**时排除，不进合成文本。

### 2. 母时钟对账：知道了就要用

`long-video.ts` 的 `runLongVideoJob` 在母时钟合成完之后、**第一次厂商画面调用之前**加了一道对账：

- `voiceDurationGap`（新导出）量出 `Σ 真实配音秒数` 与目标的相对偏差；
- 偏差 > `DURATION_TOLERANCE_RATIO`（10%）且量到的镜数 ≥ 80%（个别镜合成失败时合计是"真实 + 估算"的混合数，不拿它改稿）时：
  按**实测语速**（`稿件去标点字数 ÷ 真实配音合计`）补写一版稿件 → 重排分镜 → 重跑配音；
- **只补一轮**；第二轮更差就保留第一版配音（"照着偏差改坏"不算修好）；
- 第二轮写到 `workDir/take2/`，上一轮音频留在盘上，哪一镜用的是哪一版配音看得见；
- 母时钟量到的时长落盘为 `task.voicedSeconds`，进度面板显示「按这版稿子成片约 N 秒 / 目标 M 秒」——
  这个数跑完 18 镜也不会变（配音驱动时间轴），所以它在任何时刻都是诚实值。

### 3. 顺带更正的两处文档事实

- `voice-pace-2026-09-17.md` 写的"样音去标点 **38** 字"是笔误：探针 `probe-voice-pace.mjs` 里数的是
  **32 字**（`VOICE_PREVIEW_TEXT` 去掉「，。」），目录里的 4.1 字/秒 = 32 ÷ 7.97，与探针实测逐条对得上。
- 因此**音色目录的语速值不需要重新标定**：2026-09-21 用同一支探针复测 14 条音色，
  实测语速与目录记录逐条一致（最大偏差来自探针不叠基准韵律，13%）。
  本条缺陷里"真实语速 4.38 比目录 4.1 快 6.8%"的差额，来自**基准韵律 +2%** 与单句样本的波动，不是标定错误。
