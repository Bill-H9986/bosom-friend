# DEF-138 语境不复利：用户评过分的产出从未回到下一次的上下文（好的越好这件事从没发生过）

| 项 | 值 |
| --- | --- |
| 编号 | DEF-138 |
| 发现日期 | 2026-09-22 |
| 发现方式 | 按参考视频（光羽《AI时代赚到钱的公司，都深度理解了 context 是什么》）指向的《语境才是真正的护城河》逐条对照本产品 → 发现 `fewShotExamples` 只被一个只读接口调用 |
| 严重级 | P1（"越用越好"是产品的核心承诺之一；没有它，第 N 次永远等于第 1 次） |
| 状态 | Fixed（2026-09-22：质量语境接入助手对话与内容生成两条链路，并留痕 exampleIds） |

## 现象（代码级证据）

- 每条助手对话与每次内容生成都会写一条蒸馏样本（`recordDistillation`），带 `status` 与 `rating`，
  用户还能在界面上评分——**质量语境的原料是齐的**。
- 但选取函数 `fewShotExamples`（成功 + 评分 ≥4 或注入过知识）在整个仓库里只被
  `GET knowledge/distill/fewshot` 一个只读接口调用，**从未进过任何一次模型上下文**。
- 于是"同类任务第二次做得更好"在机制上不可能发生：模型看不到自己上一次的产出。

## 根因

**账本只进不出。** 原料（样本）与消费（上下文）之间缺一条线：
"记录"被当成了终点（导出数据集、看统计），而不是下一次的输入。

这一条正是《语境才是真正的护城河》里飞轮断掉的样子：好的语境没有回填，就没有"更好的输出 → 学到
哪些语境重要 → 改进语境文档"这一环，剩下一个只增不减的日志。

## 修复（2026-09-22）

1. `knowledge-distill.ts` 新增 `buildQualityContext(knowledge, task, limit)`：
   同类成功样例拼成上下文块（单条产出 ≤400 字、最多 2 条、明确写"不要照抄其中的事实与数字"），
   选取口径复用 `fewShotExamples`，不另立标准。
2. 接进两条真实链路：
   - 助手对话（`agent/tasks` 的 SSE 分支）——与知识笔记命中并列进上下文；
   - 内容创作生成（`createDraftGeneration`）——按任务类型取（video / image-text），聊天样例不会串过去。
3. 账本新增 `exampleIds`：这一次注入/使用了哪条样例**留痕**，数据集接口与 JSONL 导出都带上它。
   没有这份记录，"第 N 次是否真的用上了前几次的经验"就只能靠感觉。

**配套的四类语境盘点**（领域/历史/质量/约束）写在 `docs/adr/ADR-004` 附录 A：
本轮补的是**质量语境**；**历史语境**（138 条缺陷与「常见坑速查表」）与**约束语境**（成本/限频/上限）
仍然没进过上下文——那是下一步的 P0。
