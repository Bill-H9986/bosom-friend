# DEF-115 门禁 10/11/12 的断言把「视频档位 = 图片档位」写死，换视频模型就假红

| 项 | 值 |
| --- | --- |
| 编号 | DEF-115 |
| 发现日期 | 2026-09-19 |
| 发现方式 | 参数验收顺带复跑 `qa/e2e/specs/content-params.spec.ts`（装机版 31280） |
| 严重级 | P3（测试自身缺陷，不是产品缺陷；但它会让门禁长期假红，掩盖真问题） |
| 状态 | **Fixed**（断言改成「视频档位不得越出图片档位」并加注原因） |

## 现象

```
  1) specs\content-params.spec.ts:38 › 内容创作 · 分辨率与画面比例 › 图片档位与视频档位一致
     expect(imageTiers, '图片档位必须与视频档位逐字一致').toEqual(videoTiers)
     Expected: ['720p']  Received: ['720p', '1080p']
```

图片档位是 `['720p', '1080p']`（产品固定表），视频档位是 `['720p']`——因为当前配置的视频模型
`agnes-video-2.5-flash` **官方只收 720P**，界面按官方能力只摆一档（这是对的，见
`qa/reports/media-matrix-2026-09-18.md` 的「界面不提供」一节：15 个 1080p 视频组合在界面上不存在）。

## 根因

断言写的是"两边逐字相等"，而这条等式的成立**取决于环境**：
只有当用户在设置里选的视频模型同时声明 720p 与 1080p（如 `agnes-video-2.5`）时才成立。
换成只收 720P 的 flash 型号，产品行为正确、用例却红——测试把"当前这台机器的模型配置"当成了产品口径。

## 修法（已实施）

```ts
// 图片档位是产品的固定表；视频档位由**所选视频模型的官方能力**决定
expect(imageTiers, '图片档位必须是 720p/1080p').toEqual(['720p', '1080p'])
expect(videoTiers.length, '视频档位至少给出一档').toBeGreaterThan(0)
for (const tier of videoTiers)
  expect(imageTiers, '视频档位 ' + tier + ' 必须在图片档位表里').toContain(tier)
```

钉住的原意（口径一致、不出现只在一边存在的档位）保留，同时不再要求环境依赖的逐字相等。
复跑：`npx playwright test specs/content-params.spec.ts` → **3 passed**（1.2m，装机版 0.2.58 + 本轮重建前端）。
