# DEF-136 右侧 AI 助手与「我的任务」不同步：删了记录助手还留着那条对话，"新对话"把两个面板拆成两半

| 项 | 值 |
| --- | --- |
| 编号 | DEF-136 |
| 发现日期 | 2026-09-22 |
| 发现方式 | 用户反馈"右侧边栏 AI 助手与我的任务中的数据信息不同步" → 浏览器实测两侧 + 读删除与新建对话两条链路 |
| 严重级 | P2（两个面板对同一份数据给出相反的说法，用户会继续对着"已被删除的任务"说话） |
| 状态 | Fixed（2026-09-22：删除联动清缓存；详情页里"新对话"带着主区域一起走） |

## 现象（浏览器实测，2026-09-22）

先说**已经同步**的那一半（避免误判）：打开「我的任务」里的一条记录 → 右侧助手确实跟着切过去
（`useChatState` 调 `selectTask` + `setMessages`）；在助手里追问一轮 → 列表里那条记录
立刻从"33 分钟前"变成"刚刚"（`notifyAgentTasksChanged`）。这两条实测都成立。

不同步的是这两条：

1. **删了记录，助手还留着那条对话**：`TaskHistoryList` 的单个/批量删除只调 `agentApi.deleteTask`，
   从不碰 `useAgentStore` 里按 taskId 存的 `taskMessages`。于是左侧说"已删除"，右侧还显示着它、
   还能继续追问；继续追问会撞上服务端的 18100（任务不存在），前端再把它当成"会话过期"自动新开一条——
   一条已经删掉的对话会拖出一条新任务。
2. **详情页里点"新对话"**：`handleNewChat` 只 `resetAgent()`，主区域仍停在 `#/chat/task-xxx`。
   左侧页面显示旧任务、右侧助手是一条空白新对话——同一次点击把两个面板拆成两半。

## 修复（2026-09-22）

1. `useAgentStore` 新增 `forgetTasks(ids)`：清掉这些任务的本地缓存；**若当前正在看的那条被删了就一并复位**
   （否则助手会继续对着一条不存在的任务说话）。单个删除与批量删除两条路径都接上。
2. `AIAssistantPanel.handleNewChat`：主区域停在任务详情页时，带着它一起离开那条任务
   （`router.push('/chat/new')`，桌面壳里该路由没有待处理任务时由它自己的守卫落到首页，
   实测最终停在 `#/`）；停在其它功能页时不跳——助手是全局面板，点一下"新对话"就把用户从创作页拽走是另一种更糟的体验。

## 回归判据

- 浏览器实测（2026-09-22）：在详情页点"新对话"→ 主区域离开那条任务、右侧助手回到空态提示，
  两侧不再各说各话（落点是桌面壳的新对话入口 `#/`：`/chat/new` 没有待处理任务时由页面守卫落到首页）。
  删除联动的浏览器实测需要删掉用户的真实记录，本轮按代码判据 + 单元级路径覆盖，未做破坏性实测。
- 代码判据：`forgetTasks` 的两条分支（删的是当前任务 / 不是当前任务）都有明确的落点，
  没有"删了但缓存还在"的路径。

**仍然存在的粒度差异（本轮一并处理）**：同一条对话，右侧助手与"我的任务"此前都只显示正文、
都没有过程——两侧的"同一份数据"其实都缺了过程这一层。这一层已由 DEF-134 修好，
两侧现在读的是同一批过程事件。
