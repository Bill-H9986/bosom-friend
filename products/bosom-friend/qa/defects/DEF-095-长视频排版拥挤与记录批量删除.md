# DEF-095：长视频创作排版拥挤 + 生成记录不能批量删

> 编号：DEF-095（唯一、终身不变）
> 状态：Fixed
> 严重度：P3　　优先级：中低
> 缺陷类型：体验/完整性
> 关联需求：REQ-022（长视频创作）
> 报告人 / 日期 / 环境版本：用户报障（"长视频创作排版也有点拥挤！然后生成记录加一个批量删除！"）/ 2026-09-17 / 0.2.54
> 责任人 / 计划版本：Jay / 0.13.10
> 重开次数：0

## 复现步骤

1. 打开「长视频创作」；
2. 看"卖点与参数"整块（产品与卖点 / 产品图 / 时长 / 画幅 / 字幕 / 预估 / 开始生成全挤在一栏里）；
3. 展开「生成记录」（14 条时）：只能一条一条删。

## 期望结果 vs 实际结果

- 期望：参数分段清楚、一眼看得出每段在配什么；记录能勾选多条一次删掉。
- 实际：卖点那一整块从输入框到按钮没有任何分隔，产品图的两句说明还各占一行；
  记录只能逐条删——14 条失败的尝试，用户要点 14 次确认。

## 影响范围与发生频率

每次用这一页都会看到；每次清理记录都会遇到。

## 根因分析（5-Why）

- 直接原因：参数区是一个没有分段的 `flex flex-col gap-4`；记录行只有一个单条删除按钮。
- 为什么 1：功能是逐个加上去的（产品图、字幕、预估），每加一个就往下接一段，没人重新分段。
- 为什么 2：单条删除是上一轮（DEF-091）刚加的"最小可用"，批量属于同一条需求的下一步。
- 根本原因归类：**功能叠加时没有重新组织版面/操作**。

## 修复方案（改根因）

1. 参数区按 ① 产品与卖点 ② 参考素材 ③ 生成参数 ④ 预估与开始生成 四段切开，段间一条分隔线；
   容器放宽到 `max-w-6xl`，说明文字合并、字号统一到 11px 行高 5；
2. 新增批量删除：记录头「批量管理」进入选择态 → 每行复选框（生成中的置灰）→
   「全选可删的」/「删除选中」/「取消」；确认框写明条数与"成片不受影响"；
3. 服务端新增 `DELETE long-videos`（body: `{taskIds}`）：与单条同一口径（删记录不删成片），
   **生成中的跳过并如实报数**——不能因为选中的十条里有一条在跑，剩下九条一起删不掉。
