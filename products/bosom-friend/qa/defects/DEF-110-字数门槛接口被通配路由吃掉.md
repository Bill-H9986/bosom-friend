# DEF-110 新增的字数门槛接口被通配路由吃掉，返回「任务不存在」

| 项 | 值 |
| --- | --- |
| 编号 | DEF-110 |
| 发现日期 | 2026-09-19 |
| 发现方式 | DEF-108 的装机版验收：`GET long-videos/script-requirement?producer=scene&targetSeconds=300` 返回 `40404 任务不存在` |
| 严重级 | P2（新功能在真机上完全不可用，但不会影响既有功能） |
| 状态 | **已修复（0.2.58）** |
| 修复版本 | 0.2.58 |

## 现象

```
GET /bosom-friend/api/long-videos/script-requirement?producer=scene&targetSeconds=300
-> {"code":40404,"data":null,"message":"任务不存在"}
```

同一份代码在 TypeScript 编译、单元测试、类型检查全部通过的情况下，功能在真机上完全不可用。

## 根因

`server/src/api.ts` 的路由匹配（{@link matchRoute}）按**注册顺序**线性扫描，段数相同即逐个比较模板：

```ts
for (const route of routes) {
  const tpl = route.p.split('/').filter(Boolean)
  if (tpl.length !== segs.length) continue
  for (let i = 0; i < tpl.length; i += 1) {
    if (tpl[i].startsWith(':')) params[tpl[i].slice(1)] = decodeURIComponent(segs[i])
    else if (tpl[i] !== segs[i]) { ok = false; break }
  }
}
```

新路由 `long-videos/script-requirement` 与更早注册的 `long-videos/:taskId` 段数相同（2 段），
通配路由先被匹配到，于是 `script-requirement` 被当成 taskId 去查任务表，查不到就回「任务不存在」。

## 为什么门禁没拦住

1. 类型检查看不到：两条路由都是合法的 `{ m, p, h }`，模板字符串的语义不在类型系统里；
2. 单元测试看不到：本仓库的功能测试直接调插件路由表，很少从"同一段数、具体路径 vs 通配路径"的
   歧义角度构造用例；
3. 只有**真的发一次 HTTP** 才会暴露——这正是"代码读完就宣布修好"最容易翻车的地方。

## 修复方案

把 `long-videos/script-requirement` 移到 `long-videos/:taskId` **之前**注册，并在该路由的 JSDoc 里写明
「必须排在通配路由之前：路由按顺序匹配」。随后在装机版上复测：

```
script-requirement(scene,300) = {"targetSeconds":300,"requiredChars":1350,"charsPerSecond":4.5,"shots":60}
script-requirement(scene,90)  = {"targetSeconds":90,"requiredChars":405,"charsPerSecond":4.5,"shots":18}
```

## 回归用例

| 用例 | 命令 | 结果 |

| 装机版真调 HTTP | `node products/bosom-friend/qa/probes/report-installed-state.mjs` | 300 秒 → 1350 字 / 60 镜；90 秒 → 405 字 / 18 镜 |
| 长视频页显示门槛 | `node products/bosom-friend/qa/verify-duration-ui.mjs` | 页面出现「这条片要 369 字口播稿（4.1 字/秒 × 90 秒，约 18 镜）」 |
