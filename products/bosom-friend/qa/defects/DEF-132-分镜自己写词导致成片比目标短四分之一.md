# DEF-132 长视频"口播文案太短、停顿太长"：稿件按目标时长校准过，排分镜的模型却看不到它、自己另写了一份短稿

| 项 | 值 |
| --- | --- |
| 编号 | DEF-132 |
| 发现日期 | 2026-09-22 |
| 发现方式 | 用户反馈"长视频创作的口播文案还是太短了，语速和停顿太慢太长了" → 读任务记录（稿件字数 vs 各镜台词字数）+ 用真实模型复跑分镜提示词三次 |
| 严重级 | P1（每条长视频都命中：成片比目标短一截、内容少四分之一） |
| 状态 | Fixed（2026-09-22：台词由已定稿的稿件分配，分镜模型只负责画面与节拍） |

## 现象（实测证据）

用户那条 90 秒数字人口播片（任务 `lv-3796e8f1`，18 镜）：

| 层 | 值 | 证据 |
| --- | --- | --- |
| 目标时长 | 90 秒 | 任务记录 `targetSeconds` |
| 稿件 | **448 字**（已过 369 字的门槛） | 任务记录 `scriptText` / `scriptChars` |
| 18 镜台词合计 | **335 字** | 逐镜 `shots[].line` 去标点计数 |
| 逐镜配音合计 | 74.9 秒 | 任务记录 `voicedSeconds` |
| 成片真实时长 | **80.54 秒**（目标 90 秒） | `ffmpeg -i lv-lv-3796e8f1.mp4` |

稿件的四分之一（113 字）**没有进片子**。成片时长 = Σ（台词字数 ÷ 语速），
所以"台词被写短了"就等于"片子短了"——用户听到的是内容少、句子之间空得久。

## 根因

**校验的和使用的不是同一份文本。**

1. 写稿链路按目标时长校准稿件（`calibrateScript` 反复补写到 ≥ 目标 × 语速），448 字是真的够；
2. 排分镜那一次模型调用**根本没有拿到这份稿件**：`digitalHumanProducer.planShots` 的提示词只拼了
   题材、体裁要求与长度要求，`script` 参数只用来在事后给空 line 兜底（`fillMissingLines`）；
3. 于是模型按"每句 16~25 字"的要求**自己另写了一份**台词。
   门槛是 90 秒 × 4.1 字/秒 = 369 字，下面"覆盖率"一律以这个门槛为分母：

   | 轮次 | 目标 | 稿件 | 分镜台词合计 | 覆盖率（÷369） |
   | --- | --- | --- | --- | --- |
   | 用户那条（2026-09-21） | 90 秒 | 448 字 | 335 字 | 91%（也等于稿件的 75%） |
   | 真实模型复跑 A（2026-09-22，稿件写进提示词**之前**） | 90 秒 | 437 字 | 265 字 | 72% |
   | 真实模型复跑 B（2026-09-22，稿件写进提示词**之前**） | 90 秒 | 369 字 | 218 字 | 59% |
   | 真实模型复跑 C（2026-09-22，**把稿件写进提示词并要求逐字照抄之后**） | 90 秒 | 369 字 | 308 字 | 83% |
   | 真实模型复跑 D（2026-09-22，同 C 的提示词） | 90 秒 | 295 字 | 215 字 | 58% |

   后两轮说明"提示词里写清楚"不足以修好：模型会改写、会压缩，而**成片时长跟着它走**。
   复跑用的探针是 `qa/probes/probe-storyboard-coverage.mjs`（要花一次真实模型调用，不进每次门禁）。

4. 顺带暴露的第二个口径错误：母时钟对账把"**整篇稿件的字数**"除以"分镜实际合成出来的秒数"
   得到"实测语速"。分镜一丢字，这个商就系统性偏快——用户那条算出 5.98 字/秒（真实 4.47），
   于是"补写"把稿子越补越长（448 字），成片却一点都不变长。

## 为什么值得记

1. 「目标时长」是长视频最贵的参数（90 秒 = 18 次厂商调用）；短四分之一等于用户为 90 秒付钱、拿 80 秒；
2. 缺陷藏在**两个模块的交界处**：写稿模块的产物（稿件）从来没有真正交给分镜模块，两边各自"看起来都对"；
3. 记进"用户口径"的那句原话是"语速太慢、停顿太长"——真实语速是正常的 4.47 字/秒
   （335 字 ÷ 74.9 秒），用户感知到的"慢"来自**字幕与口播错位**（DEF-131）加上内容变稀。

## 修复（2026-09-22）

1. **台词由已定稿的稿件分配**：`storyboard.ts` 新增 `fitScriptToShots(shots, script, charsPerSecond)`——
   按镜头数与字数把稿件均分成与镜头一一对应的台词（句末标点 → 逗号 → 按长度硬切，分界点落在标点上），
   **只替换 line 与 seconds**，模型的 kind / visual / beat / continuity / references 一律保留。
   覆盖率因此是**构造出来的性质**，不是猜的。
2. **分镜提示词带上稿件**（`buildStoryboardPrompt` 的新 `script` 选项）：模型至少能看到"这条片在讲什么"，
   画面才有机会对着内容写；同时明确要求 line 是稿件里连续的一段、逐字照抄、覆盖整段。
   （实测模型仍会改写——覆盖率从 59% 提到 83% 仍不够——所以 line 最终由第 1 条决定；
   提示词的作用是让它的画面与真实台词对齐。）
3. **母时钟对账改用真正被合成的字数**：`voicedChars = Σ spokenCharCount(shot.line)`，
   不再拿整篇稿件的字数去除以分镜的配音秒数。
4. **分镜覆盖率留一条现场判据**：`shotsCoverTarget` 在排完分镜后量一次，不足就在日志里报出来
   （覆盖本该是构造出来的，报出来意味着切分或稿件来源被改坏了）。
