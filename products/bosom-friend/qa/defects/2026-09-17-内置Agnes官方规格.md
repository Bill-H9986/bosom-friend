# DEF-082：内容创作的时长/比例/分辨率"没起作用"——模型能力表与请求字段都不是 Agnes 官方那一套

> 登记时间：2026-09-17 ｜ 严重度：P1 ｜ 状态：Fixed ｜ 关联 REQ-001 / REQ-022 ｜ 责任人：Jay

## 1. 用户原话与要求

> 「内容创作中图片和短视频的时长、比例、分辨率等参数没起作用！」
> 「APP里还是内置Agnes AI模型厂商！这样普通用户在调用模型时只用填一个API也方便！
>   在使用图片和视频生成时也可以完全按Agnes AI官方标准进行！」
> 「不仅仅是视频！还有文本和图片模型！就是将Agnes AI官方文档作为我们APP的内置系统大模型！」

## 2. 真机复现（E2E 实例，隔离数据根）

| 请求（用户所见） | 实测产物 | 判定 |
| --- | --- | --- |
| 视频：`agnes-video-2.5-flash`，时长 10 秒，1080p，16:9 | `ai-vid-2a2af0b2.mp4` → **10.14 秒 / 1280x720** | 时长 ✅、比例 ✅、**分辨率 ❌（要 1080p 给 720p）** |
| 图文：`agnes-image-2.1-flash`，1080p，3:4 | `ai-img-9493a096.png` → **1080x1440** | 图片这条当时是对的（但请求字段是像素尺寸，见根因） |

成片分辨率对不上不是"厂商不给"这一句能解释的：**界面允许选的档位，是服务端一张硬编码的能力表说了算**——
它给每个视频模型都写死 `resolutions: ['720p','1080p']`，而 Agnes 官方对 `agnes-video-2.5-flash` 的规则是
`size` 只能是 `"720P"`（官方原文：`size must be 720P`）。用户选 1080p，厂商只可能出 720P，成品就是 720P。

## 3. 根因（三层，都是"我们的口径 ≠ 官方口径"）

1. **能力表硬编码**：`server/src/api.ts` 的 `ai/draft-generation/pricing` 给内置/用户视频模型一律写
   `resolutions: ['720p','1080p']`、`durations: [4,5,6,8,10,12]`、`aspectRatios: ['1:1','9:16','16:9']`，
   与 Agnes 官方（每个模型的 size 白名单、seconds "4"~"12"、六种画幅）不是同一份事实。
2. **图片请求字段不是官方字段**：官方 `POST /v1/images/generations` 的 `size` 是**档位**（`1K/2K/3K/4K`）、
   画幅走 `ratio`；我们发的是 `size: "1080x1920"` 这类像素尺寸——官方文档明确"不支持的精确尺寸会被标准化"，
   参数在厂商侧就已经变样了（DEF-029/P-012 的老问题换了个形态）。
3. **用户选的模型没被使用**：生成时一律用设置里的 `imageModel`/`videoModel`，界面上那个模型下拉只进了记录，
   所以"换个模型再生成"成品一模一样；而没有配置图片模型时图片会静默回落到本地模板卡片。

## 4. 修法

1. 新增 `server/src/agnes.ts`：**内置 Agnes 官方规格**——接口基址、模型目录（对话/图片/视频）、
   图片档位与画幅白名单（含官方输出像素表）、视频每个模型的 size 白名单与 seconds 区间、画幅白名单、
   参考素材上限、产品档位 → 官方档位的映射。
2. `readStoredLlm`/`parseLlmOverride`：**只填一个 API Key 就能用三个通道**——地址与
   `model`/`imageModel`/`videoModel` 由内置规格补齐（非 Agnes 的自定义厂商不受影响）。
3. `ai/draft-generation/pricing`：视频模型能力改为**按官方规格逐模型下发**（Flash 只 720p，2.5 支持 1080p），
   用户自带厂商的模型沿用产品标准档位（真实档位由"下单被拒时按厂商自报降档"的既有机制收敛）。
4. 图片请求改成官方字段：`size` 用档位（720p→1K、1080p→2K）、`ratio` 用画幅；落盘前仍按产品画布裁剪，
   成品尺寸与用户选择一致。模型被 Key 白名单拒（403）时自动换另一个内置图片模型重试，不再直接回落模板卡片。
5. 视频请求尊重**用户选的模型**：`agnes-video-2.5` 支持 1080P，`agnes-video-2.5-flash` 只 720P；
   本地模板模型（`zy-template-video`）不再冒充厂商模型，直接走本地幻灯片。
6. 设置页：内置 Agnes 卡（`id=agnes-builtin`、`builtin=true`）恒在，用户只填 API Key；
   保存时服务端把三个通道与模型目录一起补齐，界面上不给"删除"这个假动作。

## 5. 证据

- `server/test/functional/agnes.spec.ts`：12 条（档位映射、画幅白名单、每模型 size 能力、
  seconds 夹紧、素材上限、"只填 Key 补齐三通道"、内置卡落盘与回读）。
- `server/test/functional/content-params.spec.ts`：12 条通过（图片档位=视频档位、1080p+9:16=1080x1920 等）。
- 真机：E2E 实例请求 10 秒 / 1080p / 16:9 → 时长 10.14 秒（比例 16:9 生效），分辨率问题即本缺陷；
  图文 1080p+3:4 → 1080x1440。

## 5.1 真机验证时又查出的两条（同批修复）

### ① 模型名在清单里 ≠ 这把 Key 有权限（DEF-067 的同一个坑，这次是视频）

真机实测（`.dsh-build/kernel-task.log`）：

```
[VID_DBG] model=agnes-video-2.5 target=1080P remembered="" opts.res=1080p
[AI_VID_ERR] agnes create failed status=403
```

`agnes-video-2.5`（官方标注支持 720P/1080P/1K/2K）对这把 Key 回 **403**——模型出现在 `GET /v1/models` 里，
但不在 Key 的白名单里。修法三条：

1. **换模型重试**：视频生成按官方视频模型清单逐个试（用户选的排第一），401/403 时换下一个，并把
   "实际用的是哪个模型"写进生成记录（`generatedModel=video:agnes-video-2.5-flash`），不静默；
2. **结论落盘**：`llm-user.json` 新增 `modelDeniedMemory`（键 = 基址 + 模型），只在厂商真回过 401/403 之后写；
3. **模型清单据此过滤**：图片/视频的模型列表不再摆出这把 Key 用不了的模型——让用户选一个永远出不来东西的模型，
   是本项目反复踩过的坑（DEF-067）。长视频同理：口播镜不再因为一个没权限的模型把整条片判死。

### ② 厂商没出片时用图片合成顶上，却报成"成功"（假成功）

同一个 403 之后，产品用本地幻灯片（静止图片轮播）顶替，任务状态却是 `success`——用户以为拿到的是 AI 视频。
修法：这种降级**如实标 partial** 并把原因写进记录
（"厂商视频生成失败：…；已用图片合成的本地视频代替（静止画面轮播，不是 AI 视频）"），
`generatedBy` 保持 `local-template`。

### ③ `agnes-video-v2.0` 为什么没有内置（如实说明）

官方 V2.0 用的是**另一套参数契约**（`width`/`height`/`num_frames`(≤441, 8n+1)/`frame_rate`/`mode=ti2vid|keyframes`，
查询走 `GET /agnesapi?video_id=`），与 2.5 的 `seconds`/`size`/`aspect_ratio` 完全不同；
且它**不支持音频参考**（数字人口播的 `reference` 模式用不了）。
产品暂不下发这个模型：与其把 2.5 的参数发给它（会被忽略或被标准化），不如不摆出来；
要用它需要先按它的契约单独适配。
