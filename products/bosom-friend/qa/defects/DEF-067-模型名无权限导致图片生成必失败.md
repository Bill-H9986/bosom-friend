# DEF-067：设置里存的图片模型名无权限，图片/封面生成每次都 403 静默失败

> 编号：DEF-067（唯一、终身不变）
> 状态：Fixed（产品侧修法：保存前校验权限；用户侧需把模型名改成有权限的）
> 严重度：P1　　优先级：高
> 缺陷类型：代码（配置校验缺失）/ 环境集成
> 关联需求：REQ-001（内容创作的图片生成）、REQ-022（长视频）
> 报告人 / 日期 / 环境版本：2026-09-16 探针实测 / 0.2.51
> 责任人 / 计划版本：Jay / 待定
> 重开次数：0

## 复现步骤（别人照着能复现）

1. 在「设置 → 自定义大模型」里填 Agnes（base `https://api.agnes-ai.cn/v1`），把图片模型选/填成 `agnes-image-2.5-flash`；
2. 打开内容创作生成图文，或让长视频抽封面；
3. 图片生成失败，界面只给一句笼统的失败提示。

## 期望结果 vs 实际结果

- 期望：要么保存时就告诉用户"这个 key 没有该模型权限"，要么生成时把厂商原话摆出来。
- 实际：`GET /v1/models` 里**确实列出** `agnes-image-2.5-flash`，用户没有任何理由怀疑它不可用；每次调用被 403 拒。

## 影响范围与发生频率

所有把图片模型选成该名字的用户，**每次**图片/封面生成都失败。

## 根因分析（5-Why）

- 直接原因：`POST /v1/images/generations` 返回 `403 team_model_access_denied`：`This team can only access models=['agnes-2.5-flash','agnes-image-2.1-flash','agnes-video-v2.0',...]`。
- 为什么 1：厂商的 `/v1/models` 是**全平台清单**，而可用性由**key 的团队白名单**决定——两者不是一回事。
- 为什么 2：产品把"模型清单"与"模型可用性"当成同一件事：设置页让用户自由选择/填写模型名，保存时**不做任何权限校验**。
- 为什么 3：模型配置写进 `llm-user.json` 后长期不校验，直到用户真正生成才暴露，而暴露出来的是笼统失败文案。
- 根本原因归类：**缺少"保存配置前用一次最小真实调用验证"的环节**——把不可用状态推迟到用户使用路径上暴露。

## 修复方案

1. 设置页保存前（或提供"测试连接"按钮）调用一次 `GET /v1/models` **并按 key 的返回判定可用性**；有差异时当场提示"该模型无权限，可用的是 X"；
2. 图片/视频生成失败时，**把厂商原文里的 `team_model_access_denied` 与可用模型列表带进错误信息**，而不是只留一句失败；
3. 默认模型名改成实测可用的 `agnes-image-2.1-flash`（`project/bosom-friend-electron/electron/main/config/userModelConfig.ts` 里已是该值，说明是用户旧配置/手填留下的）。

## 回归用例

- 探针 `qa/probes/agnes-probe.mjs`：对无权限模型名必须拿到 403 且错误文案含可用列表；
- 待补（P1 一起做）：单测覆盖"保存无权限模型名 → 当场被拒并给出可用模型"。
