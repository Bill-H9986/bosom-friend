# DEF-104 源码态实例长期占用产品端口，装机版接入旧代码后界面缺功能（30/60 秒档位看不到）

| 项 | 值 |
| --- | --- |
| 编号 | DEF-104 |
| 发现日期 | 2026-09-18 |
| 发现方式 | 用户看图报障：内容创作的「视频时长」只有 4/5/6/8/10/12 秒，没有 30 秒与 1 分钟 |
| 严重级 | P1（功能看起来「根本没做」，实际是跑错代码） |
| 状态 | Fixed（根因已消除，防复发检查待补） |

## 现象

用户截图里「视频时长」只有六档短档位（4/5/6/8/10/12 秒），没有 30 秒 / 1 分钟。

## 排查（全部实测）

1. **不是没做**：源码态服务端在 `server/src/api.ts:2526` 给 Agnes 视频模型下发 `longDurations: [...COMPOSED_VIDEO_GEARS]`（= `[30, 60]`）与 `longDurationEstimates`；前端 `VideoModelParamsSelect` 有对应的档位按钮渲染分支，装机版 `frontend-dist/assets/index-DgU-dRa0.js` 里也确认存在这段代码。
2. **确定性复现**：用测试骨架直接调路由（`server/test/harness.ts` + `GET ai/draft-generation/pricing`，视频通道配 `agnes-video-2.5-flash`），得到 `longDurations: [30,60]`、estimates `{30: 7 片 / 5-30 分钟, 60: 15 片 / 9-63 分钟}`——**当前构建是对的**。
3. **线上却缺字段**：同一时刻问 `http://127.0.0.1:31280/bosom-friend/api/ai/draft-generation/pricing`，返回里只有 13 个属性，没有 `longDurations` / `longDurationEstimates`。
4. **根因**：占用 31280 的进程是 `node --import tsx/esm products/bosom-friend/launcher/src/bin-desktop.ts`，**启动时间 13:27:06**，而带该功能的构建产物 `server/lib/types/api.js` 是 **15:42:52** 才生成的。Node 把模块加载进内存后不会因为磁盘文件变新而重载：这个进程一直在服务两小时前的旧代码。装机版启动时看到 31280 已有产品服务，按设计**接入既有服务**（不另起内核），于是它把自己的前端指向了那个旧后端。

## 处置

停掉 13:27 那个陈旧源码态进程，重启装机版让它自起内核。重启后同一接口返回 `longDurations: [30,60]`、estimates 齐全，界面即出现这两档。

## 为什么值得记

- 症状与「功能没做」完全一致，而排查方向（前端渲染 / 服务端下发）**两处都是好的**——只看代码永远查不出来，必须比较「磁盘上的构建时间」与「进程启动时间」；
- 这类陈旧进程会一直占着端口，之后每一次装机版启动都会接入它，**看起来像装机版坏了**；
- 判据固定为两条：`Get-NetTCPConnection -LocalPort <端口>` 拿到 PID，再 `Get-Process -Id <PID> | Select StartTime` 与 `server/lib/types/api.js` 的 `LastWriteTime` 比大小；进程更早就说明它在服务旧代码。

## 待补的防复发（尚未实现）

装机版接入既有服务前，把该实例的启动时间与自身构建时间对比（或让源码态实例在启动日志里写下它所加载模块的构建时间戳），不一致就**如实提示「检测到旧版本实例在运行，建议重启」**，而不是静默接入。目前只在本条记录了判据，代码未改。
