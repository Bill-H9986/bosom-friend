# DEF-108 长视频的稿件字数门槛没有前置提示，用户很容易在填了卖点后被拒

| 项 | 值 |
| --- | --- |
| 编号 | DEF-108 |
| 发现日期 | 2026-09-19 |
| 发现方式 | 逐档矩阵跑长视频 300 秒档时，连续两次被同一句话拒收 |
| 严重级 | P2（不是崩溃，是用户不知道要填多少的摩擦） |
| 状态 | Open（口径合理，缺的是前置提示与可操作指引） |

## 现象

选 300 秒长视频，填了一段 200~460 字的卖点，提交后被拒：

```
稿件只有 1288 字，不足 300 秒所需的 1350 字；请把卖点写细一些，或把目标时长降到约 286 秒。
```

把卖点材料从 458 字加到 794 字后，同一档位通过校验并进入逐镜生成（任务 lv-61436567）。

## 口径（合理，不需要改）

server/src/long-video.ts 按「目标时长 × 音色语速」折算稿件下限（minScriptChars(targetSeconds, charsPerSecond)，默认 4.5 字/秒）：90 秒约 405 字、120 秒约 540 字、300 秒约 1350 字。不足就拒收而不是编内容——这条产品口径是对的，避免用空话凑时长。

## 问题在交互（待改进）

1. 提交前没有任何提示：用户在「长视频创作」填目标时长时，看不到这一档需要多少字卖点；失败信息是提交之后才出现的。
2. 失败文案只给了两个选择（补卖点 / 降时长），没有告诉用户当前材料折算约多少秒的量级感；实测里 300 秒档连续两次被拒（1288 字 / 997 字），第三次把材料加到 794 字才过。
3. 折算关系依赖音色语速：同一个时长目标，换一个慢音色就需要更长的稿件，界面同样没有体现。

## 建议（未实施）

- 在时长选择旁直接显示这一档约需 N 字卖点（当前已填 M 字），把校验提前成输入即可见的提示；
- 或把「补写」做成显式按钮：一键按目标时长补写到下限，而不是只把失败原因抛给用户；
- 文案里补上当前材料约合 X 秒，让用户知道差多少量级。

## 为什么值得记

这条会让用户以为功能坏了（连试两次都失败、原因还是自己材料的问题），而矩阵里 90 秒与 120 秒两档用同样的材料是一次通过的——说明不是功能不可用，而是目标时长越长、材料信息量要求越高这条关系没有被界面表达出来。
