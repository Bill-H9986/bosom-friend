# DEF-097：「加产品图（可选）」点了没反应，选择框都不弹

> 编号：DEF-097（唯一、终身不变）
> 状态：Fixed
> 严重度：P2　　优先级：高（长视频创作的产品图位直接进不去内容）
> 缺陷类型：功能/交互
> 关联需求：REQ-022（数字人 / 长视频创作）
> 报告人 / 日期 / 环境版本：用户报障 / 2026-09-17 / 0.2.54 开发端（http://127.0.0.1:31280/bosom-friend/）
> 责任人 / 计划版本：Jay / 0.13.10
> 重开次数：0

## 复现步骤

1. 打开长视频创作页；
2. 点「加产品图（可选）」；
3. 期望弹出系统文件选择框，实际**什么都不发生**：没有弹框、没有报错、页面没有任何反馈。
   （同页面的"生成""清空"等按钮都正常，所以不是页面卡死。）

## 期望结果 vs 实际结果

- 期望：点击后弹出文件选择框，选中图片 → 上传 → 出缩略图。
- 实际：点击后毫无反应。用户无法判断是"没点中"、"图片格式不对"还是"功能没做"。

## 根因分析

- 入口的实现是**按钮 + 脚本代理**：`<Button onClick={() => inputRef.current?.click()}>` 配一个
  `className="hidden"` 的 `<input type="file">`。这条路要同时成立三件事——引用没丢、
  元素在文档里、**浏览器愿意接受一次非用户手势产生的点击**。任何一条不成立，结果都是静默失败：
  脚本调用没有返回值、没有异常、没有 console 输出，界面上一点痕迹都不留。
- 「我的数字人」页的"上传形象图"是同一套写法，同一个风险面。
- 为什么没被测出来：验收与 D1~D9 自检都是**直接给 input 塞文件**（`setInputFiles`）走完上传链，
  跳过了"用户点按钮"这一步。上传链本身是好的（本轮实测：选图 → 上传签名 → PUT → confirm → 压缩 2.36MB→0.80MB → 出预览），
  坏的只有**入口**这一跳；而恰恰这一跳是用户唯一会做的动作。
- 根本原因归类：**入口把"用户手势"这件事交给了脚本**，而脚本这一跳无法自证成功。

## 修复方案（改机制，不打补丁）

**第一版（label 转发）**：两处入口改成原生 `<label htmlFor>` + `sr-only` 的 `<input type="file">`，
转发交给浏览器；禁用态用 `aria-disabled` + `title`。
→ **用户实测仍然"点了没反应"**（截图显示他跑的确实已是这一版：报障图里的「画面字幕」文案只存在于这一版）。

**第二版（现行）**：把中转层全部去掉——入口是**铺满按钮的透明 `<input type="file">`**，
用户点到的**就是输入框本身**：

1. 不再有"按钮 + JS 去 click 输入框"（脚本合成点击依赖引用、文档归属与用户激活判定，任一不成立即静默失败）；
2. 不再依赖 `<label>` 的点击转发（少一层中转）；
3. 输入框**可见**（只是 `opacity-0`），不落进"浏览器拒绝为 display:none / clip 元素开框"的灰区；
   按钮外观由一层 `aria-hidden` 的装饰 `<span>` 负责，输入框自带 `aria-label` 保住读屏名字；
4. 生成中/上传中直接把输入框 `disabled`，并把原因**写成看得见的文字**（上一版只写在 `title` 里，
   鼠标不悬停就看不到，用户看到的仍是"点了没反应"）；
5. 点击后到拿到文件之间显示"已在等系统选择框…"（窗口 `blur`/`focus` 时收掉）：
   浏览器要是根本没弹框，这句话就留在页面上——**失败从沉默变成一句人话**；
6. 保留 `data-testid`（`long-video-product-image-pick` / `digital-human-pick-avatar`）供回归用例点击。

## 说明（诚实记录）

用户机器上的控制台拿不到，"三件事里哪一条不成立"没有现场证据，所以两轮都是按机制替换，而不是补丁式重试：
第一轮去掉脚本点击（改 label 转发），第二轮把 label 转发也去掉（点到的就是输入框），
并给"点击之后没有任何后续"这条路补上一句可见的状态。

本轮另外查过、并排除的可能：数据里没有生成中的任务（`generating` 假）、
`uploadingProduct` 在 `finally` 里必然复位（不会卡住）、本机没有 Electron 窗口（用户不在桌面壳里点）、
旧构建产物里不含「画面字幕」文案（用户的截图证明他跑的是新版）。

如果第二版仍然点不动，页面会**自己说出**卡在哪一步：入口完全没反应＝点击没到元素（大概率仍是旧页面，
用 Ctrl+Shift+R 或换一个带查询串的地址打开）；提示停在"已在等系统选择框…"＝点击到了、系统框没弹出来
（那是浏览器/系统层面的事，可用下面的排查清单继续定位）。
