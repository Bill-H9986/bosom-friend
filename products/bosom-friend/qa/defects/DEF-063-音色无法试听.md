# DEF-063：音色只能看名字不能听——"女声·温柔"这类标签无法作为选择依据

> 编号：DEF-063（唯一、终身不变）
> 状态：Fixed
> 严重度：P2　　优先级：高（用户体验，直接影响成片）
> 缺陷类型：需求遗漏 / 设计
> 关联需求：长视频创作（数字人口播）
> 报告人 / 日期 / 环境版本：用户截图（音色下拉列表）/ 2026-09-16 / 0.2.51
> 责任人 / 计划版本：Jay / 待定
> 重开次数：0

## 复现步骤（别人照着做必须能复现）

1. 打开「我的数字人」→「新建数字人」→ 展开「音色」（原生 select 或新版列表）；
2. 8 个音色只有 `晓晓（女声·温柔）` 这类文字标签，没有任何可播放的示例，也没有"怎么选"的说明。

## 期望结果 vs 实际结果

- 期望：每条音色都能一键试听同一句带货口播，听完再定；页面上说清楚该按什么标准挑。
- 实际：只能按标签猜。音色一旦落到数字人形象上就长期复用，猜错的代价是**之后所有成片的声音**。

## 影响范围与发生频率

所有要建数字人的用户，每次新建都命中。

## 根因分析（5-Why，没写完禁止修复）

- 直接原因：`digital-humans/voices` 只返回 `{id, name, gender}`，前端只有 `<select>`，没有试听入口。
- 为什么 1：音色目录只被当成"枚举值"设计，没被当成"需要用户做主观判断的选项"——主观选项没有样例就无法判断。
- 为什么 2：试听要有音频，而当时唯一会出声的链路是长视频分段生成里的 `synthesizeSpeech`（写文件 + ffmpeg 读时长），没有任何"只出音频字节"的出口。
- 为什么 3：`synthesizeSpeech` 把"合成"和"读时长"绑成一个不可分的动作，读时长要 ffmpeg——一个纯播放场景就被迫背上对 ffmpeg 的依赖。
- 根本原因归类：**能力出口按调用方（分段生成）而非按能力本身切分**：试听和分段配音需要的东西不同（前者只要字节，后者要时长），却共用同一个不可配置的函数。

## 修复方案（改根因，不是压表现）

1. 服务端新增 `GET digital-humans/voices/:voiceId/preview`：按需合成样音、按「音色 + 文本」缓存到数据根 `voice-previews/`，直接返回 `audio/mpeg`（带 Range 与 max-age），前端当 `<audio src>` 用；
2. `synthesizeSpeech` 增加 `probeDuration` 选项：试听传 `false`（不读时长、不依赖 ffmpeg），分段生成保持默认 `true`（字幕时间轴与拼接对时都要真实秒数）；
3. 前端「我的数字人」把 `select` 换成带试听按钮的音色列表：同一时间只响一条、正在合成的按钮显示"停止"、失败把真实原因写在列表下方；已试听过的音色标「已试听」，创建前没试听过会提示先听一条；
4. 页面上写清选择标准（先听再选、同一声音后面每条片都用它），并把"已有数字人"卡片也接上试听按钮。

## 回归用例（必须写，验证修复且不破坏旧功能）

`server/test/functional/long-video.spec.ts`：

- 合成后响应的 `content-type` 必须是 `audio/mpeg`（不是 JSON 信封），样音落盘且**同一音色第二次复用同一份缓存**、换文本才新增一份；
- 试听调用 `synthesizeSpeech` 时必须 `probeDuration === false`；
- 未知音色当场拒绝且不去连配音服务；
- 接口给出的每个音色都必须能试听成功（列表与试听路由同一份事实源）。
