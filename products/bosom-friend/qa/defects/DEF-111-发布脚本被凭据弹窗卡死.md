# DEF-111 发布脚本取令牌时被凭据管理器的交互弹窗卡死

| 项 | 值 |
| --- | --- |
| 编号 | DEF-111 |
| 发现日期 | 2026-09-19 |
| 发现方式 | 上传 0.2.58 到 GitHub Release 时，脚本停在「upload attempt 1 (742.8 MB)」不再有输出；查进程发现 6 个 git + 2 个 git-credential-manager 挂着 |
| 严重级 | P2（工具链：无人值守的发布流程会静默挂死，没有任何超时） |
| 状态 | **已修复（0.2.58 发布流程内）** |

## 现象

`publish-release.ps1` 第一步取令牌：

```powershell
$out = ($cred | git credential fill 2>&1 | Out-String)
$token = ($out | Select-String 'password=(.+)$').Matches.Groups[1].Value.Trim()
```

现场表现：脚本没有任何输出、也不退出；任务管理器里留下 6 个 `git.exe` 与 2 个 `git-credential-manager.exe`，
桌面出现两个标题为 **Select an account** 的窗口。

## 根因

`git credential fill` 在凭据管理器**需要交互**（缓存过期、多账户、要求重新授权）时会弹窗等待人工点选，
而不是快速失败或直接读已保存的凭据。脚本把它当成同步的纯函数用，于是无人值守的发布会无限期挂住——
**没有任何超时，也没有任何日志**。

凭据本身一直都在：`cmdkey /list` 能看到 `LegacyGeneric:target=git:https://github.com`（用户 Bill-H9986）。
换句话说，卡住的不是「没有凭据」，而是「取凭据的这条路会弹窗」。

## 修复方案

脚本改为直接读 Windows 凭据管理器（P/Invoke `CredRead`，凭据类型 1 = Generic），绕开 git 的交互层：
按 `CREDENTIAL` 结构取 `CredentialBlob`（UTF-16 口令）。依次尝试三个目标名：
`git:https://github.com`、`gh:github.com:Bill-H9986`、`gh:github.com:`；都取不到就**当场失败并说明**，不进入等待。

## 回归证据

```

local installer bytes=778900239
created release id=391980193 draft=true

```

公开查询复核：`v0.2.58 draft=False -> BosomFriend-Setup-0.2.58.exe size=778900239 state=uploaded`，与本机字节数一致
（v0.2.56 / v0.2.57 同样 `state=uploaded`）。

## 关闭条件

- 脚本改成非交互取令牌后成功发布一版，且失败时快速退出而不是挂起：**已满足**。
