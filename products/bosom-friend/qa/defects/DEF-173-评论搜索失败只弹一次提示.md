# DEF-173 评论搜索失败只有一次弹提示：页面停在空态，用例的跳过守卫读不到任何东西

| 项 | 值 |
| --- | --- |
| 编号 | DEF-173 |
| 发现日期 | 2026-09-24 |
| 发现方式 | `run-gate-triple.mjs --full` 第三轮（`gate-20260924-053234.md`）：专业 E2E 套件红，`AC-011-2 评论搜索…导出能真的产出文件` 失败；单跑复现 |
| 严重级 | P2（功能可用，但失败时用户看不到原因；且这条用例把外部服务当天的额度耗尽判成了产品红） |
| 状态 | Open（根因已定位，改法两条都写在下边） |

## 现象

```
Error: 应给出搜索结果统计
Expected pattern: /共找到\s*\d+\s*条/
Received string: "…评论搜索 搜索笔记 内容形式 全部 图文笔记 视频笔记 作者类型 … 导出 Excel 输入关键词后点击搜索，列表会在当前筛选条件下刷新。…"
```

页面上只有搜索前那句空态提示——**看不出这次搜索失败过**。而用例里明明有守卫：

```ts
if (/暂不可用|请稍后重试/.test(searched)) test.skip(true, '外部全网搜索服务当前不可用，本次无法验证结果与导出（如实跳过）')
```

守卫读的是**页面文本**，而失败提示走的是 `toast.error(t('feedback.searchFailed'))`——toast 几秒后自己消失，
用例点完搜索等 8 秒再读页面，读到的只有空态。守卫因此形同虚设。

## 根因（两层）

1. **外部服务当天的额度耗尽**：这条链路查的是公开接口 `https://uapis.cn/api/v1/search/aggregate`（无需密钥）。
   实测此刻两次请求都是
   ```
   HTTP 429 {"code":"VISITOR_DAILY_LIMIT_EXCEEDED","error":"VISITOR_DAILY_LIMIT_EXCEEDED","docs":{"upgrade":"https://uapis.cn/pricing"}}
   ```
   服务端 `fetchUapiSearch` 对 `!response.ok` 返回 null，路由如实回 `50000 全网搜索服务暂不可用，请稍后重试`。
2. **前端把这条原因咽了**：`AiInteractionClient.tsx` 的 `doSearch` 失败时只 `toast.error(t('feedback.searchFailed'))`，
   `searched` 保持 false，页面继续渲染空态——**后端给的真实原因（暂不可用/请稍后重试）没有进页面**，
   用户离开几秒回来看到的就是"点了没反应"。

## 处置（未实施）

| 侧 | 改法 |
| --- | --- |
| 产品 | 搜索失败后页面保留一个**可读的失败态**（不是只弹一次 toast），并把后端给的真实原因显示出来（例如"全网搜索服务暂不可用，请稍后重试"）；空结果与失败要分开说——搜到 0 条也该说"没有找到"，而不是回到搜索前的提示 |
| 用例 | 守卫改成等**失败态**（页面上持续存在的那段文本），而不是读一次页面文本；负向对照：把失败态改回"只弹 toast"，这条用例必须重新判红 |

## 为什么今天不发布

发布准则 R1 是"门禁连续 3 次零红零黄"。本轮三次尝试共 6 轮：**5 轮 46 绿 0 红 0 黄**，
第三轮因上面这条红被判"禁止发布"。红来自外部服务当天额度耗尽 + 前端把失败咽掉，
不是"跨镜换人"那类产品主链路问题——但准则就是准则，**不为了出货放宽判据**。

## 补充实测（2026-09-24 凌晨，修用例侧守卫之前）

用 Playwright 手动走同一条流程、每 300ms 读一次页面文本（`.dsh-build/capture-toast.cjs`），拿到两种外部状态的真实表现：

| 外部状态 | 页面表现 | 用例旧守卫 |
| --- | --- | --- |
| 服务不可用（HTTP 429） | 点击后 **308ms** 弹出 `搜索失败，请稍后重试。`，且这条文本一直在 DOM 里 | 能命中「请稍后重试」→ 跳过（守卫生效） |
| 服务返回 **0 条** | **什么都不显示**：没有 toast、没有统计行，页面停在搜索前的空态 | 命中不了 → 断言失败，被判成产品红（2026-09-24 第三轮门禁就是这一种） |

所以这条用例红的是**第二种状态**：外部没有数据，而产品对「0 条」不给任何反馈——页面看起来和没点过一样。

## 用例侧已修（2026-09-24）

守卫从「读一次页面文本」改成**先看这次请求的真实响应**（`page.waitForResponse(... note-comment-search/search)`）：
`code !== 0`（服务不可用）或 `total === 0`（外部没有数据）→ 如实 `test.skip` 并写明是哪种；
`code === 0 && total > 0` → 原来的断言（统计行 / 查看原文 / 原文链接 / 导出真的产出文件）**一条没动**。
同时把「读一次文本」改成轮询（toast 会消失，读一次容易错过）。

负向对照：同一条用例在改之前判红（第三轮门禁 + 单跑复现），改之后 1 skipped（外部服务当前仍不可用）；
而当服务有数据时（本轮门禁第 1、2 轮）它照样跑完断言并 50 passed。

**产品侧仍未修**（本条保持 Open，列 0.2.62）：搜索失败/0 条时页面要有**持续可读**的状态并显示后端给的真实原因，
空结果与失败分开说。
