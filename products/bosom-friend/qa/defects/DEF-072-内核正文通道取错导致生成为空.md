# DEF-072：内核正文通道取错——所有大模型生成都拿不到正文，报「未知错误」

> 编号：DEF-072（唯一、终身不变）
> 状态：Fixed
> 严重度：P1　　优先级：高（用户可见、长视频全链路不可用）
> 缺陷类型：功能
> 关联需求：REQ-022（长视频创作）
> 报告人 / 日期 / 环境版本：2026-09-16 真机全流程实测发现 / 0.2.52 装机版
> 责任人 / 计划版本：Jay / 0.2.53
> 重开次数：0

## 复现步骤

1. 在设置里配好 Agnes 网关（提供方 id `custom-1`，模型 `agnes-2.5-flash`）；
2. 进「长视频创作」填主题，点生成；
3. 任务在 1 分钟后失败，错误是「大模型没有返回可用的稿件：未知错误」。

## 期望结果 vs 实际结果

- 期望：模型返回口播稿与分镜表，任务继续往下跑。
- 实际：每次生成都空手而归，界面只给一句没有信息量的「未知错误」。

## 影响范围与发生频率

**所有走内核的大模型生成**（长视频稿件、分镜表、提示词增强、AI 对话、客服回复）100% 失效。
单元测试全绿——因为它们注入的是测试桩，而桩按"增量通道"形状造数据。

## 根因分析（5-Why）

- 直接原因：内核客户端只收 `assistant/chunk` 里 `chunk.type === 'text-delta'` 的增量；
  而 agnes 系列模型（`api: openai-completions`）**全程不推增量**，正文只出现在回合结束的
  `assistant/message.content[].text` 里。增量通道因此永远是空串。
- 为什么 1：通道形状是照 DSH 官方流式形状写的（真流式模型确实发 text-delta），
  换到厂商网关后形状变了，但没有任何一层校验"这次到底有没有收到正文"。
- 为什么 2：空正文被折叠成 `error === undefined`，调用方再拼上兜底文案「未知错误」——
  真实原因（是超时？是空响应？是被拒？）在这一步被抹掉了，现场只剩一句无信息量的话。
- 为什么 3：**等待上限 120 秒**也是致因之一：内核会话默认带全套工具，系统提示又要求模型
  「先查后答」，于是模型会把生成请求当待办去调工具。实测不约束时 180 秒仍未结束、正文为空；
  加上「纯文本生成、不要调用工具」的约束后，同一请求 12~14 秒返回完整正文。
- 根本原因归类：**跨进程的协议形状假设没有在真实网关上验过**，且失败被折成无信息量的兜底文案，
  于是"取错通道"这种确定性缺陷拖到了真机全流程才暴露。

## 修复方案（改根因）

1. 新增 `assistantMessageTextOf()`：从 `assistant/message.content[].text` 取整段正文，
   与增量通道**互补**（工具回合的 content 只有 tool-call 块，天然返回空串，不会被当正文）；
2. 编排循环两条通道都收：增量优先（真流式时它才是完整正文），增量为空才回落到整段通道；
3. 等待上限 120s → 240s，给慢响应留余量；
4. 新增 `TEXT_ONLY_GUARD`：所有"给要求、要正文"的用途在提示词最前面声明**不要调用工具**；
5. 顺手修掉 `/ai/chat` 里把路由写死成 `'agnes'` 的问题（提供方 id 不是 agnes 时找不到路由）。

多 text 块拼接、畸形载荷与空载荷返回空串。
