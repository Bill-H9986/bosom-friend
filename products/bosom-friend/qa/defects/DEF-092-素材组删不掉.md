# DEF-092：素材组多了两条却删不掉——管理入口整条被隐藏

> 编号：DEF-092（唯一、终身不变）
> 状态：Fixed
> 严重度：P2　　优先级：中（脏数据清理不掉，用户会一直看见两条不属于自己的组）
> 缺陷类型：功能/完整性
> 关联需求：REQ-007（素材分组）、REQ-001（内容创作首屏）
> 报告人 / 日期 / 环境版本：用户报障（"为什么内容创作又多了两个素材组？要么就只一个素材组！要么就提供添加删除功能并各素材组数据独立！"）/ 2026-09-17 / 0.2.54
> 责任人 / 计划版本：Jay / 0.13.10
> 重开次数：0

## 复现步骤

1. 打开「内容创作」：素材组标签栏里出现三条——「默认素材组」「AC-007-2目标组1789400482385」「AC-007-2源组1789400482385」；
2. 想删掉多余的两条：没有入口。

## 期望结果 vs 实际结果

- 期望：要么只有一个素材组，要么能自己新建 / 重命名 / 删除，各组件内容互不干扰。
- 实际：那两条既不是用户建的，也删不掉。

## 影响范围与发生频率

只有一台机器上出现（本例），但成因是流程性的，任何一次失败的验收跑都会留下同样的残留。

## 根因分析（5-Why）

- 直接原因（数据从哪来）：`qa/e2e/specs/ac-verification.spec.ts` 的 AC-007-2 用例自建两个素材组，
  自删写在用例**末尾**——断言一失败就永远走不到那两行，空组留在**真实数据根**里
  （E2E 按设计打的就是正在运行的开发实例）。这与 `qa/e2e/README.md` 的规矩 #1"失败也会在 finally 里清理"不符。
- 直接原因（为什么删不掉）：`PlanTabBar` 只在**素材组多于一个**时才渲染，且渲染时只画标签，
  把「更多（重命名/删除）」与「新建」两个入口连同组件一起丢掉了（`MorePanel` 成了没人引用的死代码）。
  于是"多出来的组"唯一能清理的地方也没了。
- 为什么 1：标签栏的隐藏规则是"单组不显示"（避免一条没有信息量的横条），
  但管理入口也挂在这条横条上——**入口与展示耦合**，一隐藏就全没了。
- 为什么 2：服务端没有任何防丢数据的约束：默认组能删（它是首屏落点，删了内容变孤儿），
  有内容的组也能删（内容跟着消失）。
- 根本原因归类：**管理入口寄居在"展示组件"上**，加上 E2E 清理没走 finally。

## 修复方案（改根因）

1. `PlanTabBar` 恢复「更多（切换/重命名/删除）」与「新建」；有素材组就显示这条横条
   （一个组时也显示——它是唯一的管理入口，隐藏它等于让用户没法清理）；
2. 默认素材组**不可删**：界面按钮置灰并说明原因，服务端同样拒绝
   （它是内容创作的首屏落点，删了内容就成了孤儿）；
3. 组里还有内容时**拒绝删组**并如实报出条数（不替用户把内容搬走——那看起来像"东西自己跑了"）；
4. E2E 的 AC-007-2 改成建一个记一个、在 `finally` 里删干净；
5. 清掉该机器上两条残留空组（先备份 `material-groups.json`）。

## 回归用例

- `server/test/functional/content-params.spec.ts`：默认组不能删（拒绝 + 还在）；有内容的组拒绝删并报条数，
  清空后可删、重复删如实报不存在；
- `qa/e2e`：AC-007-2 的清理进 `finally`（失败也不再留残留）。

## 关闭条件

- 回归通过 + 浏览器实测（管理面板可开、默认组的删除置灰）+ 机器上的残留已清 + 证据归档。
