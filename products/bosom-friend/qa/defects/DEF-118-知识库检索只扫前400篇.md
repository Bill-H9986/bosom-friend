# DEF-118 知识库检索只扫前 400 篇：新写的笔记永远注不进对话

| 项 | 值 |
| --- | --- |
| 编号 | DEF-118 |
| 发现日期 | 2026-09-20 |
| 发现方式 | 门禁「知识库蒸馏链路」连续红：`注入·相关指令命中笔记` 与 `注入·上下文包含专属事实` 两条失败 |
| 严重级 | **P1**（功能不可用且无声：用户新记的知识永远不会进模型上下文） |
| 状态 | **已修复**（本机 0.2.59 装机版实测通过） |

## 现象

门禁自检写入一篇带专属事实的笔记，再用「写一条重庆夜景口播脚本」去查注入预览：
**命中的永远是另外两篇旧笔记**，自检笔记一次都没进过。换成不带检索词的名字也一样。

## 根因

`server/src/knowledge-distill.ts` 的 `retrieveKnowledge`：

```ts
const entries = Object.entries(knowledge.notes)
  .filter(([path]) => !path.startsWith(AUDIT_FOLDER + '/'))
  .slice(0, MAX_NOTES_SCANNED)   // ← MAX_NOTES_SCANNED = 400，按**写入顺序**截断
```

`knowledge.notes` 的顺序就是写入顺序，知识库当时是 **466 篇**，新写的笔记排在最后 →
`slice(0, 400)` 直接把它切掉。检索从不报错、页面也无异样——**只是永远查不到**。
这不是夹具问题：0.2.58 上同样是红的（当时的自检也没通过）。

## 修法

把"按写入顺序截断"换成"**按相关性粗排后再在预算内精排**"：

- 篇数没超预算（2000）时全扫；
- 超了就先用"标题 + 正文前 400 字的命中数"粗排，取最像的 2000 篇再逐段精排；
- 最终判据仍是原来的 `scorePassage`（标题命中加权 + 检索词覆盖数），只取前 3 段。

顺带把门禁自检笔记的名字改成带检索词的（`重庆夜景口播要点-<stamp>`）：
名字取成"自检知识-xxxxxx"时它只靠正文拿到 2~3 分，知识库同类笔记一多就挤不进前 3，
门禁会变成"看知识库里有多少条同类笔记"，时红时绿。

## 证据

| 项 | 结果 |
| --- | --- |
| 修复前 | `KNOWLEDGE_DISTILL FAIL checks=12 pass=10 fail=2`（命中 `知识库/原文/...` 两篇旧笔记） |
| 修复后 | `KNOWLEDGE_DISTILL PASS checks=12 pass=12 fail=0`，自检笔记排在命中列表**第一位** |
| 装机态 | 装在 0.2.59 上的服务端同步该修复后复跑通过 |

## 为什么这条值得单独记

它是"无声的功能缺失"：没有报错、没有红灯（产品自检不写新笔记就不会暴露）、
用户只会觉得"我明明记过，AI 却不知道"。**凡是"取前 N 条"的截断都要问一句：N 之外的那部分，
用户还看得见吗？**
