## 1 背景与目标

### 1.1 背景

2026-10-10 的教训：执行者用内部 id 与源码知识把流程点通了，产品负责人按同一份说明却点不通。
根因不是「没测」，而是**测的人知道得太多**——他看得见选择器、接口与日志，陌生人看不见。

旧《真人测试清单》方向是对的（只点页面、只看页面），但它的清单按板块组织、判据是「页面看见什么」，
既没有覆盖主链路的完整五环，也没有回答「失败时用户看到什么」。

### 1.2 目标（编号化）

| 编号 | 目标 | 判据 |
| --- | --- | --- |
| **G1** | 定位只用可见文字 | 剧本中出现的每一个操作对象，都是页面上肉眼可见的中文文字 |
| **G2** | 主链路五环全覆盖 | 账号 → 内容 → 出片 → 发布 → 数据，每环有动作、可见判据与失败判据 |
| **G3** | 失败也是剧本的一部分 | 每环写明失败时用户应当看到什么；看不到人话原因即判失败 |
| **G4** | 阻塞不等于失败 | 已知阻塞（登录态失效等）如实记录并停在该环，**不得**绕过、**不得**假装成功 |

## 2 术语

| 术语 | 定义 |
| --- | --- |
| **陌生人** | 从没看过这个项目的源码、接口、数据库与内部编号的人（产品负责人就是标准陌生人） |
| **可见文字** | 页面上肉眼能看到的中文文字，包括按钮文案、输入框占位符、提示、列表项、对话框标题 |
| **可见结果** | 页面上出现的业务对象变化：新增一条、字段值变化、数量变化、状态变化 |
| **假阳性** | 看起来通过、实际没办成的判定（清单见 BFS-104-R 第 7 节） |
| **三选择** | 失败时用户应看到：断点继续 / 重新生成 / 放弃 |
| **阻塞** | 因外部条件（平台登录态、厂商限流）走不下去；**必须**如实上报，不算剧本通过 |

## 3 执行流程（六步，对齐 BFS-104-R 第 4 节）

| 步 | 动作 | 陌生人怎么做 | 产出 |
| --- | --- | --- | --- |
| 1 | **发起** | 在对话主通道里，用**人话**说出剧本里的那句话 | 任务 id（页面上可见的对话时间与消息） |
| 2 | **监测** | 观察页面上依次出现的过程（谁在干活、干到哪） | 过程截图或记录 |
| 3 | **交叉** | 核对三件事是否一致：**页面上业务对象变了** + **助手说办成了** + **列表/数字确实变了** | 一致性结论 |
| 4 | **握手** | 确认产品 AI 真的在回应（不是「内核没启动」这类错误文案） | 一次真实对话记录 |
| 5 | **记录** | 把每步的可见文字与截图存进 `qa/evidence/陌生人剧本/<日期>/` | 记录文件 |
| 6 | **立缺陷** | 任何一步不通过，当场登记缺陷编号 | DEF 编号 |

**第 4 步为什么单独列**：内核是懒启动的，服务页面打得开不代表 AI 可用（DEF-252 教训）。

## 4 主链路五环剧本

> **每环三问**：那句话是什么？办成了页面上必须看到什么？办不成页面上必须看到什么？

### 4.1 第一环 · 账号（把号接进来）

| 项 | 内容 |
| --- | --- |
| **那句话** | 「帮我添加一个抖音账号」 |
| **入口（用看得见的文字找）** | 侧栏「添加频道」；或对话里直接说那句话 |
| **办成了必须看到** | ① 页面上出现扫码/登录界面或明确的操作指引；② 完成后账号列表里出现这个号（能看到昵称或头像）；③ 账号状态显示为已登录 |
| **办不成必须看到** | 人话原因（例如「登录态已失效，需要重新扫码」）+ 下一步动作；**禁止**只显示英文错误或一直转圈 |
| **判红** | 页面没有任何变化；或显示成功而列表里没有这个号 |
| **已知阻塞** | 抖音登录态失效（当前主链路阻塞项）；阻塞时如实记录并停在本环 |

### 4.2 第二环 · 内容（出一份稿子）

| 项 | 内容 |
| --- | --- |
| **那句话** | 「写一条关于（主题）的图文，存进草稿箱」 |
| **入口** | 对话主通道（首选）；或侧栏「内容创作」 |
| **办成了必须看到** | ① 页面上出现 AI 的回复（不是固定占位文案）；② 草稿箱里多出 1 条，标题与主题相关；③ 打开这条草稿能看到正文内容 |
| **办不成必须看到** | 人话原因（例如「还没有配置大模型」）+ 三选择 |
| **判红** | 回复是一段本地模板 / 幻灯片式占位内容；或助手说已存草稿而草稿箱数量没变 |
| **已知风险** | 内容创作页部分按钮存在「点了没反应」的已知缺陷（DEF-250）；对话通道办不成时必须给出可读原因 |

### 4.3 第三环 · 出片（把稿子变成片子）

| 项 | 内容 |
| --- | --- |
| **那句话** | 「做个 15 秒的视频」或「把这版稿子做成片子」 |
| **入口** | 对话主通道；或侧栏「长视频创作」「我的数字人」 |
| **办成了必须看到** | ① 页面上出现生成进度（到第几镜、还要多久）；② 完成后能预览成片，片长与所选档位一致；③ 生成记录里能查到这一条 |
| **办不成必须看到** | 人话原因 + 三选择（断点继续 / 重新生成 / 放弃）；限流时**必须**说明「免费档每分钟 1 次，预计需要 N 分钟，可能被打断」 |
| **判红** | 进度条停在某处不动且没有任何说明；或宣布完成但成片打不开、时长与档位不符 |
| **已知风险** | 免费档 `freeTierRpm=1` 与 18 镜以上的长片在数学上不兼容（DEF-249）：开跑前**必须**如实告知边界 |

### 4.4 第四环 · 发布（把片子发出去）

| 项 | 内容 |
| --- | --- |
| **那句话** | 「把这条发到抖音」 |
| **入口** | 对话主通道；发布必须由用户明确指令触发 |
| **办成了必须看到** | ① 发布前出现明确的确认（发布属拍板类动作）；② 发布记录里出现这条，带平台作品标识（可打开）；③ 账号页面对应作品能同步回来 |
| **办不成必须看到** | 人话原因（例如「账号未登录」「平台要求人工确认」）+ 三选择；**禁止**显示成功而平台上没有 |
| **判红** | 未经用户明确指令就发布；或显示成功但平台查不到；或发布动作卡在页面上根本不出现 |
| **已知阻塞** | 发布动作卡渲染缺陷（DEF-251，Open）与「已核验」回填缺口（DEF-247，Open）：当前会停在「已申请」，**这不是陌生人操作错误，必须如实记录** |

### 4.5 第五环 · 数据（看清楚结果）

| 项 | 内容 |
| --- | --- |
| **那句话** | 「这周数据怎么样」或「这条作品数据如何」 |
| **入口** | 对话主通道；或侧栏「数据中心」「全局监控」 |
| **办成了必须看到** | ① 页面上出现具体数字（播放、互动、粉丝等）；② 每条数字能指到是哪个号、哪个时间段；③ **没采集到的指标不显示成 0**，而是显示为空或「暂无数据」 |
| **办不成必须看到** | 人话原因（例如「这个号还没有同步过作品数据」）+ 下一步动作 |
| **判红** | 把没采集的指标显示成 0；或数字与平台后台明显不符且没有说明 |

## 5 定位禁用清单（违反即本次验收作废）

| 禁止 | 为什么 |
| --- | --- |
| `data-testid`、`id`、`class`、`xpath` 等内部选择器 | 陌生人看不见它们；能选通不代表用户找得到 |
| 源码里的函数名、路由名、字段名 | 陌生人不会用它们操作 |
| 接口响应体、日志、数据库查询作为通过依据 | 这些是 B 档证据，只作诊断（BFS-104-R 第 3.1 节） |
| 用「页面出现了某段文字」判成功 | 可能命中的是历史消息（假阳性第 2 条） |
| 直接改数据文件伪造业务结果 | 违反 BFS-305 与验收红线 |
| 用脚本代替人的点击与输入（除截图与录屏） | 本次验收要验的正是「陌生人能不能办成」 |

**允许的工具**：截图、录屏、复制页面文字、聊天记录导出。**只用这些**。

---

## 6 记录格式

每条剧本记录**必须**包含：

    【环】第 N 环 · 环节名
    【那句话】「……」（实际输入的原话）
    【时间】YYYY-MM-DD HH:mm（时区）
    【可见文字】我在页面上看到的关键文字（原样抄录）
    【可见结果】业务对象怎么变的（新增 / 字段值 / 数量 / 状态）
    【一致性】助手说的与页面上看到的是否一致
    【结论】PASS / FAIL / 阻塞
    【异常】缺陷编号（若有）

证据存放：`qa/evidence/陌生人剧本/<日期>/`，文件名形如 `第N环-说明.png`。

## 7 判据与验收（本件自身）

| # | 判据 | 怎么验 |
| --- | --- | --- |
| V1 | 五环齐全 | 账号 → 内容 → 出片 → 发布 → 数据每环都有动作、可见判据、失败判据 |
| V2 | 无内部定位 | 全文不出现 `data-testid` 或源码标识符作为操作手段 |
| V3 | 失败路径完整 | 每环都写明失败时用户应看到什么 |
| V4 | 阻塞诚实 | 已知阻塞逐条带缺陷编号，且写明「不算通过」 |
| V5 | 可执行 | 一个没看过项目的人拿到本件，能照着走完并能判断通过与否 |

**未达成时的处置**：V2 违反即本次验收作废重跑（判据本身失效）；V1 / V3 缺项当场补齐。

## 附录 A · 执行卡（可打印，逐项打勾）

| # | 环 | 那句话 | 看到就算过 | 通过 |
| --- | --- | --- | --- | --- |
| 1 | 账号 | 帮我添加一个抖音账号 | 账号列表出现这个号，状态为已登录 | ☐ |
| 2 | 内容 | 写一条关于（主题）的图文，存进草稿箱 | 草稿箱多 1 条，标题与主题相关 | ☐ |
| 3 | 出片 | 做个 15 秒的视频 | 进度可见 → 成片可预览且时长正确 | ☐ |
| 4 | 发布 | 把这条发到抖音 | 发布确认 → 发布记录带可打开的作品标识 | ☐ |
| 5 | 数据 | 这周数据怎么样 | 具体数字 + 能指到号与时间段；未采集的不显示 0 | ☐ |
| 6 | 失败 | 任选一环注入失败（断网 / 未登录 / 超时） | 人话原因 + 三选择 | ☐ |

**判定**：1~6 全部打勾才算主链路可用；任何一环打不上勾，按第 6 节记录并立缺陷。

## 附录 B · 假阳性速查（出现即判红）

1. 接口返回成功，但页面上没有结果；
2. 页面上出现某段文字（可能是历史消息），业务对象没变；
3. 后端先执行、前端补显示；
4. 直接调接口或写数据文件冒充「用户办成了」；
5. 用内部选择器定位成功，但页面可见文字走不通；
6. 只走成功路径，没走失败路径；
7. 工具返回「已交给前端」却当成已完成；
8. 只跑类型检查或构建就宣布可用；
9. 只看页面能打开就宣布服务可用（未验内核握手）。
