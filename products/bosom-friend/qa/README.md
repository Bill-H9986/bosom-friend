## 1 背景与目标

### 1.1 背景

旧 qa 入口写着「**最高测试权限：S 级前端监考 v3**」并要求所有验收必须由 APP 前端发起；
这条口径已被 ADR-005 与 BFS-104-R 取代——**页面不再是唯一入口，管家才是执行者**，
验收看的是「一句话办成了没」，而不是「页面点得对不对」。

同时旧入口硬编码 `http://127.0.0.1:3080/bosom-friend/`，而开发态实际端口由启动脚本决定；
端口写死在文档里，等于给执行者埋了一个必然踩的坑。

### 1.2 目标（编号化）

| 编号 | 目标 | 判据 |
| --- | --- | --- |
| **G1** | 三十秒知道该跑哪条门禁 | 本件按用途给出命令与通过标志 |
| **G2** | 判据口径唯一 | 完成判据一律指 [验收标准-一句话端到端](../docs/规范/验收标准-一句话端到端.md)，本件不另立 |
| **G3** | 脚本不膨胀 | 脚本只有两种合法用途：门禁（可重复、有 PASS/FAIL）与一次性诊断（查清即删） |
| **G4** | 失败不掩盖 | 任何门禁判红必须如实上报，不得改结论、不得用绿灯覆盖红 |

## 2 术语

| 术语 | 定义 | 出处 |
| --- | --- | --- |
| **门禁** | 可重复执行、有 PASS/FAIL 的自动检查 | BFS-108.1 |
| **一次性诊断** | 为查清某个问题临时写的脚本，结论产出后删除或升级为门禁 | BFS-305.3 |
| **C 档证据** | 一句话在页面上走通的证据（唯一算数的完成依据） | BFS-104-R 第 3.1 节 |
| **三方交叉** | 工具返回 / 助手回复 / 落库或页面数据三者一致 | BFS-104-R 第 3.2 节 |
| **负向对照** | 证明门禁真的会红的自检（`--selftest`） | BFS-108.5 |
| **陌生人的眼睛** | 只用页面可见文字定位，禁用内部 id 与源码知识 | BFS-103、2026-10-10 教训 |

## 3 门禁清单（按用途）

> **口径**：下表按**用途**归类，具体调用关系以 `qa-all.mjs` 与 `run-gate.mjs` 的实际实现为准；
> 本件不复制门禁内部逻辑，避免两处维护同一事实。

### 3.1 总入口

| 命令 | 作用 | 通过标志 |
| --- | --- | --- |
| `node products/bosom-friend/qa/qa-all.mjs` | 全量门禁总入口 | 退出码 0 |
| `node products/bosom-friend/qa/run-gate.mjs` | 静态与边界门禁（含直连检查、补丁一致性等） | 退出码 0 |
| `node products/bosom-friend/qa/session-start.mjs` | 新会话启动摘要（当前状态 + 未闭环 + 运行状态），只读 | 打印摘要 |

### 3.2 文档门禁

| 命令 | 作用 | 通过标志 |
| --- | --- | --- |
| `node products/bosom-friend/qa/verify-docs-index.mjs` | 每个文档落在登记目录；ADR 索引与状态合规 | `DOCS_INDEX_OK` |
| `node products/bosom-friend/qa/verify-docs-standard.mjs` | `docs/规范/` 下现行 A 级文档的十二项结构 | `DOCS_STANDARD_OK … exceptions=0` |
| `node products/bosom-friend/qa/verify-docs-standard.mjs --selftest` | 负向对照：证明结构门禁会红 | `SELF_TEST_OK` |

### 3.3 能力与业务门禁（举例）

## 4 脚本的两条合法用途

| 用途 | 要求 | 例子 |
| --- | --- | --- |
| **门禁** | 可重复、有 PASS/FAIL、进 `qa/`、新断言附负向对照 | `verify-docs-standard.mjs` |
| **一次性诊断** | 查清即删；删除前登记结论 | 排查某个现场问题的临时探针 |

**禁止**：用脚本绕过管家办业务（BFS-305.1）；把一次性诊断沉淀成常驻脚本（BFS-305.3）。
**判断口诀**：这件事用户自己能在界面上完成吗？不能，就该补工具，而不是写脚本。

## 6 判据与验收（本件自身）

| # | 判据 | 怎么验 |
| --- | --- | --- |
| V1 | 无废止口径 | 全文不出现「S 级前端监考」「最高测试权限」作为现行要求 |
| V2 | 无硬编码端口 | 全文不写死服务端口作为判据 |
| V3 | 命令可用 | 第 3 节列出的命令在磁盘上都存在 |
| V4 | 判据不重复 | 完成判据只引 BFS-104-R，不另立标准 |
| V5 | 脚本口径一致 | 第 4 节与 BFS-305.2 一致 |

**未达成时的处置**：V1 / V2 违反即本件失效（会误导执行者）；V3 违反当场修正。
