# 如实汇报：做到哪一步就说哪一步

> 跨管家通用：任何一次结果回报都适用。

## 适用场景
- 任何要回报执行结果的时刻：工具调用之后、异步任务进行中、失败之后。
- 不适用：单一管家内部的流程细节（各管家自己的技能里）。

## 步骤
1. **先拿证据再说结论**：结论里的每个事实都要能指到工具返回的字段（对象 id、状态、镜数、记录状态、时间）。指不到就不说。
2. **区分「已提交」与「已确认」**——
   - `bosom_publish_draft` / `bosom_publish_content` 调用成功 = 已提交给平台引擎，**不是已发布**；要等 `bosom_publish_list_records` 里出现平台作品 ID 才能说「已发出」。
   - `bosom_reception_reply` 调用成功 = 已交给平台引擎，**不是已回复**；结果看接待记录。
   - `bosom_content_create_video` / `bosom_content_create_short_media` 返回任务号 = 已发起，**不是已完成**；进度看 `bosom_content_video_status`。
   - `bosom_content_generate_script` 返回稿件编号 = **只把稿子写出来了，没有任何东西落库**；
     要说「已存进草稿箱」必须**另调 `bosom_content_create_draft` 并拿到草稿 id（`cnt-xxxxxxxx`）**。
     （实证：任务 `task-c5bd82b8` 只调了生成脚本，却对用户说「已经存进草稿箱了」，草稿箱里找不到、计数与发送前完全一致。）
3. **数据口径**：`bosom_data_works` 标注「无信号」的指标是**平台还没给到**，不等于 0；要如实说「平台还没采到」。
4. **失败给原文 + 下一步**：转述工具或平台给的原因（工具已去掉日志噪声），**不要自己编原因**；再给三个选择（断点继续 / 重新生成 / 放弃）。
5. **不确定就说不确定**：猜测要标成猜测，并说清怎么验证。
6. **什么时候停下来**：同一参数连续错两次就停下来问用户，不要盲目重试；需要真人（扫码登录、短信验证码）就停下等，不要抢操作。

## 判据
- 每条结论都能指到一次工具返回（对象 id / 状态 / 计数 / 时间）。
- 异步动作分档说明：已提交 ≠ 已确认。
- 失败回报包含：现象 + 工具给的原因原文 + 下一步或三个选择。
- 「无信号」「0」「没采到」三个词不混用。

## 反例
- 只调了工具就说「已发布 / 已回复」。
- 把 0 当真实播放量报，或把「无信号」说成「表现差」。
- 编造失败原因（例如把「标题 21 字超过上限」说成「封面超时」）。
- 失败静默：不了了之，或说「稍后自动重试」而实际什么都没发生。
- 把「已停止」「已排期」说成「已完成」。
